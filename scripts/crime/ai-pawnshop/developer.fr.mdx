ai-pawnshop n’a **aucun export, event ni state bag** pour les autres scripts. Les boutiques et les casses sont des données du panneau, et les objets et l’argent passent par AI Core.

## Argent

Les ventes aux prêteurs sur gages vont sur le **Money account** du panneau avec le motif de registre `pawn:<shopId>` (par exemple `pawn:pawn_vinewood`).

## Quels véhicules une casse accepte

Une casse n’accepte que les véhicules du monde. Elle refuse :

- les véhicules créés par le serveur (type de population 7, « mission ») : locations, voitures de métier et de service, voitures possédées sorties par un garage, le fourgon blindé, et tout véhicule que votre propre script fait apparaître sur le serveur ;
- les véhicules enregistrés dans ai-vehicles (une plaque possédée).

Ainsi, un véhicule créé depuis le serveur avec le `spawnVehicle` de la lib ne peut jamais être démonté, ce qui protège les véhicules de travail et les locations sans code supplémentaire.

## Alimenter un prêteur sur gages depuis votre script

Une boutique achète tous les objets listés sous **What it buys**. Pour permettre aux joueurs de vendre le butin de votre script, donnez-leur un objet et ajoutez-le à la liste d’une boutique dans le panneau ; aucun code n’est nécessaire du côté d’ai-pawnshop.

## Callbacks privés

Le contrat propre du script (`resource/common/pawn.ts`). Le serveur vérifie la distance, le stock et le temps de recharge à chaque appel. Ils peuvent changer d’une version à l’autre : ne les appelez pas depuis d’autres ressources.

| Nom | Direction | Ce qu’il transporte |
| --- | --- | --- |
| `ai-pawnshop:offers` | callback client | `(shopId)` : répond `{ ok, offers }`, ce que cette boutique achète et que le joueur porte. |
| `ai-pawnshop:sell` | callback client | `(shopId, item, count)` : vendre des objets. |
| `ai-pawnshop:scrapStart` | callback client | `(yardId, netId)` : commencer à démonter un véhicule ; le serveur exécute la barre de progression et paie. |
