<Callout type="info">
Do not call ai-appearance or read its table from your script. Use AI Core's appearance layer: lib `appearance` (server `appearance.get(charId)`, client `appearance.apply(ped, look)`, `appearance.read(ped)`, `appearance.openMenu(...)`, `appearance.wearOutfit(outfit)`, `appearance.reloadSkin()`), or `aiLib.appearance` in Lua. It works with every clothing script AI Core supports, so the owner can replace ai-appearance. See the [lib reference](/docs/developers/api/lib-client).
</Callout>

## Client exports

Typed `AiAppearanceClientExports` in `@aifivem/shared`. AI Core's appearance adapter calls them.

### ApplyAppearance

Puts an ai-appearance look on a ped.

**Side:** Client · **Waits:** no

```ts title="Signature"
ApplyAppearance(ped: number, appearance: unknown): boolean
```

```lua title="Lua"
local ok = exports['ai-appearance']:ApplyAppearance(ped, look)
```

#### Parameters

<TypeTable
  type={{
    ped: { type: 'number', description: 'Ped handle. It must already have the look\'s model (create it with that model first).', required: true },
    appearance: { type: 'Appearance', description: 'ai-appearance\'s own look JSON (`version: 1`), as stored in `ai_appearance_characters.data`. Treat it as opaque.', required: true },
  }}
/>

#### Returns

`boolean`: `true` when the look was applied. `false` when the look is invalid or the ped's model is not the look's model.

### GetPedAppearance

Reads the look the local player wears.

**Side:** Client · **Waits:** no

```ts title="Signature"
GetPedAppearance(ped: number): unknown
```

#### Returns

The local player's `Appearance`, or `null` for any other ped.

### WearOutfit

Puts a job outfit (uniform) on the local player. Only the listed pieces change, and the outfit is never saved as the player's own look.

**Side:** Client · **Waits:** no

```ts title="Signature"
WearOutfit(outfit: JobOutfit): void
```

```lua title="Lua"
exports['ai-appearance']:WearOutfit({ components = { { id = 11, collection = '', index = 55, texture = 0 } }, props = {} })
```

#### JobOutfit

<TypeTable
  type={{
    components: { type: 'OutfitPiece[]', description: 'Clothing components (GTA component ids 0-11: 4 legs, 6 shoes, 8 undershirt, 11 torso...).', required: true },
    props: { type: 'OutfitPiece[]', description: 'Props (GTA prop ids: 0 hat, 1 glasses, 2 ears, 6 watch, 7 bracelet).', required: true },
  }}
/>

#### OutfitPiece

<TypeTable
  type={{
    id: { type: 'number', description: 'The component or prop id.', required: true },
    collection: { type: 'string', description: 'The clothing collection name; `""` for the base game.', required: true },
    index: { type: 'number', description: 'The drawable index inside that collection (0-1023). For a prop, -1 takes it off.', required: true },
    texture: { type: 'number', description: 'The texture (colour variant) of the drawable.', required: true },
  }}
/>

#### Returns

Nothing.

### ReloadSkin

Puts the saved look back on the local player (takes a job outfit off). **Side:** Client · **Waits:** no.

```ts title="Signature"
ReloadSkin(): void
```

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance } from "@aifivem/lib/client";
import type { JobOutfit } from "@aifivem/shared";

// Through AI Core: works with ai-appearance and the other supported clothing scripts.
const uniform: JobOutfit = {
  components: [
    { id: 11, collection: "", index: 55, texture: 0 },
    { id: 4, collection: "", index: 35, texture: 0 },
  ],
  props: [{ id: 0, collection: "", index: 46, texture: 0 }],
};

RegisterCommand("uniform", () => appearance.wearOutfit(uniform), false);
RegisterCommand("ownclothes", () => appearance.reloadSkin(), false);
```
</Tab>
<Tab value="Lua">
```lua
-- fxmanifest.lua: shared_script '@ai-lib/init.lua'
local uniform = {
    components = {
        { id = 11, collection = '', index = 55, texture = 0 },
        { id = 4, collection = '', index = 35, texture = 0 },
    },
    props = { { id = 0, collection = '', index = 46, texture = 0 } },
}

RegisterCommand('uniform', function() aiLib.appearance.wearOutfit(uniform) end, false)
RegisterCommand('ownclothes', function() aiLib.appearance.reloadSkin() end, false)
```
</Tab>
</Tabs>

<Callout type="warn">
Outfit pieces are addressed by collection name and the index inside it, not by GTA's global drawable number. The base game is collection `""`. Through AI Core, `appearance.wearOutfit` and `reloadSkin` answer `false` when the running clothing script has no job outfit support.
</Callout>

## Events

| Event | Side | Arguments | What it is |
| --- | --- | --- | --- |
| `ai-core:client:characterPortrait` | Client (local) | `charId: number, url: string` | ai-appearance sends each card's portrait (`https://nui-img/...`) to AI Core's character screen. |

ai-appearance listens to AI Core's server event `characterScreen (src, charIds)` to know which portraits to make, and to lib `onCharacter` to dress a loaded character or start the creator.

## Database

Table `ai_appearance_characters`: `char_id` (= `ai_core_characters.id`) and `data` (the `Appearance` JSON). Only ai-appearance writes it. AI Core's adapter reads it for `GetCharacterAppearance`.

## Log channel

`purchases`: every paid store visit (through AI Core's logs: console, Discord, Fivemanage, FiveM Stats as the owner set them).
