<Callout type="info">
N’appelez pas ai-appearance et ne lisez pas sa table depuis votre script. Utilisez la couche apparence d’AI Core : `appearance` de la lib (serveur `appearance.get(charId)`, client `appearance.apply(ped, look)`, `appearance.read(ped)`, `appearance.openMenu(...)`, `appearance.wearOutfit(outfit)`, `appearance.reloadSkin()`), ou `aiLib.appearance` en Lua. Elle fonctionne avec chaque script de vêtements pris en charge par AI Core, donc le propriétaire peut remplacer ai-appearance. Voir la [référence de la lib](/fr/docs/developers/api/lib-client).
</Callout>

## Exports client

Typés `AiAppearanceClientExports` dans `@aicore-fivem/shared`. L’adaptateur apparence d’AI Core les appelle.

### ApplyAppearance

Applique une apparence ai-appearance à un ped.

**Côté :** client · **Attend :** non

```ts title="Signature"
ApplyAppearance(ped: number, appearance: unknown): boolean
```

```lua title="Lua"
local ok = exports['ai-appearance']:ApplyAppearance(ped, look)
```

#### Paramètres

<TypeTable
  type={{
    ped: { type: 'number', description: 'Handle du ped. Il doit déjà avoir le modèle de l’apparence (créez-le d’abord avec ce modèle).', required: true },
    appearance: { type: 'Appearance', description: 'Le JSON d’apparence propre à ai-appearance (`version: 1`), tel que stocké dans `ai_appearance_characters.data`. Traitez-le comme opaque.', required: true },
  }}
/>

#### Retour

`boolean` : `true` quand l’apparence a été appliquée. `false` quand l’apparence est invalide ou que le modèle du ped n’est pas celui de l’apparence.

### GetPedAppearance

Lit l’apparence que porte le joueur local.

**Côté :** client · **Attend :** non

```ts title="Signature"
GetPedAppearance(ped: number): unknown
```

#### Retour

L’`Appearance` du joueur local, ou `null` pour tout autre ped.

### WearOutfit

Met une tenue de métier (uniforme) au joueur local. Seules les pièces listées changent, et la tenue n’est jamais enregistrée comme l’apparence propre du joueur.

**Côté :** client · **Attend :** non

```ts title="Signature"
WearOutfit(outfit: JobOutfit): void
```

```lua title="Lua"
exports['ai-appearance']:WearOutfit({ components = { { id = 11, collection = '', index = 55, texture = 0 } }, props = {} })
```

#### JobOutfit

<TypeTable
  type={{

    props: { type: 'OutfitPiece[]', description: 'Accessoires (id de props GTA : 0 chapeau, 1 lunettes, 2 oreilles, 6 montre, 7 bracelet).', required: true },
  }}
/>

#### OutfitPiece

<TypeTable
  type={{
    id: { type: 'number', description: 'L’id du composant ou du prop.', required: true },
    collection: { type: 'string', description: 'Le nom de la collection de vêtements ; `""` pour le jeu de base.', required: true },
    index: { type: 'number', description: 'L’index du drawable dans cette collection (0-1023). Pour un prop, -1 le retire.', required: true },
    texture: { type: 'number', description: 'La texture (variante de couleur) du drawable.', required: true },
  }}
/>

#### Retour

Rien.

### ReloadSkin

Remet l’apparence enregistrée au joueur local (retire une tenue de métier). **Côté :** client · **Attend :** non.

```ts title="Signature"
ReloadSkin(): void
```

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance } from "@aicore-fivem/lib/client";
import type { JobOutfit } from "@aicore-fivem/shared";

// Via AI Core : fonctionne avec ai-appearance et les autres scripts de vêtements pris en charge.
const uniform: JobOutfit = {
  components: [
    { id: 11, collection: "", index: 55, texture: 0 },
    { id: 4, collection: "", index: 35, texture: 0 },
  ],
  props: [{ id: 0, collection: "", index: 46, texture: 0 }],
};

RegisterCommand("uniform", () => appearance.wearOutfit(uniform), false);
RegisterCommand("ownclothes", () => appearance.reloadSkin(), false);
```
</Tab>
<Tab value="Lua">
```lua
-- fxmanifest.lua : shared_script '@ai-lib/init.lua'
local uniform = {
    components = {
        { id = 11, collection = '', index = 55, texture = 0 },
        { id = 4, collection = '', index = 35, texture = 0 },
    },
    props = { { id = 0, collection = '', index = 46, texture = 0 } },
}

RegisterCommand('uniform', function() aiLib.appearance.wearOutfit(uniform) end, false)
RegisterCommand('ownclothes', function() aiLib.appearance.reloadSkin() end, false)
```
</Tab>
</Tabs>

<Callout type="warn">
Les pièces de tenue sont désignées par le nom de la collection et l’index dans celle-ci, pas par le numéro de drawable global de GTA. Le jeu de base est la collection `""`. Via AI Core, `appearance.wearOutfit` et `reloadSkin` répondent `false` quand le script de vêtements qui tourne ne prend pas en charge les tenues de métier.
</Callout>

## Events

| Event | Côté | Arguments | Ce que c’est |
| --- | --- | --- | --- |
| `ai-core:client:characterPortrait` | client (local) | `charId: number, url: string` | ai-appearance envoie le portrait de chaque carte (`https://nui-img/...`) à l’écran des personnages d’AI Core. |

ai-appearance écoute l’event serveur `characterScreen (src, charIds)` d’AI Core pour savoir quels portraits créer, et le `onCharacter` de la lib pour habiller un personnage chargé ou lancer le créateur.

## Base de données

Table `ai_appearance_characters` : `char_id` (= `ai_core_characters.id`) et `data` (le JSON `Appearance`). Seul ai-appearance l’écrit. L’adaptateur d’AI Core la lit pour `GetCharacterAppearance`.
