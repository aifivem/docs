<Callout type="info">
Vos propres scripts ne devraient pas appeler directement ai-weathersync. Utilisez plutôt la couche heure et météo d’AI Core : `world` de la lib en TypeScript (`world.setWeather`, `world.setTime`...) ou `aiLib.world` en Lua, documentés dans la [référence de la lib](/fr/docs/developers/api/lib-server). Cette couche fonctionne avec le script météo que fait tourner le serveur, quel qu’il soit, donc le propriétaire peut remplacer ai-weathersync sans casser votre script. Les exports ci-dessous sont destinés aux scripts écrits pour qb-weathersync et aux cas particuliers.
</Callout>

## Exports

Chaque export est **côté serveur** et répond sous deux noms : `exports['ai-weathersync']` et `exports['qb-weathersync']` (ai-weathersync fait un `provide` de qb-weathersync). Aucun n’attend. Ils ne sont pas typés dans `@aifivem/shared` ; depuis TypeScript, appelez-les avec `callExport("ai-weathersync", name, ...args)` de la lib.

Les changements faits via `setBlackout`, `setTimeFreeze` et `setDynamicWeather` durent jusqu’à ce que le propriétaire change ce réglage du panneau ou que la ressource redémarre.

### setWeather

Change immédiatement la météo du monde. Il ne touche pas aux régions météo.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
setWeather(type: string): boolean
```

```lua title="Lua"
local ok = exports['ai-weathersync']:setWeather('RAIN')
```

#### Paramètres

<TypeTable
  type={{
    type: { type: 'string', description: 'Un nom de météo GTA : EXTRASUNNY, CLEAR, NEUTRAL, SMOG, FOGGY, OVERCAST, CLOUDS, CLEARING, RAIN, THUNDER, SNOW, BLIZZARD, SNOWLIGHT, XMAS ou HALLOWEEN. Les minuscules sont acceptées.', required: true },
  }}
/>

#### Retour

`boolean` : `true` quand la météo a changé. `false` quand `type` n’est pas un nom de météo connu.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aifivem/lib/server";

// Un orage pour un événement ; le cycle météo du panneau reprend à partir d’ici.
const ok = callExport("ai-weathersync", "setWeather", "THUNDER") === true;
if (!ok) console.log("unknown weather");
```
</Tab>
<Tab value="Lua">
```lua
local ok = exports['ai-weathersync']:setWeather('THUNDER')
if not ok then print('unknown weather') end
```
</Tab>
</Tabs>

<Callout type="warn">
Avec **Changing weather** activé, le changement suivant arrive quand même selon le minuteur du panneau, à partir de la position de la nouvelle météo dans la liste (ou de la première entrée quand la nouvelle météo n’est pas dans la liste).
</Callout>

### setTime

Règle l’horloge du monde. L’horloge continue de tourner à la vitesse du panneau à partir de la nouvelle heure.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
setTime(hour: number, minute?: number): boolean
```

```lua title="Lua"
local ok = exports['ai-weathersync']:setTime(22, 30)
```

#### Paramètres

<TypeTable
  type={{
    hour: { type: 'number', description: 'Heure de la journée, 0-23. Les décimales sont tronquées, les valeurs au-delà de 23 reviennent au début (24 = 0).', required: true },
    minute: { type: 'number', description: 'Minute, 0-59. Les décimales sont tronquées.', default: '0' },
  }}
/>

#### Retour

`boolean` : `true` quand l’horloge a été réglée. `false` quand `hour` n’est pas un nombre.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aifivem/lib/server";

callExport("ai-weathersync", "setTime", 22, 30);
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-weathersync']:setTime(22, 30)
```
</Tab>
</Tabs>

### setBlackout

Active ou désactive le blackout : les lumières de la ville s’éteignent, les phares des véhicules restent.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
setBlackout(on: boolean): boolean
```

```lua title="Lua"
exports['ai-weathersync']:setBlackout(true)
```

#### Paramètres

<TypeTable
  type={{
    on: { type: 'boolean', description: '`true` éteint les lumières. Toute autre valeur les rallume.', required: true },
  }}
/>

#### Retour

`boolean` : toujours `true`.

### setTimeFreeze

Arrête ou redémarre l’horloge à l’heure actuelle.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
setTimeFreeze(on: boolean): boolean
```

```lua title="Lua"
exports['ai-weathersync']:setTimeFreeze(true)
```

#### Paramètres

<TypeTable
  type={{
    on: { type: 'boolean', description: '`true` arrête l’horloge. Toute autre valeur la laisse tourner.', required: true },
  }}
/>

#### Retour

`boolean` : toujours `true`.

### setDynamicWeather

Active ou désactive les changements de météo automatiques.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
setDynamicWeather(on: boolean): boolean
```

```lua title="Lua"
exports['ai-weathersync']:setDynamicWeather(false)
```

#### Paramètres

<TypeTable
  type={{
    on: { type: 'boolean', description: '`true` laisse la météo changer toutes les **Change every** minutes. Toute autre valeur garde la météo actuelle.', required: true },
  }}
/>

#### Retour

`boolean` : toujours `true`.

### nextWeatherStage

Fait passer immédiatement la météo du monde à l’entrée suivante de la liste du panneau (retour à la première après la dernière).

**Côté :** serveur · **Attend :** non

```ts title="Signature"
nextWeatherStage(): boolean
```

```lua title="Lua"
exports['ai-weathersync']:nextWeatherStage()
```

#### Retour

`boolean` : toujours `true`.

### Getters

Chacun lit l’état actuel et n’attend pas.

| Export | Renvoie |
| --- | --- |
| `getWeatherState(): string` | Le nom de la météo actuelle du monde, par exemple `"CLEAR"`. Les régions ne sont pas incluses. |
| `getTime(): { hour: number, minute: number }` | L’heure de jeu actuelle. En Lua, une table avec `hour` et `minute`. |
| `getBlackoutState(): boolean` | Indique si le blackout est activé (la valeur de l’export, sinon celle du panneau). |
| `getTimeFreezeState(): boolean` | Indique si l’horloge est arrêtée. |
| `getDynamicWeather(): boolean` | Indique si la météo change d’elle-même. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aifivem/lib/server";

const time = callExport("ai-weathersync", "getTime") as { hour: number; minute: number };
const weather = callExport("ai-weathersync", "getWeatherState") as string;
console.log(`It is ${time.hour}:${String(time.minute).padStart(2, "0")}, weather ${weather}`);
```
</Tab>
<Tab value="Lua">
```lua
local time = exports['ai-weathersync']:getTime()
local weather = exports['ai-weathersync']:getWeatherState()
print(('It is %d:%02d, weather %s'):format(time.hour, time.minute, weather))
```
</Tab>
</Tabs>

<Callout type="warn">
`getTime` répond une table (`{ hour, minute }`), alors que le qb-weathersync d’origine répond deux valeurs (`hour, minute`). Un script Lua écrit pour qb-weathersync qui fait `local h, m = exports['qb-weathersync']:getTime()` reçoit la table dans `h`. L’export `GetTime` propre à AI Core et `world.getTime()` de la lib lisent les deux formes et répondent toujours `{ hour, minute }`.
</Callout>

## Clés GlobalState

ai-weathersync publie son état en GlobalState, écrit par le serveur uniquement quand quelque chose change. Lisez-les ; ne les écrivez jamais.

| Clé | Valeur | Quand elle change |
| --- | --- | --- |
| `ai:clock` | `{ base: number, at: number, scale: number, frozen: boolean }` : la minute de jeu de la journée (`base`, 0-1439) à l’heure serveur `at` (ms, `Date.now()`), qui avance de `scale` minutes de jeu par minute réelle, ou reste fixe tant que `frozen`. | Changement du panneau, `setTime`, `setTimeFreeze`. |
| `ai:weather` | `{ type: string, blackout: boolean }` : la météo et le blackout du monde. | Chaque changement de météo et `setBlackout`. |
| `ai:rweather:<regionId>` | `string` : la météo actuelle d’une région. Retirée quand la région est supprimée. | Selon le minuteur propre à la région. |

L’heure n’est pas envoyée chaque minute : chaque client la calcule à partir de `ai:clock` et de sa propre horloge (décalage pris une fois auprès du serveur).

## Events

ai-weathersync n’a pas d’events pour les autres scripts. Pour mettre la synchronisation en pause sur un client (un intérieur, une cinématique), utilisez les exports client `PauseWorldSync` / `ResumeWorldSync` d’AI Core ou `world.pauseSync(reason)` / `resumeSync(reason)` de la lib (voir les [exports client d’ai-core](/fr/docs/developers/api/core-client)). ai-weathersync n’écoute que la pause d’AI Core.
