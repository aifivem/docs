<Callout type="info">
Tus propios scripts no deberían llamar directamente a ai-weathersync. Usa en su lugar la capa de hora y clima de AI Core: `world` de la lib en TypeScript (`world.setWeather`, `world.setTime`...) o `aiLib.world` en Lua, documentados en la [referencia de la lib](/es/docs/developers/api/lib-server). Esa capa funciona con el script de clima que use el servidor, así que el dueño puede reemplazar ai-weathersync sin romper tu script. Los exports de abajo son para scripts escritos para qb-weathersync y para casos especiales.
</Callout>

## Exports

Cada export es **de servidor** y responde bajo dos nombres: `exports['ai-weathersync']` y `exports['qb-weathersync']` (ai-weathersync hace `provide` de qb-weathersync). Ninguno espera. No están tipados en `@aicore-fivem/shared`; desde TypeScript llámalos con `callExport("ai-weathersync", name, ...args)` de la lib.

Los cambios hechos con `setBlackout`, `setTimeFreeze` y `setDynamicWeather` duran hasta que el dueño cambia ese ajuste del panel o se reinicia el recurso.

### setWeather

Cambia al momento el clima del mundo. No toca las regiones de clima.

**Lado:** Servidor · **Espera:** no

```ts title="Firma"
setWeather(type: string): boolean
```

```lua title="Lua"
local ok = exports['ai-weathersync']:setWeather('RAIN')
```

#### Parámetros

<TypeTable
  type={{
    type: { type: 'string', description: 'Un nombre de clima de GTA: EXTRASUNNY, CLEAR, NEUTRAL, SMOG, FOGGY, OVERCAST, CLOUDS, CLEARING, RAIN, THUNDER, SNOW, BLIZZARD, SNOWLIGHT, XMAS o HALLOWEEN. Se aceptan minúsculas.', required: true },
  }}
/>

#### Devuelve

`boolean`: `true` cuando el clima cambió. `false` cuando `type` no es un nombre de clima conocido.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aicore-fivem/lib/server";

// Una tormenta para un evento; el ciclo de clima del panel continúa desde aquí.
const ok = callExport("ai-weathersync", "setWeather", "THUNDER") === true;
if (!ok) console.log("unknown weather");
```
</Tab>
<Tab value="Lua">
```lua
local ok = exports['ai-weathersync']:setWeather('THUNDER')
if not ok then print('unknown weather') end
```
</Tab>
</Tabs>

<Callout type="warn">
Con **Changing weather** activado, el siguiente cambio sigue llegando con el temporizador del panel, desde la posición del nuevo clima en la lista (o la primera entrada cuando el nuevo clima no está en la lista).
</Callout>

### setTime

Fija el reloj del mundo. El reloj sigue avanzando a la velocidad del panel desde la nueva hora.

**Lado:** Servidor · **Espera:** no

```ts title="Firma"
setTime(hour: number, minute?: number): boolean
```

```lua title="Lua"
local ok = exports['ai-weathersync']:setTime(22, 30)
```

#### Parámetros

<TypeTable
  type={{
    hour: { type: 'number', description: 'Hora del día, 0-23. Los decimales se cortan, los valores por encima de 23 dan la vuelta (24 = 0).', required: true },
    minute: { type: 'number', description: 'Minuto, 0-59. Los decimales se cortan.', default: '0' },
  }}
/>

#### Devuelve

`boolean`: `true` cuando se fijó el reloj. `false` cuando `hour` no es un número.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aicore-fivem/lib/server";

callExport("ai-weathersync", "setTime", 22, 30);
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-weathersync']:setTime(22, 30)
```
</Tab>
</Tabs>

### setBlackout

Activa o desactiva el apagón: las luces de la ciudad se apagan, las de los vehículos se quedan.

**Lado:** Servidor · **Espera:** no

```ts title="Firma"
setBlackout(on: boolean): boolean
```

```lua title="Lua"
exports['ai-weathersync']:setBlackout(true)
```

#### Parámetros

<TypeTable
  type={{
    on: { type: 'boolean', description: '`true` apaga las luces. Cualquier otra cosa las vuelve a encender.', required: true },
  }}
/>

#### Devuelve

`boolean`: siempre `true`.

<TypeTable
  type={{

### setDynamicWeather

Activa o desactiva los cambios automáticos de clima.

**Lado:** Servidor · **Espera:** no

```ts title="Firma"
setDynamicWeather(on: boolean): boolean
```

```lua title="Lua"
exports['ai-weathersync']:setDynamicWeather(false)
```

#### Parámetros

<TypeTable
  type={{

/>

#### Devuelve

`boolean`: siempre `true`.

### nextWeatherStage

Pasa al momento el clima del mundo a la siguiente entrada de la lista del panel (vuelve a la primera después de la última).

**Lado:** Servidor · **Espera:** no

```ts title="Firma"
nextWeatherStage(): boolean
```

```lua title="Lua"
exports['ai-weathersync']:nextWeatherStage()
```

#### Devuelve

`boolean`: siempre `true`.

### Getters

Cada uno lee el estado actual y no espera.

| Export | Devuelve |
| --- | --- |
| `getWeatherState(): string` | El nombre del clima actual del mundo, por ejemplo `"CLEAR"`. Las regiones no se incluyen. |
| `getTime(): { hour: number, minute: number }` | La hora actual del juego. En Lua, una tabla con `hour` y `minute`. |
| `getBlackoutState(): boolean` | Si el apagón está activado (el valor del export, si no el del panel). |
| `getTimeFreezeState(): boolean` | Si el reloj está detenido. |
| `getDynamicWeather(): boolean` | Si el clima cambia solo. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aicore-fivem/lib/server";

const time = callExport("ai-weathersync", "getTime") as { hour: number; minute: number };
const weather = callExport("ai-weathersync", "getWeatherState") as string;
console.log(`It is ${time.hour}:${String(time.minute).padStart(2, "0")}, weather ${weather}`);
```
</Tab>
<Tab value="Lua">
```lua
local time = exports['ai-weathersync']:getTime()
local weather = exports['ai-weathersync']:getWeatherState()
print(('It is %d:%02d, weather %s'):format(time.hour, time.minute, weather))
```
</Tab>
</Tabs>

<Callout type="warn">
`getTime` responde una tabla (`{ hour, minute }`), mientras que el qb-weathersync original responde dos valores (`hour, minute`). Un script Lua escrito para qb-weathersync que hace `local h, m = exports['qb-weathersync']:getTime()` recibe la tabla en `h`. El export propio `GetTime` de AI Core y `world.getTime()` de la lib leen las dos formas y siempre responden `{ hour, minute }`.
</Callout>

## Claves de GlobalState

ai-weathersync publica su estado como GlobalState, que el servidor solo escribe cuando algo cambia. Léelas; nunca las escribas.

| Clave | Valor | Cuándo cambia |
| --- | --- | --- |
| `ai:clock` | `{ base: number, at: number, scale: number, frozen: boolean }`: el minuto de juego del día (`base`, 0-1439) en la hora del servidor `at` (ms, `Date.now()`), avanzando `scale` minutos de juego por minuto real, o detenido mientras `frozen`. | Cambio en el panel, `setTime`, `setTimeFreeze`. |
| `ai:weather` | `{ type: string, blackout: boolean }`: el clima y el apagón del mundo. | Cada cambio de clima y `setBlackout`. |
| `ai:rweather:<regionId>` | `string`: el clima actual de una región. Se quita cuando se borra la región. | Con el temporizador propio de la región. |

La hora no se envía cada minuto: cada cliente la calcula a partir de `ai:clock` y su propio reloj (el desfase se toma una vez del servidor).

## Eventos

ai-weathersync no tiene eventos para otros scripts. Para pausar la sincronización en un cliente (un interior, una cinemática), usa los exports de cliente `PauseWorldSync` / `ResumeWorldSync` de AI Core o `world.pauseSync(reason)` / `resumeSync(reason)` de la lib (mira los [exports de cliente de ai-core](/es/docs/developers/api/core-client)). ai-weathersync solo escucha la pausa de AI Core.
