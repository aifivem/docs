ai-target place de petits marqueurs sur les personnes, les objets, les véhicules et les lieux avec lesquels un joueur peut interagir. Le joueur en regarde un, appuie sur la touche d’interaction (**E**), et l’action s’exécute. Quand un point a plusieurs actions, un petit menu s’ouvre pour en choisir une.

## Ce qu’il fait en jeu

- **Des marqueurs près de la caméra.** Chaque point d’interaction à portée affiche un marqueur, un peu avant d’être à portée, pour que les joueurs voient où ils peuvent faire quelque chose.
- **Focus.** Le marqueur que regarde le joueur prend le focus et affiche son action.
- **Une seule touche.** La même touche d’interaction que les invites (le **E** d’ai-lib) utilise le marqueur qui a le focus.
- **Plusieurs options.** Un point avec plus d’une action affiche « N options » et ouvre un petit menu.
- **Restrictions par métier.** Une option peut être limitée à des métiers ou des gangs (et à un grade minimum). Les autres joueurs ne la voient pas.

## Invite ou ciblage : le propriétaire choisit

Chaque script `ai-*` crée ses lieux (boutiques, stockages, PNJ, portes) via les points d’interaction d’AI Core. Le propriétaire choisit leur apparence, pour tous les scripts à la fois, dans l’onglet **General** d’AI Core (carte **Interaction**, **Interaction style**) :

- **Prompt and key** (par défaut) : une boîte à droite de l’écran et la touche d’interaction quand on est proche.
- **Target eye** : les points deviennent des marqueurs de ciblage. Cela nécessite un script de ciblage comme ai-target ; sans lui, l’invite est utilisée.

Avec **Prompt and key** choisi, ai-target tourne quand même, mais seuls les scripts qui appellent eux-mêmes l’API d’ox_target (scripts tiers) y placent des marqueurs.

## Installation

La recipe txAdmin d’AI Core l’installe. À la main : placez le dossier dans `resources/[ai]/` et ajoutez `ensure ai-target` à `server.cfg` après `ensure ai-core`. Il nécessite ai-core. Il n’a pas de table de base de données.

Ne faites pas tourner ox_target à côté (ai-target répond au nom d’ox_target). Réglez ensuite **Interaction style** sur **Target eye** dans l’onglet General si vous voulez que chaque script `ai-*` l’utilise.

## Réglages du panneau

Aucun qui lui soit propre. Le seul réglage est l’**Interaction style** d’AI Core (ci-dessus).

## Commandes

Aucune.

## Raccourcis clavier

ai-target n’a pas de touche propre. Il utilise la touche d’interaction d’ai-lib :

| Touche par défaut | Ce qu’elle fait | Nom dans les réglages de GTA |
| --- | --- | --- |
| E | Utilise le marqueur qui a le focus (ou l’invite à l’écran) | Interact with the prompt on screen |

## Fonctionne avec d’autres scripts

- **Remplace ox_target** (`provide 'ox_target'`). Les scripts qui appellent `exports.ox_target:addBoxZone(...)`, `addModel`, `addEntity`, `addGlobalVehicle` et les autres exports d’ox_target placent leurs options sur ai-target.
- **Vous pouvez le remplacer.** Les points d’interaction d’AI Core fonctionnent aussi avec tgiann-radialmenu-target, tgiann-target, sleepless_interact, ox_target, qb-target et interact (darktrovx). Retirez ai-target et démarrez l’un d’eux ; le premier qui tourne dans cet ordre est utilisé. Voir [Compatibilité](/fr/docs/compatibility).

## Limites connues

- Les **options globales** d’ox_target (`addGlobalOption`, des options rattachées à rien) ne sont pas proposées : elles ont leur place dans un menu radial. Un script qui l’appelle reçoit un avertissement dans la console.
- La portée d’une option est au plus de 50 m (2,5 m par défaut).
