ai-chat answers FiveM's `chat` resource API, so you write chat code the standard FiveM way. Exports answer under both `exports['ai-chat']` and `exports.chat`.

## ChatMessage

The message shape every export and event takes.

<TypeTable
  type={{
    args: { type: 'string[]', description: '`[author, text]` or `[text]`. Colour codes `^0`-`^9` are drawn; HTML is not.', required: true },
    color: { type: '[number, number, number] | string', description: 'Author colour: `[r, g, b]` (0-255) or a CSS colour.' },
    multiline: { type: 'boolean', description: 'Lets the text wrap over several lines.' },
    channel: { type: 'string', description: 'Id of a panel channel; its tag is shown before the author.' },
  }}
/>

## Server exports

### addMessage

Sends a chat line to one player, several players or everyone.

**Side:** Server · **Waits:** no

```ts title="Signature"
addMessage(target: number | number[], message: ChatMessage): void
```

```lua title="Lua"
exports.chat:addMessage(source, { args = { 'Bank', 'Your salary arrived.' }, color = { 61, 247, 158 } })
```

#### Parameters

<TypeTable
  type={{
    target: { type: 'number | number[]', description: 'A server id, a list of server ids, or `-1` for everyone.', required: true },
    message: { type: 'ChatMessage', description: 'The line to show.', required: true },
  }}
/>

#### Returns

Nothing. A message without a valid `args` list is dropped.

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aifivem/lib/server";

function announce(text: string): void {
  callExport("chat", "addMessage", -1, { args: ["City", text], color: [61, 247, 158], multiline: true });
}
announce("The bank closes in 10 minutes.");
```
</Tab>
<Tab value="Lua">
```lua
local function announce(text)
    exports.chat:addMessage(-1, { args = { 'City', text }, color = { 61, 247, 158 }, multiline = true })
end
announce('The bank closes in 10 minutes.')
```
</Tab>
</Tabs>

### registerMessageHook

Runs your function for every message a player sends, before it is delivered. The hook can change the message, change who gets it, or cancel it. Hooks are removed when your resource stops.

**Side:** Server · **Waits:** no

```ts title="Signature"
registerMessageHook(hook: (source: number, message: ChatMessage, ref: HookRef) => void): void
```

#### HookRef

<TypeTable
  type={{
    updateMessage: { type: '(change: Partial<ChatMessage>) => void', description: 'Merges `change` into the message.' },
    cancel: { type: '() => void', description: 'Drops the message: nobody gets it.' },
    setRouting: { type: '(target: number | number[]) => void', description: 'Sends it to these server ids instead (`-1` for everyone).' },
  }}
/>

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { callExport } from "@aifivem/lib/server";

callExport("chat", "registerMessageHook", (source: number, message: { args: string[] }, ref: { cancel(): void }) => {
  const text = message.args[message.args.length - 1] ?? "";
  if (/discord\.gg\//i.test(text)) ref.cancel();
});
```
</Tab>
<Tab value="Lua">
```lua
exports.chat:registerMessageHook(function(source, message, ref)
    local text = message.args[#message.args] or ''
    if text:lower():find('discord%.gg/') then ref.cancel() end
end)
```
</Tab>
</Tabs>

### registerMode

Adds a channel from a script (FiveM's chat modes). Its callback decides who gets each message, like a message hook. The mode is removed when your resource stops.

**Side:** Server · **Waits:** no

```ts title="Signature"
registerMode(data: { name: string; displayName?: string; color?: string; cb?: (source: number, message: ChatMessage, ref: HookRef) => void }): void
```

<TypeTable
  type={{
    name: { type: 'string', description: 'Mode id.', required: true },
    displayName: { type: 'string', description: 'Text shown for the mode.', default: 'name' },
    color: { type: 'string', description: 'CSS colour of the mode.', default: '"#ffffff"' },
    cb: { type: '(source, message, ref) => void', description: 'Routes each message of the mode (`ref.setRouting`, `ref.cancel`).' },
  }}
/>

## Client exports

| Export | What it does |
| --- | --- |
| `addMessage(message: ChatMessage \| string): void` | Shows a line on this player's chat only. |
| `addSuggestion(name: string, help: string, params?: { name: string, help: string }[]): void` | Adds a command suggestion for this player. |

## Events

### chatMessage (server)

Fires on the server for every message a player sends, before delivery. Cancel it (`CancelEvent()`) to drop the message.

**Side:** Server (local event)

| Argument | Type | What it is |
| --- | --- | --- |
| `source` | `number` | The sender's server id. |
| `author` | `string` | The author shown (the character name). |
| `text` | `string` | The message text. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
on("chatMessage", (source: number, author: string, text: string) => {
  console.log(`[chat] ${author} (${source}): ${text}`);
});
```
</Tab>
<Tab value="Lua">
```lua
AddEventHandler('chatMessage', function(source, author, text)
    print(('[chat] %s (%d): %s'):format(author, source, text))
end)
```
</Tab>
</Tabs>

### Client events ai-chat listens to

Send them from the server (`TriggerClientEvent`) or from a client script (`TriggerEvent`).

| Event | Arguments | What it does |
| --- | --- | --- |
| `chat:addMessage` | `message: ChatMessage \| string` | Shows a line. |
| `chatMessage` | `author: string, color: [r, g, b], text: string` | Shows a line (old style). |
| `chat:addSuggestion` | `name: string, help: string, params?: { name, help }[]` | Adds one suggestion. |
| `chat:addSuggestions` | `suggestions: { name, help, params? }[]` | Adds several suggestions. |
| `chat:removeSuggestion` | `name: string` | Removes a suggestion. |
| `chat:addMode` / `chat:removeMode` | `mode` / `name` | Adds or removes a script mode on this client. |
| `chat:clear` | none | Empties this player's chat. |

<Callout type="warn">
`chat:addTemplate` is ignored: templates (HTML) are never drawn. Messages typed by players are not sent through `_chat:messageEntered`; listen to `chatMessage` on the server.
</Callout>
