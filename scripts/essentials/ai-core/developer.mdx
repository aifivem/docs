## How to call it

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Typed as AiCoreServerExports in @aifivem/shared.
const core = resourceExport("ai-core");
const character = core.GetCharacter(source);
```

Most of the time you do not call ai-core's exports yourself: the lib's helpers (`money`, `inventory`, `online`, `onCharacter`, `vehicleKeys`, `dispatch`...) wrap them.
</Tab>
<Tab value="Lua">
```lua
local character = exports['ai-core']:GetCharacter(source)
```

Or through ai-lib's Lua helpers (`shared_script '@ai-lib/init.lua'`, then `aiLib.inventory`, `aiLib.online`...).
</Tab>
</Tabs>

## Framework bridges

Scripts written for ESX, QBCore, Qbox or vRP do not need ai-core's own API: ai-core answers theirs (`ESX.GetPlayerFromId`, `QBCore.Functions.GetPlayer`, `exports.qbx_core:GetPlayer`, vRP's Proxy and Tunnel). What each bridge answers and its limits are on [Compatibility](/docs/compatibility).

## State bags and GlobalState

| Key | Where | Value |
| --- | --- | --- |
| `ai:duty:<job>` | GlobalState | Number of on-duty members of that job. |
| `ai:pvp` | GlobalState | Whether players can hurt each other. |
| `ai:inventory`, `ai:vehicleKeys`, `ai:appearance`, `ai:medical`, `ai:fuel`, `ai:garages`, `ai:mdt`, `ai:notify` | GlobalState | The resource name of the script ai-core uses for that job. |

The full list with their shapes is in the [server exports](/docs/developers/api/core-server) and [events](/docs/developers/api/events) references.
