## Como chamá-lo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// Tipado como AiCoreServerExports em @aicore-fivem/shared.
const core = resourceExport("ai-core");
const character = core.GetCharacter(source);
```

Na maior parte do tempo você não chama os exports do ai-core por conta própria: os helpers da lib (`money`, `inventory`, `online`, `onCharacter`, `vehicleKeys`, `dispatch`...) os envolvem.
</Tab>
<Tab value="Lua">
```lua
local character = exports['ai-core']:GetCharacter(source)
```

Ou pelos helpers Lua do ai-lib (`shared_script '@ai-lib/init.lua'`, depois `aiLib.inventory`, `aiLib.online`...).
</Tab>
</Tabs>

## Pontes de frameworks

Scripts escritos para ESX, QBCore, Qbox ou vRP não precisam da API própria do ai-core: o ai-core responde às deles (`ESX.GetPlayerFromId`, `QBCore.Functions.GetPlayer`, `exports.qbx_core:GetPlayer`, o Proxy e o Tunnel do vRP). O que cada ponte responde e os limites dela estão em [Compatibilidade](/pt/docs/compatibility).

## State bags e GlobalState

| Chave | Onde | Valor |
| --- | --- | --- |
| `ai:duty:<job>` | GlobalState | Número de membros em serviço daquele emprego. |
| `ai:pvp` | GlobalState | Se os jogadores podem machucar uns aos outros. |
| `ai:inventory`, `ai:vehicleKeys`, `ai:appearance`, `ai:medical`, `ai:fuel`, `ai:garages`, `ai:mdt`, `ai:notify` | GlobalState | O nome do recurso do script que o ai-core usa para aquela tarefa. |

A lista completa com os formatos está nas referências de [exports do servidor](/pt/docs/developers/api/core-server) e de [eventos](/pt/docs/developers/api/events).
