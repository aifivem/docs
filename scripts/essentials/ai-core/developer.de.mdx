## So rufst du es auf

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Typisiert als AiCoreServerExports in @aifivem/shared.
const core = resourceExport("ai-core");
const character = core.GetCharacter(source);
```

Meistens rufst du die Exports von ai-core nicht selbst auf: Die Helfer der Lib (`money`, `inventory`, `online`, `onCharacter`, `vehicleKeys`, `dispatch`...) kapseln sie.
</Tab>
<Tab value="Lua">
```lua
local character = exports['ai-core']:GetCharacter(source)
```

Oder über die Lua-Helfer von ai-lib (`shared_script '@ai-lib/init.lua'`, dann `aiLib.inventory`, `aiLib.online`...).
</Tab>
</Tabs>

## Framework-Brücken

Skripte, die für ESX, QBCore, Qbox oder vRP geschrieben wurden, brauchen die eigene API von ai-core nicht: ai-core beantwortet ihre (`ESX.GetPlayerFromId`, `QBCore.Functions.GetPlayer`, `exports.qbx_core:GetPlayer`, Proxy und Tunnel von vRP). Was jede Brücke beantwortet und wo ihre Grenzen liegen, steht unter [Kompatibilität](/de/docs/compatibility).

## State Bags und GlobalState

| Schlüssel | Wo | Wert |
| --- | --- | --- |
| `ai:duty:<job>` | GlobalState | Anzahl der Mitglieder dieses Jobs im Dienst. |
| `ai:pvp` | GlobalState | Ob Spieler einander verletzen können. |
| `ai:inventory`, `ai:vehicleKeys`, `ai:appearance`, `ai:medical`, `ai:fuel`, `ai:garages`, `ai:mdt`, `ai:notify` | GlobalState | Der Ressourcenname des Skripts, das ai-core für diese Aufgabe nutzt. |

Die vollständige Liste mit ihren Strukturen steht in den Referenzen [Server-Exports](/de/docs/developers/api/core-server) und [Events](/de/docs/developers/api/events).
