## Cómo llamarlo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Tipado como AiCoreServerExports en @aifivem/shared.
const core = resourceExport("ai-core");
const character = core.GetCharacter(source);
```

La mayoría de las veces no llamas tú a los exports de ai-core: las utilidades de la lib (`money`, `inventory`, `online`, `onCharacter`, `vehicleKeys`, `dispatch`...) los envuelven.
</Tab>
<Tab value="Lua">
```lua
local character = exports['ai-core']:GetCharacter(source)
```

O mediante las utilidades Lua de ai-lib (`shared_script '@ai-lib/init.lua'`, después `aiLib.inventory`, `aiLib.online`...).
</Tab>
</Tabs>

## Puentes de frameworks

Los scripts escritos para ESX, QBCore, Qbox o vRP no necesitan la API propia de ai-core: ai-core responde a la suya (`ESX.GetPlayerFromId`, `QBCore.Functions.GetPlayer`, `exports.qbx_core:GetPlayer`, el Proxy y el Tunnel de vRP). Lo que responde cada puente y sus límites están en [Compatibilidad](/es/docs/compatibility).

## State bags y GlobalState

| Clave | Dónde | Valor |
| --- | --- | --- |
| `ai:duty:<job>` | GlobalState | Número de miembros de servicio de ese trabajo. |
| `ai:pvp` | GlobalState | Si los jugadores pueden hacerse daño entre sí. |
| `ai:inventory`, `ai:vehicleKeys`, `ai:appearance`, `ai:medical`, `ai:fuel`, `ai:garages`, `ai:mdt`, `ai:notify` | GlobalState | El nombre del recurso del script que usa ai-core para esa tarea. |

La lista completa con sus formas está en las referencias de [exports de servidor](/es/docs/developers/api/core-server) y de [eventos](/es/docs/developers/api/events).
