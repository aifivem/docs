## Comment l’appeler

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Typé AiCoreServerExports dans @aifivem/shared.
const core = resourceExport("ai-core");
const character = core.GetCharacter(source);
```

La plupart du temps, vous n’appelez pas vous-même les exports d’ai-core : les utilitaires de la lib (`money`, `inventory`, `online`, `onCharacter`, `vehicleKeys`, `dispatch`...) les enveloppent.
</Tab>
<Tab value="Lua">
```lua
local character = exports['ai-core']:GetCharacter(source)
```

Ou via les utilitaires Lua d’ai-lib (`shared_script '@ai-lib/init.lua'`, puis `aiLib.inventory`, `aiLib.online`...).
</Tab>
</Tabs>

## Ponts de framework

Les scripts écrits pour ESX, QBCore, Qbox ou vRP n’ont pas besoin de l’API propre à ai-core : ai-core répond à la leur (`ESX.GetPlayerFromId`, `QBCore.Functions.GetPlayer`, `exports.qbx_core:GetPlayer`, le Proxy et le Tunnel de vRP). Ce à quoi répond chaque pont et ses limites se trouvent sur la page [Compatibilité](/fr/docs/compatibility).

## State bags et GlobalState

| Clé | Où | Valeur |
| --- | --- | --- |
| `ai:duty:<job>` | GlobalState | Nombre de membres en service de ce métier. |
| `ai:pvp` | GlobalState | Indique si les joueurs peuvent se blesser entre eux. |
| `ai:inventory`, `ai:vehicleKeys`, `ai:appearance`, `ai:medical`, `ai:fuel`, `ai:garages`, `ai:mdt`, `ai:notify` | GlobalState | Le nom de ressource du script qu’ai-core utilise pour cette tâche. |

La liste complète avec leurs formes se trouve dans les références des [exports serveur](/fr/docs/developers/api/core-server) et des [events](/fr/docs/developers/api/events).
