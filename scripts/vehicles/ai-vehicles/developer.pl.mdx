ai-vehicles ma tylko eksporty serwera. Wszystkie są synchroniczne (bez Promise, bez czekania w Lua), z wyjątkiem `SpawnVehicle`, który odpowiada przez callback. Typy są w `@aicore-fivem/shared` (`vehicles.ts`).

```ts title="TypeScript"
import { resourceExport } from "@aicore-fivem/lib/server";
const vehicles = resourceExport("ai-vehicles");
```

```lua title="Lua"
local vehicles = exports['ai-vehicles']
```

<Callout type="info">
Aby dawać, zabierać lub sprawdzać klucze, zaparkować pojazd w garażu lub odczytać paliwo, używaj warstw biblioteki (`vehicleKeys`, `garages`, `fuel`): działają z każdym skryptem kluczy, garaży lub paliwa, którego używa serwer. Wywołuj ai-vehicles bezpośrednio tylko w sprawie samej własności.
</Callout>

## Eksporty serwera

### CreateVehicle

Rejestruje nowy posiadany pojazd i go parkuje. Używaj, gdy gracz dostaje pojazd (zakup, nagroda, prezent od administratora). Nie tworzy auta w świecie: wyjmij je przez `SpawnVehicle` albo pozwól graczowi odebrać je w garażu.

**Strona:** serwer · **Czeka:** nie

```ts title="Sygnatura"
CreateVehicle(owner: VehicleOwner, model: string, garage: string | null, props?: VehicleProps): { id: number; plate: string } | null
```

```lua title="Lua"
local created = exports['ai-vehicles']:CreateVehicle(owner, model, garage, props) -- { id = number, plate = string } albo nil
```

#### Parametry

<TypeTable
  type={{
    owner: { type: 'VehicleOwner', description: 'Kto będzie właścicielem.', required: true },
    model: { type: 'string', description: 'Nazwa modelu (`"sultan"`). Zapisywana małymi literami. Model nie jest sprawdzany: przekaż model, który istnieje.', required: true },
    garage: { type: 'string | null', description: 'ID garażu ai-garages, w którym czeka (`"pillbox"`). `null`: bez garażu (pojazd floty jest wtedy widoczny w każdym garażu swojej pracy lub gangu).', required: true },
    props: { type: 'VehicleProps', description: 'Wygląd początkowy. Ignorowany, gdy nie jest prawidłowym obiektem `VehicleProps`. Tablica w środku jest zawsze zastępowana własną tablicą pojazdu.' },
  }}
/>

#### Zwraca

`{ id, plate }` nowego pojazdu. `null`, gdy `owner` nie jest prawidłowym właścicielem albo `model` nie jest tekstem.

#### Przykład

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");
const vehicles = resourceExport("ai-vehicles");

// Daje graczowi Sultana zaparkowanego w garażu Motel Parking.
export function giveSultan(source: number): string | null {
  const character = core.GetCharacter(source);
  if (!character) return null;
  const created = vehicles.CreateVehicle(
    { type: "character", id: String(character.id) },
    "sultan",
    "pillbox",
  );
  return created?.plate ?? null;
}
```
</Tab>
<Tab value="Lua">
```lua

  local character = exports['ai-core']:GetCharacter(source)

  local created = exports['ai-vehicles']:CreateVehicle(
    { type = 'character', id = tostring(character.id) }, 'sultan', 'pillbox')
  return created and created.plate
end
```

```ts
    if (netId === null) console.log(`vehicle ${vehicleId} could not come out`);
  });
}
```

## Zdarzenia

### ai-vehicles:owners

Wywoływane, gdy pojazdy trafiają do pamięci ai-vehicles lub zmieniają właściciela oraz gdy tablice opuszczają pamięć. Jedna paczka na tick serwera. Odczytaj `GetPlateOwners` raz przy starcie, a potem nakładaj te paczki, aby utrzymywać kopię przypisań tablica-właściciel. Nazwa to `VEHICLES_EVENTS.owners` w `@aicore-fivem/shared`.

**Strona:** serwer (zdarzenie lokalne, niewysyłane do klientów)

<TypeTable
  type={{
    puts: { type: 'Array<[plate: string, type: VehicleOwnerType, id: string]>', description: 'Pojazdy, które trafiły do pamięci lub dostały nowego właściciela.', required: true },
    removes: { type: 'string[]', description: 'Tablice, które opuściły pamięć (właściciel wyszedł z gry, pojazd został usunięty).', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";
import { VEHICLES_EVENTS } from "@aicore-fivem/shared";

const owners = new Map<string, string>();
for (const [plate, type, id] of resourceExport("ai-vehicles").GetPlateOwners())
  owners.set(plate, `${type}:${id}`);

on(VEHICLES_EVENTS.owners, (puts: [string, string, string][], removes: string[]) => {
  for (const [plate, type, id] of puts) owners.set(plate, `${type}:${id}`);
  for (const plate of removes) owners.delete(plate);
});
```
</Tab>
<Tab value="Lua">
```lua
local owners = {}
for _, row in ipairs(exports['ai-vehicles']:GetPlateOwners()) do
  owners[row[1]] = row[2] .. ':' .. row[3]
end

AddEventHandler('ai-vehicles:owners', function(puts, removes)
  for _, row in ipairs(puts) do owners[row[1]] = row[2] .. ':' .. row[3] end
  for _, plate in ipairs(removes) do owners[plate] = nil end
end)
```
</Tab>
</Tabs>

## State bagi

ai-vehicles ustawia je na każdym posiadanym pojeździe, który tworzy w świecie. Nazwy są w `VEHICLE_BAGS` (`@aicore-fivem/shared`).

| Bag | Typ | Znaczenie |
| --- | --- | --- |
| `ai:owned` | `true` | Encja jest posiadanym pojazdem. |
| `ai:vid` | `number` | Jej ID w ai-vehicles. |
| `ai:props` | `VehicleProps` | Zapisany wygląd. Nakłada go klient ai-core, który jest właścicielem encji. |
| `ai:setup` | `VehicleSetup` | Wygląd spawnu dla pojazdu bez props, nakładany raz. |
| `fuel` | `number` | Paliwo 0-100. Od tego momentu utrzymuje je skrypt paliwa. |

```lua title="Lua (klient)"
local vehicle = GetVehiclePedIsIn(PlayerPedId(), false)
if Entity(vehicle).state['ai:owned'] then
  print('owned vehicle', Entity(vehicle).state['ai:vid'])
end
```

## API qbx_vehicles

ai-vehicles robi `provide` dla `qbx_vehicles`, więc te wywołania do niego trafiają. Kształty są zgodne z Qbox: `state` to `0` na zewnątrz, `1` garaż, `2` parking policyjny.

| Eksport | Co robi |
| --- | --- |
| `GetPlayerVehicles(filters: { citizenid?, garage? })` | Pojazdy postaci online, opcjonalnie tylko z jednego garażu. Zwraca `{ id, citizenid, modelName, garage, state, depotPrice, props }[]`. |
