Presque tous les scripts FiveM sont écrits pour ESX, QBCore, Qbox ou vRP, les faire tourner est donc un objectif principal. AI Core ne fournit aucun script tiers et ne favorise aucun éditeur : vous installez les vôtres.

## Trois couches

<Steps>
<Step>

### Pont de framework

AI Core fournit `es_extended`, `qb-core` et `qbx_core` et répond à leurs exports, objets core, objets joueur, callbacks, événements et inclusions de fichiers (`@qb-core/shared/locale.lua`, `@es_extended/imports.lua`, `@qbx_core/modules/playerdata.lua`), si bien que les scripts écrits pour ESX, QBCore ou Qbox voient AI Core comme leur framework et tournent sans modification. Pour les scripts vRP, AI Core fournit aussi `vrp` (voir **Scripts vRP** plus bas). Leurs menus, invites de texte, barres de progression et boîtes de saisie sont dessinés avec l’interface propre à AI Core.

</Step>
<Step>

### Couches d’intégration

AI Core et les scripts `ai-*` ont besoin de choses que d’autres scripts fournissent. Chaque catégorie a une seule interface et chaque script pris en charge est un adaptateur. AI Core détecte le script installé au démarrage et quand des scripts démarrent ou s’arrêtent ; le panneau d’administration peut forcer le choix.

| Catégorie | Exemples |
| --- | --- |
| Inventaire | ai-inventory, ox_inventory, qb-inventory, tgiann-inventory et d’autres |
| Clés de véhicule | ai-vehiclekeys, qbx_vehiclekeys et d’autres |
| Dispatch (alertes police) | ai-policealert et scripts d’alerte |
| Téléphone | tgiann-phone, lb-phone |
| Vêtements | ai-appearance, tgiann-clothing |
| Mort | ai-death, qbx_medical, qb-ambulancejob, esx_ambulancejob, ars_ambulancejob |
| Météo et heure | ai-weathersync, qb-weathersync, Renewed-Weathersync, cd_easytime |
| Prison | ai-prison, qb-prison |
| Menu radial | ai-radialmenu, qb-radialmenu, ox_lib |

</Step>
<Step>

### Remplaçants

Plusieurs scripts `ai-*` répondent à l’API du script qu’ils remplacent, si bien que les scripts tiers fonctionnent avec eux sans adaptateur : ai-mysql remplace oxmysql (ainsi que mysql-async et ghmattimysql), ai-inventory remplace ox_inventory et qb-inventory, ai-target ox_target, ai-voice pma-voice, ai-chat chat, ai-vehicles et ai-vehiclekeys les scripts de véhicules Qbox.

</Step>
</Steps>

Consultez la liste des [scripts compatibles](/fr/scripts) pour voir avec quoi AI Core s’intègre aujourd’hui.

## Scripts vRP

AI Core fournit aussi `vrp`, si bien que les scripts écrits pour le framework vRP le trouvent et tournent avec les personnages, l’argent, les métiers, les gangs et l’inventaire d’AI Core. Il n’y a aucun réglage : toutes les versions ci-dessous sont prises en charge en même temps, et AI Core les distingue à la façon dont elles l’appellent.

| Version de vRP | Ce qui fonctionne |
| --- | --- |
| vRP 1.0 | Les scripts qui utilisent `Proxy` / `Tunnel` avec `vRP.*` et `vRPclient.*` : utilisateurs, argent, groupes et permissions, inventaire et coffres, identité, faim et soif, menus, invites de texte, notifications, blips et marqueurs. |
| vRPex, Zirix, Dunko | La même chose, plus les fonctions ajoutées par ces forks de vRP 1 (`format`, `hasPermissions`, `tryBankPayment` et d’autres). |
| L’ancien style d’appel de vRP 0.5 | Les appels qui passent leurs arguments dans une table avec un callback, comme `vRP.getUserId({source})`. |
| vRP 2 et vRP 3 | Les extensions qu’un script charge avec `vRP.loadScript`. Chacune tourne dans son propre bac à sable (sandbox) dans AI Core : ses globales ne touchent jamais un autre script, et tout ce qu’elle a enregistré est retiré quand sa ressource s’arrête. |

Les menus, invites de texte et demandes oui / non des scripts vRP sont dessinés avec le menu et les boîtes de dialogue d’AI Core. Quand un script ajoute des entrées au menu principal de vRP, les joueurs l’ouvrent avec **F7** ; vous pouvez changer la touche dans **Keybinds** du panel d’administration.

AI Core a été testé sur un serveur en marche avec sept scripts vRP publics : vrp_basic_mission, vrp_chests, vrp_blips, self_storages, vrp_drugfarms, vrp_worlditems et party_system.

## Installer un script vRP

<Steps>
<Step>

### Retirer le vRP d’origine

AI Core est désormais votre ressource `vrp`, l’originale doit donc partir. Si votre serveur a un dossier `vrp` ou un pilote de base de données vRP (`vrp_mysql`, `vrp_oxmysql`, `vrp_ghmattimysql`, `vRP-db-drivers`), supprimez le dossier et sa ligne `ensure` dans `server.cfg`. Tant que l’un d’eux est encore là, AI Core refuse les connexions et indique le dossier à supprimer.

</Step>
<Step>

### Ajouter le script

Placez le dossier du script dans `resources/[standalone]/` et ajoutez `ensure <nom du dossier>` dans `server.cfg` sous les lignes `ensure ai-*`, comme pour tout autre script. Ne modifiez pas le script : sa dépendance `vrp` et son inclusion `@vrp/lib/utils.lua` atteignent AI Core d’elles-mêmes.

</Step>
<Step>

### Le démarrer et distribuer ses permissions

Redémarrez le serveur et essayez les fonctions du script en jeu. Ouvrez ensuite le panel d’administration (**F10**) et l’onglet **vRP scripts** d’AI Core : **Asked permissions** liste chaque nom de permission demandé par le script. Décidez qui obtient chacune, comme l’explique la section suivante.

</Step>
</Steps>

## L’onglet vRP scripts

Les scripts vRP ne demandent pas « ce joueur est-il policier ? ». Ils demandent des noms de permission (`police.service`), des noms de groupe (`police`, `vip`) et des identifiants d’objet (`edible|tacos`). L’onglet **vRP scripts**, dans la partie AI Core du panel d’administration, décide de ce que ces noms veulent dire sur votre serveur. Chaque changement est enregistré tout de suite, sans redémarrage. L’onglet a cinq cartes :

<Steps>
<Step>

### Built-in rules (règles intégrées)

Ces trois interrupteurs répondent à chaque nom de permission qu’aucune règle ne mentionne, si bien que beaucoup de scripts fonctionnent avant même que vous ajoutiez une règle :

- **Job permissions go to the job** : une permission qui commence par le nom d’un métier, comme `police.service`, va aux membres de ce métier. Avec **Only while on duty** activé, ils ne l’ont qu’en service.
- **admin. permissions go to admins** : une permission qui commence par `admin.`, comme `admin.tickets`, va aux joueurs qui ont les droits d’admin (ACE `ai.admin`).
- **player. permissions go to everyone** : une permission qui commence par `player.`, comme `player.phone`, va à tous les joueurs.

</Step>
<Step>

### Asked permissions (permissions demandées)

Chaque nom de permission que vos scripts ont demandé, avec un champ de recherche. Appuyez sur **Add rule** à côté d’un nom et une règle pour lui apparaît en haut de **Permission rules**. Une nouvelle règle donne la permission aux admins seulement, jusqu’à ce que vous choisissiez qui doit l’avoir.

</Step>
<Step>

### Permission rules (règles de permission)

Une ligne par règle. Dans **Permission name**, écrivez la permission (`police.service`), ou un nom qui finit par `*` (`police.*`) pour couvrir toutes les permissions qui commencent ainsi. Dans **Who has it**, choisissez :

- **Members of a job** : choisissez le métier et le **Lowest grade** (ce grade et tous ceux au-dessus). Activez **Only on duty** s’ils ne doivent l’avoir qu’en service.
- **Members of a gang** : choisissez le gang et le grade le plus bas.
- **Characters in a group** : écrivez un nom de groupe que les scripts donnent (voir **Group names**).
- **Admins** ou **Everyone**.

Plusieurs règles peuvent nommer la même permission : quiconque correspond à l’une d’elles l’a. Dès qu’une règle nomme une permission, les règles intégrées ne comptent plus pour elle. Le panel refuse un grade que le métier ou le gang n’a pas.

</Step>
<Step>

### Group names (noms de groupe)

Les scripts vRP donnent et vérifient les groupes par leur nom. Le nom propre d’un métier ou d’un gang (`police`, `ballas`) fonctionne sans ligne. Pour tout autre nom qu’un script utilise (`Coronel`, `sheriff`), ajoutez une ligne : écrivez-le dans **Group name** et choisissez ce qu’il signifie dans **Means** :

- **A job grade** ou **A gang grade** : quand un script donne ce groupe, le personnage reçoit ce métier ou ce gang à ce grade ; quand un script le vérifie, la réponse est oui pour ce grade et tous ceux au-dessus.
- **Admins** : la vérification répond oui pour les joueurs qui ont les droits d’admin. Un script ne peut jamais rendre quelqu’un admin : donner ce groupe est refusé.

Un nom sans ligne reste un groupe à part, enregistré avec le personnage.

</Step>
<Step>

### Item names (noms d’objet)

Reliez un identifiant d’objet qu’un script utilise (**Name scripts use**, comme `edible|tacos`) à un objet de votre inventaire (**Inventory item**, choisi dans la liste). Un identifiant qui est déjà le nom d’un de vos objets n’a pas besoin de ligne. Sans ligne, `wbody|WEAPON_X` désigne l’objet arme et tout autre identifiant `a|b` désigne `b`.

</Step>
</Steps>

<Callout>
Exemple : un script de police demande `police.service`, mais votre métier de police s’appelle `lspd`. Ajoutez une règle de permission avec le nom `police.service`, **Members of a job**, le métier `lspd`, le grade le plus bas 0 et **Only on duty** activé. Chaque policier en service a maintenant la permission.
</Callout>

## Ce qui ne fonctionne pas avec vRP

- **Creative v5.** Son API (noms en PascalCase, `@vrp/lib/Utils.lua`, `@vrp/config/*.lua`) est différente et n’est pas prise en charge.
- **Le SQL sur les tables propres à vRP.** AI Core garde ses propres données, donc un script qui lit ou écrit `vrp_users`, `vrp_user_identities`, `vrp_user_data`, `vrp_srv_data` ou des tables semblables avec ses propres requêtes ne trouve rien.
- **Les modules vRP qu’AI Core n’a pas :** annuaire du téléphone, maisons, entreprises, véhicules possédés et garages, aptitudes, casiers de police et prison, magasins, transformateurs d’objets, distributeurs, audio et radio, barres de progression, bans et whitelist, et les missions de vRP 1 (les missions de vRP 2 / 3 fonctionnent). Un script qui les utilise perd cette partie.
- **Les menus n’ont ni gauche ni droite.** Les options qui changent une valeur avec les flèches ne prennent qu’un choix simple.
- **`vRP:playerSpawn` se déclenche une fois par chargement de personnage**, pas après une réapparition : les réapparitions appartiennent au script de mort.
- **`vrp` apparaît toujours comme démarré.** Un script qui gère plusieurs frameworks et vérifie vRP en premier prend son code vRP. Si vous voulez son code ESX ou QBCore, choisissez ce framework dans la configuration du script.
- **Une extension vRP 2 / 3 tourne dans AI Core**, donc son temps CPU apparaît sous `ai-core` dans `resmon`. Si elle échoue, la console écrit une ligne avec son fichier et AI Core continue de tourner.

## Remplacer un script ai-*

Si vous installez un script payant qui remplace un script `ai-*` (par exemple un autre inventaire), AI Core vous indique quel dossier supprimer et refuse les connexions tant que les deux tournent, pour que deux scripts ne se disputent jamais la même tâche.

## Ajouter un script

Prendre en charge un nouveau script est une petite tâche répétable : copiez le modèle d’adaptateur de la catégorie, remplissez ses appels, ajoutez une ligne au registre. Vous pouvez demander à votre IA de le faire.
