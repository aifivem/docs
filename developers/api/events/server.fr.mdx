ai-core déclenche ces événements sur le serveur avec `TriggerEvent` (locaux : les autres ressources serveur les entendent, les clients jamais). Le miroir `online` de la lib et les ponts ESX / QB / vRP reposent dessus ; c’est donc le moyen le moins coûteux de suivre les joueurs : aucun appel d’export, aucune interrogation en boucle.

Le handler de chaque événement s’exécute de façon **synchrone** pendant qu’ai-core est au milieu du changement : gardez les handlers courts et n’attendez jamais à l’intérieur. Si vous devez attendre (une écriture en base de données), lancez-la sans bloquer.

### ai-core:playerLoaded

Le personnage d’un joueur a été chargé et ses données envoyées à son client. Se déclenche une fois par chargement de personnage, aussi après un changement de personnage. Avec le choix d’apparition activé, il se déclenche avant que le joueur choisisse où apparaître ; `ai-core:playerSpawned` suit le choix.

**Côté :** Serveur · **Constante :** `CORE.playerLoadedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    character: { type: 'CharacterInfo', description: 'Le personnage : `id`, `citizenid`, `slot`, `firstname`, `lastname`, `birthdate`, `sex`, `nationality`.', required: true, typeDescriptionLink: '/docs/developers/api/types#characterinfo' },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aicore-fivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`#${character.id} ${character.firstname} ${character.lastname} loaded (src ${src})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('#%d %s %s loaded (src %d)'):format(character.id, character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Les personnages déjà chargés avant le démarrage de votre ressource ne le déclenchent jamais pour vous. Utilisez `onCharacter({ loaded })` de la lib (`aiLib.onCharacter` en Lua), qui les rejoue.
</Callout>

### ai-core:playerSpawned

Le personnage chargé a été placé dans le monde. Se déclenche juste après `ai-core:playerLoaded`, ou après que le joueur a choisi un point d’apparition quand le serveur le laisse choisir. Utilisez-le pour ce qui a besoin du ped dans le monde (un message de bienvenue, une téléportation).

**Côté :** Serveur · **Constante :** `CORE.playerSpawnedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    charId: { type: 'number', description: 'L’id du personnage apparu.', required: true },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { notify } from "@aicore-fivem/lib/server";
import { CORE } from "@aicore-fivem/shared";
import { Locale } from "common";

on(CORE.playerSpawnedEvent, (src: number, _charId: number) => {
  notify(src, Locale("WELCOME_BACK"), "info");
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
local Locale = aiLib.locale()

AddEventHandler('ai-core:playerSpawned', function(src, charId)
  aiLib.notify(src, Locale('WELCOME_BACK'), 'info')
end)
```
</Tab>
</Tabs>

### ai-core:playerUnloaded

Un personnage est libéré : le joueur a quitté le serveur, ou est revenu à l’écran des personnages. Se déclenche **avant** qu’ai-core abandonne le personnage, si bien que les exports d’ai-core répondent encore pour lui dans votre handler. Nettoyez ici tout ce que vous gardez par joueur.

**Côté :** Serveur · **Constante :** `CORE.playerUnloadedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    charId: { type: 'number', description: 'L’id du personnage en cours de déchargement.', required: true },
    reason: { type: '"dropped" | "switch"', description: '`dropped` : le joueur est parti. `switch` : il est revenu à l’écran des personnages et reste connecté.', required: true, typeDescriptionLink: '/docs/developers/api/types#unloadreason' },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE } from "@aicore-fivem/shared";

const activeJobs = new Map<number, string>();

on(CORE.playerUnloadedEvent, (src: number, _charId: number, reason: "dropped" | "switch") => {
  activeJobs.delete(src);
  console.log(`${src} unloaded (${reason})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
local activeJobs = {}

AddEventHandler('ai-core:playerUnloaded', function(src, charId, reason)
  activeJobs[src] = nil
  print(('%d unloaded (%s)'):format(src, reason))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Avec `reason = "switch"`, le même id serveur peut charger un autre personnage un instant plus tard. Indexez vos données par personnage avec `charId` ou effacez-les ici ; ne supposez jamais qu’un id serveur garde un seul personnage.
</Callout>

### ai-core:moneyChanged

Le solde d’un compte d’un personnage chargé a changé. Se déclenche après l’application du changement, une fois par changement, seulement quand le solde a vraiment bougé.

**Côté :** Serveur · **Constante :** `CORE.moneyChangedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    account: { type: 'string', description: 'Le nom du compte (`"cash"`, `"bank"`, ou un autre compte que définit le panneau).', required: true },
    balance: { type: 'number', description: 'Le nouveau solde.', required: true },
    delta: { type: 'number', description: 'De combien il a changé : positif pour l’argent entrant, négatif pour l’argent sortant.', required: true },
    reason: { type: 'string', description: 'La raison donnée par le script qui a déplacé l’argent (écrite dans le log d’argent).', required: true },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE } from "@aicore-fivem/shared";

// Signale au staff les gros paiements en liquide.
on(CORE.moneyChangedEvent, (src: number, account: string, balance: number, delta: number, reason: string) => {
  if (account === "cash" && delta >= 100_000)
    console.log(`${src} got $${delta} cash (${reason}), now $${balance}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"

AddEventHandler('ai-core:moneyChanged', function(src, account, balance, delta, reason)
  if account == 'cash' and delta >= 100000 then
    print(('%d got $%d cash (%s), now $%d'):format(src, delta, reason, balance))
  end
end)
```
</Tab>
</Tabs>

### ai-core:jobsChanged

La liste des métiers d’un personnage chargé a changé : un métier ajouté ou retiré, ou un grade modifié.

**Côté :** Serveur · **Constante :** `CORE.jobsChangedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    jobs: { type: 'JobMembership[]', description: 'La nouvelle liste complète : `{ job, grade }` pour chaque métier.', required: true, typeDescriptionLink: '/docs/developers/api/types#jobmembership' },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type JobMembership } from "@aicore-fivem/shared";

on(CORE.jobsChangedEvent, (src: number, jobs: JobMembership[]) => {
  const police = jobs.find((m) => m.job === "police");
  console.log(police ? `${src} is police grade ${police.grade}` : `${src} is not police`);
});
```

<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:jobsChanged', function(src, jobs)
  for _, m in ipairs(jobs) do
    if m.job == 'police' then return print(('%d is police grade %d'):format(src, m.grade)) end
  end
  print(('%d is not police'):format(src))
end)
```
</Tab>
</Tabs>

### ai-core:itemUsed

Un joueur a utilisé un objet. Transporte les besoins que donne l’objet (faim, soif, stress), pour qu’un HUD ou un script de besoins les applique sans connaître l’inventaire. ai-hud l’écoute.

**Côté :** Serveur · **Constante :** `CORE.itemUsedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    name: { type: 'string', description: 'Le nom de l’objet (`"sandwich"`).', required: true },
    status: { type: 'Record<string, number> | null', description: 'Les besoins que donne l’objet, par nom (`{ hunger: 25 }`), tels que les fixe la définition de l’objet. `null` quand l’objet n’en donne aucun.', required: true },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/needs.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.itemUsedEvent, (src: number, name: string, status: Record<string, number> | null) => {
  if (!status) return;
  for (const [need, amount] of Object.entries(status))
    console.log(`${src} used ${name}: ${need} ${amount > 0 ? "+" : ""}${amount}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server/needs.lua"
AddEventHandler('ai-core:itemUsed', function(src, name, status)
  if not status then return end
  for need, amount in pairs(status) do
    print(('%d used %s: %s %s'):format(src, name, need, amount))
  end
end)
```
</Tab>
</Tabs>

<Callout type="warn">
Aujourd’hui, seul ai-inventory signale les utilisations d’objets à ai-core : avec un autre inventaire, cet événement ne se déclenche pas. Écoutez cet événement, et non l’événement d’utilisation propre à un inventaire, pour que votre script fonctionne quand ai-inventory est l’inventaire et continue de fonctionner quand d’autres seront ajoutés.
</Callout>

### ai-core:playerDied

Un joueur avec un personnage chargé est mort. ai-core le tient du propre rapport de mort de ped de FXServer (FXServer 38039 ou plus récent), si bien qu’aucun client n’est cru sur parole.

**Côté :** Serveur · **Constante :** `CORE.playerDiedEvent`

#### Arguments

<TypeTable
  type={{
    src: { type: 'number', description: 'L’id serveur du joueur mort.', required: true },
    killer: { type: 'number | null', description: 'L’id serveur du joueur dont le ped est crédité du meurtre par le jeu, `null` quand ce n’était pas un joueur chargé (un PNJ, une chute, une voiture sans joueur). Peut être `src` lui-même.', required: true },
    weaponHash: { type: 'number', description: 'Le hash de l’arme ou de la cause que rapporte le jeu.', required: true },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/killfeed.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.playerDiedEvent, (src: number, killer: number | null, weaponHash: number) => {
  if (killer !== null && killer !== src)
    console.log(`${GetPlayerName(String(killer))} killed ${GetPlayerName(String(src))} (weapon ${weaponHash})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server/killfeed.lua"
AddEventHandler('ai-core:playerDied', function(src, killer, weaponHash)
  if killer and killer ~= src then
    print(('%s killed %s (weapon %d)'):format(GetPlayerName(killer), GetPlayerName(src), weaponHash))
  end
end)
```
</Tab>
</Tabs>

<Callout type="info">
Il s’agit de la mort dans le jeu, pas de l’état « à terre » du script de mort : un script de mort peut garder en vie un joueur à terre pour l’animer. Pour savoir si un joueur est à terre, utilisez `medical` de la lib serveur ou les exports médicaux serveur d’ai-core.
</Callout>

## Événements des autres scripts ai-*

Ceux-ci sont déclenchés par des scripts ai-*, pas par ai-core, mais beaucoup de ressources les écoutent. Leur référence complète se trouve sur la page développeur de chaque script.

### ai-vehicles:owners

Les propriétaires des véhicules possédés en mémoire ont changé (un personnage chargé avec son garage, un véhicule acheté, vendu ou supprimé). Se déclenche au plus une fois par tick serveur avec tous les changements de ce tick. Les scripts de clés l’utilisent pour garder une table plaque vers propriétaire sans interroger ai-vehicles à chaque fois.

**Côté :** Serveur · **Constante :** `VEHICLES_EVENTS.owners`

#### Arguments

<TypeTable
  type={{
    puts: { type: '[plate: string, ownerType: string, ownerId: string][]', description: 'Plaques ajoutées ou modifiées, avec le type de propriétaire (`"character"`, `"job"`, `"gang"`, `"resource"`) et l’id du propriétaire.', required: true },
    removes: { type: 'string[]', description: 'Plaques qui ne sont plus en mémoire.', required: true },
  }}
/>

#### Écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/owners.ts"
import { resourceExport } from "@aicore-fivem/lib/server";
import { VEHICLES_EVENTS } from "@aicore-fivem/shared";

const owners = new Map<string, string>();

// Partir de la liste complète, puis suivre les changements.
for (const [plate, type, id] of resourceExport("ai-vehicles").GetPlateOwners()) owners.set(plate, `${type}:${id}`);
```

### chatMessage

ai-chat déclenche l’événement FiveM classique `chatMessage` avant de livrer le message d’un joueur. Appeler `CancelEvent()` dans votre handler supprime le message.

**Côté :** Serveur · **Constante :** aucune (le nom propre à FiveM)

#### Arguments

    author: { type: 'string', description: 'Le nom d’auteur affiché dans le chat.', required: true },
    text: { type: 'string', description: 'Le texte du message.', required: true },
  }}
/>
