ai-core mówi innym skryptom, gdy coś się zmienia: postać się wczytała, pieniądze się przesunęły, praca się zmieniła, gracz został powalony, HUD się ukrył. Twój skrypt **nasłuchuje** zamiast pytać w kółko. Ta sekcja wymienia każde zdarzenie i każdą wspólną wartość stanu, których używają inne zasoby.

## Trzy rodzaje

| Rodzaj | Co to jest | Jak nasłuchiwać |
| --- | --- | --- |
| **Zdarzenie lokalne** | Wysyłane po jednej stronie (serwer lub jeden klient) dla każdego zasobu po tej stronie. Nigdy nie przechodzi przez sieć. Większość zdarzeń ai-core jest lokalna. | TS: `on(name, handler)`. Lua: `AddEventHandler(name, handler)`. |
| **Zdarzenie sieciowe** | Wysyłane z serwera do klienta jednego gracza (lub w drugą stronę). | Klient TS: `onServerEvent(name, ...)` z liba. Klient Lua: `aiLib.onServerEvent(name, handler)`. |
| **State bag** | Wartość zapisana w GlobalState, na graczu lub na encji. Każdy może ją czytać; zapisuje ją tylko zasób, do którego należy. | `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup` z liba albo `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` w Lua. |

## Strony

| Strona | Co |
| --- | --- |
| [Zdarzenia serwerowe](/pl/docs/developers/api/events/server) | Postać wczytana, pojawiona, zwolniona; pieniądze, prace, służba, gangi, metadane; użyty przedmiot; śmierć gracza; definicje prac i gangów; zmiana ekwipunku. |
| [Zdarzenia klienckie](/pl/docs/developers/api/events/client) | Wczytanie lub zwolnienie lokalnej postaci, stan powalenia, wartości w pamięci podręcznej, widoczność HUD, synchronizacja świata, podpowiedzi klawiszy, pas bezpieczeństwa. |
| [Zdarzenia sieciowe](/pl/docs/developers/api/events/net) | Kanał danych gracza, którego klient może nasłuchiwać, i własny ruch ai-core, którego nie wolno wywoływać. |
| [Zdarzenia UI ai-lib](/pl/docs/developers/api/events/ai-lib-ui) | Odpowiedzi menu, okien wprowadzania, podpowiedzi i paska postępu, dla skryptów, które same wywołują eksporty ai-lib. |
| [State bagi](/pl/docs/developers/api/events/state-bags) | `PLAYER_BAGS`, `VEHICLE_BAGS` i każdy klucz GlobalState zapisywany przez ai-core. |
| [Zdarzenia mostu frameworków](/pl/docs/developers/api/events/framework-bridge) | Zdarzenia ESX, QB / Qbox i vRP, które ai-core wysyła dla skryptów napisanych dla tych frameworków, i zdarzenia frameworków, na które odpowiada. |

## Nazwy pochodzą ze stałych

W TypeScript nigdy nie wpisuj nazwy zdarzenia ręcznie. To stałe w `@aicore-fivem/shared`:

| Stała | Zdarzenia |
| --- | --- |
| `CORE` | Serwerowe i klienckie zdarzenia ai-core (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) i klucze GlobalState (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | Odpowiedzi UI ai-lib. |
| `VEHICLES_EVENTS` | Kanał właścicieli z ai-vehicles. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | Klucze state bagów. |

Lua nie ma stałych: używaj stringa pokazanego obok każdego zdarzenia.

## Pierwsze nasłuchiwanie

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aicore-fivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Dla całego życia postaci na serwerze (wczytana, zwolniona i postacie, które są już w świecie, gdy twój zasób się restartuje) używaj `onCharacter({ loaded, unloaded })` z liba (`aiLib.onCharacter` w Lua) zamiast ręcznie obsługiwać dwa zdarzenia. Zasób, który startuje późno, przegapia zdarzenia wysłane przed jego startem; `onCharacter` odtwarza te postacie za ciebie.
</Callout>

<Callout type="warn">
Lokalne zdarzenia ai-core są lokalne celowo. Nigdy nie rób `RegisterNetEvent` (ani `onNet`) dla żadnej z ich nazw: pozwoliłoby to klientowi dowolnego gracza wysłać fałszywe `ai-core:moneyChanged` lub `ai-core:playerLoaded` do twojego handlera. Zwykłe `AddEventHandler` / `on` słyszy tylko zdarzenia wysłane po tej samej stronie.
</Callout>
