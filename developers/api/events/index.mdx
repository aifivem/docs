ai-core tells other scripts when something changes: a character loaded, money moved, a job changed, the player went down, the HUD hid. Your script **listens** instead of asking again and again. This section lists every event and shared state value other resources use.

## The three kinds

| Kind | What it is | How you listen |
| --- | --- | --- |
| **Local event** | Fired on one side (server or one client) for every resource on that side. Never crosses the network. Most ai-core events are local. | TS: `on(name, handler)`. Lua: `AddEventHandler(name, handler)`. |
| **Net event** | Sent from the server to one player's client (or the other way). | TS client: `onServerEvent(name, ...)` from the lib. Lua client: `aiLib.onServerEvent(name, handler)`. |
| **State bag** | A value stored on GlobalState, a player or an entity. Everyone can read it; only the owning resource writes it. | The lib's `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup`, or `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` in Lua. |

## Names come from constants

In TypeScript, never type an event name by hand. They are constants in `@aifivem/shared`:

| Constant | Events |
| --- | --- |
| `CORE` | ai-core's server and client events (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) and GlobalState keys (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | ai-lib's UI answers. |
| `VEHICLES_EVENTS` | ai-vehicles' owner feed. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | State bag keys. |

Lua has no constants: use the string shown next to each event.

## A first listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aifivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
For a character's whole life on the server (loaded, unloaded, and the characters already in the world when your resource restarts), use the lib's `onCharacter({ loaded, unloaded })` (`aiLib.onCharacter` in Lua) instead of the two events by hand. A resource that starts late misses events fired before it started; `onCharacter` replays those characters for you.
</Callout>

<Callout type="warn">
ai-core's local events are local on purpose. Never `RegisterNetEvent` (or `onNet`) one of their names: that would let any player's client fire a fake `ai-core:moneyChanged` or `ai-core:playerLoaded` into your handler. Plain `AddEventHandler` / `on` only hears events fired on the same side.
</Callout>
