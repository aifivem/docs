title: Events der Framework-Brücke
description: Die ESX-, QB- / Qbox- und vRP-Events, die ai-core auslöst, damit für diese Frameworks geschriebene Skripte weiter funktionieren, mit ihren genauen Argumenten, und die Framework-Events, die ai-core beantwortet.
icon: Cable
---

ai-core gibt sich als `es_extended`, `qb-core`, `qbx_core` und `vrp` aus, sodass für diese Frameworks geschriebene Skripte ohne Änderungen laufen. Dazu gehört, die eigenen Events des Frameworks auszulösen, wenn sich in ai-core etwas ändert: Ein Charakter lädt, Geld bewegt sich, ein Job ändert sich. Diese Seite listet jedes Framework-Event, das die Brücke auslöst, mit den Argumenten, wie die Brücke sie sendet, und die Framework-Events, die sie beantwortet.

**Neuer Code sollte diese nicht nutzen.** Schreibe gegen die eigenen Events von ai-core ([Server](/de/docs/developers/api/events/server), [Client](/de/docs/developers/api/events/client)) und die Lib: Sie tragen mehr (mehrere Jobs, Gangs, Dienst) und hängen nicht von der Form eines Frameworks ab. Diese Seite ist dafür da, bestehende ESX- / QB- / vRP-Skripte zu betreiben und zu reparieren.

<Callout type="info">
Die Framework-Ansichten führen einen Job pro Spieler: den Job, in dem der Spieler im Dienst ist, sonst seinen ersten Job. ai-core selbst erlaubt mehrere Jobs. ESX hat keine Gang; das Konto `money` von ESX ist `cash` von ai-core.
</Callout>

## QBCore und Qbox: Server

Die Brücke löst diese auf dem Server mit `TriggerEvent` aus. Qbox-Skripte hören auf dieselben QBCore-Namen; die Brücke löst kein reines Qbox-Event aus.

## QBCore und Qbox: Client

Werden im eigenen Client des Spielers mit `TriggerEvent` ausgelöst.

| Event | Wann | Argumente |
| --- | --- | --- |
| `QBCore:Client:OnPlayerLoaded` | Der Charakter steht in der Welt. | keine |
| `QBCore:Client:OnPlayerUnload` | Der Spieler ist zum Charakterbildschirm zurückgekehrt. | keine |
| `QBCore:Player:SetPlayerData` | Nach dem Laden und nach jeder Änderung von Geld, Job, Gang oder Metadaten. | `(PlayerData: table)` die ganzen QB-PlayerData. |
| `QBCore:Client:OnJobUpdate` | Der Framework-Job hat sich geändert. | `(job: table)` die QB-Job-Tabelle (wie auf dem Server). |
| `QBCore:Client:SetDuty` | Der Dienst hat sich für denselben Job geändert. | `(onDuty: boolean)` |
| `QBCore:Client:OnGangUpdate` | Die Framework-Gang hat sich geändert. | `(gang: table)` die QB-Gang-Tabelle. |
| `QBCore:Client:OnMoneyChange` | Ein Kontostand hat sich geändert. | `(account: string, balance: number)` der Kontoname von ai-core und der neue Kontostand. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
on("QBCore:Client:OnPlayerLoaded", () => console.log("loaded"));
on("QBCore:Client:OnJobUpdate", (job: { name: string }) => console.log(`job: ${job.name}`));
on("QBCore:Client:SetDuty", (onDuty: boolean) => console.log(`on duty: ${onDuty}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('QBCore:Client:OnPlayerLoaded', function() print('loaded') end)
AddEventHandler('QBCore:Client:OnJobUpdate', function(job) print(('job: %s'):format(job.name)) end)
AddEventHandler('QBCore:Client:SetDuty', function(onDuty) print(('on duty: %s'):format(tostring(onDuty))) end)
```
</Tab>
</Tabs>

<Callout type="warn">
`QBCore:Client:OnMoneyChange` trägt `(account, balance)`, den neuen Kontostand, nicht die eigenen Argumente von qb-core. Ein QB-Skript, das ihn als Betrag liest, sieht den Kontostand. Bevorzuge `QBCore:Player:SetPlayerData` oder `onPlayerData("money", ...)` von ai-core.
</Callout>

## Framework-Events, die ai-core beantwortet

Für ein Framework geschriebene Skripte senden diese Events und erwarten, dass das Framework antwortet. ai-core beantwortet sie stattdessen.

| Event | Seite | Was ai-core tut |
| --- | --- | --- |
| `QBCore:GetObject`, `esx:getSharedObject` | beide | Ruft den Callback mit dem Core-Objekt auf (`QBCore` / `ESX`). |
| `QBCore:Server:TriggerCallback`, `esx:triggerServerCallback` | Server (von Clients) | Führt den mit `CreateCallback` / `RegisterServerCallback` registrierten Framework-Callback aus und antwortet. Höchstens 30 Anfragen pro Spieler in beliebigen 10 Sekunden. |
| `QBCore:Notify`, `esx:showNotification`, `esx:showAdvancedNotification`, `ESX:Notify` | Client (vom Server) | Zeigt die Benachrichtigung von ai-lib. |
| `esx:showHelpNotification`, `ESX:TextUI`, `ESX:HideUI`, `qb-core:client:DrawText`, `qb-core:client:ChangeText`, `qb-core:client:HideText`, `qb-core:client:KeyPressed` | Client | Zeigt oder verbirgt die Aufforderung von ai-lib. |
| `qb-menu:client:openMenu`, `qb-menu:client:closeMenu` | Client | Öffnet oder schließt das Menü von ai-lib mit den qb-menu-Einträgen. |
| `progressbar:client:cancel` | Client | Bricht den Fortschrittsbalken der Brücke ab. |
| `police:server:policeAlert` | Server | Sendet einen Polizeialarm an der Position des Spielers an das aktive Alarmsystem. Clients senden `(text)` (einen pro Spieler in 10 Sekunden); Server-Skripte lösen es per `TriggerEvent` mit `(text, camId, playerSource)` aus. |
| `qb-weathersync:client:DisableSync` / `EnableSync`, `cd_easytime:PauseSync`, `vSync:toggle` | Client | Werden als Pause-Gründe der Wetter- und Zeitsynchronisierung gezählt (siehe [Wetter- und Zeitsynchronisierung](/de/docs/developers/api/core-client/world)). |
