ai-core löst diese Events auf dem Server mit `TriggerEvent` aus (lokal: andere Server-Ressourcen hören sie, Clients nie). Der `online`-Spiegel der Lib und die ESX- / QB- / vRP-Brücken bauen darauf auf, deshalb sind sie der günstigste Weg, Spielern zu folgen: kein Export-Aufruf, kein Polling.

Der Handler jedes Events läuft **synchron**, während ai-core mitten in der Änderung ist: Halte Handler kurz und warte nie darin. Wenn du warten musst (ein Schreiben in die Datenbank), starte es, ohne zu blockieren.

### ai-core:playerLoaded

Der Charakter eines Spielers wurde geladen und seine Daten an seinen Client gesendet. Wird einmal pro Laden eines Charakters ausgelöst, auch nach einem Charakterwechsel. Mit aktiver Spawn-Wahl wird es ausgelöst, bevor der Spieler wählt, wo er erscheint; `ai-core:playerSpawned` folgt auf die Wahl.

**Seite:** Server · **Konstante:** `CORE.playerLoadedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers.', required: true },
    character: { type: 'CharacterInfo', description: 'Der Charakter: `id`, `citizenid`, `slot`, `firstname`, `lastname`, `birthdate`, `sex`, `nationality`.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#characterinfo' },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aicore-fivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`#${character.id} ${character.firstname} ${character.lastname} loaded (src ${src})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('#%d %s %s loaded (src %d)'):format(character.id, character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Für Charaktere, die bereits geladen waren, bevor deine Ressource gestartet ist, wird dies für dich nie ausgelöst. Nutze `onCharacter({ loaded })` der Lib (`aiLib.onCharacter` in Lua), das sie nachspielt.
</Callout>

### ai-core:playerSpawned

Der geladene Charakter wurde in die Welt gesetzt. Wird direkt nach `ai-core:playerLoaded` ausgelöst oder nachdem der Spieler einen Spawnpunkt gewählt hat, wenn der Server ihn wählen lässt. Nutze es für Dinge, die den Ped in der Welt brauchen (eine Willkommensnachricht, ein Teleport).

**Seite:** Server · **Konstante:** `CORE.playerSpawnedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers.', required: true },
    charId: { type: 'number', description: 'Die ID des Charakters, der gespawnt ist.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>

```ts title="resource/server/index.ts"
import { CORE } from "@aicore-fivem/shared";
import { Locale } from "common";
```

</Tab>

### ai-core:playerUnloaded

Ein Charakter wird losgelassen: Der Spieler hat den Server verlassen oder ist zum Charakterbildschirm zurückgekehrt. Wird **ausgelöst, bevor** ai-core den Charakter verwirft, sodass die Exports von ai-core in deinem Handler noch für ihn antworten. Räume hier alles auf, was du pro Spieler hältst.

**Seite:** Server · **Konstante:** `CORE.playerUnloadedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers.', required: true },
    charId: { type: 'number', description: 'Die ID des Charakters, der entladen wird.', required: true },
    reason: { type: '"dropped" | "switch"', description: '`dropped`: Der Spieler ist gegangen. `switch`: Er ist zum Charakterbildschirm zurückgekehrt und bleibt verbunden.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#unloadreason' },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE } from "@aicore-fivem/shared";

const activeJobs = new Map<number, string>();

on(CORE.playerUnloadedEvent, (src: number, _charId: number, reason: "dropped" | "switch") => {
  activeJobs.delete(src);
  console.log(`${src} unloaded (${reason})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
local activeJobs = {}

AddEventHandler('ai-core:playerUnloaded', function(src, charId, reason)
  activeJobs[src] = nil
  print(('%d unloaded (%s)'):format(src, reason))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Mit `reason = "switch"` kann dieselbe Server-ID einen Moment später einen anderen Charakter laden. Schlüssele deine Daten pro Charakter über `charId` oder lösche sie hier; nimm nie an, dass eine Server-ID bei einem Charakter bleibt.
</Callout>

### ai-core:moneyChanged

Ein Kontostand eines geladenen Charakters hat sich geändert. Wird ausgelöst, nachdem die Änderung angewendet wurde, einmal pro Änderung, nur wenn sich der Kontostand wirklich bewegt hat.

**Seite:** Server · **Konstante:** `CORE.moneyChangedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers.', required: true },
    account: { type: 'string', description: 'Der Kontoname (`"cash"`, `"bank"` oder ein anderes Konto, das das Panel definiert).', required: true },
    balance: { type: 'number', description: 'Der neue Kontostand.', required: true },
    delta: { type: 'number', description: 'Um wie viel er sich geändert hat: positiv für eingehendes, negativ für ausgehendes Geld.', required: true },
    reason: { type: 'string', description: 'Der Grund, den das Skript angegeben hat, das das Geld bewegt hat (wird ins Geld-Log geschrieben).', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE } from "@aicore-fivem/shared";

// Markiert große Bargeldzahlungen für das Team.
on(CORE.moneyChangedEvent, (src: number, account: string, balance: number, delta: number, reason: string) => {
  if (account === "cash" && delta >= 100_000)
    console.log(`${src} got $${delta} cash (${reason}), now $${balance}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
-- Markiert große Bargeldzahlungen für das Team.
AddEventHandler('ai-core:moneyChanged', function(src, account, balance, delta, reason)
  if account == 'cash' and delta >= 100000 then
    print(('%d got $%d cash (%s), now $%d'):format(src, delta, reason, balance))
  end
end)
```
</Tab>
</Tabs>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>

```ts title="resource/server/index.ts"
on(CORE.jobsChangedEvent, (src: number, jobs: JobMembership[]) => {
  const police = jobs.find((m) => m.job === "police");
```

```lua title="server.lua"
  end
  print(('%d is not police'):format(src))
end)
```
</Tab>
</Tabs>

### ai-core:itemUsed

Ein Spieler hat ein Item benutzt. Trägt die Bedürfnisse, die das Item gibt (Hunger, Durst, Stress), sodass ein HUD oder Bedürfnis-Skript sie anwendet, ohne das Inventar zu kennen. ai-hud hört darauf.

**Seite:** Server · **Konstante:** `CORE.itemUsedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers.', required: true },
    name: { type: 'string', description: 'Der Item-Name (`"sandwich"`).', required: true },
    status: { type: 'Record<string, number> | null', description: 'Die Bedürfnisse, die das Item gibt, nach Namen (`{ hunger: 25 }`), so wie die Item-Definition sie festlegt. `null`, wenn das Item keine gibt.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/needs.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.itemUsedEvent, (src: number, name: string, status: Record<string, number> | null) => {
  if (!status) return;
  for (const [need, amount] of Object.entries(status))
    console.log(`${src} used ${name}: ${need} ${amount > 0 ? "+" : ""}${amount}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server/needs.lua"
AddEventHandler('ai-core:itemUsed', function(src, name, status)
  if not status then return end
  for need, amount in pairs(status) do
    print(('%d used %s: %s %s'):format(src, name, need, amount))
  end
end)
```
</Tab>
</Tabs>

<Callout type="warn">
Derzeit meldet nur ai-inventory Item-Benutzungen an ai-core: Mit einem anderen Inventar wird dieses Event nicht ausgelöst. Höre auf dieses Event, nicht auf das eigene Benutzungs-Event eines Inventars, damit dein Skript funktioniert, wenn ai-inventory das Inventar ist, und weiter funktioniert, wenn andere hinzukommen.
</Callout>

### ai-core:playerDied

Ein Spieler mit geladenem Charakter ist gestorben. ai-core übernimmt das aus der eigenen Ped-Todesmeldung von FXServer (FXServer 38039 oder neuer), sodass keinem Client vertraut wird.

**Seite:** Server · **Konstante:** `CORE.playerDiedEvent`

#### Argumente

<TypeTable
  type={{
    src: { type: 'number', description: 'Die Server-ID des Spielers, der gestorben ist.', required: true },
    killer: { type: 'number | null', description: 'Die Server-ID des Spielers, dessen Ped das Spiel den Kill zuschreibt, `null`, wenn es kein geladener Spieler war (ein NPC, ein Sturz, ein Auto ohne Spieler). Es kann `src` selbst sein.', required: true },
    weaponHash: { type: 'number', description: 'Der Hash der Waffe oder Ursache, die das Spiel meldet.', required: true },
  }}

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/killfeed.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.playerDiedEvent, (src: number, killer: number | null, weaponHash: number) => {
  if (killer !== null && killer !== src)
    console.log(`${GetPlayerName(String(killer))} killed ${GetPlayerName(String(src))} (weapon ${weaponHash})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server/killfeed.lua"
AddEventHandler('ai-core:playerDied', function(src, killer, weaponHash)
  if killer and killer ~= src then
    print(('%s killed %s (weapon %d)'):format(GetPlayerName(killer), GetPlayerName(src), weaponHash))
  end
end)
```
</Tab>
</Tabs>

<Callout type="info">
Das ist der Tod im Spiel, nicht der Zustand „am Boden“ des Tod-Skripts: Ein Tod-Skript kann einen Spieler am Boden am Leben halten, um ihn zu animieren. Für „ist dieser Spieler am Boden“ nutze `medical` der Server-Lib oder die Medizin-Exports des Servers von ai-core.
</Callout>

## Events anderer ai-*-Skripte

Diese werden von ai-*-Skripten ausgelöst, nicht von ai-core, aber viele Ressourcen hören darauf. Ihre vollständige Referenz steht auf der Developer-Seite jedes Skripts.

### ai-vehicles:owners

Die Besitzer der Fahrzeuge mit Besitzer im Speicher haben sich geändert (ein Charakter wurde mit seiner Garage geladen, ein Fahrzeug gekauft, verkauft oder gelöscht). Wird höchstens einmal pro Server-Tick mit jeder Änderung dieses Ticks ausgelöst. Schlüssel-Skripte nutzen es, um eine Zuordnung von Kennzeichen zu Besitzer zu führen, ohne ai-vehicles jedes Mal zu fragen.

**Seite:** Server · **Konstante:** `VEHICLES_EVENTS.owners`

#### Argumente

<TypeTable
  type={{
    puts: { type: '[plate: string, ownerType: string, ownerId: string][]', description: 'Hinzugefügte oder geänderte Kennzeichen, mit dem Besitzertyp (`"character"`, `"job"`, `"gang"`, `"resource"`) und der Besitzer-ID.', required: true },
    removes: { type: 'string[]', description: 'Kennzeichen, die nicht mehr im Speicher sind.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/owners.ts"
import { resourceExport } from "@aicore-fivem/lib/server";
import { VEHICLES_EVENTS } from "@aicore-fivem/shared";

const owners = new Map<string, string>();

// Mit der vollständigen Liste beginnen, dann den Änderungen folgen.
for (const [plate, type, id] of resourceExport("ai-vehicles").GetPlateOwners()) owners.set(plate, `${type}:${id}`);
```

### chatMessage

ai-chat löst das klassische FiveM-Event `chatMessage` aus, bevor es die Nachricht eines Spielers zustellt. `CancelEvent()` in deinem Handler aufzurufen verwirft die Nachricht.

**Seite:** Server · **Konstante:** keine (der eigene Name von FiveM)
