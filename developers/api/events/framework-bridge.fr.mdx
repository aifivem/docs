---
title: Événements du pont de framework
description: Les événements ESX, QB / Qbox et vRP que déclenche ai-core pour que les scripts écrits pour ces frameworks continuent de fonctionner, avec leurs arguments exacts, et les événements de framework auxquels ai-core répond.
icon: Cable
---

ai-core se présente comme `es_extended`, `qb-core`, `qbx_core` et `vrp`, si bien que les scripts écrits pour ces frameworks tournent sans modification. Cela passe notamment par le déclenchement des propres événements du framework quand quelque chose change dans ai-core : un personnage se charge, de l’argent bouge, un métier change. Cette page liste chaque événement de framework que déclenche le pont, avec les arguments tels que le pont les envoie, et les événements de framework auxquels il répond.

**Le nouveau code ne doit pas les utiliser.** Écrivez avec les propres événements d’ai-core ([serveur](/fr/docs/developers/api/events/server), [client](/fr/docs/developers/api/events/client)) et la lib : ils transportent davantage (plusieurs métiers, gangs, service) et ne dépendent pas de la forme d’un framework. Cette page sert à faire tourner et à corriger des scripts ESX / QB / vRP existants.

<Callout type="info">
Les vues de framework gardent un seul métier par joueur : le métier dans lequel le joueur est en service, sinon son premier métier. ai-core lui-même autorise plusieurs métiers. ESX n’a pas de gang ; le compte `money` d’ESX est le `cash` d’ai-core.
</Callout>

## QBCore et Qbox : serveur

Le pont les déclenche sur le serveur avec `TriggerEvent`. Les scripts Qbox écoutent les mêmes noms QBCore ; le pont ne déclenche aucun événement propre à Qbox.

### QBCore:Server:PlayerLoaded

Un personnage a été chargé (depuis `ai-core:playerLoaded`).

**Côté :** Serveur

<TypeTable
  type={{
    Player: { type: 'table', description: 'L’objet Player de QB : `PlayerData` (`source`, `citizenid`, `name`, `money`, `charinfo`, `job`, `gang`, `metadata`...) et `Functions` (`AddMoney`, `RemoveMoney`, `SetJob`, `GetMetaData`...).', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("QBCore:Server:PlayerLoaded", (player: { PlayerData: { source: number; citizenid: string } }) => {
  console.log(`${player.PlayerData.citizenid} loaded (src ${player.PlayerData.source})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('QBCore:Server:PlayerLoaded', function(Player)
  print(('%s loaded (src %d)'):format(Player.PlayerData.citizenid, Player.PlayerData.source))
end)
```
</Tab>
</Tabs>

## QBCore et Qbox : client

Déclenchés sur le propre client du joueur avec `TriggerEvent`.

| Événement | Quand | Arguments |
| --- | --- | --- |
| `QBCore:Client:OnPlayerLoaded` | Le personnage se tient dans le monde. | aucun |
| `QBCore:Client:OnPlayerUnload` | Le joueur est revenu à l’écran des personnages. | aucun |
| `QBCore:Player:SetPlayerData` | Après le chargement et après chaque changement d’argent, de métier, de gang ou de métadonnées. | `(PlayerData: table)` tout le PlayerData de QB. |
| `QBCore:Client:OnJobUpdate` | Le métier de framework a changé. | `(job: table)` la table de métier QB (comme sur le serveur). |
| `QBCore:Client:SetDuty` | Le service a changé pour le même métier. | `(onDuty: boolean)` |
| `QBCore:Client:OnGangUpdate` | Le gang de framework a changé. | `(gang: table)` la table de gang QB. |
| `QBCore:Client:OnMoneyChange` | Le solde d’un compte a changé. | `(account: string, balance: number)` le nom de compte d’ai-core et le nouveau solde. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
on("QBCore:Client:OnPlayerLoaded", () => console.log("loaded"));
on("QBCore:Client:OnJobUpdate", (job: { name: string }) => console.log(`job: ${job.name}`));
on("QBCore:Client:SetDuty", (onDuty: boolean) => console.log(`on duty: ${onDuty}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('QBCore:Client:OnPlayerLoaded', function() print('loaded') end)
AddEventHandler('QBCore:Client:OnJobUpdate', function(job) print(('job: %s'):format(job.name)) end)
AddEventHandler('QBCore:Client:SetDuty', function(onDuty) print(('on duty: %s'):format(tostring(onDuty))) end)
```
</Tab>
</Tabs>

<Callout type="warn">
`QBCore:Client:OnMoneyChange` transporte `(account, balance)`, le nouveau solde, et non les arguments propres à qb-core. Un script QB qui le lit comme un montant voit le solde. Préférez `QBCore:Player:SetPlayerData` ou `onPlayerData("money", ...)` d’ai-core.
</Callout>

## ESX : client

Déclenchés sur le propre client du joueur avec `TriggerEvent`.

| Événement | Quand | Arguments |

## vRP

Le pont vRP d’ai-core déclenche les événements serveur de vRP. Le `user_id` de vRP est l’**id de personnage** d’ai-core.

### vRP:playerSpawn

Le personnage a été placé dans le monde. Se déclenche 2 secondes après qu’ai-core l’a fait apparaître, comme vRP. Uniquement pour l’apparition d’un chargement de personnage : les réapparitions après la mort viennent du script de mort et ne le déclenchent pas.

**Côté :** Serveur

<TypeTable
  type={{

    source: { type: 'number', description: 'L’id serveur du joueur.', required: true },
    first_spawn: { type: 'boolean', description: '`true` pour la première apparition depuis le chargement de ce personnage.', required: true },

/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("vRP:playerSpawn", (userId: number, source: number, firstSpawn: boolean) => {
  if (firstSpawn) console.log(`user ${userId} spawned (src ${source})`);
```

<Tab value="Lua">

### vRP:playerJoinGroup et vRP:playerLeaveGroup

Le personnage a obtenu ou perdu un groupe vRP. Les groupes sont les métiers d’ai-core, le gang actif, les noms de groupes que le propriétaire du serveur a associés dans le panneau (onglet "vRP scripts"), et les groupes supplémentaires qu’ajoutent les scripts vRP. Se déclenche à chaque changement, y compris ceux qu’ai-core ou un autre script fait sans vRP.

**Côté :** Serveur

<TypeTable
  type={{
    user_id: { type: 'number', description: 'L’id du personnage.', required: true },
    group: { type: 'string', description: 'Le nom du groupe.', required: true },
    gtype: { type: '"job" | "gang" | nil', description: '`job` pour un métier, `gang` pour un gang, `nil` pour tout autre groupe.', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("vRP:playerJoinGroup", (userId: number, group: string, gtype?: string) => console.log(`user ${userId} joined ${group} (${gtype ?? "group"})`));
on("vRP:playerLeaveGroup", (userId: number, group: string) => console.log(`user ${userId} left ${group}`));
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('vRP:playerJoinGroup', function(user_id, group, gtype)
  print(('user %d joined %s (%s)'):format(user_id, group, gtype or 'group'))
end)
AddEventHandler('vRP:playerLeaveGroup', function(user_id, group, gtype)
  print(('user %d left %s'):format(user_id, group))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Les extensions vRP 2 et 3 reçoivent du pont leurs propres événements d’extension (`characterLoad`, `playerJoin`, `characterUnload`, `playerLeave`, `playerSpawn`, `playerDeath`, `playerMoneyUpdate`, `playerJoinGroup` / `playerLeaveGroup` et d’autres) via le système d’événements d’extension de vRP, et non comme événements FiveM. Non déclenchés : `vRP:save`, `vRP:playerRejoin`, `vRPcli:playerSpawned`.
</Callout>

## Événements de framework auxquels ai-core répond

Les scripts écrits pour un framework envoient ces événements en attendant que le framework réponde. ai-core y répond à sa place.

| Événement | Côté | Ce que fait ai-core |
| --- | --- | --- |
| `QBCore:GetObject`, `esx:getSharedObject` | les deux | Appelle le callback avec l’objet core (`QBCore` / `ESX`). |
| `QBCore:Server:TriggerCallback`, `esx:triggerServerCallback` | serveur (depuis les clients) | Exécute le callback de framework enregistré avec `CreateCallback` / `RegisterServerCallback` et répond. Au plus 30 requêtes par joueur sur toute période de 10 secondes. |
| `QBCore:Notify`, `esx:showNotification`, `esx:showAdvancedNotification`, `ESX:Notify` | client (depuis le serveur) | Affiche la notification d’ai-lib. |
| `esx:showHelpNotification`, `ESX:TextUI`, `ESX:HideUI`, `qb-core:client:DrawText`, `qb-core:client:ChangeText`, `qb-core:client:HideText`, `qb-core:client:KeyPressed` | client | Affiche ou masque l’invite d’ai-lib. |
| `qb-menu:client:openMenu`, `qb-menu:client:closeMenu` | client | Ouvre ou ferme le menu d’ai-lib avec les entrées de qb-menu. |
| `progressbar:client:cancel` | client | Annule la barre de progression du pont. |
| `police:server:policeAlert` | serveur | Envoie une alerte police au système d’alertes actif, à la position du joueur. Les clients envoient `(text)` (une par joueur toutes les 10 secondes) ; les scripts serveur le déclenchent avec `TriggerEvent` et `(text, camId, playerSource)`. |
| `qb-weathersync:client:DisableSync` / `EnableSync`, `cd_easytime:PauseSync`, `vSync:toggle` | client | Comptés comme raisons de pause de la synchro de la météo et de l’heure (voir [Synchro de la météo et de l’heure](/fr/docs/developers/api/core-client/world)). |
