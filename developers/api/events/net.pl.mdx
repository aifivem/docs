Zdarzenie sieciowe podróżuje między serwerem a klientem jednego gracza. ai-core wysyła ich bardzo mało: własne dane gracza wychodzą raz, gdy postać się wczytuje, potem tylko wartości, które się zmieniają, i tylko do tego gracza. Wszystko inne, czego potrzebuje twój skrypt, to [zdarzenie klienckie](/pl/docs/developers/api/events/client) albo [state bag](/pl/docs/developers/api/events/state-bags).

<Callout type="info">
Rzadko potrzebujesz tych zdarzeń bezpośrednio. `onPlayerData(key, handler)` z liba (TypeScript) i `aiLib.playerData.onChange(key, handler)` (Lua) nasłuchują obu za ciebie, scalają łatki pieniędzy i metadanych i czytają wartości startowe z ai-core.
</Callout>

### ai-core:client:playerData

Serwer wysyła jedną wartość własnych danych gracza: całą wartość jednego klucza. Wysyłane raz na klucz, gdy postać się wczytuje, potem za każdym razem, gdy ta wartość się zmienia (praca, służba, gang...).

**Strona:** Serwer do własnego klienta gracza

#### Argumenty

<TypeTable
  type={{
    key: { type: '"character" | "money" | "jobs" | "duty" | "job" | "gangs" | "activeGang" | "metadata"', description: 'Która to wartość z `AiPlayerData`.', required: true, typeDescriptionLink: '/docs/developers/api/types#aiplayerdata' },
    value: { type: 'unknown', description: 'Cała nowa wartość tego klucza (jej typ to typ pola w `AiPlayerData`).', required: true },
  }}
/>

#### Nasłuchiwanie

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { onPlayerData } from "@aicore-fivem/lib/client";

// Lib nasłuchuje ai-core:client:playerData i playerDataPatch za ciebie.
onPlayerData("job", (job) => console.log(`main job: ${job.job} grade ${job.grade}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- Tylko z serwera: aiLib.onServerEvent odrzuca lokalne fałszywki.
aiLib.onServerEvent('ai-core:client:playerData', function(key, value)
  if key == 'job' then print(('main job: %s grade %d'):format(value.job, value.grade)) end
end)
```
</Tab>
</Tabs>

### ai-core:client:playerDataPatch

Serwer wysyła tylko zmienione wpisy wartości mapy: `money` (nowe saldo jednego konta) lub `metadata` (jeden klucz). Scal łatkę z tym, co masz.

**Strona:** Serwer do własnego klienta gracza

#### Argumenty

<TypeTable
  type={{
    key: { type: '"money" | "metadata"', description: 'Która mapa się zmieniła.', required: true },
    patch: { type: 'Record<string, unknown>', description: 'Tylko zmienione wpisy, na przykład `{ cash: 450 }`. Wpis metadanych ustawiony na `null` został usunięty.', required: true },
  }}
/>

#### Nasłuchiwanie

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { getPlayerData, onPlayerData } from "@aicore-fivem/lib/client";

// Lib scala łatki: handler dostaje całą scaloną mapę pieniędzy.
const show = (money: Record<string, number>): void => SendNUIMessage({ action: "cash", data: money.cash ?? 0 });
show(getPlayerData("money") ?? {});
onPlayerData("money", show);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- aiLib.playerData scala łatki: handler dostaje całą scaloną tabelę pieniędzy.
local function show(money) SendNUIMessage({ action = 'cash', data = (money and money.cash) or 0 }) end
show(aiLib.playerData.get('money'))
aiLib.playerData.onChange('money', show)
```
</Tab>
</Tabs>

<Callout type="warn">
Na kliencie nasłuchuj zdarzeń sieciowych tylko przez `onServerEvent` z liba (TypeScript) lub `aiLib.onServerEvent` (Lua). Sprawdzają, czy zdarzenie naprawdę przyszło z serwera; goły handler `RegisterNetEvent` działa też wtedy, gdy inny kliencki zasób wyśle tę nazwę lokalnie.
</Callout>

## Własny ruch ai-core: nie wywołuj

Te zdarzenia sieciowe i callbacki to wewnętrzny ruch ai-core między jego serwerem a klientem (lub libem). Są wymienione, abyś rozpoznał je w logach. Nigdy nie wywołuj ich z innego skryptu i nie buduj na nich: ich argumenty mogą się zmienić.

| Nazwa | Kierunek | Co |
| --- | --- | --- |
| `ai-core:client:spawn` | serwer do klienta | Umieszcza wczytaną postać w świecie. |
| `ai-core:client:chooseSpawn` | serwer do klienta | Opcje pojawienia się do wyboru przez gracza. |
| `ai-core:client:openCharacters` | serwer do klienta | Pokazuje ponownie ekran postaci po zmianie postaci. |
| `ai-core:client:characterLooks` | serwer do klienta (latent) | Wyglądy na ekranie postaci. |
| `ai-core:client:bills` | serwer do klienta | Otwarte rachunki ai-core gracza, dla listy rachunków. |
| `ai-core:client:stress` | serwer do klienta | Stres dla HUD, który przyjmuje go tylko z własnego klienta. |
| `ai-core:client:vehicleKeys`, `ai-core:client:garages` | serwer do klienta | Wywołania dla skryptów kluczy i garaży, które mają tylko klienckie API. |
| `ai-core:clientError`, `ai-core:fuelReport` | klient do serwera | Raporty błędów klienckich paczek; poziomy paliwa z klienckich skryptów paliwa. |
| `ai-core:characters`, `ai-core:createCharacter`, `ai-core:deleteCharacter`, `ai-core:selectCharacter`, `ai-core:spawnChoice`, `ai-core:payBill`, `ai-core:vehicleType` | callbacki | Ekran postaci, wybór miejsca pojawienia się, rachunki i tworzenie pojazdów. |
| `ai-core:admin:*`, `<resource>:admin:world` | obie | Panel administratora i dane panelu każdego zasobu. |
| `ai-lib:client:notify`, `ai-lib:progressFor`, `ai-lib:minigameFor`, `ai-lib:client:progressForCancel` | serwer do klienta | Powiadomienia ai-lib, paski postępu i minigry uruchamiane przez serwer (używaj `notify`, `progressFor`, `minigameFor` z liba). |
