O ai-core avisa outros scripts quando algo muda: um personagem carregou, o dinheiro se moveu, um emprego mudou, o jogador caiu, o HUD se escondeu. Seu script **escuta** em vez de perguntar repetidamente. Esta seção lista cada evento e valor de estado compartilhado que os outros recursos usam.

## Os três tipos

| Tipo | O que é | Como escutar |
| --- | --- | --- |
| **Evento local** | Disparado num lado (servidor ou um cliente) para cada recurso desse lado. Nunca cruza a rede. A maioria dos eventos do ai-core é local. | TS: `on(name, handler)`. Lua: `AddEventHandler(name, handler)`. |
| **Net event** | Enviado do servidor para o cliente de um jogador (ou o contrário). | Cliente TS: `onServerEvent(name, ...)` da lib. Cliente Lua: `aiLib.onServerEvent(name, handler)`. |
| **State bag** | Um valor guardado no GlobalState, num jogador ou numa entidade. Todos podem lê-lo; só o recurso dono o escreve. | `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup` da lib, ou `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` em Lua. |

## Os nomes vêm de constantes

Em TypeScript, nunca digite um nome de evento à mão. Eles são constantes em `@aifivem/shared`:

| Constante | Eventos |
| --- | --- |
| `CORE` | Os eventos de servidor e de cliente do ai-core (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) e as chaves de GlobalState (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | As respostas de UI do ai-lib. |
| `VEHICLES_EVENTS` | O feed de donos do ai-vehicles. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | Chaves de state bags. |

O Lua não tem constantes: use a string mostrada ao lado de cada evento.

## Um primeiro listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aifivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Para a vida inteira de um personagem no servidor (carregado, descarregado e os personagens já no mundo quando seu recurso reinicia), use o `onCharacter({ loaded, unloaded })` da lib (`aiLib.onCharacter` em Lua) em vez dos dois eventos à mão. Um recurso que inicia tarde perde os eventos disparados antes de ele iniciar; o `onCharacter` repete esses personagens para você.
</Callout>

<Callout type="warn">
Os eventos locais do ai-core são locais de propósito. Nunca use `RegisterNetEvent` (ou `onNet`) com um dos nomes deles: isso deixaria o cliente de qualquer jogador disparar um `ai-core:moneyChanged` ou `ai-core:playerLoaded` falso no seu handler. Um `AddEventHandler` / `on` simples só ouve eventos disparados no mesmo lado.
</Callout>
