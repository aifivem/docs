A net event travels between the server and one player's client. ai-core sends very few of them: a player's own data goes out once when the character loads, then only the values that change, and only to that player. Everything else your script needs is a [client event](/docs/developers/api/events/client) or a [state bag](/docs/developers/api/events/state-bags).

<Callout type="info">
You rarely need these events directly. The lib's `onPlayerData(key, handler)` (TypeScript) and `aiLib.playerData.onChange(key, handler)` (Lua) listen to both of them for you, merge the money and metadata patches, and read the starting values from ai-core.
</Callout>

### ai-core:client:playerData

The server sends one value of the player's own data: the whole value of one key. Fires once per key when the character loads, then each time that value changes (a job, duty, a gang...).

**Side:** Server to the player's own client

#### Arguments

<TypeTable
  type={{
    key: { type: '"character" | "money" | "jobs" | "duty" | "job" | "gangs" | "activeGang" | "metadata"', description: 'Which value of `AiPlayerData` this is.', required: true, typeDescriptionLink: '/docs/developers/api/types#aiplayerdata' },
    value: { type: 'unknown', description: 'The whole new value of that key (its type is the field\'s type in `AiPlayerData`).', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { onPlayerData } from "@aifivem/lib/client";

// The lib listens to ai-core:client:playerData and playerDataPatch for you.
onPlayerData("job", (job) => console.log(`main job: ${job.job} grade ${job.grade}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- Only from the server: aiLib.onServerEvent drops local fakes.
aiLib.onServerEvent('ai-core:client:playerData', function(key, value)
  if key == 'job' then print(('main job: %s grade %d'):format(value.job, value.grade)) end
end)
```
</Tab>
</Tabs>

### ai-core:client:playerDataPatch

The server sends only the changed entries of a map value: `money` (one account's new balance) or `metadata` (one key). Merge the patch into what you have.

**Side:** Server to the player's own client

#### Arguments

<TypeTable
  type={{
    key: { type: '"money" | "metadata"', description: 'Which map changed.', required: true },
    patch: { type: 'Record<string, unknown>', description: 'Only the changed entries, for example `{ cash: 450 }`. A metadata entry set to `null` was removed.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { getPlayerData, onPlayerData } from "@aifivem/lib/client";

// The lib merges patches: the handler gets the whole merged money map.
const show = (money: Record<string, number>): void => SendNUIMessage({ action: "cash", data: money.cash ?? 0 });
show(getPlayerData("money") ?? {});
onPlayerData("money", show);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- aiLib.playerData merges patches: the handler gets the whole merged money table.
local function show(money) SendNUIMessage({ action = 'cash', data = (money and money.cash) or 0 }) end
show(aiLib.playerData.get('money'))
aiLib.playerData.onChange('money', show)
```
</Tab>
</Tabs>

<Callout type="warn">
On a client, listen to net events only through the lib's `onServerEvent` (TypeScript) or `aiLib.onServerEvent` (Lua). They check that the event really came from the server; a bare `RegisterNetEvent` handler also runs when another client resource fires the name locally.
</Callout>

## ai-core's own traffic: do not trigger

These net events and callbacks are ai-core's internal traffic between its server and its client (or the lib). They are listed so you recognize them in logs. Never trigger them from another script, and do not build on them: their arguments may change.

| Name | Direction | What |
| --- | --- | --- |
| `ai-core:client:spawn` | server to client | Puts the loaded character into the world. |
| `ai-core:client:chooseSpawn` | server to client | Spawn options for the player to pick. |
| `ai-core:client:openCharacters` | server to client | Shows the character screen again after a switch. |
| `ai-core:client:characterLooks` | server to client (latent) | The character screen's looks. |
| `ai-core:client:bills` | server to client | The player's open ai-core bills, for the bill list. |
| `ai-core:client:stress` | server to client | Stress for a HUD that only takes it from its own client. |
| `ai-core:client:vehicleKeys`, `ai-core:client:garages` | server to client | Calls for key and garage scripts that only have a client API. |
| `ai-core:clientError`, `ai-core:fuelReport` | client to server | Error reports of client bundles; fuel levels from client-side fuel scripts. |
| `ai-core:characters`, `ai-core:createCharacter`, `ai-core:deleteCharacter`, `ai-core:selectCharacter`, `ai-core:spawnChoice`, `ai-core:payBill`, `ai-core:vehicleType` | callbacks | The character screen, spawn choice, bills and vehicle spawning. |
| `ai-core:admin:*`, `<resource>:admin:world` | both | The admin panel and the panel data of every resource. |
| `ai-lib:client:notify`, `ai-lib:progressFor`, `ai-lib:minigameFor`, `ai-lib:client:progressForCancel` | server to client | ai-lib's notifications, server-run progress bars and minigames (use the lib's `notify`, `progressFor`, `minigameFor`). |
