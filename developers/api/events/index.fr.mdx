ai-core prévient les autres scripts quand quelque chose change : un personnage chargé, de l’argent déplacé, un métier modifié, le joueur à terre, le HUD masqué. Votre script **écoute** au lieu de redemander sans cesse. Cette section liste chaque événement et chaque valeur d’état partagée qu’utilisent les autres ressources.

## Les trois sortes

| Sorte | Ce que c’est | Comment écouter |
| --- | --- | --- |
| **Événement local** | Déclenché d’un côté (le serveur ou un client) pour chaque ressource de ce côté. Ne traverse jamais le réseau. La plupart des événements d’ai-core sont locaux. | TS : `on(name, handler)`. Lua : `AddEventHandler(name, handler)`. |
| **Événement réseau** | Envoyé du serveur au client d’un joueur (ou dans l’autre sens). | Client TS : `onServerEvent(name, ...)` de la lib. Client Lua : `aiLib.onServerEvent(name, handler)`. |
| **State bag** | Une valeur stockée sur GlobalState, un joueur ou une entité. Tout le monde peut la lire ; seule la ressource propriétaire l’écrit. | `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup` de la lib, ou `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` en Lua. |

## Les noms viennent de constantes

En TypeScript, ne tapez jamais un nom d’événement à la main. Ce sont des constantes de `@aifivem/shared` :

| Constante | Événements |
| --- | --- |
| `CORE` | Les événements serveur et client d’ai-core (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) et les clés GlobalState (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | Les réponses UI d’ai-lib. |
| `VEHICLES_EVENTS` | Le flux des propriétaires d’ai-vehicles. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | Clés de state bag. |

Lua n’a pas de constantes : utilisez la chaîne indiquée à côté de chaque événement.

## Un premier écouteur

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aifivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Pour toute la vie d’un personnage sur le serveur (chargé, déchargé, et les personnages déjà dans le monde quand votre ressource redémarre), utilisez `onCharacter({ loaded, unloaded })` de la lib (`aiLib.onCharacter` en Lua) au lieu des deux événements à la main. Une ressource qui démarre tard manque les événements déclenchés avant son démarrage ; `onCharacter` rejoue ces personnages pour vous.
</Callout>

<Callout type="warn">
Les événements locaux d’ai-core sont locaux à dessein. N’utilisez jamais `RegisterNetEvent` (ou `onNet`) sur l’un de leurs noms : cela laisserait le client de n’importe quel joueur envoyer un faux `ai-core:moneyChanged` ou `ai-core:playerLoaded` dans votre handler. Un simple `AddEventHandler` / `on` n’entend que les événements déclenchés du même côté.
</Callout>
