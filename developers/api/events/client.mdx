ai-core's client fires these events with `TriggerEvent` on the player's own game. Every client resource of that player hears them; other players never do. They describe the **local** player only.

### ai-core:client:playerLoaded

The local player's character stands in the world. Start your per-character client work here (HUD values, job blips, loops).

**Side:** Client · **Constant:** `CORE.clientPlayerLoadedEvent`

#### Arguments

<TypeTable
  type={{
    data: { type: 'AiPlayerData', description: 'Everything about the character at this moment: `character`, `money`, `jobs`, `duty`, `job`, `gangs`, `activeGang`, `metadata`. Same as the `GetPlayerData` export.', required: true, typeDescriptionLink: '/docs/developers/api/types#aiplayerdata' },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aicore-fivem/lib/client";
import { CORE, type AiPlayerData } from "@aicore-fivem/shared";

const core = resourceExport("ai-core");

function start(data: AiPlayerData): void {
  console.log(`hello ${data.character?.firstname}, cash ${data.money.cash ?? 0}`);
}

// Also covers a resource restart while the player is already in the world.
const now = core.GetPlayerData();
if (now) start(now);
on(CORE.clientPlayerLoadedEvent, start);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
local function start(data)
  print(('hello %s, cash %d'):format(data.character.firstname, data.money.cash or 0))
end

-- Also covers a resource restart while the player is already in the world.
local now = exports['ai-core']:GetPlayerData()
if now then start(now) end
AddEventHandler('ai-core:client:playerLoaded', start)
```
</Tab>
</Tabs>

### ai-core:client:playerUnloaded

The local character was let go: the player went back to the character screen. Stop per-character work and clear what you kept for that character. (When the player leaves the server, their game closes; nothing fires.)

**Side:** Client · **Constant:** `CORE.clientPlayerUnloadedEvent`

#### Arguments

None.

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.clientPlayerUnloadedEvent, () => {
  SendNUIMessage({ action: "reset" });
});
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('ai-core:client:playerUnloaded', function()
  SendNUIMessage({ action = 'reset' })
end)
```
</Tab>
</Tabs>

### ai-core:client:dead

The local player went down (dead or last stand) or got up, in whichever death script runs. Fires only on a change.

**Side:** Client · **Constant:** `CORE.clientDeadEvent` · **Lib:** `medical.onChange`

#### Arguments

<TypeTable
  type={{
    dead: { type: 'boolean', description: '`true`: the player went down. `false`: they got up (revived, respawned).', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { medical } from "@aicore-fivem/lib/client";

// Same as on(CORE.clientDeadEvent, ...).
medical.onChange((dead) => {
  if (dead) SendNUIMessage({ action: "close" });
});
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('ai-core:client:dead', function(dead)
  if dead then SendNUIMessage({ action = 'close' }) end
end)
```
</Tab>
</Tabs>

### ai-core:client:cache

A cached value of the local player changed. One watcher in ai-core reads the ped, vehicle, seat and weapon for every resource and fires this only when a value changes, so no resource has to poll them. The lib's `cache` and `onCache` (`aiLib.cache` and `aiLib.cache.onChange` in Lua) are built on it; use those.

**Side:** Client · **Constant:** `CORE.clientCacheEvent`

#### Arguments

<TypeTable
  type={{
    key: { type: '"ped" | "vehicle" | "seat" | "weapon"', description: 'Which value changed.', required: true, typeDescriptionLink: '/docs/developers/api/types#playercache' },
    value: { type: 'number | false', description: '`ped`: the new ped handle. `vehicle`: the vehicle handle, `false` on foot. `seat`: the seat index (`-1` = driver), `false` on foot. `weapon`: the weapon hash in hand, `false` when unarmed.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { onCache } from "@aicore-fivem/lib/client";

onCache("vehicle", (vehicle, old) => {
  if (vehicle !== false) console.log(`entered vehicle ${vehicle}`);
  else if (old !== false) console.log("left the vehicle");
});
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
aiLib.cache.onChange('vehicle', function(vehicle, old)
  if vehicle then print(('entered vehicle %d'):format(vehicle))
  elseif old then print('left the vehicle') end
end)
```
</Tab>
</Tabs>

<TypeTable

### ai-core:client:worldSync

The weather and time sync was paused or runs again. A weather script listens to it. See [Weather and time sync](/docs/developers/api/core-client/world).

**Side:** Client · **Constant:** `CORE.clientWorldSyncEvent`

#### Arguments

<TypeTable
  type={{
    paused: { type: 'boolean', description: '`true`: stop applying the server\'s weather and time. `false`: apply them again.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/weather.ts"
import { CORE } from "@aicore-fivem/shared";

on(CORE.clientWorldSyncEvent, (paused: boolean) => {
```

### ai-core:client:definitions

A job or gang was added, changed or deleted in the admin panel. Fires on every client, once per job or gang that changed. Pair it with the `GetDefinitions` export.

**Side:** Client · **Constant:** `CORE.clientDefinitionsEvent`

#### Arguments

<TypeTable
  type={{
    file: { type: '"jobs" | "gangs"', description: 'Which list changed.', required: true },
    name: { type: 'string', description: 'The job or gang name.', required: true },
    definition: { type: 'unknown', description: 'The new record as the panel stores it, `null` when it was deleted.', required: true },
  }}
/>

#### Listener

See the example of [GetDefinitions](/docs/developers/api/core-client/player#getdefinitions).

### ai-core:client:characterPortrait

A portrait picture for a character card on the character screen. A clothing script (ai-appearance) fires it; ai-core's character screen listens and shows the picture. Fire it yourself only if you write a clothing script.

**Side:** Client · **Constant:** `CORE.clientCharacterPortraitEvent` · **Fired by:** the clothing script, heard by ai-core

#### Arguments

<TypeTable
  type={{
    charId: { type: 'number', description: 'The character id of the card.', required: true },
    url: { type: 'string', description: 'The picture url, for example a headshot texture `https://nui-img/<txd>/<txd>`.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/portraits.ts"
import { CORE } from "@aicore-fivem/shared";

// A clothing script hands a portrait to the character screen.
export function sendPortrait(charId: number, txd: string): void {
  emit(CORE.clientCharacterPortraitEvent, charId, `https://nui-img/${txd}/${txd}`);
}
```
</Tab>
<Tab value="Lua">
```lua title="client/portraits.lua"
-- A clothing script hands a portrait to the character screen.
local function sendPortrait(charId, txd)
  TriggerEvent('ai-core:client:characterPortrait', charId, ('https://nui-img/%s/%s'):format(txd, txd))
end
```
</Tab>
</Tabs>

### ai-core:client:seatbelt

The local player's seat belt changed, in whichever seat belt script ai-core reads. Fires from the scripts that tell changes (ai-smallresources, qbx_seatbelt); with a HUD's own belt, read `GetSeatbelt` when you need it.

**Side:** Client · **Constant:** `CORE.clientSeatbeltEvent` · **Lib:** `seatbelt.onChange`

#### Arguments

<TypeTable
  type={{
    worn: { type: 'boolean | null', description: '`true`: belt on. `false`: belt off. `null`: the script gave no clear answer.', required: true },
  }}
/>

#### Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/hud.ts"
import { seatbelt } from "@aicore-fivem/lib/client";

seatbelt.onChange((worn) => SendNUIMessage({ action: "belt", data: worn === true }));
```
</Tab>
<Tab value="Lua">
```lua title="client/hud.lua"
aiLib.seatbelt.onChange(function(worn)
  SendNUIMessage({ action = 'belt', data = worn == true })
end)
```
</Tab>
</Tabs>

## Internal client events

The lib's `Keybind` talks to ai-core's client with two local events. Do not fire or answer them yourself; use `Keybind` (TS) or `aiLib.Keybind` (Lua).

| Event | Constant | Direction | Arguments |
| --- | --- | --- | --- |
| `ai-core:client:keybind` | `KEYBIND.announceEvent` | lib to ai-core | `(info: KeybindInfo)` a keybind waits for its default key. |
| `ai-core:client:keybindKey` | `KEYBIND.keyEvent` | ai-core to lib | `(resource: string, name: string, key: string)` the key to register: the panel's key, else the script's own. |
