ai-core avisa a otros scripts cuando algo cambia: se cargó un personaje, se movió dinero, cambió un trabajo, el jugador cayó, se ocultó el HUD. Tu script **escucha** en lugar de preguntar una y otra vez. Esta sección lista cada evento y cada valor de estado compartido que usan otros recursos.

## Los tres tipos

| Tipo | Qué es | Cómo se escucha |
| --- | --- | --- |
| **Evento local** | Se dispara en un lado (el servidor o un cliente) para todos los recursos de ese lado. Nunca cruza la red. La mayoría de los eventos de ai-core son locales. | TS: `on(name, handler)`. Lua: `AddEventHandler(name, handler)`. |
| **Evento de red** | Se envía del servidor al cliente de un jugador (o al revés). | Cliente TS: `onServerEvent(name, ...)` de la lib. Cliente Lua: `aiLib.onServerEvent(name, handler)`. |
| **State bag** | Un valor guardado en GlobalState, en un jugador o en una entidad. Todo el mundo puede leerlo; solo lo escribe el recurso dueño. | `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup` de la lib, o `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` en Lua. |

## Los nombres vienen de constantes

En TypeScript, nunca escribas a mano el nombre de un evento. Son constantes de `@aifivem/shared`:

| Constante | Eventos |
| --- | --- |
| `CORE` | Los eventos de servidor y de cliente de ai-core (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) y las claves de GlobalState (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | Las respuestas de la interfaz de ai-lib. |
| `VEHICLES_EVENTS` | El canal de dueños de ai-vehicles. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | Claves de state bags. |

Lua no tiene constantes: usa la cadena que aparece junto a cada evento.

## Un primer listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aifivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Para toda la vida de un personaje en el servidor (cargado, descargado, y los personajes que ya están en el mundo cuando tu recurso se reinicia), usa el `onCharacter({ loaded, unloaded })` de la lib (`aiLib.onCharacter` en Lua) en lugar de los dos eventos a mano. Un recurso que se inicia tarde se pierde los eventos disparados antes de que se iniciara; `onCharacter` vuelve a pasarte esos personajes.
</Callout>

<Callout type="warn">
Los eventos locales de ai-core son locales a propósito. Nunca hagas `RegisterNetEvent` (ni `onNet`) con uno de sus nombres: eso permitiría al cliente de cualquier jugador disparar un `ai-core:moneyChanged` o `ai-core:playerLoaded` falso dentro de tu handler. Un `AddEventHandler` / `on` normal solo oye los eventos disparados en el mismo lado.
</Callout>
