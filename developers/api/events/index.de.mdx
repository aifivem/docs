ai-core teilt anderen Skripten mit, wenn sich etwas ändert: ein Charakter wurde geladen, Geld wurde bewegt, ein Job hat sich geändert, der Spieler ist zu Boden gegangen, das HUD wurde ausgeblendet. Dein Skript **hört zu**, statt immer wieder zu fragen. Dieser Bereich listet jedes Event und jeden gemeinsamen Zustandswert, den andere Ressourcen nutzen.

## Die drei Arten

| Art | Was es ist | Wie du zuhörst |
| --- | --- | --- |
| **Lokales Event** | Wird auf einer Seite (Server oder ein Client) für jede Ressource auf dieser Seite ausgelöst. Überquert nie das Netzwerk. Die meisten Events von ai-core sind lokal. | TS: `on(name, handler)`. Lua: `AddEventHandler(name, handler)`. |
| **Net-Event** | Wird vom Server an den Client eines Spielers gesendet (oder umgekehrt). | TS-Client: `onServerEvent(name, ...)` aus der Lib. Lua-Client: `aiLib.onServerEvent(name, handler)`. |
| **State Bag** | Ein Wert, der auf GlobalState, einem Spieler oder einer Entity gespeichert ist. Jeder kann ihn lesen; nur die besitzende Ressource schreibt ihn. | `GlobalKey`, `PlayerState`, `EntityState`, `GlobalGroup` der Lib oder `GlobalState[...]`, `Player(src).state[...]`, `Entity(e).state[...]` in Lua. |

## Namen kommen aus Konstanten

Tippe in TypeScript nie einen Eventnamen von Hand. Sie sind Konstanten in `@aifivem/shared`:

| Konstante | Events |
| --- | --- |
| `CORE` | Die Server- und Client-Events von ai-core (`CORE.playerLoadedEvent`, `CORE.clientDeadEvent`...) und GlobalState-Schlüssel (`CORE.pvpStateKey`...). |
| `KEY_HINTS` | `KEY_HINTS.changedEvent`. |
| `MENU_EVENTS`, `LIB_UI` | Die UI-Antworten von ai-lib. |
| `VEHICLES_EVENTS` | Der Besitzer-Feed von ai-vehicles. |
| `VRP` | `VRP.configEvent`. |
| `PLAYER_BAGS`, `VEHICLE_BAGS`, `INVENTORY_STATE_KEY`, `APPEARANCE_STATE_KEY`, `dutyCountKey(job)`... | State-Bag-Schlüssel. |

Lua hat keine Konstanten: Nutze den String, der neben jedem Event steht.

## Ein erster Listener

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { CORE, type CharacterInfo } from "@aifivem/shared";

on(CORE.playerLoadedEvent, (src: number, character: CharacterInfo) => {
  console.log(`${character.firstname} ${character.lastname} joined as ${src}`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('ai-core:playerLoaded', function(src, character)
  print(('%s %s joined as %d'):format(character.firstname, character.lastname, src))
end)
```
</Tab>
</Tabs>

<Callout type="info">
Für das ganze Leben eines Charakters auf dem Server (geladen, entladen und die Charaktere, die schon in der Welt sind, wenn deine Ressource neu startet) nutze `onCharacter({ loaded, unloaded })` der Lib (`aiLib.onCharacter` in Lua), statt die beiden Events von Hand zu verwenden. Eine Ressource, die spät startet, verpasst Events, die vor ihrem Start ausgelöst wurden; `onCharacter` spielt diese Charaktere für dich nach.
</Callout>

<Callout type="warn">
Die lokalen Events von ai-core sind absichtlich lokal. Nutze nie `RegisterNetEvent` (oder `onNet`) für einen ihrer Namen: Damit könnte der Client jedes Spielers ein gefälschtes `ai-core:moneyChanged` oder `ai-core:playerLoaded` in deinen Handler auslösen. Ein einfaches `AddEventHandler` / `on` hört nur Events, die auf derselben Seite ausgelöst werden.
</Callout>
