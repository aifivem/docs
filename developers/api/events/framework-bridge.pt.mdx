---
title: Eventos da ponte de frameworks
description: Os eventos de ESX, QB / Qbox e vRP que o ai-core dispara para que scripts escritos para esses frameworks continuem funcionando, com os argumentos exatos, e os eventos de framework que o ai-core responde.
icon: Cable
---

O ai-core se apresenta como `es_extended`, `qb-core`, `qbx_core` e `vrp`, então scripts escritos para esses frameworks rodam sem alterações. Parte disso é disparar os eventos próprios do framework quando algo muda no ai-core: um personagem carrega, o dinheiro se move, um emprego muda. Esta página lista cada evento de framework que a ponte dispara, com os argumentos como a ponte os envia, e os eventos de framework que ela responde.

**Código novo não deve usar estes eventos.** Escreva com base nos eventos próprios do ai-core ([servidor](/pt/docs/developers/api/events/server), [cliente](/pt/docs/developers/api/events/client)) e na lib: eles trazem mais (vários empregos, gangues, serviço) e não dependem do formato de um framework. Esta página é para rodar e corrigir scripts existentes de ESX / QB / vRP.

<Callout type="info">
As visões do framework guardam um emprego por jogador: o emprego em que o jogador está em serviço, senão o primeiro emprego dele. O ai-core em si permite vários empregos. O ESX não tem gangue; a conta `money` do ESX é a `cash` do ai-core.
</Callout>

## QBCore e Qbox: servidor

A ponte dispara estes no servidor com `TriggerEvent`. Os scripts de Qbox escutam os mesmos nomes do QBCore; a ponte não dispara nenhum evento exclusivo do Qbox.

## QBCore e Qbox: cliente

Disparados no próprio cliente do jogador com `TriggerEvent`.

| Evento | Quando | Argumentos |
| --- | --- | --- |
| `QBCore:Client:OnPlayerLoaded` | O personagem está no mundo. | nenhum |
| `QBCore:Client:OnPlayerUnload` | O jogador voltou para a tela de personagens. | nenhum |
| `QBCore:Player:SetPlayerData` | Depois do carregamento e depois de cada mudança de dinheiro, emprego, gangue ou metadata. | `(PlayerData: table)` o PlayerData inteiro do QB. |
| `QBCore:Client:OnJobUpdate` | O emprego de framework mudou. | `(job: table)` a tabela de emprego do QB (como no servidor). |
| `QBCore:Client:SetDuty` | O serviço mudou no mesmo emprego. | `(onDuty: boolean)` |
| `QBCore:Client:OnGangUpdate` | A gangue de framework mudou. | `(gang: table)` a tabela de gangue do QB. |
| `QBCore:Client:OnMoneyChange` | O saldo de uma conta mudou. | `(account: string, balance: number)` o nome da conta no ai-core e o novo saldo. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
on("QBCore:Client:OnPlayerLoaded", () => console.log("loaded"));
on("QBCore:Client:OnJobUpdate", (job: { name: string }) => console.log(`job: ${job.name}`));
on("QBCore:Client:SetDuty", (onDuty: boolean) => console.log(`on duty: ${onDuty}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('QBCore:Client:OnPlayerLoaded', function() print('loaded') end)
AddEventHandler('QBCore:Client:OnJobUpdate', function(job) print(('job: %s'):format(job.name)) end)
AddEventHandler('QBCore:Client:SetDuty', function(onDuty) print(('on duty: %s'):format(tostring(onDuty))) end)
```
</Tab>
</Tabs>

<Callout type="warn">
`QBCore:Client:OnMoneyChange` traz `(account, balance)`, o novo saldo, não os argumentos próprios do qb-core. Um script de QB que o lê como uma quantia vê o saldo. Prefira `QBCore:Player:SetPlayerData` ou o `onPlayerData("money", ...)` do ai-core.
</Callout>

## ESX: cliente

Disparados no próprio cliente do jogador com `TriggerEvent`.

| Evento | Quando | Argumentos |
| --- | --- | --- |
| `esx:playerLoaded` | O personagem está no mundo. | `(PlayerData: table, isNew: false)` o PlayerData de cliente do ESX. |

### vRP:playerSpawn

O personagem foi colocado no mundo. Dispara 2 segundos depois que o ai-core o fez aparecer, como no vRP. Só para o spawn de um carregamento de personagem: os respawns depois da morte vêm do script de morte e não o disparam.

**Lado:** Servidor

<TypeTable
  type={{
    user_id: { type: 'number', description: 'O id do personagem.', required: true },
    source: { type: 'number', description: 'O id de servidor do jogador.', required: true },
    first_spawn: { type: 'boolean', description: '`true` para o primeiro spawn desde que este personagem foi carregado.', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("vRP:playerSpawn", (userId: number, source: number, firstSpawn: boolean) => {
  if (firstSpawn) console.log(`user ${userId} spawned (src ${source})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('vRP:playerSpawn', function(user_id, source, first_spawn)

end)
```

### vRP:playerJoinGroup and vRP:playerLeaveGroup

O personagem ganhou ou perdeu um grupo do vRP. Os grupos são os empregos do ai-core, a gangue ativa, os nomes de grupos que o dono do servidor mapeou no painel (aba "vRP scripts") e grupos extras que scripts de vRP adicionam. Dispara a cada mudança, também em mudanças que o ai-core ou outro script faz sem o vRP.

**Lado:** Servidor

<TypeTable
  type={{
    user_id: { type: 'number', description: 'O id do personagem.', required: true },
    group: { type: 'string', description: 'O nome do grupo.', required: true },
    gtype: { type: '"job" | "gang" | nil', description: '`job` para um emprego, `gang` para uma gangue, `nil` para qualquer outro grupo.', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">

</Tab>
<Tab value="Lua">
```lua title="server.lua"

  print(('user %d joined %s (%s)'):format(user_id, group, gtype or 'group'))

  print(('user %d left %s'):format(user_id, group))

```
</Tab>

<Callout type="info">
As extensões de vRP 2 e 3 recebem os próprios eventos de extensão da ponte (`characterLoad`, `playerJoin`, `characterUnload`, `playerLeave`, `playerSpawn`, `playerDeath`, `playerMoneyUpdate`, `playerJoinGroup` / `playerLeaveGroup` e outros) pelo sistema de eventos de extensão do vRP, não como eventos do FiveM. Não disparados: `vRP:save`, `vRP:playerRejoin`, `vRPcli:playerSpawned`.
</Callout>

## Eventos de framework que o ai-core responde

Scripts escritos para um framework enviam estes eventos esperando que o framework responda. O ai-core responde no lugar dele.

| Evento | Lado | O que o ai-core faz |
| --- | --- | --- |
| `QBCore:GetObject`, `esx:getSharedObject` | ambos | Chama o callback com o core object (`QBCore` / `ESX`). |
| `QBCore:Server:TriggerCallback`, `esx:triggerServerCallback` | servidor (vindo dos clientes) | Roda o callback de framework registrado com `CreateCallback` / `RegisterServerCallback` e responde. No máximo 30 pedidos por jogador em quaisquer 10 segundos. |
| `QBCore:Notify`, `esx:showNotification`, `esx:showAdvancedNotification`, `ESX:Notify` | cliente (vindo do servidor) | Mostra a notificação do ai-lib. |
| `esx:showHelpNotification`, `ESX:TextUI`, `ESX:HideUI`, `qb-core:client:DrawText`, `qb-core:client:ChangeText`, `qb-core:client:HideText`, `qb-core:client:KeyPressed` | cliente | Mostra ou esconde o prompt do ai-lib. |
| `qb-menu:client:openMenu`, `qb-menu:client:closeMenu` | cliente | Abre ou fecha o menu do ai-lib com os itens do qb-menu. |
| `progressbar:client:cancel` | cliente | Cancela a barra de progresso da ponte. |
| `police:server:policeAlert` | servidor | Envia um alerta à polícia pelo sistema de alertas ativo na posição do jogador. Os clientes enviam `(text)` (um por jogador em 10 segundos); scripts de servidor o disparam com `TriggerEvent` e `(text, camId, playerSource)`. |
| `qb-weathersync:client:DisableSync` / `EnableSync`, `cd_easytime:PauseSync`, `vSync:toggle` | cliente | Contados como motivos de pausa da sincronização de clima e hora (veja [Sincronização de clima e hora](/pt/docs/developers/api/core-client/world)). |
