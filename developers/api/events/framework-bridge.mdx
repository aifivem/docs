description: The ESX, QB / Qbox and vRP events ai-core fires so scripts written for those frameworks keep working, with their exact arguments, and the framework events ai-core answers.
icon: Cable
---

ai-core presents itself as `es_extended`, `qb-core`, `qbx_core` and `vrp`, so scripts written for those frameworks run without changes. Part of that is firing the framework's own events when something changes in ai-core: a character loads, money moves, a job changes. This page lists every framework event the bridge fires, with the arguments as the bridge sends them, and the framework events it answers.

**New code should not use these.** Write against ai-core's own events ([server](/docs/developers/api/events/server), [client](/docs/developers/api/events/client)) and the lib: they carry more (several jobs, gangs, duty) and do not depend on a framework shape. This page is for running and fixing existing ESX / QB / vRP scripts.

<Callout type="info">
The framework views keep one job per player: the job the player is on duty in, else their first job. ai-core itself allows several jobs. ESX has no gang; ESX's `money` account is ai-core's `cash`.
</Callout>

## QBCore and Qbox: server

The bridge fires these on the server with `TriggerEvent`. Qbox scripts listen to the same QBCore names; the bridge fires no Qbox-only event.

### QBCore:Server:PlayerLoaded

A character was loaded (from `ai-core:playerLoaded`).

**Side:** Server

<TypeTable
  type={{
    Player: { type: 'table', description: 'The QB Player object: `PlayerData` (`source`, `citizenid`, `name`, `money`, `charinfo`, `job`, `gang`, `metadata`...) and `Functions` (`AddMoney`, `RemoveMoney`, `SetJob`, `GetMetaData`...).', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("QBCore:Server:PlayerLoaded", (player: { PlayerData: { source: number; citizenid: string } }) => {
  console.log(`${player.PlayerData.citizenid} loaded (src ${player.PlayerData.source})`);
});
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('QBCore:Server:PlayerLoaded', function(Player)
  print(('%s loaded (src %d)'):format(Player.PlayerData.citizenid, Player.PlayerData.source))
end)
```
</Tab>
</Tabs>

## QBCore and Qbox: client

Fired on the player's own client with `TriggerEvent`.

| Event | When | Arguments |
| --- | --- | --- |
| `QBCore:Client:OnPlayerLoaded` | The character stands in the world. | none |
| `QBCore:Client:OnPlayerUnload` | The player went back to the character screen. | none |
| `QBCore:Player:SetPlayerData` | After load and after every money, job, gang or metadata change. | `(PlayerData: table)` the whole QB PlayerData. |
| `QBCore:Client:OnJobUpdate` | The framework job changed. | `(job: table)` the QB job table (as on the server). |
| `QBCore:Client:SetDuty` | Duty changed for the same job. | `(onDuty: boolean)` |
| `QBCore:Client:OnGangUpdate` | The framework gang changed. | `(gang: table)` the QB gang table. |
| `QBCore:Client:OnMoneyChange` | An account balance changed. | `(account: string, balance: number)` ai-core's account name and the new balance. |

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
on("QBCore:Client:OnPlayerLoaded", () => console.log("loaded"));
on("QBCore:Client:OnJobUpdate", (job: { name: string }) => console.log(`job: ${job.name}`));
on("QBCore:Client:SetDuty", (onDuty: boolean) => console.log(`on duty: ${onDuty}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('QBCore:Client:OnPlayerLoaded', function() print('loaded') end)
AddEventHandler('QBCore:Client:OnJobUpdate', function(job) print(('job: %s'):format(job.name)) end)
AddEventHandler('QBCore:Client:SetDuty', function(onDuty) print(('on duty: %s'):format(tostring(onDuty))) end)
```
</Tab>
</Tabs>

<Callout type="warn">
`QBCore:Client:OnMoneyChange` carries `(account, balance)`, the new balance, not qb-core's own arguments. A QB script that reads it as an amount sees the balance. Prefer `QBCore:Player:SetPlayerData` or ai-core's `onPlayerData("money", ...)`.
</Callout>

## ESX: client

Fired on the player's own client with `TriggerEvent`.

| Event | When | Arguments |
| --- | --- | --- |
| `esx:playerLoaded` | The character stands in the world. | `(PlayerData: table, isNew: false)` ESX's client PlayerData. |
| `esx:onPlayerLogout` | The player went back to the character screen. | none |
| `esx:setAccountMoney` | An account balance changed. | `(account: { name, money, label })`; `name` is `"money"` for ai-core's `cash`. |
| `esx:setJob` | The framework job changed. | `(job: table, lastJob: table \| nil)` ESX job tables (as on the server). |
| `esx:setPlayerData` | `ESX.SetPlayerData` ran: the ped changed (model swap, respawn) or the metadata changed. | `(key: string, value: any)` |

<Tabs items={['TypeScript', 'Lua']}>

```ts title="resource/client/index.ts"
on("esx:playerLoaded", () => console.log("loaded"));
on("esx:setAccountMoney", (account: { name: string; money: number }) => console.log(`${account.name}: ${account.money}`));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
AddEventHandler('esx:playerLoaded', function(playerData, isNew) print('loaded') end)
```

### vRP:playerJoinGroup and vRP:playerLeaveGroup

The character got or lost a vRP group. Groups are ai-core's jobs, the active gang, the group names the server owner mapped in the panel (tab "vRP scripts"), and extra groups vRP scripts add. Fires for every change, also changes ai-core or another script makes without vRP.

**Side:** Server

<TypeTable
  type={{
    user_id: { type: 'number', description: 'The character id.', required: true },
    group: { type: 'string', description: 'The group name.', required: true },
    gtype: { type: '"job" | "gang" | nil', description: '`job` for a job, `gang` for a gang, `nil` for any other group.', required: true },
  }}
/>

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
on("vRP:playerJoinGroup", (userId: number, group: string, gtype?: string) => console.log(`user ${userId} joined ${group} (${gtype ?? "group"})`));
on("vRP:playerLeaveGroup", (userId: number, group: string) => console.log(`user ${userId} left ${group}`));
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
AddEventHandler('vRP:playerJoinGroup', function(user_id, group, gtype)
  print(('user %d joined %s (%s)'):format(user_id, group, gtype or 'group'))
end)
AddEventHandler('vRP:playerLeaveGroup', function(user_id, group, gtype)
  print(('user %d left %s'):format(user_id, group))
end)
```
</Tab>
</Tabs>

<Callout type="info">
vRP 2 and 3 extensions get their own extension events from the bridge (`characterLoad`, `playerJoin`, `characterUnload`, `playerLeave`, `playerSpawn`, `playerDeath`, `playerMoneyUpdate`, `playerJoinGroup` / `playerLeaveGroup` and others) through vRP's extension event system, not as FiveM events. Not fired: `vRP:save`, `vRP:playerRejoin`, `vRPcli:playerSpawned`.
</Callout>

## Framework events ai-core answers

Scripts written for a framework send these events expecting the framework to answer. ai-core answers them instead.

| Event | Side | What ai-core does |
| --- | --- | --- |
| `QBCore:GetObject`, `esx:getSharedObject` | both | Calls the callback with the core object (`QBCore` / `ESX`). |
| `QBCore:Server:TriggerCallback`, `esx:triggerServerCallback` | server (from clients) | Runs the framework callback registered with `CreateCallback` / `RegisterServerCallback` and answers. At most 30 requests per player in any 10 seconds. |
| `QBCore:Notify`, `esx:showNotification`, `esx:showAdvancedNotification`, `ESX:Notify` | client (from the server) | Shows ai-lib's notification. |
| `esx:showHelpNotification`, `ESX:TextUI`, `ESX:HideUI`, `qb-core:client:DrawText`, `qb-core:client:ChangeText`, `qb-core:client:HideText`, `qb-core:client:KeyPressed` | client | Shows or hides ai-lib's prompt. |
| `qb-menu:client:openMenu`, `qb-menu:client:closeMenu` | client | Opens or closes ai-lib's menu with the qb-menu items. |
| `progressbar:client:cancel` | client | Cancels the bridge's progress bar. |
| `police:server:policeAlert` | server | Sends a police alert to the active alert system at the player's position. Clients send `(text)` (one per player in 10 seconds); server scripts `TriggerEvent` it with `(text, camId, playerSource)`. |
| `qb-weathersync:client:DisableSync` / `EnableSync`, `cd_easytime:PauseSync`, `vSync:toggle` | client | Counted as pause reasons of the weather and time sync (see [Weather and time sync](/docs/developers/api/core-client/world)). |
