Скрипты ai-* никогда не вызывают друг друга для общей задачи: предметы, ключи, оповещения, тюрьма, медицина, внешность, пункты радиального меню и погода идут через ai-core (библиотеку), который вызывает экспорты ниже. Вызывайте их сами только для того, что относится к конкретному скрипту. Экспорты, типизированные в `@aicore-fivem/shared`, работают с `resourceExport("ai-...")`; остальные через `callExport(resource, name, ...args)` или обычный вызов `exports[...]`.

Если скрипт заменяет другой (`provide`), имена экспортов того скрипта тоже отвечают, поэтому `exports.ox_inventory:AddItem(...)` попадает в ai-inventory.

## ai-lib

Общий интерфейс игрока. Клиентские экспорты, типизированы `AiLibClientExports`; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` и `lockpick` библиотеки вызывают их за вас.

| Экспорт | Что |
| --- | --- |
| `Notify(notification: Notification): void` | Карточка уведомления (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Показывает полосу прогресса на `duration` мс (действие выполняет вызывающий). |
| `HideProgress(): void` | Скрывает её. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Показывает или обновляет подсказку вызывающего; `at` рисует её над точкой в мире. |
| `HidePrompt(id: string): void` | Скрывает подсказку. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Меню; выбор приходит как `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Диалог ввода; значения приходят как `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Проверка навыка или отмычка; результат приходит как `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Закрывает открытое меню или диалог ввода вызывающего (ответ null). |

Серверное событие `ai-lib:client:notify` (`LIB_UI.notifyEvent`) с `Notification` показывает карточку на экране этого игрока.

## ai-inventory

Серверные экспорты (собственные): другие скрипты ai-* доходят до них через слой инвентаря ai-core.

| Экспорт | Что |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Добавляет предметы. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Убирает предметы. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Сколько штук. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Все стаки с названиями. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Поместится ли. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | `handler`, вернувший false, оставляет предмет; иначе забирается его количество `consume`. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Хранилище. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Открывает инвентарь на экране игрока. |
| `ClearInventory(inv: number \| string): void` | Очищает его. |
| `Items(name?: string): unknown` | Одно определение предмета (формат ox) или все. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Переносимый вес и лимит в граммах. |

Клиентские экспорты: `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (собственный инвентарь с землёй, багажником или бардачком рядом), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Локальное событие сервера `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### API ox_inventory

ai-inventory делает `provide` для `ox_inventory` и отвечает на его экспорты (ox_inventory 2.44). Инвентари называются как в ox: source игрока, имя хранилища, `{ id, owner }` для личных хранилищ, номер для багажников.

- Сервер: `AddItem` (возвращает `success, response`, вызывает `cb`), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (хранилище, игрок, магазин), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Клиент: `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon`; `displayMetadata`, `weaponWheel`, `setStashTarget` принимаются и ничего не делают.
- Без ответа: хуки (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (магазины берутся из панели).

### API qb-inventory

ai-inventory делает `provide` для `qb-inventory` (API 2.0). Возвращаемые предметы несут оба формата: `count` / `metadata` и `amount` / `info`.

- Сервер: `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (имя, список или `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Клиент: `HasItem`, `CloseInventory`.
- Без ответа: хуки и слушатели, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.

## ai-vehicles

Личный транспорт. Серверные экспорты, типизированы `AiVehiclesServerExports`. `VehicleOwner` - это `{ type: "character" \| "job" \| "gang" \| "resource", id }`.

| Экспорт | Что |
| --- | --- |
| `CreateVehicle(owner: VehicleOwner, model: string, garage: string \| null, props?): { id, plate } \| null` | Регистрирует новый личный транспорт. |
| `GetVehicle(ref: number \| string): OwnedVehicle \| null` | Транспорт по id или номеру. |
| `GetVehicles(owner: VehicleOwner): OwnedVehicle[]` | Транспорт персонажа онлайн или автопарк работы или банды. |
| `IsOwnedPlate(plate: string): boolean` | Принадлежит ли номер личному транспорту. |
| `GetVehicleIdByEntity(entity: number): number \| null` | Id заспавненного личного транспорта. |
| `GetPlateOwners(): [plate, type, id][]` | Весь личный транспорт в памяти (затем следите за `ai-vehicles:owners`). |
| `GetEntity(id: number): number \| null` | Заспавненная сущность транспорта. |
| `SaveVehicle(id: number, change: { props?, fuel?, engine?, body?, state?, garage? }): void` | Сохраняет состояние и внешний вид; сохранённый тюнинг остаётся. |
| `SaveTuning(id: number, props: unknown): void` | Сохраняет полные свойства с тюнингом (только тюнинг-мастерские). |
| `StoreVehicle(id: number, garage: string \| null, state?: VehicleState): void` | Ставит транспорт в гараж (`garage`, `out`, `impound`). |
| `SetOwner(id: number, owner: VehicleOwner): void` | Меняет владельца. |
| `DeleteVehicle(id: number): void` | Удаляет транспорт. |
| `SpawnVehicle(id: number, at: { x, y, z, heading }, asker: number, cb: (netId: number \| null) => void, purpose?: KeyPurpose, setup?): void` | Создаёт сущность; `cb` получает её net id. |

ai-vehicles делает `provide` для `qbx_vehicles`: `GetPlayerVehicles(filters)`, `GetPlayerVehicle(id)`, `CreatePlayerVehicle(request)`, `SetPlayerVehicleOwner(id, citizenid)`, `DeletePlayerVehicles(idType, idValue)`, `GetVehicleIdByPlate(plate)`, `DoesPlayerVehiclePlateExist(plate)`, `SaveVehicle(entity, options)` (фильтры по citizenid требуют, чтобы владелец был онлайн).

## ai-vehiclekeys

| Экспорт | Что |
| --- | --- |
| `HasKeys(source: number, vehicle: number \| string): boolean` | Есть ли у игрока ключи. |
| `GiveKeys(source: number, vehicle: number \| string): void` | Выдаёт ключи. |
| `RemoveKeys(source: number, vehicle: number \| string): void` | Забирает ключи. |
| `SetLockState(vehicle, state)` | Запирает (`"lock"`, `true`, `2`) или отпирает сущность транспорта. |
| `IsPlayerNearVehicle(source, vehicle)` | Стоит ли игрок рядом с транспортом. |

## ai-death

| Экспорт | Что |
| --- | --- |

| `Heal(source: number): void` | Полное здоровье для игрока, который не упал. |

## ai-radialmenu

## ai-target

## ai-voice

Заменяет pma-voice 7.x (делает `provide` для `pma-voice`, `mumble-voip`, `tokovoip`, `toko-voip`, `tokovoip_script`).

- Сервер, имена pma-voice: `setPlayerRadio`, `setPlayerCall`, `getPlayersInRadioChannel` / `GetPlayersInRadioChannel`, `addChannelCheck`, `overrideRadioNameGetter`, `isValidPlayer`.
- Сервер, собственные: `getBackend`, `setPlayerProximityMode(source, index)`, `setPlayerRange(source, metres | null)`, `getPlayerProximity(source)`, `toggleMute(source, seconds?)`, `addProximityCheck(fn(source, index, distance))` (false запрещает), `addPlayerRadioListen` / `removePlayerRadioListen` / `setPlayerRadioActive(source, channel)`, `getPlayerRadioChannels(source)` (`{ active, channels }`), `addCallCheck(fn(source, callId))` (true разрешает), `setPlayerCallSpeaker(source, on)` / `getPlayerCallSpeaker(source)`, `setPlayerSubmix(source, name | null)`.
- Клиент: клиентские экспорты pma-voice (`setRadioChannel`, `setCallChannel`, `setRadioVolume`, `setCallVolume`, `setVoiceProperty`, `overrideProximityRange`, `toggleMutePlayer`, `toggleRadioAnim`...) плюс `addRadioDisableBit` / `removeRadioDisableBit`, `registerCustomSubmix`, `setEffectSubmix`; собственные `addRadioChannel` / `removeRadioChannel` / `setActiveRadioChannel` / `getRadioChannels`, `setCallSpeaker` / `getCallSpeaker`, `setRadioAnimDisabled`, `createSubmix(name, spec)` / `getSubmix` / `editSubmix` / `listSubmixes`, `cycleProximity`, `getBackend`, `isRadioTalking`.
- Локальные события: клиент `pma-voice:setTalkingMode`, `pma-voice:radioActive`, `pma-voice:toggleRadioAnim`; сервер `pma-voice:playerMuted`.
