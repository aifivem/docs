Os scripts ai-* nunca chamam uns aos outros para uma tarefa compartilhada: itens, chaves, alertas, prisão, médico, aparências, itens do radial e clima passam pelo ai-core (a lib), que chama os exports abaixo. Chame-os você mesmo só para o que é específico daquele script. Exports tipados em `@aicore-fivem/shared` funcionam com `resourceExport("ai-...")`; os outros com `callExport(resource, name, ...args)` ou uma chamada simples a `exports[...]`.

Quando um script substitui outro (`provide`), os nomes de export do outro script também respondem, então `exports.ox_inventory:AddItem(...)` chega ao ai-inventory.

## ai-lib

A interface compartilhada do jogador. Exports de cliente, tipados `AiLibClientExports`; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` e `lockpick` da lib os chamam por você.

| Export | O quê |
| --- | --- |
| `Notify(notification: Notification): void` | Um cartão de notificação (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Mostra a barra de progresso por `duration` ms (quem chama executa a ação). |
| `HideProgress(): void` | Esconde a barra. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Mostra ou atualiza o prompt de quem chama; `at` o desenha sobre um ponto do mundo. |
| `HidePrompt(id: string): void` | Esconde um prompt. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Um menu; a escolha chega como `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Um diálogo de entrada; os valores chegam como `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Um skill check ou lockpick; o resultado chega como `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Fecha o menu ou a entrada abertos de quem chama (respondido com null). |

O evento de servidor `ai-lib:client:notify` (`LIB_UI.notifyEvent`) com uma `Notification` mostra um cartão na tela daquele jogador.

## ai-inventory

Exports de servidor (próprios): os outros scripts ai-* chegam a eles pela camada de inventário do ai-core.

| Export | O quê |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Adiciona itens. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Remove itens. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Quantos há. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Cada pilha com seu rótulo. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Se cabe. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | Se `handler` retornar false o item fica; senão a quantidade `consume` dele é tirada. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Um stash. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Abre um inventário na tela de um jogador. |
| `ClearInventory(inv: number \| string): void` | Esvazia o inventário. |
| `Items(name?: string): unknown` | Uma definição de item (formato do ox), ou todas. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Peso carregado e limite em gramas. |

Exports de cliente: `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (o próprio inventário com o chão, o porta-malas ou o porta-luvas ao redor), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Evento local do servidor `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### API do ox_inventory

O ai-inventory faz `provide` de `ox_inventory` e responde aos seus exports (ox_inventory 2.44). Os inventários têm os nomes do ox: o source de um jogador, um nome de stash, `{ id, owner }` para stashes pessoais, uma placa para porta-malas.

- Servidor: `AddItem` (retorna `success, response`, chama `cb`), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (stash, jogador, loja), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Cliente: `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon`; `displayMetadata`, `weaponWheel`, `setStashTarget` são aceitos e não fazem nada.
- Sem resposta: hooks (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (as lojas vêm do painel).

### API do qb-inventory

O ai-inventory faz `provide` de `qb-inventory` (API 2.0). Os itens retornados trazem os dois formatos: `count` / `metadata` e `amount` / `info`.

- Servidor: `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (nome, lista ou `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Cliente: `HasItem`, `CloseInventory`.
- Sem resposta: hooks e listeners, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.

## ai-vehicles

Veículos com dono. Exports de servidor, tipados `AiVehiclesServerExports`. `VehicleOwner` é `{ type: "character" \| "job" \| "gang" \| "resource", id }`.

| Export | O quê |
| --- | --- |
| `CreateVehicle(owner: VehicleOwner, model: string, garage: string \| null, props?): { id, plate } \| null` | Registra um novo veículo com dono. |
| `GetVehicle(ref: number \| string): OwnedVehicle \| null` | Um veículo por id ou placa. |
| `GetVehicles(owner: VehicleOwner): OwnedVehicle[]` | Veículos de um personagem online, ou a frota de um emprego ou gangue. |
| `IsOwnedPlate(plate: string): boolean` | Se uma placa pertence a um veículo com dono. |
| `GetVehicleIdByEntity(entity: number): number \| null` | O id de um veículo com dono que está no mundo. |
| `GetPlateOwners(): [plate, type, id][]` | Todo veículo com dono em memória (depois siga `ai-vehicles:owners`). |
| `GetEntity(id: number): number \| null` | A entidade de um veículo no mundo. |
| `SaveVehicle(id: number, change: { props?, fuel?, engine?, body?, state?, garage? }): void` | Salva condição e aparência; o tuning salvo continua. |
| `SaveTuning(id: number, props: unknown): void` | Salva as props completas com o tuning (só oficinas de tuning). |
| `StoreVehicle(id: number, garage: string \| null, state?: VehicleState): void` | Guarda um veículo em uma garagem (`garage`, `out`, `impound`). |
| `SetOwner(id: number, owner: VehicleOwner): void` | Muda o dono. |
| `DeleteVehicle(id: number): void` | Apaga um veículo. |
| `SpawnVehicle(id: number, at: { x, y, z, heading }, asker: number, cb: (netId: number \| null) => void, purpose?: KeyPurpose, setup?): void` | Cria a entidade; `cb` recebe seu net id. |

O ai-vehicles faz `provide` de `qbx_vehicles`: `GetPlayerVehicles(filters)`, `GetPlayerVehicle(id)`, `CreatePlayerVehicle(request)`, `SetPlayerVehicleOwner(id, citizenid)`, `DeletePlayerVehicles(idType, idValue)`, `GetVehicleIdByPlate(plate)`, `DoesPlayerVehiclePlateExist(plate)`, `SaveVehicle(entity, options)` (filtros por citizenid precisam do dono online).

## ai-death

Exports de servidor, tipados `AiDeathServerExports`; `Revive` e `IsDead` também sob `qbx_medical`. Os scripts usam a camada médica do ai-core (`medical` da lib) em vez deles.

| Export | O quê |
| --- | --- |
| `Revive(source: number): boolean` | Levanta um jogador caído; false quando não está caído. |
| `IsDead(source: number): boolean` | Se o jogador está caído. |
| `Heal(source: number): void` | Vida cheia para um jogador que não está caído. |

## ai-radialmenu

Exports de cliente próprios (tipados `AiRadialClientExports`): `AddItem(item)` (`onSelect` é aceito como `onPressed`), `RemoveItem(id, parent?)`, `Refresh()`. Os scripts usam `radial` da lib.

Ele faz `provide` das APIs de outras rodas:

- `qb-radialmenu`: `AddOption(data, id?)` retorna o id, `RemoveOption(id)`.
- `tgiann-radialmenu-target`: `AddMenuItem(item | items, parentId?)`, `RemoveMenuItem(id, parentId?)`, `ClearMenuItems()`, `RegisterSubMenu({ id, items })`, `RefreshMenu()`, `DisableMenu(state)`, `IsMenuDisabled()`, `OpenMenu()`, `CloseMenu()`, `IsMenuOpen()`, `HasMenuItem(id)`, `SetMenuItemHidden(id, state)`, `IsMenuItemHidden(id)`, `UpdateMenuItem(id, { label?, icon? })`, `ResetMenuItem(id)`.

## ai-target

Responde à API de cliente do ox_target sob `ai-target` e `ox_target`: `addSphereZone`, `addBoxZone`, `addPolyZone`, `removeZone`, `zoneExists`, `addModel`, `removeModel`, `addEntity`, `removeEntity`, `addLocalEntity`, `removeLocalEntity`, `addGlobalPed` / `Vehicle` / `Object` / `Player` e seus `removeGlobal*`, `disableTargeting`, `isActive`. `addGlobalOption` não é oferecido (registra um aviso). ## ai-voice

Substitui o pma-voice 7.x (faz `provide` de `pma-voice`, `mumble-voip`, `tokovoip`, `toko-voip`, `tokovoip_script`).

- Servidor, nomes do pma-voice: `setPlayerRadio`, `setPlayerCall`, `getPlayersInRadioChannel` / `GetPlayersInRadioChannel`, `addChannelCheck`, `overrideRadioNameGetter`, `isValidPlayer`.
- Servidor, próprios: `getBackend`, `setPlayerProximityMode(source, index)`, `setPlayerRange(source, metres | null)`, `getPlayerProximity(source)`, `toggleMute(source, seconds?)`, `addProximityCheck(fn(source, index, distance))` (false recusa), `addPlayerRadioListen` / `removePlayerRadioListen` / `setPlayerRadioActive(source, channel)`, `getPlayerRadioChannels(source)` (`{ active, channels }`), `addCallCheck(fn(source, callId))` (true permite), `setPlayerCallSpeaker(source, on)` / `getPlayerCallSpeaker(source)`, `setPlayerSubmix(source, name | null)`.
- Cliente: os exports de cliente do pma-voice (`setRadioChannel`, `setCallChannel`, `setRadioVolume`, `setCallVolume`, `setVoiceProperty`, `overrideProximityRange`, `toggleMutePlayer`, `toggleRadioAnim`...) mais `addRadioDisableBit` / `removeRadioDisableBit`, `registerCustomSubmix`, `setEffectSubmix`; próprios `addRadioChannel` / `removeRadioChannel` / `setActiveRadioChannel` / `getRadioChannels`, `setCallSpeaker` / `getCallSpeaker`, `setRadioAnimDisabled`, `createSubmix(name, spec)` / `getSubmix` / `editSubmix` / `listSubmixes`, `cycleProximity`, `getBackend`, `isRadioTalking`.
- Eventos locais: cliente `pma-voice:setTalkingMode`, `pma-voice:radioActive`, `pma-voice:toggleRadioAnim`; servidor `pma-voice:playerMuted`.

## ai-chat
