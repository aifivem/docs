Les pages de l’API écrivent les types par leur nom (`Vec3`, `ActionResult`, `InventoryRef`...). Cette page explique chacun une seule fois : ses champs, ce que signifie chaque champ, et une valeur d’exemple.

D’où vient un type :

| Package | Import | Types |
| --- | --- | --- |
| `@aicore-fivem/shared` | `import type { AiPlayerData } from "@aicore-fivem/shared";` | Tout ce qui est sur cette page, sauf indication contraire dans le titre. |
| `@aicore-fivem/lib/shared` | `import type { Vec3 } from "@aicore-fivem/lib/shared";` | `Vec3`, `Vec4`, `AccessRule`, `BlipStyle`, `ZoneShape`, `VehicleProps`, `VehicleSetup`, `PlacePed`. |
| `@aicore-fivem/lib/client` | `import type { ProgressOptions } from "@aicore-fivem/lib/client";` | `ProgressOptions`. |
| `@aicore-fivem/lib/server` | `import type { ProgressForOptions } from "@aicore-fivem/lib/server";` | `ProgressForOptions`. |

<Callout type="info">
Lua n’a pas de types à l’exécution. Une table Lua avec les mêmes clés est la même valeur : `{ x = 1.0, y = 2.0, z = 3.0 }` est un `Vec3`. Les tableaux sont des listes Lua (`{ 'police', 'sheriff' }`), `null` est `nil`. Voir [Lib pour Lua](/fr/docs/developers/api/lua) pour les vecteurs.
</Callout>

## Positions

### Vec3

Un point dans le monde, en mètres. Dans GTA, `x` est l’est, `y` le nord, `z` le haut.

<TypeTable
  type={{
    x: { type: 'number', description: 'Position est-ouest en mètres.', required: true },
    y: { type: 'number', description: 'Position nord-sud en mètres.', required: true },
    z: { type: 'number', description: 'Hauteur en mètres.', required: true },
  }}
/>

```ts title="Exemple"
const counter: Vec3 = { x: 25.7, y: -1347.3, z: 29.5 };
```

```lua title="Lua"
local counter = vector3(25.7, -1347.3, 29.5) -- ou { x = 25.7, y = -1347.3, z = 29.5 }
```

### Vec4

Un point avec une orientation : là où se tient un ped ou apparaît un véhicule, et la direction vers laquelle il regarde. Les champs `vec4` du panneau et l’outil de point du panneau stockent cette forme.

<TypeTable
  type={{
    x: { type: 'number', description: 'Position est-ouest en mètres.', required: true },
    y: { type: 'number', description: 'Position nord-sud en mètres.', required: true },
    z: { type: 'number', description: 'Hauteur en mètres.', required: true },
    heading: { type: 'number', description: "Direction en degrés, 0-360 (celle de GTA : 0 = nord, sens antihoraire).", required: true },
  }}
/>

```ts title="Exemple"
const spawn: Vec4 = { x: -42.1, y: -1098.4, z: 26.4, heading: 158.0 };
```

<Callout type="info">
Un `vector4` Lua appelle l’orientation `w`. Les lecteurs de la lib ([readVec4](/fr/docs/developers/api/lib-shared/input#readvec4)) acceptent à la fois `heading` et `w`.
</Callout>

### ZoneShape

Une zone dans le monde. Utilisée par les `Zones` côté client et par les vérifications de zone côté serveur ([géométrie des zones](/fr/docs/developers/api/lib-shared/zones)). C’est l’une de trois formes, choisie par `type`.

**Sphere** (une boule autour d’un point) :

<TypeTable
  type={{
    type: { type: '"sphere"', description: 'Choisit cette forme.', required: true },
    center: { type: 'Vec3', description: 'Centre de la boule.', required: true, typeDescription: '{ x, y, z }' },
    radius: { type: 'number', description: 'Rayon en mètres.', required: true },
  }}
/>

**Cylinder** (un cercle au sol, qui s’étend vers le haut et vers le bas) :

<TypeTable
  type={{
    type: { type: '"cylinder"', description: 'Choisit cette forme.', required: true },
    center: { type: 'Vec3', description: 'Centre du cercle.', required: true },
    radius: { type: 'number', description: 'Rayon sur le plan du sol, en mètres.', required: true },
    height: { type: 'number', description: 'Jusqu’où la zone s’étend vers le haut et vers le bas depuis `center.z`, en mètres (la hauteur totale est le double).', required: true },
  }}
/>

**Poly** (un polygone au sol entre deux hauteurs) :

<TypeTable
  type={{
    type: { type: '"poly"', description: 'Choisit cette forme.', required: true },
    points: { type: 'Array<{ x: number; y: number }>', description: 'Coins au sol, dans l’ordre autour de la zone. Au moins 3.', required: true },
    minZ: { type: 'number', description: 'Hauteur la plus basse dans la zone.', required: true },
    maxZ: { type: 'number', description: 'Hauteur la plus haute dans la zone.', required: true },
  }}
/>

```ts title="Exemple"
const yard: ZoneShape = { type: "sphere", center: { x: 440.1, y: -981.2, z: 30.7 }, radius: 25 };
const lot: ZoneShape = {
  type: "poly",
  points: [ { x: 210, y: -810 }, { x: 240, y: -800 }, { x: 230, y: -770 }, { x: 200, y: -780 } ],
  minZ: 28,
  maxZ: 36,
};
```

## Résultats

### ActionResult

Ce que chaque action serveur répond à un client : soit un succès, soit une clé de langue que le client affiche comme raison. Des champs supplémentaires peuvent accompagner la branche de succès (`ActionResult<{ id: number }>`). Le nouvel état lui-même ne voyage jamais dans la réponse : il arrive sous forme de delta.

**Succès :**

<TypeTable
  type={{
    ok: { type: 'true', description: 'L’action s’est exécutée.', required: true },
    '...T': { type: 'T', description: 'Champs supplémentaires d’`ActionResult<T>` (par exemple l’id du nouvel enregistrement).' },
  }}
/>

**Refus :**

<TypeTable
  type={{
    ok: { type: 'false', description: 'L’action a été refusée.', required: true },
    error: { type: 'string', description: 'Une clé de langue des `locales/*.json` de la ressource (`"NOT_ENOUGH_MONEY"`). Le client la traduit et l’affiche.', required: true },
  }}
/>

```ts title="Exemple"
const done: ActionResult = { ok: true };
const created: ActionResult<{ id: number }> = { ok: true, id: 42 };
const refused: ActionResult = { ok: false, error: "NOT_ENOUGH_MONEY" };
```

```lua title="Lua"
return { ok = true }
return aiLib.fail('NOT_ENOUGH_MONEY') -- { ok = false, error = 'NOT_ENOUGH_MONEY' }
```

Construisez les refus avec [fail](/fr/docs/developers/api/lib-shared/input#fail) ; lisez les réponses avec [isActionOk](/fr/docs/developers/api/lib-shared/input#isactionok) et [replyError](/fr/docs/developers/api/lib-shared/input#replyerror).

## Argent

### Noms de comptes

L’argent vit dans des comptes nommés. La liste **Accounts** du panneau fixe ceux qui existent ; ai-core est livré avec ceux-ci :

| Nom | Libellé | Montant de départ |
| --- | --- | --- |
| `cash` | Cash | 500 |
| `bank` | Bank | 5000 |
| `black_money` | Dirty money | 0 |
| `crypto` | Crypto | 0 |

Un propriétaire de serveur peut ajouter, renommer ou supprimer des comptes dans le panneau : lisez donc la liste avec l’export `GetAccountTypes` au lieu de la supposer. Quand la liste est vide, ai-core garde un seul compte `cash`.

```ts title="Exemple"
core.AddMoney(source, "bank", 250, "Paycheck");
```

## Inventaire

### InventoryRef

Sur quel inventaire travaille un appel.

| Valeur | Signification |
| --- | --- |
| `number` | L’id serveur d’un joueur : le propre inventaire de ce joueur. |
| `string` | N’importe quel autre inventaire par son id : un nom de coffre, un id de coffre de véhicule ou de boîte à gants. |

```ts title="Exemple"
inventory.addItem(source, "water", 2);          // un joueur
inventory.addItem("police_evidence", "phone", 1); // un coffre
```

### ItemMetadata

Données libres stockées sur une pile d’objets (`Record<string, unknown>`) : un numéro de série, une durabilité, une note. Chaque inventaire affiche lui-même certaines clés (`label`, `description`, `image` dans la plupart).

```ts title="Exemple"
const metadata: ItemMetadata = { serial: "AB-1029", durability: 100 };
```

<Callout type="warn">
Gardez les métadonnées petites et compatibles JSON (chaînes, nombres, booléens, objets et tableaux simples). Deux piles avec des métadonnées différentes ne s’empilent jamais ensemble.
</Callout>

### UsableItemHandler

`(source: number, item: UsedItem) => unknown` : s’exécute quand un joueur utilise l’objet. Renvoyer `false` garde l’objet dans les inventaires qui retirent eux-mêmes un objet utilisé (ai-inventory retire la quantité `consume` de l’objet) ; les autres inventaires suivent leurs propres réglages d’objets.

```ts title="Exemple"
const onUse: UsableItemHandler = (source, item) => {
  if (item.metadata.durability === 0) return false; // le garder
  return true;
};
```
