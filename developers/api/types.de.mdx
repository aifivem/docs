---

Die API-Seiten schreiben Typen beim Namen (`Vec3`, `ActionResult`, `InventoryRef`...). Diese Seite erklärt jeden einmal: seine Felder, was jedes Feld bedeutet, und einen Beispielwert.

Woher ein Typ kommt:

| Paket | Import | Typen |
| --- | --- | --- |
| `@aifivem/shared` | `import type { AiPlayerData } from "@aifivem/shared";` | Alles auf dieser Seite, sofern die Überschrift nichts anderes sagt. |
| `@aifivem/lib/shared` | `import type { Vec3 } from "@aifivem/lib/shared";` | `Vec3`, `Vec4`, `AccessRule`, `BlipStyle`, `ZoneShape`, `VehicleProps`, `VehicleSetup`, `PlacePed`. |
| `@aifivem/lib/client` | `import type { ProgressOptions } from "@aifivem/lib/client";` | `ProgressOptions`. |
| `@aifivem/lib/server` | `import type { ProgressForOptions } from "@aifivem/lib/server";` | `ProgressForOptions`. |

<Callout type="info">
Lua hat zur Laufzeit keine Typen. Eine Lua-Tabelle mit denselben Schlüsseln ist derselbe Wert: `{ x = 1.0, y = 2.0, z = 3.0 }` ist ein `Vec3`. Arrays sind Lua-Listen (`{ 'police', 'sheriff' }`), `null` ist `nil`. Siehe [Lib für Lua](/de/docs/developers/api/lua) für Vektoren.
</Callout>

## Positionen

### Vec3

Ein Punkt in der Welt, in Metern. GTAs `x` ist Osten, `y` ist Norden, `z` ist oben.

<TypeTable
  type={{
    x: { type: 'number', description: 'Ost-West-Position in Metern.', required: true },
    y: { type: 'number', description: 'Nord-Süd-Position in Metern.', required: true },
    z: { type: 'number', description: 'Höhe in Metern.', required: true },
  }}
/>

```ts title="Example"
const counter: Vec3 = { x: 25.7, y: -1347.3, z: 29.5 };
```

```lua title="Lua"
local counter = vector3(25.7, -1347.3, 29.5) -- oder { x = 25.7, y = -1347.3, z = 29.5 }
```

### Vec4

Ein Punkt mit Ausrichtung: wo ein Ped steht oder ein Fahrzeug spawnt und in welche Richtung es schaut. `vec4`-Felder des Panels und das Punkt-Werkzeug des Panels speichern diese Form.

<TypeTable
  type={{
    x: { type: 'number', description: 'Ost-West-Position in Metern.', required: true },
    y: { type: 'number', description: 'Nord-Süd-Position in Metern.', required: true },
    z: { type: 'number', description: 'Höhe in Metern.', required: true },
    heading: { type: 'number', description: 'Richtung in Grad, 0-360 (wie bei GTA: 0 = Norden, gegen den Uhrzeigersinn).', required: true },
  }}
/>

```ts title="Example"
const spawn: Vec4 = { x: -42.1, y: -1098.4, z: 26.4, heading: 158.0 };
```

<Callout type="info">
Ein Lua-`vector4` nennt die Ausrichtung `w`. Die Leser der Lib ([readVec4](/de/docs/developers/api/lib-shared/input#readvec4)) akzeptieren sowohl `heading` als auch `w`.
</Callout>

### ZoneShape

Ein Bereich in der Welt. Wird von Client-`Zones` und von serverseitigen Bereichsprüfungen genutzt ([Zonengeometrie](/de/docs/developers/api/lib-shared/zones)). Es ist eine von drei Formen, gewählt über `type`.

**Kugel** (eine Kugel um einen Punkt):

<TypeTable
  type={{
    type: { type: '"sphere"', description: 'Wählt diese Form.', required: true },
    center: { type: 'Vec3', description: 'Mittelpunkt der Kugel.', required: true, typeDescription: '{ x, y, z }' },
    radius: { type: 'number', description: 'Radius in Metern.', required: true },
  }}
/>

**Zylinder** (ein Kreis am Boden, der nach oben und unten reicht):

<TypeTable
  type={{
    type: { type: '"cylinder"', description: 'Wählt diese Form.', required: true },
    center: { type: 'Vec3', description: 'Mittelpunkt des Kreises.', required: true },
    radius: { type: 'number', description: 'Radius auf der Bodenebene, in Metern.', required: true },
    height: { type: 'number', description: 'Wie weit die Zone von `center.z` nach oben und unten reicht, in Metern (die Gesamthöhe ist das Doppelte).', required: true },
  }}
/>

**Polygon** (ein Bodenpolygon zwischen zwei Höhen):

<TypeTable
  type={{
    type: { type: '"poly"', description: 'Wählt diese Form.', required: true },
    points: { type: 'Array<{ x: number; y: number }>', description: 'Ecken am Boden, der Reihe nach um den Bereich herum. Mindestens 3.', required: true },
    minZ: { type: 'number', description: 'Niedrigste Höhe innerhalb der Zone.', required: true },
    maxZ: { type: 'number', description: 'Höchste Höhe innerhalb der Zone.', required: true },
  }}
/>

```ts title="Example"
const yard: ZoneShape = { type: "sphere", center: { x: 440.1, y: -981.2, z: 30.7 }, radius: 25 };
const lot: ZoneShape = {
  type: "poly",
  points: [ { x: 210, y: -810 }, { x: 240, y: -800 }, { x: 230, y: -770 }, { x: 200, y: -780 } ],
  minZ: 28,
  maxZ: 36,
};
```

## Ergebnisse

### ActionResult

Was jede Server-Aktion einem Client antwortet: entweder Erfolg oder einen Sprachschlüssel, den der Client als Grund anzeigt. Zusätzliche Felder können im Erfolgszweig mitfahren (`ActionResult<{ id: number }>`). Der neue Zustand selbst reist nie in der Antwort: Er kommt als Delta an.

**Erfolg:**

<TypeTable
  type={{
    ok: { type: 'true', description: 'Die Aktion lief.', required: true },
    '...T': { type: 'T', description: 'Zusätzliche Felder von `ActionResult<T>` (zum Beispiel die ID des neuen Datensatzes).' },
  }}
/>

**Ablehnung:**

<TypeTable
  type={{
    ok: { type: 'false', description: 'Die Aktion wurde abgelehnt.', required: true },
    error: { type: 'string', description: 'Ein Sprachschlüssel aus `locales/*.json` der Ressource (`"NOT_ENOUGH_MONEY"`). Der Client übersetzt und zeigt ihn.', required: true },
  }}
/>

```ts title="Example"
const done: ActionResult = { ok: true };
const created: ActionResult<{ id: number }> = { ok: true, id: 42 };
const refused: ActionResult = { ok: false, error: "NOT_ENOUGH_MONEY" };
```

```lua title="Lua"
return { ok = true }
return aiLib.fail('NOT_ENOUGH_MONEY') -- { ok = false, error = 'NOT_ENOUGH_MONEY' }
```

Baue Ablehnungen mit [fail](/de/docs/developers/api/lib-shared/input#fail); lies Antworten mit [isActionOk](/de/docs/developers/api/lib-shared/input#isactionok) und [replyError](/de/docs/developers/api/lib-shared/input#replyerror).

## Spieler und Charaktere

### AiPlayerData

Die Spielerdaten, die ai-core an den eigenen Client eines Spielers schickt: ein vollständiger Snapshot, wenn der Charakter lädt, danach nur der Schlüssel, der sich geändert hat. Wird auch vom Export `GetPlayerData` auf beiden Seiten zurückgegeben. Andere Seiten nennen es eventuell „Spielerdaten“.

<TypeTable
  type={{
    character: { type: 'CharacterInfo | null', description: 'Der geladene Charakter, `null` auf dem Charakterbildschirm.', required: true },
    money: { type: 'Record<string, number>', description: 'Kontostand pro Kontoname (`{ cash: 500, bank: 5000 }`). Siehe [Kontonamen](#kontonamen).', required: true },
    jobs: { type: 'JobMembership[]', description: 'Jeder Job, den der Charakter hat, im Dienst oder nicht.', required: true },
    duty: { type: 'string | null', description: 'Der Job, für den der Charakter im Dienst ist, `null`, wenn außer Dienst.', required: true },
    job: { type: 'JobMembership', description: 'Der Job, den andere Skripte als „den“ Job sehen: der Dienst-Job, sonst der letzte im Dienst, sonst der erste, sonst arbeitslos.', required: true },
    gangs: { type: 'GangMembership[]', description: 'Jede Gang, in der der Charakter ist.', required: true },
    activeGang: { type: 'string | null', description: 'Die Gang, für die der Charakter gerade handelt, `null`, wenn keine.', required: true },
    metadata: { type: 'Record<string, unknown>', description: 'Frei gestaltete Werte, die mit dem Charakter gespeichert werden (Framework-Brücken legen hier QB- / ESX-Metadaten ab). Änderungen reisen pro Schlüssel.', required: true },
  }}
/>

```ts title="Example"
const data: AiPlayerData = {
  character: { id: 12, citizenid: "AB12CD34", slot: 1, firstname: "Jane", lastname: "Doe", birthdate: "1994-05-12", sex: "female", nationality: "American" },
  money: { cash: 500, bank: 5000, black_money: 0, crypto: 0 },
  jobs: [{ job: "police", grade: 2 }],
  duty: "police",
  job: { job: "police", grade: 2 },
  gangs: [],
  activeGang: null,
  metadata: { hunger: 80, thirst: 75 },
};
```

## Geld

### Kontonamen

Geld liegt in benannten Konten. Die Liste **Accounts** (Konten) des Panels legt fest, welche existieren; ai-core wird mit diesen ausgeliefert:

| Name | Label | Startbetrag |
| --- | --- | --- |
| `cash` | Cash | 500 |
| `bank` | Bank | 5000 |
| `black_money` | Dirty money | 0 |
| `crypto` | Crypto | 0 |

Ein Serverbesitzer kann im Panel Konten hinzufügen, umbenennen oder entfernen, also lies die Liste mit dem Export `GetAccountTypes`, statt sie anzunehmen. Wenn die Liste leer ist, behält ai-core ein einzelnes Konto `cash`.

```ts title="Example"
core.AddMoney(source, "bank", 250, "Paycheck");
```

### LookupSource

| --- | --- |
| `"item"` | Items des aktiven Inventars. |
| `"job"` | Jobs aus der Liste Jobs des Panels. |
| `"gang"` | Gangs aus der Liste Gangs des Panels. |
| `"account"` | Geldkonten. |
| `"resource"` | Gestartete Ressourcen. |
| `"player"` | Online-Spieler, per Citizen-ID. |
| `"vehicle"` | Jedes Fahrzeugmodell, das das Spiel des Admins hat, Addons eingeschlossen. Wird vom Server nie abgelehnt (er kann keine Modelle auflisten). |
| `"ped"` | Die Ped-Modelle von GTA. Wird vom Server nie abgelehnt. |

## vRP-Brücke

### VrpConfig

Die vRP-Berechtigungszuordnung des Panels (`data/vrp.json`), wie die vRP-Brücke von ai-core sie liest (Server-Export `GetVrpConfig`; das lokale Event `ai-core:vrp:config` trägt nach einer Änderung dieselbe Form).

<TypeTable
  type={{
    defaults: { type: '{ jobPrefix: boolean; jobOnDuty: boolean; adminPrefix: boolean; playerPrefix: boolean }', description: 'Eingebaute Regeln, die gelten, wenn kein Eintrag von `permissions` die Berechtigung nennt: `jobPrefix`: `<job>.*` = Mitglied dieses Jobs (nur im Dienst mit `jobOnDuty`); `adminPrefix`: `admin.*` = Admin (`ai.admin`); `playerPrefix`: `player.*` = alle.', required: true },

    groups: { type: 'Record<string, VrpGroupAlias>', description: 'vRP-Gruppenname zu dem, was er in ai-core bedeutet, Felder unten.', required: true },
    items: { type: 'Record<string, string>', description: 'vRP-Item-ID (`"edible|tacos"`, `"wbody|WEAPON_PISTOL"`) zu Inventar-Item-Name.', required: true },

<TypeTable
