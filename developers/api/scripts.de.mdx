ai-*-Skripte rufen sich für eine gemeinsame Aufgabe nie gegenseitig auf: Items, Schlüssel, Alarme, Gefängnis, Medizin, Aussehen, Radialeinträge und Wetter laufen über ai-core (die Lib), das die Exports unten aufruft. Ruf sie selbst nur für das auf, was diesem Skript eigen ist. In `@aicore-fivem/shared` typisierte Exports funktionieren mit `resourceExport("ai-...")`; die anderen mit `callExport(resource, name, ...args)` oder einem normalen `exports[...]`-Aufruf.

Wo ein Skript ein anderes ersetzt (`provide`), antworten auch die Export-Namen des anderen Skripts, sodass `exports.ox_inventory:AddItem(...)` bei ai-inventory ankommt.

## ai-lib

Die gemeinsame Spieler-UI. Client-Exports, typisiert als `AiLibClientExports`; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` und `lockpick` der Lib rufen sie für dich auf.

| Export | Was |
| --- | --- |
| `Notify(notification: Notification): void` | Eine Benachrichtigungskarte (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Zeigt den Fortschrittsbalken für `duration` ms (der Aufrufer führt die Aktion aus). |
| `HideProgress(): void` | Blendet ihn aus. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Zeigt oder aktualisiert den Prompt des Aufrufers; `at` zeichnet ihn über einen Punkt in der Welt. |
| `HidePrompt(id: string): void` | Blendet einen Prompt aus. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Ein Menü; die Auswahl kommt als `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Ein Eingabedialog; die Werte kommen als `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Ein Skill-Check oder Schlossknacken; das Ergebnis kommt als `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Schließt das offene Menü oder die Eingabe des Aufrufers (mit null beantwortet). |

Das Server-Event `ai-lib:client:notify` (`LIB_UI.notifyEvent`) mit einer `Notification` zeigt eine Karte auf dem Bildschirm dieses Spielers.

## ai-inventory

Server-Exports (eigene): Andere ai-*-Skripte erreichen sie über die Inventarebene von ai-core.

| Export | Was |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Fügt Items hinzu. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Entfernt Items. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Wie viele. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Jeder Stapel mit seinem Label. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Ob es passt. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | Gibt `handler` false zurück, bleibt das Item; sonst wird seine `consume`-Menge genommen. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Ein Lager. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Öffnet ein Inventar auf dem Bildschirm eines Spielers. |
| `ClearInventory(inv: number \| string): void` | Leert es. |
| `Items(name?: string): unknown` | Eine Item-Definition (ox-Form) oder alle. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Getragenes Gewicht und Limit in Gramm. |

Client-Exports: `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (eigenes Inventar mit Boden, Kofferraum oder Handschuhfach daneben), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Lokales Server-Event `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### ox_inventory-API

ai-inventory `provide`t `ox_inventory` und beantwortet dessen Exports (ox_inventory 2.44). Inventare heißen wie in ox: eine Spieler-Source, ein Lagername, `{ id, owner }` für persönliche Lager, ein Kennzeichen für Kofferräume.

- Server: `AddItem` (gibt `success, response` zurück, ruft `cb` auf), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (Lager, Spieler, Shop), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Client: `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon`; `displayMetadata`, `weaponWheel`, `setStashTarget` werden angenommen und tun nichts.
- Nicht beantwortet: Hooks (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (Shops kommen aus dem Panel).

### qb-inventory-API

ai-inventory `provide`t `qb-inventory` (2.0-API). Zurückgegebene Items tragen beide Formen: `count` / `metadata` und `amount` / `info`.

- Server: `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (Name, Liste oder `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Client: `HasItem`, `CloseInventory`.
- Nicht beantwortet: Hooks und Listener, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.

## ai-vehicles

Fahrzeuge in Besitz. Server-Exports, typisiert als `AiVehiclesServerExports`. `VehicleOwner` ist `{ type: "character" \| "job" \| "gang" \| "resource", id }`.

| Export | Was |
| --- | --- |
| `CreateVehicle(owner: VehicleOwner, model: string, garage: string \| null, props?): { id, plate } \| null` | Registriert ein neues Fahrzeug in Besitz. |
| `GetVehicle(ref: number \| string): OwnedVehicle \| null` | Ein Fahrzeug nach ID oder Kennzeichen. |
| `GetVehicles(owner: VehicleOwner): OwnedVehicle[]` | Fahrzeuge eines Online-Charakters oder eine Job- oder Gang-Flotte. |
| `IsOwnedPlate(plate: string): boolean` | Ob ein Kennzeichen zu einem Fahrzeug in Besitz gehört. |
| `GetVehicleIdByEntity(entity: number): number \| null` | Die ID eines gespawnten Fahrzeugs in Besitz. |
| `GetPlateOwners(): [plate, type, id][]` | Jedes Fahrzeug in Besitz im Speicher (danach `ai-vehicles:owners` folgen). |
| `GetEntity(id: number): number \| null` | Die gespawnte Entity eines Fahrzeugs. |
| `SaveVehicle(id: number, change: { props?, fuel?, engine?, body?, state?, garage? }): void` | Speichert Zustand und Aussehen; das gespeicherte Tuning bleibt. |
| `SaveTuning(id: number, props: unknown): void` | Speichert die vollen Props mit Tuning (nur Tuning-Werkstätten). |
| `StoreVehicle(id: number, garage: string \| null, state?: VehicleState): void` | Stellt ein Fahrzeug in eine Garage (`garage`, `out`, `impound`). |
| `SetOwner(id: number, owner: VehicleOwner): void` | Ändert den Besitzer. |
| `DeleteVehicle(id: number): void` | Löscht ein Fahrzeug. |
| `SpawnVehicle(id: number, at: { x, y, z, heading }, asker: number, cb: (netId: number \| null) => void, purpose?: KeyPurpose, setup?): void` | Erzeugt die Entity; `cb` bekommt ihre Net-ID. |

ai-vehicles `provide`t `qbx_vehicles`: `GetPlayerVehicles(filters)`, `GetPlayerVehicle(id)`, `CreatePlayerVehicle(request)`, `SetPlayerVehicleOwner(id, citizenid)`, `DeletePlayerVehicles(idType, idValue)`, `GetVehicleIdByPlate(plate)`, `DoesPlayerVehiclePlateExist(plate)`, `SaveVehicle(entity, options)` (citizenid-Filter brauchen den Besitzer online).

## ai-death

| Export | Was |

## ai-radialmenu

Eigene Client-Exports (typisiert als `AiRadialClientExports`): `AddItem(item)` (`onSelect` wird als `onPressed` angenommen), `RemoveItem(id, parent?)`, `Refresh()`. Skripte nutzen Lib `radial`.

Es `provide`t die APIs anderer Räder:

- `qb-radialmenu`: `AddOption(data, id?)` gibt die ID zurück, `RemoveOption(id)`.
- `tgiann-radialmenu-target`: `AddMenuItem(item | items, parentId?)`, `RemoveMenuItem(id, parentId?)`, `ClearMenuItems()`, `RegisterSubMenu({ id, items })`, `RefreshMenu()`, `DisableMenu(state)`, `IsMenuDisabled()`, `OpenMenu()`, `CloseMenu()`, `IsMenuOpen()`, `HasMenuItem(id)`, `SetMenuItemHidden(id, state)`, `IsMenuItemHidden(id)`, `UpdateMenuItem(id, { label?, icon? })`, `ResetMenuItem(id)`.

## ai-target

Beantwortet die ox_target-Client-API unter `ai-target` und `ox_target`: `addSphereZone`, `addBoxZone`, `addPolyZone`, `removeZone`, `zoneExists`, `addModel`, `removeModel`, `addEntity`, `removeEntity`, `addLocalEntity`, `removeLocalEntity`, `addGlobalPed` / `Vehicle` / `Object` / `Player` und ihre `removeGlobal*`, `disableTargeting`, `isActive`. `addGlobalOption` wird nicht angeboten (es loggt eine Warnung). ## ai-voice

Ersetzt pma-voice 7.x (`provide`t `pma-voice`, `mumble-voip`, `tokovoip`, `toko-voip`, `tokovoip_script`).

- Server, pma-voice-Namen: `setPlayerRadio`, `setPlayerCall`, `getPlayersInRadioChannel` / `GetPlayersInRadioChannel`, `addChannelCheck`, `overrideRadioNameGetter`, `isValidPlayer`.
- Server, eigene: `getBackend`, `setPlayerProximityMode(source, index)`, `setPlayerRange(source, metres | null)`, `getPlayerProximity(source)`, `toggleMute(source, seconds?)`, `addProximityCheck(fn(source, index, distance))` (false lehnt ab), `addPlayerRadioListen` / `removePlayerRadioListen` / `setPlayerRadioActive(source, channel)`, `getPlayerRadioChannels(source)` (`{ active, channels }`), `addCallCheck(fn(source, callId))` (true erlaubt), `setPlayerCallSpeaker(source, on)` / `getPlayerCallSpeaker(source)`, `setPlayerSubmix(source, name | null)`.
