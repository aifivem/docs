Te obiekty nigdy nie rozmawiają z konkretnym skryptem. Pytają **ai-core**, a ai-core przekazuje wywołanie do skryptu, którego serwer używa do tego zadania: ai-death albo inny skrypt śmierci, ai-appearance albo tgiann-clothing, dowolny obsługiwany skrypt emotek albo menu radialnego. Twój skrypt działa dalej, gdy właściciel któryś wymieni. Jak działają warstwy, opisuje strona [Warstwy i most](/pl/docs/developers/layers).

Gdy nie działa żaden skrypt danego rodzaju, wywołania odpowiadają `false`, `null` albo własną wartością gry, jak mówi każdy wpis.

## medical

### medical.isDead

Czy lokalny gracz jest powalony (martwy albo w last stand), w dowolnym działającym skrypcie śmierci. Skrypty śmierci trzymają powalonego peda przy życiu, żeby go animować, więc samo `IsEntityDead` ich nie wykrywa. Po pierwszym wywołaniu to odczyt z pamięci.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
medical.isDead(): boolean
```

Brak odpowiednika w Lua: wywołaj `exports['ai-core']:IsDead()` i nasłuchuj lokalnego zdarzenia `ai-core:client:dead` (`dead`).

#### Zwracana wartość

`boolean`: `true`, gdy warstwa medyczna ai-core mówi, że gracz jest powalony, albo ped jest martwy dla gry.

#### Przykład

```ts
import { medical, notify } from "@aifivem/lib/client";

RegisterCommand(
  "phone",
  () => {
    if (medical.isDead()) return notify("You cannot use the phone now", "error");
    SetNuiFocus(true, true);
  },
  false,
);
```

### medical.onChange

Uruchamia handler, gdy lokalny gracz zostanie powalony albo wstanie.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
medical.onChange(fn: (dead: boolean) => void): void
```

Brak odpowiednika w Lua: `AddEventHandler('ai-core:client:dead', function(dead) end)`.

#### Parametry

<TypeTable
  type={{
    fn: { type: '(dead: boolean) => void', description: 'Dostaje true, gdy gracz został powalony, false, gdy wstał.', required: true },
  }}
/>

#### Zwracana wartość

`void`.

#### Przykład

```ts
import { medical, Points } from "@aifivem/lib/client";

const points = new Points();
medical.onChange(() => points.refresh()); // punkty, których canShow czyta medical.isDead()
```

## appearance

Wygląd pedów przez warstwę wyglądu ai-core, niezależnie od tego, jaki skrypt ubrań działa.

### appearance.apply

Nakłada zapisany wygląd na peda o modelu tego wyglądu. Pobierz wygląd na serwerze przez `appearance.get(charId)`, utwórz peda z `look.model`, potem nałóż. Na własnym pedzie gracza zmienia jego ubrania.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
appearance.apply(ped: number, look: CharacterAppearance): boolean
```

```lua title="Lua"
local ok = aiLib.appearance.apply(ped, look)
```

#### Parametry

<TypeTable
  type={{
    ped: { type: 'number', description: 'Ped do ubrania. Jego model musi być look.model.', required: true },
    look: { type: 'CharacterAppearance', description: '{ model: number; data: unknown }: hash modelu i własne dane skryptu ubrań. Traktuj data jako nieprzezroczyste.', required: true },
  }}
/>

Typ to [`CharacterAppearance`](/pl/docs/developers/api/types#characterappearance).

#### Zwracana wartość

`boolean`: `false`, gdy peda już nie ma, model się różni albo nie działa żaden skrypt ubrań.

#### Przykład

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance, LocalPed, triggerServerCallback } from "@aifivem/lib/client";
import type { CharacterAppearance } from "@aifivem/shared";

// Śpiąca kopia postaci, ubrana jak ona.
export async function showSleeper(charId: number): Promise<void> {
  const look = (await triggerServerCallback("mysleep:look", [charId]).catch(() => null)) as CharacterAppearance | null;
  if (!look) return;
  new LocalPed({
    model: look.model,
    coords: { x: 151.2, y: -1004.6, z: 29.4, heading: 90 },
    onSpawn: (ped) => appearance.apply(ped, look),
  });
}
```
</Tab>
<Tab value="Lua">
```lua
local function showSleeper(charId)
    CreateThread(function()
        local look = aiLib.triggerServerCallback('mysleep:look', { charId })
        if type(look) ~= 'table' then return end
        aiLib.LocalPed.new({
            model = look.model,
            coords = vector4(151.2, -1004.6, 29.4, 90.0),
            onSpawn = function(ped) aiLib.appearance.apply(ped, look) end,
        })
    end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
Sprawdź, co wysyła serwer, zanim to rzutujesz. Ped utworzony z innym modelem niż `look.model` nie może przyjąć wyglądu: `apply` odpowiada `false`.
</Callout>

## fuel

### fuel.get

Poziom paliwa pojazdu. Serwer trzyma state bag `fuel` dla każdego pojazdu niezależnie od skryptu paliwa, więc to odczyt z pamięci; bez tego bagu to poziom zbiornika z gry.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
fuel.get(vehicle: number): number
```

Brak odpowiednika w Lua: czytaj `Entity(vehicle).state.fuel`. Ustawianie paliwa jest tylko na serwerze (`fuel.set` na stronie [Pojazdy](/pl/docs/developers/api/lib-server/vehicles)).

#### Parametry

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Pojazd, który zna ten klient.', required: true },
  }}
/>

#### Zwracana wartość

`number`: 0-100.

#### Przykład

```ts
import { cache, every, fuel } from "@aifivem/lib/client";

every(1000, () => {
  if (cache.vehicle !== false) SendNUIMessage({ action: "fuel", data: Math.round(fuel.get(cache.vehicle)) });
});
```

### inventory.hasItem
