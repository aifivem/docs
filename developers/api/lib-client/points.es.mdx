Un **punto** es cualquier lugar que usa un jugador: el mostrador de una tienda, una puerta, un NPC, un sitio de devolución, cada cajero automático, el maletero de cada coche. Lo describes una vez (dónde, qué texto, qué pasa) y la lib lo dibuja de la forma que eligió el dueño del servidor.

## Prompt o target

El dueño elige el estilo de interacción en el panel de administración de ai-core (**Interaction**). El mismo `onPressed` se ejecuta en ambos casos, así que a tu script nunca le importa cuál está activo.

| Estilo | Lo que ve el jugador |
| --- | --- |
| **Prompt** | Una caja de "pulsa E" en el lado derecho de la pantalla mientras el jugador está dentro del radio del punto. La tecla es un único keybind reasignable de ai-lib (por defecto `E`), así que nada sondea las teclas en cada frame. |
| **Target** | Una opción en el ojo de target sobre el sitio, el NPC, el objeto o el vehículo. Necesita que esté en marcha uno de los scripts de target para los que la lib tiene un adaptador. Cuando hay varios en marcha, gana el primero en este orden: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

Cuando el dueño eligió target pero no hay ningún script de target en marcha, cada punto es un prompt. Un punto puede anular la elección del dueño: `promptOnly` mantiene un prompt (cosas que se hacen desde un vehículo: surtidores de combustible, lavaderos de coches), `preferTarget` usa una opción de target siempre que haya un script de target en marcha (asientos). Cuando un script de target arranca o se detiene, o el dueño cambia el estilo, cada punto se adapta solo.

<Callout type="info">
Solo se ejecuta una acción de punto de tu recurso a la vez. Cuando `onPressed` devuelve una promise, los demás puntos de tu recurso ignoran las pulsaciones hasta que termina, así que nunca necesitas tu propio indicador `busy`. El jugador también debe pasar `canShow` en el momento de la pulsación.
</Callout>

// Un almacén que solo puede abrir la policía; el texto sigue un estado.
let locked = true;
points.add("evidence", {
  coords: { x: 474.9, y: -996.4, z: 26.3 },

    if (reply) locked = !locked;
    points.refresh("evidence");

});

// canShow lee el trabajo: compruébalo de nuevo cuando cambien los trabajos, el servicio o las bandas.
onMembershipChange(() => points.refresh());

### points.addModel

### points.refresh

Vuelve a leer `canShow` y las etiquetas que son funciones. Llámalo cuando cambie algo que leen: el trabajo, el servicio, un vehículo, un estado que envió el servidor. Los prompts se actualizan al momento; las opciones de target leen `canShow` cuando se abre el ojo, y una etiqueta cambiada se vuelve a poner.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
points.refresh(id?: string): void
```

```lua title="Lua"
points:refresh() -- todos los puntos del grupo
```

#### Parámetros

<TypeTable
  type={{
    id: { type: 'string', description: 'Solo este punto (una caja registradora robada entre cientos). Todos los puntos del grupo si se omite. Solo TypeScript: Lua siempre refresca el grupo entero.' },
  }}
/>

#### Devuelve

`void`.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">

## Puntos a partir de registros del panel

La mayoría de los puntos vienen de un archivo de registros del panel de administración de tu script (tiendas, garajes, mostradores de alquiler). Refleja el archivo en el cliente con [`AdminWorld`](#new-adminworld) y luego construye los puntos de cada registro con [`RecordObjects`](#new-recordobjects): un registro editado reconstruye solo sus propios puntos, y uno eliminado los quita.

### new RecordObjects

Mantiene los objetos del mundo de un archivo de registros (puntos, blips, peds, zonas) al día con el archivo, registro a registro. `build(key, record)` crea los objetos de un registro y devuelve cómo quitarlos. Construye todos los registros en su constructor.

**Lado:** Cliente y servidor (desde `@aicore-fivem/lib/shared`) · **Espera:** no

```ts title="Firma"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

Sin equivalente en Lua.

#### Parámetros

<TypeTable
  type={{
    source: { type: 'RecordSource', description: 'Dónde vive el archivo: un AdminWorld en el cliente (un AdminPanel en el servidor).', required: true },
    file: { type: 'string', description: 'El nombre del archivo de registros, sin data/ ni .json (locations).', required: true },
    records: { type: 'RecordReader<T> | ReadonlyMap<string, T>', description: 'Un lector (key, raw) => T | null que procesa un registro (null lo deja fuera), o una vista de registros que ya mantienes del mismo archivo (world.records(file, readOne)), para que cada edición se procese una sola vez.', required: true },

#### Ejemplo

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aicore-fivem/lib/client";
import { readVec3, RecordObjects, str } from "@aicore-fivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// Cambió un ajuste que leen todas las tiendas: reconstrúyelas todas.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` construye en su constructor. Créalo después de todo lo que lee `build`, y dentro de `build` usa el argumento `record`: un campo de clase que guarda el `RecordObjects` aún no está asignado durante esa primera construcción.
</Callout>

### new AdminWorld

La copia en el cliente de los archivos de mundo del panel de tu script (los archivos cuyo esquema dice `sync: "all"`, consulta [Panel de administración](/es/docs/developers/api/lib-server/admin-panel)). Lee la copia que FiveM guardó en caché al arrancar, pregunta una vez al servidor por los registros cambiados desde entonces y luego sigue los cambios en vivo. Nunca sondea.

**Lado:** Cliente · **Espera:** no (la promise `ready` indica cuándo llegaron los cambios desde el arranque)

```ts title="Firma"
new AdminWorld(files: string[])
```

Sin equivalente en Lua.
