Diese Objekte sprechen nie mit einem bestimmten Skript. Sie fragen **ai-core**, und ai-core leitet an das Skript weiter, das der Server für diese Aufgabe betreibt: ai-death oder ein anderes Death-Skript, ai-appearance oder tgiann-clothing, jedes unterstützte Emote- oder Radial-Skript. Dein Skript funktioniert weiter, wenn der Betreiber eins austauscht. Wie die Ebenen funktionieren, steht unter [Ebenen und die Brücke](/de/docs/developers/layers).

Wenn kein Skript dieser Art läuft, antworten die Aufrufe mit `false`, `null` oder dem eigenen Wert des Spiels, wie jeder Eintrag sagt.

## medical

### medical.isDead

Ob der lokale Spieler am Boden ist (tot oder im Last Stand), in dem Death-Skript, das gerade läuft. Death-Skripte halten einen bewusstlosen Ped am Leben, um ihn zu animieren, daher übersieht `IsEntityDead` allein sie. Nach dem ersten Aufruf ein Speicherzugriff.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
medical.isDead(): boolean
```

Kein Lua-Zwilling: Rufe `exports['ai-core']:IsDead()` auf und höre auf das lokale Event `ai-core:client:dead` (`dead`).

#### Rückgabewert

`boolean`: `true`, wenn die Medical-Ebene von ai-core sagt, dass der Spieler am Boden ist, oder der Ped für das Spiel tot ist.

#### Beispiel

```ts
import { medical, notify } from "@aicore-fivem/lib/client";

RegisterCommand(
  "phone",
  () => {
    if (medical.isDead()) return notify("You cannot use the phone now", "error");
    SetNuiFocus(true, true);
  },
  false,
);
```

### medical.onChange

Führt einen Handler aus, wenn der lokale Spieler zu Boden geht oder aufsteht.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
medical.onChange(fn: (dead: boolean) => void): void
```

Kein Lua-Zwilling: `AddEventHandler('ai-core:client:dead', function(dead) end)`.

#### Parameter

<TypeTable
  type={{
    fn: { type: '(dead: boolean) => void', description: 'Bekommt true, wenn der Spieler zu Boden ging, false, wenn er aufgestanden ist.', required: true },
  }}
/>

#### Rückgabewert

`void`.

#### Beispiel

```ts
import { medical, Points } from "@aicore-fivem/lib/client";

const points = new Points();
medical.onChange(() => points.refresh()); // Punkte, deren canShow medical.isDead() liest
```

## appearance

Aussehen auf Peds über die Aussehens-Ebene von ai-core, egal welches Kleidungs-Skript läuft.

### appearance.apply

Legt ein gespeichertes Aussehen auf einen Ped mit dem Modell des Aussehens. Hole das Aussehen auf dem Server mit `appearance.get(charId)`, erstelle den Ped mit `look.model` und wende es dann an. Auf dem eigenen Ped des Spielers ändert es seine Kleidung.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
appearance.apply(ped: number, look: CharacterAppearance): boolean
```

```lua title="Lua"
local ok = aiLib.appearance.apply(ped, look)
```

#### Parameter

<TypeTable
  type={{
    ped: { type: 'number', description: 'Der Ped, der eingekleidet wird. Sein Modell muss look.model sein.', required: true },
    look: { type: 'CharacterAppearance', description: '{ model: number; data: unknown }: der Modell-Hash und die eigenen Daten des Kleidungs-Skripts. Behandle data als undurchsichtig.', required: true },
  }}
/>

Der Typ ist [`CharacterAppearance`](/de/docs/developers/api/types#characterappearance).

#### Rückgabewert

`boolean`: `false`, wenn der Ped verschwunden ist, das Modell abweicht oder kein Kleidungs-Skript läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance, LocalPed, triggerServerCallback } from "@aicore-fivem/lib/client";
import type { CharacterAppearance } from "@aicore-fivem/shared";

// Eine schlafende Kopie eines Charakters, gekleidet wie er.
export async function showSleeper(charId: number): Promise<void> {
  const look = (await triggerServerCallback("mysleep:look", [charId]).catch(() => null)) as CharacterAppearance | null;
  if (!look) return;
  new LocalPed({
    model: look.model,
    coords: { x: 151.2, y: -1004.6, z: 29.4, heading: 90 },
    onSpawn: (ped) => appearance.apply(ped, look),
  });
}
```
</Tab>
<Tab value="Lua">
```lua
local function showSleeper(charId)
    CreateThread(function()
        local look = aiLib.triggerServerCallback('mysleep:look', { charId })
        if type(look) ~= 'table' then return end
        aiLib.LocalPed.new({
            model = look.model,
            coords = vector4(151.2, -1004.6, 29.4, 90.0),
            onSpawn = function(ped) aiLib.appearance.apply(ped, look) end,
        })
    end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
Prüfe, was der Server sendet, bevor du es castest. Ein Ped, der mit einem anderen Modell als `look.model` erstellt wurde, kann das Aussehen nicht übernehmen: `apply` antwortet mit `false`.
</Callout>

</Tab>

## fuel

### fuel.get

Der Spritstand eines Fahrzeugs. Der Server hält für jedes Fahrzeug einen State Bag `fuel`, egal welches Sprit-Skript läuft, daher ist dies ein Speicherzugriff; ohne diesen Bag ist es der Tankstand des Spiels.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
fuel.get(vehicle: number): number
```

Kein Lua-Zwilling: Lies `Entity(vehicle).state.fuel`. Sprit setzen geht nur auf dem Server (`fuel.set` auf [Fahrzeuge](/de/docs/developers/api/lib-server/vehicles)).

#### Parameter

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Ein Fahrzeug, das dieser Client kennt.', required: true },
  }}
/>

#### Rückgabewert

`number`: 0-100.

#### Beispiel

```ts
import { cache, every, fuel } from "@aicore-fivem/lib/client";

every(1000, () => {
  if (cache.vehicle !== false) SendNUIMessage({ action: "fuel", data: Math.round(fuel.get(cache.vehicle)) });
});
```

### inventory.hasItem

Ob der Spieler mindestens `count` Stück eines Items hat. Nutze es in `canShow`, damit der Spieler nur sieht, was er tun kann; der Server prüft erneut.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
inventory.hasItem(item: string, count?: number): boolean
```

```lua title="Lua"
local has = aiLib.inventory.hasItem(item, count)
```

#### Parameter

<TypeTable
  type={{
    item: { type: 'string', description: 'Der Item-Name (lockpick).', required: true },
    count: { type: 'number', description: 'Wie viele gebraucht werden.', default: '1' },
  }}
/>

#### Rückgabewert

`boolean`: `true`, wenn der Spieler genug hat.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, Points } from "@aicore-fivem/lib/client";

const points = new Points();
points.addVehicle("lockpick", {
  label: "Lockpick",
  icon: "unlock",
  canShow: (vehicle) => GetVehicleDoorLockStatus(vehicle) >= 2 && inventory.hasItem("lockpick"),
  onPressed: (vehicle) => emitNet("mykeys:lockpick", NetworkGetNetworkIdFromEntity(vehicle)),
});
```
</Tab>
<Tab value="Lua">
```lua

points:addVehicle('lockpick', {
    label = 'Lockpick',
    icon = 'unlock',
    canShow = function(vehicle)

    end,
    onPressed = function(vehicle) TriggerServerEvent('mykeys:lockpick', NetworkGetNetworkIdFromEntity(vehicle)) end,

```
</Tab>

### inventory.currentWeapon

Das Waffen-Item in der Hand des Spielers: sein Name, Label und Bild.

**Seite:** Client · **Wartet:** nein

```ts title="Signatur"
inventory.currentWeapon(): HeldWeapon | null
```

```lua title="Lua"
local weapon = aiLib.inventory.currentWeapon() -- table oder nil
```

#### Rückgabewert

[`HeldWeapon`](/de/docs/developers/api/types#heldweapon) `{ name: string; label: string; image?: string }` (`name` wie `WEAPON_PISTOL`, `image` eine `nui://`-URL, wenn das Inventar eine hat), oder `null` (`nil`), wenn die Hand leer ist.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, onCache } from "@aicore-fivem/lib/client";

// Lies es, wenn sich die Waffe ändert, nie in jedem Frame.
onCache("weapon", () => SendNUIMessage({ action: "weapon", data: inventory.currentWeapon() }));
```
</Tab>
<Tab value="Lua">
```lua
aiLib.cache.onChange('weapon', function()
    SendNUIMessage({ action = 'weapon', data = aiLib.inventory.currentWeapon() })
end)
```
</Tab>
</Tabs>
