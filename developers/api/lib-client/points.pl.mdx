**Punkt** to każde miejsce, z którego korzysta gracz: lada sklepu, drzwi, NPC, miejsce zwrotu, każdy bankomat, bagażnik każdego auta. Opisujesz go raz (gdzie, jaki tekst, co się dzieje), a lib rysuje go tak, jak wybrał właściciel serwera.

## Prompt albo target

Właściciel wybiera styl interakcji w panelu administratora ai-core (**Interaction** [Interakcja]). W obu przypadkach działa to samo `onPressed`, więc twojego skryptu nie obchodzi, który jest włączony.

| Styl | Co widzi gracz |
| --- | --- |
| **Prompt** | Ramka "naciśnij E" po prawej stronie ekranu, gdy gracz stoi w promieniu punktu. Klawisz to jeden klawisz do przypisania w ai-lib (domyślnie `E`), więc nic nie odpytuje klawiszy co klatkę. |
| **Target** | Opcja w oku targetu na miejscu, NPC, obiekcie albo pojeździe. Wymaga, żeby działał jeden ze skryptów targetu, dla których lib ma adapter. Gdy działa kilka, wygrywa pierwszy w tej kolejności: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

Gdy właściciel wybrał target, ale nie działa żaden skrypt targetu, każdy punkt jest promptem. Punkt może nadpisać wybór właściciela: `promptOnly` zostawia prompt (rzeczy robione z pojazdu: dystrybutory, myjnie), `preferTarget` używa opcji targetu zawsze, gdy działa skrypt targetu (siedzenia). Gdy skrypt targetu startuje albo się zatrzymuje albo właściciel zmienia styl, każdy punkt przechodzi sam.

<Callout type="info">
Naraz działa tylko jedna akcja punktu twojego zasobu. Gdy `onPressed` zwraca promise, pozostałe punkty twojego zasobu ignorują naciśnięcia, aż się zakończy, więc nigdy nie potrzebujesz własnej flagi `busy`. W chwili naciśnięcia gracz musi też przejść `canShow`.
</Callout>

### points.addModel

### points.refresh

Ponownie czyta `canShow` i etykiety-funkcje. Wywołaj ją, gdy zmieniło się coś, co czytają: praca, służba, pojazd, stan wysłany przez serwer. Prompty aktualizują się od razu; opcje targetu czytają `canShow`, gdy oko się otwiera, a zmieniona etykieta jest zakładana ponownie.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
points.refresh(id?: string): void
```

```lua title="Lua"
points:refresh() -- każdy punkt grupy
```

#### Parametry

<TypeTable
  type={{
    id: { type: 'string', description: 'Tylko ten punkt (okradziona kasa spośród setek). Każdy punkt grupy, gdy pominięty. Tylko TypeScript: Lua zawsze odświeża całą grupę.' },
  }}
/>

#### Zwracana wartość

`void`.

#### Przykład

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { EntityState, onCache, onMembershipChange, Points, stateBoolean } from "@aicore-fivem/lib/client";

const robbed = new EntityState("robbed", stateBoolean);

robbed.onChange((netId) => points.refresh(`register:${netId}`));
```

</Callout>

Przestawia każdy punkt grupy na bieżący styl interakcji. Lib wywołuje to sam, gdy właściciel zmieni styl albo skrypt targetu wystartuje lub się zatrzyma; nigdy tego nie potrzebujesz.

**Strona:** Klient · **Czeka:** nie

```ts title="Sygnatura"
points.restyle(): void
```

Brak odpowiednika w Lua (Lua też sam zmienia styl).

#### Zwracana wartość

`void`.

## Punkty z rekordów panelu

Większość punktów pochodzi z pliku rekordów panelu administratora twojego skryptu (sklepy, garaże, punkty wypożyczeń). Odwzoruj plik na kliencie przez [`AdminWorld`](#new-adminworld), potem zbuduj punkty każdego rekordu przez [`RecordObjects`](#new-recordobjects): edytowany rekord przebudowuje tylko własne punkty, usunięty je usuwa.

### new RecordObjects

Utrzymuje obiekty świata z pliku rekordów (punkty, blipy, pedy, strefy) zgodne z plikiem, po jednym rekordzie. `build(key, record)` tworzy obiekty jednego rekordu i zwraca, jak je usunąć. Buduje każdy rekord w konstruktorze.

**Strona:** Klient i serwer (z `@aicore-fivem/lib/shared`) · **Czeka:** nie

```ts title="Sygnatura"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

#### Przykład

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aicore-fivem/lib/client";
import { readVec3, RecordObjects, str } from "@aicore-fivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// Zmieniło się ustawienie, które czyta każdy sklep: przebuduj je wszystkie.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` buduje w konstruktorze. Utwórz go po wszystkim, co czyta `build`, a wewnątrz `build` używaj argumentu `record`: pole klasy, które trzyma `RecordObjects`, podczas tego pierwszego budowania nie jest jeszcze przypisane.
</Callout>

### new AdminWorld

Kliencka kopia światowych plików panelu twojego skryptu (plików, których schemat mówi `sync: "all"`, zobacz [Panel administratora](/pl/docs/developers/api/lib-server/admin-panel)). Czyta kopię zapisaną przez FiveM w pamięci podręcznej przy starcie, raz pyta serwer o rekordy zmienione od tego czasu, potem śledzi zmiany na żywo. Nigdy nie odpytuje.

**Strona:** Klient · **Czeka:** nie (promise `ready` mówi, kiedy przyszły zmiany od startu)
