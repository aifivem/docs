Ein **Punkt** ist jeder Ort, den ein Spieler nutzt: eine Ladentheke, eine Tür, ein NPC, ein Rückgabeplatz, jeder Geldautomat, der Kofferraum jedes Autos. Du beschreibst ihn einmal (wo, welcher Text, was passiert), und die Lib zeichnet ihn so, wie der Serverbetreiber es gewählt hat.

## Prompt oder Target

Der Betreiber wählt den Interaktionsstil im Admin-Panel von ai-core (**Interaction**). Dasselbe `onPressed` läuft in beiden Fällen, daher ist es deinem Skript egal, welcher aktiv ist.

| Stil | Was der Spieler sieht |
| --- | --- |
| **Prompt** | Ein „Drücke E“-Feld rechts auf dem Bildschirm, solange der Spieler im Radius des Punkts steht. Die Taste ist ein einziges neu belegbares Keybind in ai-lib (Standard `E`), daher fragt nichts in jedem Frame Tasten ab. |
| **Target** | Eine Option im Target-Auge auf der Stelle, dem NPC, dem Objekt oder dem Fahrzeug. Dafür muss eines der Target-Skripte laufen, für die die Lib einen Adapter hat. Wenn mehrere laufen, gewinnt das erste in dieser Reihenfolge: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

Wenn der Betreiber Target gewählt hat, aber kein Target-Skript läuft, ist jeder Punkt ein Prompt. Ein Punkt kann die Wahl des Betreibers überschreiben: `promptOnly` behält einen Prompt (Dinge, die aus einem Fahrzeug heraus getan werden: Zapfsäulen, Waschanlagen), `preferTarget` nutzt eine Target-Option, sobald ein Target-Skript läuft (Sitze). Wenn ein Target-Skript startet oder stoppt oder der Betreiber den Stil wechselt, zieht jeder Punkt von selbst um.

<Callout type="info">
Es läuft immer nur eine Punktaktion deiner Ressource zur Zeit. Wenn `onPressed` ein Promise zurückgibt, ignorieren die anderen Punkte deiner Ressource Tastendrücke, bis es abgeschlossen ist, daher brauchst du nie ein eigenes `busy`-Flag. Der Spieler muss außerdem im Moment des Drückens `canShow` bestehen.
</Callout>

### points.refresh

Liest `canShow` und Label-Funktionen erneut. Rufe es auf, wenn sich etwas geändert hat, das sie lesen: der Job, der Dienst, ein Fahrzeug, ein Zustand, den der Server gesendet hat. Prompts aktualisieren sich sofort; Target-Optionen lesen `canShow`, wenn das Auge öffnet, und ein geändertes Label wird neu gesetzt.

**Seite:** Client · **Wartet:** nein

## Punkte aus Panel-Einträgen

Die meisten Punkte kommen aus einer Records-Datei des Admin-Panels deines Skripts (Shops, Garagen, Mietschalter). Spiegle die Datei auf dem Client mit [`AdminWorld`](#new-adminworld) und baue dann die Punkte jedes Eintrags mit [`RecordObjects`](#new-recordobjects): Ein bearbeiteter Eintrag baut nur seine eigenen Punkte neu auf, ein gelöschter entfernt sie.

### new RecordObjects

Hält die Weltobjekte einer Records-Datei (Punkte, Blips, Peds, Zonen) Eintrag für Eintrag im Gleichschritt mit der Datei. `build(key, record)` erstellt die Objekte eines Eintrags und gibt zurück, wie sie entfernt werden. Es baut jeden Eintrag in seinem Konstruktor.

**Seite:** Client und Server (aus `@aifivem/lib/shared`) · **Wartet:** nein

```ts title="Signatur"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

Kein Lua-Zwilling.

#### Beispiel

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aifivem/lib/client";
import { readVec3, RecordObjects, str } from "@aifivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// Eine Einstellung, die jeder Shop liest, hat sich geändert: alle neu bauen.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` baut in seinem Konstruktor. Erstelle es nach allem, was `build` liest, und nutze in `build` das Argument `record`: Ein Klassenfeld, das das `RecordObjects` hält, ist während dieses ersten Aufbaus noch nicht zugewiesen.
</Callout>

### new AdminWorld

Die Client-Kopie der Welt-Panel-Dateien deines Skripts (die Dateien, deren Schema `sync: "all"` sagt, siehe [Admin-Panel](/de/docs/developers/api/lib-server/admin-panel)). Sie liest die Kopie, die FiveM beim Start gecacht hat, fragt den Server einmal nach den seitdem geänderten Einträgen und folgt dann Live-Änderungen. Sie fragt nie zyklisch ab.

**Seite:** Client · **Wartet:** nein (das `ready`-Promise sagt, wann die Änderungen seit dem Start angekommen sind)

```ts title="Signatur"
new AdminWorld(files: string[])
```

Kein Lua-Zwilling.

#### Beispiel

```ts
import { AdminWorld } from "@aifivem/lib/client";
import { num, record } from "@aifivem/lib/shared";

const world = new AdminWorld(["settings"]);
const settings = world.view("settings", (raw) => ({
  radius: num(record(raw).radius, 2),
}));

world.onChange("settings", () => console.log("new radius", settings.value.radius));
```
