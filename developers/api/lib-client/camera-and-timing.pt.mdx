Uma câmera de script para vitrines e cenas, um job por frame que você liga só enquanto é necessário, a metade do cliente do streaming por área do servidor, e o relógio do servidor para contagens regressivas. Trabalho periódico em geral é `every(ms, fn)` (veja [Lib: compartilhada e fivem](/pt/docs/developers/api/lib-shared)); nunca `setInterval` nem um `setTick` puro.

## ScriptCamera

### new ScriptCamera

Uma câmera de script: a vista de vitrine de uma loja, um editor, uma cena, binóculos. `start` a cria e mostra, os outros métodos a movem e alteram, `stop` volta suavemente para a câmera do jogo e a destrói. Uma câmera ainda rodando quando o seu recurso para é devolvida na hora, então o jogador nunca fica preso nela.

**Lado:** Cliente · **Espera:** não

```ts title="Signature"
new ScriptCamera(type?: string)
```

Sem equivalente em Lua: recursos Lua usam `CreateCam`, `RenderScriptCams` e `DestroyCam`.

#### Exemplo

```ts
import { ScriptCamera } from "@aicore-fivem/lib/client";

const camera = new ScriptCamera();
const CAR = { x: -44.4, y: -1097.1, z: 26.4 };

export function openShowroom(): void {
  camera.start({ x: -40.2, y: -1100.5, z: 27.6 }, { pointAt: CAR, fov: 50 }, 800);
}

export function frontView(): void {
  camera.glideTo({ x: -47.5, y: -1093.8, z: 27.2 }, { pointAt: CAR, fov: 45 }, 1200);
}

export function closeShowroom(): void {
  camera.stop(800);
}
```

### camera.move

#### Parâmetros

<TypeTable

### camera.glideTo

Faz a transição para um novo plano: uma segunda câmera no novo lugar assume a partir desta, e a antiga é destruída depois da transição. Tremor e desfoque são levados junto. Inicia a câmera quando está parada (ou quando `ms` é 0).

**Lado:** Cliente · **Espera:** não

```ts title="Signature"
camera.glideTo(at: Vec3, view: CameraView, ms: number): void
```

#### Parâmetros

<TypeTable

    view: { type: 'CameraView', description: 'O novo olhar.', required: true },
    ms: { type: 'number', description: 'Duração da transição em milissegundos.', required: true },

## TickLoop

### new TickLoop

Um job por frame (`every(0, fn)` no único agendador do seu recurso) que fica desligado até você ligá-lo. Use para qualquer coisa que precisa rodar a cada frame só às vezes: desenhar um marcador enquanto está perto, uma prévia de posicionamento, desativar o tiro enquanto mira em um amigo.

**Lado:** Cliente · **Espera:** não

```ts title="Signature"
new TickLoop(onFrame: () => void, name?: string)
```

Sem equivalente em Lua: `aiLib.every(0, fn, { active = false, name = name })` e `job:set(active)`.

#### Parâmetros

<TypeTable
  type={{
    onFrame: { type: '() => void', description: 'Roda a cada frame enquanto o loop está ligado. Um erro lançado é registrado em log (no máximo uma vez a cada 10 s) e o loop continua rodando.', required: true },
    name: { type: 'string', description: 'Um nome mostrado nos logs de erro.' },
  }}
/>

#### Membros

<TypeTable
  type={{
    running: { type: 'boolean', description: 'Propriedade somente leitura: se o loop está ligado.' },
    'set(active)': { type: '(active: boolean) => void', description: 'Liga (true) ou desliga (false) o loop.' },
  }}
/>

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { TickLoop, Zones } from "@aicore-fivem/lib/client";

const SPOT = { x: 215.8, y: -810.1, z: 30.7 };
const light = new TickLoop(() => {
  DrawLightWithRange(SPOT.x, SPOT.y, SPOT.z + 2, 61, 247, 158, 8, 4);
}, "garageLight");

const zones = new Zones();
zones.add("garage", {
  shape: { type: "sphere", center: SPOT, radius: 25 },
  onEnter: () => light.set(true),
  onExit: () => light.set(false),
});
```
</Tab>
<Tab value="Lua">
```lua
local SPOT = vector3(215.8, -810.1, 30.7)
local light = aiLib.every(0, function()
    DrawLightWithRange(SPOT.x, SPOT.y, SPOT.z + 2.0, 61, 247, 158, 8.0, 4.0)
end, { active = false, name = 'garageLight' })

local zones = aiLib.Zones.new()
zones:add('garage', {
    shape = { type = 'sphere', center = SPOT, radius = 25.0 },
    onEnter = function() light:set(true) end,
    onExit = function() light:set(false) end,
})
```
</Tab>
</Tabs>

<Callout type="info">
Todo job do seu recurso roda a partir de um único `setTick` que só existe enquanto algum job está ligado. Crie o loop uma vez no topo do arquivo e ligue-o e desligue-o, em vez de criar um novo a cada início.
</Callout>

## AreaFollower

### new AreaFollower

A metade do cliente de um `AreaStream` do servidor ([Streaming por área](/pt/docs/developers/api/lib-server/area-stream)): ele informa ao servidor em qual célula da grade o jogador está sempre que ela muda (verificado a cada 2 segundos enquanto iniciado), para que o servidor envie só os objetos do mundo (drops, plantas, props colocados) ao redor do jogador. Crie um no topo do arquivo.

**Lado:** Cliente · **Espera:** não

```ts title="Signature"
new AreaFollower(event: string, cellSize?: number)
```

Sem equivalente em Lua.

#### Parâmetros

<TypeTable
  type={{
    event: { type: 'string', description: 'O net event que o servidor escuta; ele recebe (cx, cy), as coordenadas da célula.', required: true },
    cellSize: { type: 'number', description: 'Tamanho da célula em metros. Precisa ser igual ao cellSize do stream do servidor.', default: '64' },
  }}
/>

#### Membros

<TypeTable
  type={{
    'start()': { type: '() => void', description: 'Envia a célula atual agora e a cada mudança.' },
    'stop()': { type: '() => void', description: 'Para de informar.' },
  }}
/>

#### Exemplo

```ts title="resource/client/index.ts"
import { AreaFollower, onServerEvent } from "@aicore-fivem/lib/client";

const follower = new AreaFollower("myplants:cell");
follower.start();

const plants = new Map<number, unknown>();

// O stream envia (reset, puts, removes): um snapshot com reset true, depois só mudanças.
onServerEvent(
  "myplants:area",
  {
    args: ([reset, puts, removes]) =>
      typeof reset === "boolean" && Array.isArray(puts) && Array.isArray(removes)
        ? ([reset, puts, removes] as const)
        : null,
  },
  (reset, puts, removes) => {
    if (reset) plants.clear();
    for (const plant of puts as Array<{ id?: unknown } | null>)
      if (typeof plant?.id === "number") plants.set(plant.id, plant);
    for (const id of removes) if (typeof id === "number") plants.delete(id);
  },
);
```

<Callout type="warn">
O servidor verifica uma célula informada contra a posição real do jogador (`followReported` só aceita células a até uma célula do ped), então um trapaceiro não consegue pedir uma área distante.
</Callout>

## ServerClock

### new ServerClock

O relógio do servidor em um cliente. Os relógios do cliente e do servidor podem diferir, então uma contagem regressiva até um horário do servidor (o cooldown de um roubo, o fim de um leilão) precisa ser convertida para o horário local primeiro. Chame `sync` com o `Date.now()` do servidor sempre que chegar um snapshot ou uma mensagem de início.

**Lado:** Cliente (de `@aicore-fivem/lib/shared`) · **Espera:** não

```ts title="Signature"
new ServerClock()
```

Sem equivalente em Lua.

#### Membros

<TypeTable
  type={{
    'sync(serverNow)': { type: '(serverNow: number) => void', description: 'Pega o deslocamento a partir do Date.now() do servidor que acabou de chegar.' },
    'now()': { type: '() => number', description: 'O Date.now() do servidor agora mesmo.' },
    'toLocal(serverTime)': { type: '(serverTime: number) => number', description: 'Um horário do servidor como um horário Date.now() local, para contagens regressivas no relógio local.' },
  }}
/>

#### Exemplo

```ts title="resource/client/index.ts"
import { every, onServerEvent } from "@aicore-fivem/lib/client";
import { ServerClock } from "@aicore-fivem/lib/shared";

const clock = new ServerClock();
let endsAt = 0; // horário local

onServerEvent(
  "myauction:state",
  { args: ([now, ends]) => (typeof now === "number" && typeof ends === "number" ? [now, ends] : null) },
  (now, ends) => {
    clock.sync(now);
    endsAt = clock.toLocal(ends);
  },
);

every(1000, () => {
  const left = Math.max(0, Math.round((endsAt - Date.now()) / 1000));
  SendNUIMessage({ action: "countdown", data: left });
});
```

<Callout type="info">
O servidor envia o horário de fim uma vez; o cliente faz a contagem regressiva no próprio relógio. Nunca envie o tempo restante a cada segundo.
</Callout>
