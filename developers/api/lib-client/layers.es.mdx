Estos objetos nunca hablan con un script concreto. Preguntan a **ai-core**, y ai-core reenvía al script que use el servidor para esa tarea: ai-death u otro script de muerte, ai-appearance o tgiann-clothing, cualquier script de emotes o de menú radial compatible. Tu script sigue funcionando cuando el dueño cambia uno. Cómo funcionan las capas está en [Capas y el puente](/es/docs/developers/layers).

Cuando no hay ningún script de ese tipo en marcha, las llamadas responden `false`, `null` o el propio valor del juego, como indica cada entrada.

## medical

### medical.isDead

Si el jugador local está derribado (muerto o en last stand), en el script de muerte que funcione. Los scripts de muerte mantienen vivo un ped derribado para animarlo, así que `IsEntityDead` por sí solo no los detecta. Una lectura en memoria después de la primera llamada.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
medical.isDead(): boolean
```

Sin equivalente en Lua: llama a `exports['ai-core']:IsDead()` y escucha el evento local `ai-core:client:dead` (`dead`).

#### Devuelve

`boolean`: `true` cuando la capa médica de ai-core dice que el jugador está derribado, o el ped está muerto para el juego.

#### Ejemplo

```ts
import { medical, notify } from "@aifivem/lib/client";

RegisterCommand(
  "phone",
  () => {
    if (medical.isDead()) return notify("You cannot use the phone now", "error");
    SetNuiFocus(true, true);
  },
  false,
);
```

### medical.onChange

Ejecuta un handler cuando el jugador local cae derribado o se levanta.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
medical.onChange(fn: (dead: boolean) => void): void
```

Sin equivalente en Lua: `AddEventHandler('ai-core:client:dead', function(dead) end)`.

#### Parámetros

<TypeTable
  type={{
    fn: { type: '(dead: boolean) => void', description: 'Recibe true cuando el jugador cayó derribado, false cuando se levantó.', required: true },
  }}
/>

#### Devuelve

`void`.

#### Ejemplo

```ts
import { medical, Points } from "@aifivem/lib/client";

const points = new Points();
medical.onChange(() => points.refresh()); // puntos cuyo canShow lee medical.isDead()
```

## appearance

El aspecto de los peds a través de la capa de apariencia de ai-core, sea cual sea el script de ropa que funcione.

### appearance.apply

Pone un aspecto guardado en un ped del modelo de ese aspecto. Obtén el aspecto en el servidor con `appearance.get(charId)`, crea el ped con `look.model` y luego aplícalo. En el propio ped del jugador cambia su ropa.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
appearance.apply(ped: number, look: CharacterAppearance): boolean
```

```lua title="Lua"
local ok = aiLib.appearance.apply(ped, look)
```

#### Parámetros

<TypeTable
  type={{
    ped: { type: 'number', description: 'El ped que se viste. Su modelo debe ser look.model.', required: true },
    look: { type: 'CharacterAppearance', description: '{ model: number; data: unknown }: el hash del modelo y los datos propios del script de ropa. Trata data como opaco.', required: true },
  }}
/>

El tipo es [`CharacterAppearance`](/es/docs/developers/api/types#characterappearance).

#### Devuelve

`boolean`: `false` cuando el ped ya no existe, el modelo es distinto o no hay script de ropa en marcha.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance, LocalPed, triggerServerCallback } from "@aifivem/lib/client";
import type { CharacterAppearance } from "@aifivem/shared";

// Una copia dormida de un personaje, vestida como él.
export async function showSleeper(charId: number): Promise<void> {
  const look = (await triggerServerCallback("mysleep:look", [charId]).catch(() => null)) as CharacterAppearance | null;
  if (!look) return;
  new LocalPed({
    model: look.model,
    coords: { x: 151.2, y: -1004.6, z: 29.4, heading: 90 },
    onSpawn: (ped) => appearance.apply(ped, look),
  });
}
```
</Tab>
<Tab value="Lua">
```lua
local function showSleeper(charId)
    CreateThread(function()
        local look = aiLib.triggerServerCallback('mysleep:look', { charId })
        if type(look) ~= 'table' then return end
        aiLib.LocalPed.new({
            model = look.model,
            coords = vector4(151.2, -1004.6, 29.4, 90.0),
            onSpawn = function(ped) aiLib.appearance.apply(ped, look) end,
        })
    end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
Comprueba lo que envía el servidor antes de convertirlo. Un ped creado con un modelo distinto de `look.model` no puede recibir el aspecto: `apply` responde `false`.
</Callout>

## fuel

### fuel.get

El nivel de combustible de un vehículo. El servidor mantiene un state bag `fuel` para cada vehículo sea cual sea el script de combustible que funcione, así que es una lectura en memoria; sin ese state bag es el nivel del depósito del juego.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
fuel.get(vehicle: number): number
```

Sin equivalente en Lua: lee `Entity(vehicle).state.fuel`. Fijar el combustible es solo de servidor (`fuel.set` en [Vehículos](/es/docs/developers/api/lib-server/vehicles)).

#### Parámetros

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Un vehículo que este cliente conoce.', required: true },
  }}
/>

#### Devuelve

`number`: 0-100.

#### Ejemplo

```ts
import { cache, every, fuel } from "@aifivem/lib/client";

every(1000, () => {
  if (cache.vehicle !== false) SendNUIMessage({ action: "fuel", data: Math.round(fuel.get(cache.vehicle)) });
});
```

### inventory.hasItem

Si el jugador tiene al menos `count` unidades de un objeto. Úsalo en `canShow` para que el jugador solo vea lo que puede hacer; el servidor lo comprueba de nuevo.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
inventory.hasItem(item: string, count?: number): boolean
```

```lua title="Lua"
local has = aiLib.inventory.hasItem(item, count)
```

#### Parámetros

<TypeTable
  type={{
    item: { type: 'string', description: 'El nombre del objeto (lockpick).', required: true },
    count: { type: 'number', description: 'Cuántos se necesitan.', default: '1' },
  }}
/>

#### Devuelve

`boolean`: `true` cuando el jugador tiene suficientes.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, Points } from "@aifivem/lib/client";

const points = new Points();
points.addVehicle("lockpick", {
  label: "Lockpick",
  icon: "unlock",
  canShow: (vehicle) => GetVehicleDoorLockStatus(vehicle) >= 2 && inventory.hasItem("lockpick"),
  onPressed: (vehicle) => emitNet("mykeys:lockpick", NetworkGetNetworkIdFromEntity(vehicle)),
});
```
</Tab>

### inventory.currentWeapon

El objeto de arma en la mano del jugador: su nombre, su etiqueta y su imagen.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
inventory.currentWeapon(): HeldWeapon | null
```

```lua title="Lua"
local weapon = aiLib.inventory.currentWeapon() -- table o nil
```

#### Devuelve

[`HeldWeapon`](/es/docs/developers/api/types#heldweapon) `{ name: string; label: string; image?: string }` (`name` como `WEAPON_PISTOL`, `image` una URL `nui://` cuando el inventario tiene una), o `null` (`nil`) cuando la mano está vacía.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, onCache } from "@aifivem/lib/client";

// Léelo cuando cambie el arma, nunca en cada frame.
onCache("weapon", () => SendNUIMessage({ action: "weapon", data: inventory.currentWeapon() }));
```
</Tab>
<Tab value="Lua">
```lua
aiLib.cache.onChange('weapon', function()
    SendNUIMessage({ action = 'weapon', data = aiLib.inventory.currentWeapon() })
end)
```

</Tab>
