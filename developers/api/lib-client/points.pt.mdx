Um **ponto** é qualquer lugar que um jogador usa: o balcão de uma loja, uma porta, um NPC, um local de devolução, todo caixa eletrônico, o porta-malas de todo carro. Você o descreve uma vez (onde, qual texto, o que acontece) e a lib o desenha do jeito que o dono do servidor escolheu.

## Prompt ou target

O dono escolhe o estilo de interação no painel de administração do ai-core (**Interaction**). O mesmo `onPressed` roda de qualquer forma, então o seu script nunca se importa com qual está ativo.

| Estilo | O que o jogador vê |
| --- | --- |
| **Prompt** | Uma caixa "aperte E" no lado direito da tela enquanto o jogador está dentro do raio do ponto. A tecla é um único keybind reconfigurável no ai-lib (padrão `E`), então nada verifica teclas a cada frame. |
| **Target** | Uma opção no olho de target no local, no NPC, no objeto ou no veículo. Precisa que esteja rodando um dos scripts de target para os quais a lib tem adaptador. Quando vários rodam, vence o primeiro nesta ordem: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

Quando o dono escolheu target mas nenhum script de target está rodando, todo ponto é um prompt. Um ponto pode sobrepor a escolha do dono: `promptOnly` mantém um prompt (coisas feitas de dentro de um veículo: bombas de combustível, lava-rápidos), `preferTarget` usa uma opção de target sempre que um script de target roda (assentos). Quando um script de target inicia ou para, ou o dono troca o estilo, todo ponto muda sozinho.

<Callout type="info">
Só uma ação de ponto do seu recurso roda por vez. Quando `onPressed` retorna uma promise, os outros pontos do seu recurso ignoram os apertos até ela terminar, então você nunca precisa da sua própria flag `busy`. O jogador também precisa passar em `canShow` no momento do aperto.
</Callout>

// Um baú que só a polícia pode abrir; o texto acompanha um estado.
let locked = true;
points.add("evidence", {

    if (reply) locked = !locked;
    points.refresh("evidence");

});

// canShow lê o emprego: verifique de novo quando empregos, serviço ou gangues mudarem.
onMembershipChange(() => points.refresh());

### points.refresh

Lê de novo `canShow` e os rótulos que são funções. Chame quando algo que eles leem mudou: o emprego, o serviço, um veículo, um estado que o servidor enviou. Os prompts se atualizam na hora; as opções de target leem `canShow` quando o olho abre, e um rótulo alterado é colocado de novo.

**Lado:** Cliente · **Espera:** não

```ts title="Signature"
points.refresh(id?: string): void
```

```lua title="Lua"
points:refresh() -- todos os pontos do grupo
```

#### Parâmetros

<TypeTable
  type={{
    id: { type: 'string', description: 'Só este ponto (um caixa roubado entre centenas). Todos os pontos do grupo quando omitido. Só TypeScript: Lua sempre atualiza o grupo inteiro.' },
  }}
/>

#### Retorno

`void`.

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts

const robbed = new EntityState("robbed", stateBoolean);

```

## Pontos a partir de registros do painel

A maioria dos pontos vem de um arquivo de records do painel de administração do seu script (lojas, garagens, balcões de aluguel). Espelhe o arquivo no cliente com [`AdminWorld`](#new-adminworld), depois construa os pontos de cada registro com [`RecordObjects`](#new-recordobjects): um registro editado reconstrói só os próprios pontos, um apagado os remove.

### new RecordObjects

Mantém os objetos do mundo de um arquivo de records (pontos, blips, peds, zonas) em sincronia com o arquivo, um registro por vez. `build(key, record)` cria os objetos de um registro e retorna como removê-los. Ele constrói todos os registros no construtor.

**Lado:** Cliente e servidor (de `@aifivem/lib/shared`) · **Espera:** não

```ts title="Signature"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

Sem equivalente em Lua.

#### Parâmetros

<TypeTable
  type={{
    source: { type: 'RecordSource', description: 'Onde o arquivo fica: um AdminWorld no cliente (um AdminPanel no servidor).', required: true },
    file: { type: 'string', description: 'O nome do arquivo de records, sem data/ e .json (locations).', required: true },
    records: { type: 'RecordReader<T> | ReadonlyMap<string, T>', description: 'Um leitor (key, raw) => T | null que interpreta um registro (null o deixa de fora), ou uma visão de records que você já mantém do mesmo arquivo (world.records(file, readOne)), para que cada edição seja interpretada uma vez.', required: true },
    build: { type: '(key: string, record: T) => (() => void) | void', description: 'Cria os objetos de um registro e retorna uma função que os remove.', required: true },
  }}
/>

#### Membros

<TypeTable
  type={{
    records: { type: 'ReadonlyMap<string, T>', description: 'Os registros interpretados por chave, sempre atuais. Procure um registro em onPressed em vez de capturá-lo.' },
    'rebuild(key)': { type: '(key: string) => void', description: 'Remove e constrói de novo um registro (ele some quando o registro some). Chamado sozinho em uma edição.' },
    'rebuildAll()': { type: '() => void', description: 'Remove e constrói de novo todos os registros. Chame quando uma configuração que todo registro lê muda (um estilo de blip, um raio).' },

#### Exemplo

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aifivem/lib/client";
import { readVec3, RecordObjects, str } from "@aifivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// Uma configuração que toda loja lê mudou: reconstrua todas.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` constrói no construtor. Crie-o depois de tudo o que `build` lê, e dentro de `build` use o argumento `record`: um campo de classe que guarda o `RecordObjects` ainda não foi atribuído durante essa primeira construção.
</Callout>

### new AdminWorld

A cópia no cliente dos arquivos de mundo do painel do seu script (os arquivos cujo schema diz `sync: "all"`, veja [Painel de administração](/pt/docs/developers/api/lib-server/admin-panel)). Ela lê a cópia que o FiveM guardou em cache na inicialização, pergunta ao servidor uma vez pelos registros alterados desde então, e depois acompanha as mudanças ao vivo. Nunca fica consultando.

**Lado:** Cliente · **Espera:** não (a promise `ready` avisa quando as mudanças desde a inicialização chegaram)

```ts title="Signature"
new AdminWorld(files: string[])
```

Sem equivalente em Lua.
