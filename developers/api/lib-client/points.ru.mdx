**Точка** это любое место, которым пользуется игрок: прилавок магазина, дверь, NPC, место возврата, каждый банкомат, багажник каждой машины. Вы описываете её один раз (где, какой текст, что происходит), а lib рисует её так, как выбрал владелец сервера.

## Prompt или target

Владелец выбирает стиль взаимодействия в админ-панели ai-core (**Interaction**). В обоих случаях выполняется один и тот же `onPressed`, поэтому вашему скрипту неважно, какой стиль включён.

| Стиль | Что видит игрок |
| --- | --- |
| **Prompt** | Окно «нажмите E» справа на экране, пока игрок стоит внутри радиуса точки. Клавиша это одна переназначаемая клавиша в ai-lib (по умолчанию `E`), поэтому ничто не опрашивает клавиши каждый кадр. |
| **Target** | Опция в глазе target на месте, NPC, объекте или транспорте. Для этого должен быть запущен один из target-скриптов, для которых в lib есть адаптер. Если запущено несколько, побеждает первый в таком порядке: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

Если владелец выбрал target, но ни один target-скрипт не запущен, каждая точка становится подсказкой (prompt). Точка может переопределить выбор владельца: `promptOnly` оставляет подсказку (действия из транспорта: топливные колонки, автомойки), `preferTarget` использует опцию target всегда, когда запущен target-скрипт (сиденья). Когда target-скрипт запускается или останавливается или владелец переключает стиль, каждая точка переходит сама.

<Callout type="info">
Одновременно выполняется только одно действие точки вашего ресурса. Когда `onPressed` возвращает promise, остальные точки вашего ресурса игнорируют нажатия, пока он не завершится, поэтому собственный флаг `busy` вам никогда не нужен. Кроме того, в момент нажатия игрок должен проходить `canShow`.
</Callout>

### new Points

Создаёт группу точек. Создайте одну группу на функцию в начале файла и добавляйте в неё точки.

```ts title="Сигнатура"

```

```lua title="Lua"

import { callAction, createLocale, hasJob, onMembershipChange, Points } from "@aicore-fivem/lib/client";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const points = new Points();

// Прилавок магазина с продавцом и блипом на карте.
points.add("shop", {
  coords: { x: 25.7, y: -1347.3, z: 29.5 },
  label: Locale("OPEN_SHOP"),
  icon: "basket-shopping",
  ped: { model: "mp_m_shopkeep_01", coords: { x: 24.5, y: -1346.6, z: 29.5, heading: 270 } },
  blip: { sprite: 52, color: 2, label: Locale("SHOP") },
  onPressed: () => callAction("myshop:open", [], { fallback: "SHOP_FAILED" }),
});

// Хранилище, которое может открыть только полиция; текст следует состоянию.
let locked = true;
points.add("evidence", {
  coords: { x: 474.9, y: -996.4, z: 26.3 },
  label: () => (locked ? Locale("UNLOCK") : Locale("LOCK")),
  icon: "box-archive",
  canShow: () => hasJob(["police"], 2),
  onPressed: async () => {
    const reply = await callAction("myscript:toggle", [], { fallback: "TOGGLE_FAILED" });
    if (reply) locked = !locked;
    points.refresh("evidence");
  },
});

// canShow читает работу: проверяем снова, когда меняются работы, дежурство или банды.
onMembershipChange(() => points.refresh());
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
local t = aiLib.locale()
local points = aiLib.Points.new()

points:add('shop', {
    coords = vector3(25.7, -1347.3, 29.5),
    label = t('OPEN_SHOP'),
    icon = 'basket-shopping',
    ped = { model = 'mp_m_shopkeep_01', coords = vector4(24.5, -1346.6, 29.5, 270.0) },
    blip = { sprite = 52, color = 2, label = t('SHOP') },
    onPressed = function()
        CreateThread(function()
            aiLib.callAction('myshop:open', {}, { fallback = 'SHOP_FAILED' })
        end)
    end,
})

local function isPolice()
    for _, m in ipairs(aiLib.playerData.get('jobs') or {}) do
        if m.job == 'police' and m.grade >= 2 then return true end
    end
    return false
end

points:add('evidence', {
    coords = vector3(474.9, -996.4, 26.3),
    label = t('OPEN_EVIDENCE'),
    icon = 'box-archive',
    canShow = isPolice,
    onPressed = function() TriggerServerEvent('myscript:openEvidence') end,
})

aiLib.playerData.onChange('jobs', function() points:refresh() end)
```

<Callout type="warn">
`canShow` решает только то, что видит игрок. Сервер должен снова проверить (работу, расстояние, запасы) в своём обработчике. Читер может вызвать ваше серверное событие без всякой точки.
</Callout>

### points.addModel

Добавляет точку на каждый объект мира с определёнными моделями (банкоматы, торговые автоматы, мусорные контейнеры, стулья) или заменяет точку с тем же id. В режиме target это опция target на этих моделях; в режиме prompt подсказка показывается рядом с ближайшим объектом. Поиск ближайшего объекта выполняется один раз в ai-lib для всех ресурсов, два раза в секунду, и приостанавливается, пока игрок стоит на месте.

**Сторона:** Клиент · **Ждёт:** нет

```ts title="Сигнатура"
points.addModel(id: string, options: ModelPointOptions): void
```

```lua title="Lua"
points:addModel(id, options)
```

### points.refresh

Заново читает `canShow` и функции подписей. Вызывайте, когда изменилось то, что они читают: работа, дежурство, транспорт, состояние, которое прислал сервер. Подсказки обновляются сразу; опции target читают `canShow` при открытии глаза, а изменённая подпись ставится заново.

**Сторона:** Клиент · **Ждёт:** нет

```ts title="Сигнатура"
points.refresh(id?: string): void
```

```lua title="Lua"
points:refresh() -- каждая точка группы
```

#### Параметры

### points.restyle

Переводит все точки группы на текущий стиль взаимодействия. Lib вызывает это сама, когда владелец переключает стиль или target-скрипт запускается или останавливается; вам это никогда не нужно.

**Сторона:** Клиент · **Ждёт:** нет

```ts title="Сигнатура"
points.restyle(): void
```

Lua-аналога нет (Lua тоже меняет стиль сам).

#### Возвращает

`void`.

## Точки из записей панели

Большинство точек берутся из файла записей админ-панели вашего скрипта (магазины, гаражи, стойки аренды). Зеркалируйте файл на клиенте через [`AdminWorld`](#new-adminworld), затем стройте точки каждой записи через [`RecordObjects`](#new-recordobjects): изменённая запись перестраивает только свои точки, удалённая их убирает.

### new RecordObjects

Поддерживает объекты мира из файла записей (точки, блипы, педы, зоны) в соответствии с файлом, по одной записи за раз. `build(key, record)` создаёт объекты одной записи и возвращает способ их удалить. Он строит все записи в своём конструкторе.

**Сторона:** Клиент и сервер (из `@aicore-fivem/lib/shared`) · **Ждёт:** нет

```ts title="Сигнатура"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

Lua-аналога нет.

#### Параметры

<TypeTable
  type={{
    source: { type: 'RecordSource', description: 'Где находится файл: AdminWorld на клиенте (AdminPanel на сервере).', required: true },
    file: { type: 'string', description: 'Имя файла записей без data/ и .json (locations).', required: true },
    records: { type: 'RecordReader<T> | ReadonlyMap<string, T>', description: 'Функция чтения (key, raw) => T | null, которая разбирает одну запись (null её пропускает), или представление записей того же файла, которое вы уже держите (world.records(file, readOne)), чтобы каждая правка разбиралась один раз.', required: true },
    build: { type: '(key: string, record: T) => (() => void) | void', description: 'Создаёт объекты одной записи и возвращает функцию, которая их удаляет.', required: true },
  }}
/>

#### Члены

<TypeTable
  type={{
    records: { type: 'ReadonlyMap<string, T>', description: 'Разобранные записи по ключу, всегда актуальные. Ищите запись в onPressed, а не захватывайте её.' },
    'rebuild(key)': { type: '(key: string) => void', description: 'Удаляет и заново строит одну запись (она исчезает, если исчезла запись). Вызывается сам при правке.' },
    'rebuildAll()': { type: '() => void', description: 'Удаляет и заново строит все записи. Вызывайте, когда меняется настройка, которую читает каждая запись (стиль блипа, радиус).' },
  }}
/>

#### Пример

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aicore-fivem/lib/client";
import { readVec3, RecordObjects, str } from "@aicore-fivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// Изменилась настройка, которую читает каждый магазин: перестраиваем все.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` строит в своём конструкторе. Создавайте его после всего, что читает `build`, а внутри `build` используйте аргумент `record`: поле класса, которое хранит `RecordObjects`, во время этой первой постройки ещё не присвоено.
</Callout>

### new AdminWorld

Клиентская копия мировых файлов панели вашего скрипта (файлов, в схеме которых указано `sync: "all"`, см. [Админ-панель](/ru/docs/developers/api/lib-server/admin-panel)). Она читает копию, которую FiveM закэшировал при старте, один раз спрашивает сервер о записях, изменённых с тех пор, а затем следует живым изменениям. Никогда не опрашивает.

**Сторона:** Клиент · **Ждёт:** нет (promise `ready` сообщает, когда пришли изменения с момента старта)

```ts title="Сигнатура"
new AdminWorld(files: string[])
```

Lua-аналога нет.

#### Параметры

<TypeTable
  type={{
    files: { type: 'string[]', description: 'Имена мировых файлов, которые зеркалирует этот клиент, без data/ и .json. Каждый должен быть указан в files вашего fxmanifest.', required: true },
  }}
/>

#### Члены

<TypeTable
  type={{
    ready: { type: 'Promise<void>', description: 'Выполняется, как только применены изменения с момента старта (или их не удалось загрузить). С этого момента данные актуальны.' },
    'get(file)': { type: '(file: string) => Record<string, unknown>', description: 'Сырое содержимое файла: объект настроек или { key: record } для файла записей. Только для чтения; разбирайте то, что используете. {} для неизвестного файла.' },
    'onChange(file, handler)': { type: '(file: string, handler: (key: string | undefined, value: unknown) => void) => void', description: 'Выполняется при каждом изменении файла. key это изменённая запись (undefined, если изменился весь файл или файл настроек); value это новая запись или null, если она удалена.' },
    'view(file, read)': { type: '<T>(file: string, read: (raw: unknown) => T) => { readonly value: T }', description: 'Файл настроек, разобранный через read и разбираемый заново при каждом изменении, до запуска обработчиков onChange. Читайте box.value.' },
    'records(file, readOne)': { type: '<T>(file: string, readOne: RecordReader<T>) => ReadonlyMap<string, T>', description: 'Файл записей, разобранный запись за записью (readOne возвращает null, чтобы пропустить запись). Правка разбирает только изменённую запись.' },

/>

#### Пример

```ts
import { AdminWorld } from "@aicore-fivem/lib/client";
import { num, record } from "@aicore-fivem/lib/shared";

const world = new AdminWorld(["settings"]);
const settings = world.view("settings", (raw) => ({
  radius: num(record(raw).radius, 2),
}));

world.onChange("settings", () => console.log("new radius", settings.value.radius));
```
