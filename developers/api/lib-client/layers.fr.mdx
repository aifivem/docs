Ces objets ne parlent jamais à un script précis. Ils interrogent **ai-core**, et ai-core transmet au script que le serveur fait tourner pour cette tâche : ai-death ou un autre script de mort, ai-appearance ou tgiann-clothing, n’importe quel script d’emotes ou de menu radial pris en charge. Votre script continue de fonctionner quand le propriétaire en change. Le fonctionnement des couches est décrit dans [Couches et pont](/fr/docs/developers/layers).

Quand aucun script de ce type ne tourne, les appels répondent `false`, `null` ou la valeur propre au jeu, comme l’indique chaque entrée.

## medical

### medical.isDead

Indique si le joueur local est à terre (mort ou en last stand), quel que soit le script de mort qui tourne. Les scripts de mort gardent en vie un ped à terre pour l’animer, si bien que `IsEntityDead` seul ne les détecte pas. Une lecture en mémoire après le premier appel.

**Côté :** client · **Attend :** non

```ts title="Signature"
medical.isDead(): boolean
```

Pas d’équivalent Lua : appelez `exports['ai-core']:IsDead()` et écoutez l’événement local `ai-core:client:dead` (`dead`).

#### Retour

`boolean` : `true` quand la couche médicale d’ai-core indique que le joueur est à terre, ou que le ped est mort pour le jeu.

#### Exemple

```ts
import { medical, notify } from "@aifivem/lib/client";

RegisterCommand(
  "phone",
  () => {
    if (medical.isDead()) return notify("You cannot use the phone now", "error");
    SetNuiFocus(true, true);
  },
  false,
);
```

### medical.onChange

Exécute un gestionnaire quand le joueur local tombe à terre ou se relève.

**Côté :** client · **Attend :** non

```ts title="Signature"
medical.onChange(fn: (dead: boolean) => void): void
```

Pas d’équivalent Lua : `AddEventHandler('ai-core:client:dead', function(dead) end)`.

#### Paramètres

<TypeTable
  type={{
    fn: { type: '(dead: boolean) => void', description: 'Reçoit true quand le joueur est tombé à terre, false quand il s’est relevé.', required: true },
  }}
/>

#### Retour

`void`.

#### Exemple

```ts
import { medical, Points } from "@aifivem/lib/client";

const points = new Points();
medical.onChange(() => points.refresh()); // les points dont canShow lit medical.isDead()
```

## appearance

L’apparence des peds via la couche d’apparence d’ai-core, quel que soit le script de vêtements qui tourne.

### appearance.apply

Applique une apparence enregistrée à un ped du modèle de cette apparence. Récupérez l’apparence sur le serveur avec `appearance.get(charId)`, créez le ped avec `look.model`, puis appliquez-la. Sur le ped du joueur lui-même, cela change ses vêtements.

**Côté :** client · **Attend :** non

```ts title="Signature"
appearance.apply(ped: number, look: CharacterAppearance): boolean
```

```lua title="Lua"
local ok = aiLib.appearance.apply(ped, look)
```

#### Paramètres

<TypeTable
  type={{
    ped: { type: 'number', description: 'Le ped à habiller. Son modèle doit être look.model.', required: true },
    look: { type: 'CharacterAppearance', description: '{ model: number; data: unknown } : le hash du modèle et les données propres au script de vêtements. Traitez data comme opaque.', required: true },
  }}
/>

Le type est [`CharacterAppearance`](/fr/docs/developers/api/types#characterappearance).

#### Retour

`boolean` : `false` quand le ped a disparu, que le modèle diffère ou qu’aucun script de vêtements ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { appearance, LocalPed, triggerServerCallback } from "@aifivem/lib/client";
import type { CharacterAppearance } from "@aifivem/shared";

// Une copie endormie d’un personnage, habillée comme lui.
export async function showSleeper(charId: number): Promise<void> {
  const look = (await triggerServerCallback("mysleep:look", [charId]).catch(() => null)) as CharacterAppearance | null;
  if (!look) return;
  new LocalPed({
    model: look.model,
    coords: { x: 151.2, y: -1004.6, z: 29.4, heading: 90 },
    onSpawn: (ped) => appearance.apply(ped, look),
  });
}
```
</Tab>
<Tab value="Lua">
```lua
local function showSleeper(charId)
    CreateThread(function()
        local look = aiLib.triggerServerCallback('mysleep:look', { charId })
        if type(look) ~= 'table' then return end
        aiLib.LocalPed.new({
            model = look.model,
            coords = vector4(151.2, -1004.6, 29.4, 90.0),
            onSpawn = function(ped) aiLib.appearance.apply(ped, look) end,
        })
    end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
Vérifiez ce que le serveur envoie avant de le convertir. Un ped créé avec un autre modèle que `look.model` ne peut pas prendre l’apparence : `apply` répond `false`.
</Callout>

**Côté :** client · **Attend :** non

```ts title="Signature"

```

```lua title="Lua"

```

#### Paramètres

<TypeTable
  type={{

`boolean` : `false` quand ce n’est pas possible (aucun script de vêtements, un modèle qu’il ne prend pas en charge).

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>

```ts
});
```
</Tab>
<Tab value="Lua">

## fuel

### fuel.get

Le niveau de carburant d’un véhicule. Le serveur tient un state bag `fuel` pour chaque véhicule quel que soit le script de carburant qui tourne, c’est donc une lecture en mémoire ; sans ce state bag, c’est le niveau du réservoir du jeu.

**Côté :** client · **Attend :** non

```ts title="Signature"
fuel.get(vehicle: number): number
```

Pas d’équivalent Lua : lisez `Entity(vehicle).state.fuel`. Régler le carburant se fait uniquement côté serveur (`fuel.set` dans [Véhicules](/fr/docs/developers/api/lib-server/vehicles)).

#### Paramètres

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Un véhicule connu de ce client.', required: true },
  }}
/>

#### Retour

`number` : 0-100.

#### Exemple

```ts
import { cache, every, fuel } from "@aifivem/lib/client";

every(1000, () => {
  if (cache.vehicle !== false) SendNUIMessage({ action: "fuel", data: Math.round(fuel.get(cache.vehicle)) });
});
```

**Côté :** client · **Attend :** non

```ts title="Signature"

```

```lua title="Lua"

```

#### Paramètres

<TypeTable

#### RadialItem

    icon: { type: 'string', description: 'Nom d’icône Font Awesome solid sans fa- (car, key), ou une url d’image.' },

```ts
  id: "myscript:police",
  label: Locale("POLICE"),
  icon: "shield-halved",
  canShow: () => hasJob(["police"]),
  items: [
    { id: "myscript:cuff", label: Locale("CUFF"), icon: "handcuffs", onPressed: () => emitNet("mypolice:cuff") },
  ],
});
```
</Tab>

## inventory

### inventory.hasItem

Indique si le joueur possède au moins `count` exemplaires d’un objet. Utilisez-la dans `canShow` pour que le joueur ne voie que ce qu’il peut faire ; le serveur vérifie de nouveau.

**Côté :** client · **Attend :** non

```ts title="Signature"
inventory.hasItem(item: string, count?: number): boolean
```

```lua title="Lua"
local has = aiLib.inventory.hasItem(item, count)
```

#### Paramètres

<TypeTable
  type={{
    item: { type: 'string', description: 'Le nom de l’objet (lockpick).', required: true },
    count: { type: 'number', description: 'Combien il en faut.', default: '1' },
  }}
/>

#### Retour

`boolean` : `true` quand le joueur en a assez.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, Points } from "@aifivem/lib/client";

const points = new Points();
points.addVehicle("lockpick", {
  label: "Lockpick",
  icon: "unlock",
  canShow: (vehicle) => GetVehicleDoorLockStatus(vehicle) >= 2 && inventory.hasItem("lockpick"),
  onPressed: (vehicle) => emitNet("mykeys:lockpick", NetworkGetNetworkIdFromEntity(vehicle)),
});
```
</Tab>
<Tab value="Lua">
```lua
local points = aiLib.Points.new()
points:addVehicle('lockpick', {
    label = 'Lockpick',
    icon = 'unlock',
    canShow = function(vehicle)
        return GetVehicleDoorLockStatus(vehicle) >= 2 and aiLib.inventory.hasItem('lockpick')
    end,
    onPressed = function(vehicle) TriggerServerEvent('mykeys:lockpick', NetworkGetNetworkIdFromEntity(vehicle)) end,
})
```
</Tab>
</Tabs>

### inventory.currentWeapon

L’objet arme dans la main du joueur : son nom, son libellé et son image.

**Côté :** client · **Attend :** non

```ts title="Signature"
inventory.currentWeapon(): HeldWeapon | null
```

```lua title="Lua"
local weapon = aiLib.inventory.currentWeapon() -- table ou nil
```

#### Retour

[`HeldWeapon`](/fr/docs/developers/api/types#heldweapon) `{ name: string; label: string; image?: string }` (`name` comme `WEAPON_PISTOL`, `image` une url `nui://` quand l’inventaire en a une), ou `null` (`nil`) quand la main est vide.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, onCache } from "@aifivem/lib/client";

// À lire quand l’arme change, jamais à chaque frame.
onCache("weapon", () => SendNUIMessage({ action: "weapon", data: inventory.currentWeapon() }));
```
</Tab>
<Tab value="Lua">
```lua
aiLib.cache.onChange('weapon', function()
    SendNUIMessage({ action = 'weapon', data = aiLib.inventory.currentWeapon() })
end)
```
</Tab>
</Tabs>
