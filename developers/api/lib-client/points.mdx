A **point** is any place a player uses: a shop counter, a door, an NPC, a return spot, every ATM, the trunk of every car. You describe it once (where, what text, what happens) and the lib draws it the way the server owner picked.

## Prompt or target

The owner picks the interaction style in ai-core's admin panel (**Interaction**). The same `onPressed` runs either way, so your script never cares which one is on.

| Style | What the player sees |
| --- | --- |
| **Prompt** | A "press E" box on the right side of the screen while the player stands inside the point's radius. The key is one rebindable keybind in ai-lib (default `E`), so nothing polls keys every frame. |
| **Target** | An option in the target eye on the spot, the NPC, the object or the vehicle. It needs one of the target scripts the lib has an adapter for to be running. When several run, the first in this order wins: `ai-target`, `tgiann-radialmenu-target`, `tgiann-target`, `sleepless_interact`, `ox_target`, `qb-target`, `interact`. |

When the owner picked target but no target script runs, every point is a prompt. A point can override the owner's choice: `promptOnly` keeps a prompt (things done from a vehicle: fuel pumps, car washes), `preferTarget` uses a target option whenever a target script runs (seats). When a target script starts or stops, or the owner switches the style, every point moves over by itself.

<Callout type="info">
Only one point action of your resource runs at a time. When `onPressed` returns a promise, the other points of your resource ignore presses until it settles, so you never need your own `busy` flag. The player must also pass `canShow` at the moment of the press.
</Callout>

```ts title="resource/client/index.ts"
const points = new Points();

// A shop counter with a shopkeeper and a map blip.
points.add("shop", {
  coords: { x: 25.7, y: -1347.3, z: 29.5 },
  label: Locale("OPEN_SHOP"),
  icon: "basket-shopping",
  ped: { model: "mp_m_shopkeep_01", coords: { x: 24.5, y: -1346.6, z: 29.5, heading: 270 } },
  blip: { sprite: 52, color: 2, label: Locale("SHOP") },

});

// A stash only police can open; the text follows a state.
let locked = true;
points.add("evidence", {
  coords: { x: 474.9, y: -996.4, z: 26.3 },

    const reply = await callAction("myscript:toggle", [], { fallback: "TOGGLE_FAILED" });
    if (reply) locked = !locked;
    points.refresh("evidence");
  },
});

// canShow reads the job: check it again when jobs, duty or gangs change.
onMembershipChange(() => points.refresh());
```

```lua title="client.lua"
    icon = 'box-archive',
```

### points.addModel

Adds a point on every world object of some models (ATMs, vending machines, dumpsters, chairs), or replaces the point with the same id. In target mode it is a target option on those models; in prompt mode a prompt shows near the closest one. The scan for the nearest object runs once in ai-lib for every resource, two times a second, and pauses while the player stands still.

**Side:** Client · **Waits:** no

## Points from panel records

Most points come from a records file of your script's admin panel (shops, garages, rental counters). Mirror the file on the client with [`AdminWorld`](#new-adminworld), then build each record's points with [`RecordObjects`](#new-recordobjects): an edited record rebuilds only its own points, a deleted one removes them.

### new RecordObjects

Keeps the world objects of a records file (points, blips, peds, zones) in step with the file one record at a time. `build(key, record)` makes one record's objects and returns how to remove them. It builds every record in its constructor.

**Side:** Client and server (from `@aicore-fivem/lib/shared`) · **Waits:** no

```ts title="Signature"
new RecordObjects<T>(
  source: RecordSource,
  file: string,
  records: RecordReader<T> | ReadonlyMap<string, T>,
  build: (key: string, record: T) => (() => void) | void,
)
```

No Lua twin.

#### Parameters

<TypeTable
  type={{
    source: { type: 'RecordSource', description: 'Where the file lives: an AdminWorld on the client (an AdminPanel on the server).', required: true },
    file: { type: 'string', description: 'The records file name, without data/ and .json (locations).', required: true },
    records: { type: 'RecordReader<T> | ReadonlyMap<string, T>', description: 'A reader (key, raw) => T | null that parses one record (null leaves it out), or a records view you already keep of the same file (world.records(file, readOne)), so each edit is parsed once.', required: true },
    build: { type: '(key: string, record: T) => (() => void) | void', description: 'Makes the objects of one record and returns a function that removes them.', required: true },
  }}
/>

#### Members

<TypeTable
  type={{
    records: { type: 'ReadonlyMap<string, T>', description: 'The parsed records by key, always current. Look a record up in onPressed instead of capturing it.' },
    'rebuild(key)': { type: '(key: string) => void', description: 'Removes and builds again one record (it is gone when the record is). Called by itself on an edit.' },
    'rebuildAll()': { type: '() => void', description: 'Removes and builds every record again. Call it when a setting every record reads changes (a blip style, a radius).' },
  }}
/>

#### Example

```ts title="resource/client/index.ts"
import { AdminWorld, callAction, createLocale, Points } from "@aicore-fivem/lib/client";
import { readVec3, RecordObjects, str } from "@aicore-fivem/lib/shared";

const Locale = createLocale<typeof import("../../locales/en.json")>();
const world = new AdminWorld(["settings", "shops"]);
const points = new Points();

interface Shop { label: string; coords: { x: number; y: number; z: number } }
const readShop = (_key: string, raw: Record<string, unknown>): Shop | null => {
  const coords = readVec3(raw.coords);
  return coords ? { label: str(raw.label, "Shop"), coords } : null;
};

const shops = new RecordObjects(world, "shops", readShop, (id, shop) => {
  points.add(id, {
    coords: shop.coords,
    label: Locale("OPEN_SHOP", shop.label),
    onPressed: () => callAction("myshop:open", [id], { fallback: "SHOP_FAILED" }),
  });
  return () => points.remove(id);
});

// A setting every shop reads changed: rebuild them all.
world.onChange("settings", () => shops.rebuildAll());
```

<Callout type="warn">
`RecordObjects` builds in its constructor. Create it after everything `build` reads, and inside `build` use the `record` argument: a class field that holds the `RecordObjects` is not assigned yet during that first build.
</Callout>

```ts
import { num, record } from "@aicore-fivem/lib/shared";

const world = new AdminWorld(["settings"]);
const settings = world.view("settings", (raw) => ({
  radius: num(record(raw).radius, 2),
}));

world.onChange("settings", () => console.log("new radius", settings.value.radius));
```
