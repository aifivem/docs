Ein **Client-Export** ist eine Funktion, die die Clientseite von ai-core jeder anderen Ressource im Spiel desselben Spielers anbietet. Dein Client-Skript ruft sie auf, um die Daten des lokalen Spielers zu lesen, das HUD auszublenden, einen Eintrag im Radialmenü hinzuzufügen, ein Item zu prüfen, ein Emote abzuspielen und so weiter.

Die meisten dieser Exports sind **Ebenen**: ai-core erledigt die Aufgabe nicht selbst, sondern leitet den Aufruf an das Skript weiter, das der Server für diese Aufgabe nutzt (das Inventar, das Kleidungs-Skript, das Radialmenü, das Emote-Menü, das Tod-Skript, das MDT). Dein Skript ruft einen Namen auf und funktioniert weiter, wenn der Serverbesitzer eines dieser Skripte gegen ein anderes tauscht.

## Bevor du anfängst

- Jeder Client-Export ist **synchron**: Er antwortet sofort und wartet nie. Nichts auf diesen Seiten gibt ein Promise zurück, und nichts braucht in Lua einen Thread. Der eine Export, dessen Antwort Zeit braucht (`OpenItemPicker`), antwortet über ein Event.
- Rufe sie nur aus **Client**-Code auf. Der Server hat seine eigene Liste: [Server-Exports von ai-core](/de/docs/developers/api/core-server).
- ai-core muss gestartet sein. Eine Ressource, die ohne ai-core laufen kann, nutzt in TypeScript `optionalExport("ai-core")` (es ist `null`, solange ai-core gestoppt ist).
- Jeder Export antwortet auch mit vertauschter Groß-/Kleinschreibung des ersten Buchstabens: `GetPlayerData` und `getPlayerData` sind dieselbe Funktion.
- Was eine Ressource über diese Exports hinzufügt (Gründe zum Ausblenden des HUD, Tastenhinweise, Radial-Einträge, Pausen der Welt-Synchronisierung), gehört dieser Ressource. ai-core entfernt es, wenn die Ressource stoppt, sodass ein Absturz oder Neustart nie ein ausgeblendetes HUD oder einen toten Menüeintrag zurücklässt.

## Einen Export aufrufen

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aifivem/lib/client";

// Ein typisiertes Handle, oben in der Datei. Die Typen kommen aus @aifivem/shared (AiCoreClientExports).
const core = resourceExport("ai-core");

RegisterCommand(
  "myjob",
  () => {
    const data = core.GetPlayerData();
    console.log(data ? `job: ${data.job.job}` : "no character loaded");
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('myjob', function()
  local data = exports['ai-core']:GetPlayerData()
  print(data and ('job: %s'):format(data.job.job) or 'no character loaded')
end, false)
```
</Tab>
</Tabs>

## Nutze den Lib-Helfer, wenn es einen gibt

Die meisten Exports haben einen Helfer in `@aifivem/lib/client` und denselben Helfer auf `aiLib` für Lua-Ressourcen (`shared_script '@ai-lib/init.lua'`). Die Helfer rufen den Export für dich auf, prüfen seine Antwort und fügen einen Änderungs-Listener hinzu, wo es einen gibt. Bevorzuge sie; rufe den Export direkt auf, wenn du die Lib nicht nutzen kannst.

## Rufe Exports nicht in jedem Frame auf

Exports überqueren eine Ressourcengrenze, was mehr kostet als ein lokaler Funktionsaufruf. Lies einen Wert einmal und folge dann dem Event, das dir sagt, wann er sich ändert. Jede Seite nennt dieses Event; sie sind alle in [Events und Zustand](/de/docs/developers/api/events) aufgelistet.

<Callout type="info">
Die Menüs, Eingabedialoge, Benachrichtigungen, Aufforderungen, der Fortschrittsbalken und die Minispiele gehören zu ai-lib, nicht zu ai-core. Nutze `notify`, `menu`, `input`, `progress` und `skillCheck` der Lib (oder dieselben Namen auf `aiLib`).
</Callout>
