Ces exports lisent ce qu’ai-core sait du joueur assis devant ce jeu : son personnage, son argent, ses métiers et ses gangs. Le serveur envoie ces données au propre client du joueur une fois au chargement du personnage, puis seulement les valeurs qui changent. Les données d’aucun autre joueur n’atteignent jamais ce client.

<Callout type="info">
En TypeScript, utilisez `getPlayerData(key)` et `onPlayerData(key, handler)` de la lib au lieu d’appeler `GetPlayerData` encore et encore. En Lua, utilisez `aiLib.playerData.get(key)` et `aiLib.playerData.onChange(key, handler)`. Ils lisent l’export une fois, puis suivent chaque changement que pousse ai-core.
</Callout>

### GetPlayerData

Renvoie tout ce qu’ai-core sait du personnage chargé du joueur local dans une seule table : personnage, argent, métiers, service, métier principal, gangs, gang actif et métadonnées. Utilisez-le pour lire les données une fois au démarrage de votre ressource ; suivez les changements avec `onPlayerData` (TS) ou `aiLib.playerData.onChange` (Lua).

**Côté :** Client · **Attend :** non

```ts title="Signature"
GetPlayerData(): AiPlayerData | null
```

```lua title="Lua"
local data = exports['ai-core']:GetPlayerData() -- table ou nil
```

#### Paramètres

Aucun.

#### Retour

[`AiPlayerData`](/fr/docs/developers/api/types#aiplayerdata) tant qu’un personnage se tient dans le monde, `null` (`nil` en Lua) sur l’écran des personnages, avant le chargement du premier personnage, et après que le joueur est revenu à l’écran des personnages.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { getPlayerData, onPlayerData } from "@aicore-fivem/lib/client";

// Affiche un blip réservé à la police tant que le joueur est en service comme policier.
let blip = 0;

function updateBlip(duty: string | null): void {
  if (duty === "police" && blip === 0) {
    blip = AddBlipForCoord(441.8, -982.0, 30.7); // Commissariat de Mission Row
    SetBlipSprite(blip, 60);
  } else if (duty !== "police" && blip !== 0) {
    RemoveBlip(blip);
    blip = 0;
  }
}

// Lire une fois (la lib demande GetPlayerData à ai-core pour vous), puis suivre chaque changement.
updateBlip(getPlayerData("duty") ?? null);
onPlayerData("duty", (duty) => updateBlip(duty));
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- fxmanifest.lua : dependency 'ai-lib' et shared_script '@ai-lib/init.lua'
-- Affiche un blip réservé à la police tant que le joueur est en service comme policier.
local blip = 0

local function updateBlip(duty)
  if duty == 'police' and blip == 0 then
    blip = AddBlipForCoord(441.8, -982.0, 30.7) -- Commissariat de Mission Row
    SetBlipSprite(blip, 60)
  elseif duty ~= 'police' and blip ~= 0 then
    RemoveBlip(blip)
    blip = 0
  end
end

-- Lire une fois (aiLib demande GetPlayerData à ai-core pour vous), puis suivre chaque changement.
updateBlip(aiLib.playerData.get('duty'))
aiLib.playerData.onChange('duty', updateBlip)
```
</Tab>
</Tabs>

<Callout type="warn">
C’est la copie propre au joueur, pour afficher des choses à l’écran. Ne décidez jamais à partir d’elle de quelque chose que le serveur doit croire (un paiement, un objet, l’accès à un coffre) : le serveur revérifie avec ses propres exports.
</Callout>

### IsPlayerLoaded

Indique si un personnage se tient dans le monde sur ce client. Utilisez-le avant de lancer quoi que ce soit qui a besoin d’un personnage (un HUD, une boucle de métier) quand votre ressource peut démarrer après que le joueur s’est déjà chargé.

**Côté :** Client · **Attend :** non

```ts title="Signature"
IsPlayerLoaded(): boolean
```

```lua title="Lua"
local loaded = exports['ai-core']:IsPlayerLoaded() -- boolean
```

#### Paramètres

Aucun.

#### Retour

`boolean` : `true` une fois le personnage placé dans le monde, `false` sur l’écran des personnages, pendant que le joueur choisit un point d’apparition, et après qu’il est revenu à l’écran des personnages.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aicore-fivem/lib/client";
import { CORE } from "@aicore-fivem/shared";

const core = resourceExport("ai-core");

function start(): void {
  console.log("character ready, starting the job loop");
}

// Le joueur a pu se charger avant le démarrage de cette ressource (un redémarrage) : vérifier d’abord, puis écouter.
if (core.IsPlayerLoaded()) start();
on(CORE.clientPlayerLoadedEvent, start);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
local function start()
  print('character ready, starting the job loop')
end

-- Le joueur a pu se charger avant le démarrage de cette ressource (un redémarrage) : vérifier d’abord, puis écouter.
if exports['ai-core']:IsPlayerLoaded() then start() end
AddEventHandler('ai-core:client:playerLoaded', start)
```
</Tab>
</Tabs>

### GetDefinitions

Renvoie chaque métier ou chaque gang tel que le panneau d’administration les stocke (libellés, grades et les autres champs que le panneau modifie). Les ponts de framework l’utilisent pour construire les tables de métiers ESX / QB. Lisez-le une fois, puis suivez l’événement client `ai-core:client:definitions`, qui se déclenche pour chaque métier ou gang que le panneau modifie.

**Côté :** Client · **Attend :** non

```ts title="Signature"
GetDefinitions(file: "jobs" | "gangs"): Record<string, unknown> | null
```

```lua title="Lua"
local jobs = exports['ai-core']:GetDefinitions('jobs') -- table indexée par nom de métier, ou nil
```

#### Paramètres

<TypeTable
  type={{
    file: { type: '"jobs" | "gangs"', description: 'Quel fichier du panneau lire : tous les métiers, ou tous les gangs.', required: true },
  }}
/>

#### Retour

`Record<string, unknown>` : un enregistrement par métier ou gang, indexé par son nom (`police`, `ambulance`). Les enregistrements sont les données propres du panneau et ne sont pas vérifiés. `null` quand `file` n’est ni `"jobs"` ni `"gangs"`.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aicore-fivem/lib/client";
import { CORE } from "@aicore-fivem/shared";

const core = resourceExport("ai-core");

// Une copie locale de chaque métier, tenue à jour.
const jobs: Record<string, unknown> = { ...(core.GetDefinitions("jobs") ?? {}) };

on(CORE.clientDefinitionsEvent, (file: string, name: string, definition: unknown) => {
  if (file !== "jobs") return;
  if (definition === null) delete jobs[name];
  else jobs[name] = definition;
});
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
-- Une copie locale de chaque métier, tenue à jour.
local jobs = exports['ai-core']:GetDefinitions('jobs') or {}

AddEventHandler('ai-core:client:definitions', function(file, name, definition)
  if file ~= 'jobs' then return end
  jobs[name] = definition -- nil quand le métier a été supprimé
end)
```
</Tab>
</Tabs>

<Callout type="info">
Pour les noms et libellés des grades d’un métier ou d’un gang sur le serveur, utilisez les exports serveur d’ai-core ou la lib serveur ; c’est le serveur qui vérifie les grades.
</Callout>
