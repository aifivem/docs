Diese Exports laufen über die **Aussehens-Ebene** von ai-core: Das Kleidungs-Skript, das der Server nutzt (ai-appearance, tgiann-clothing, illenium-appearance, qb-clothing, crm-appearance, rcore_clothing, bl_appearance), erledigt die Arbeit. Dein Skript berührt nie das eigene Format eines Kleidungs-Skripts und funktioniert deshalb weiter, wenn der Serverbesitzer es wechselt.

Ein **Aussehen** ([`CharacterAppearance`](/de/docs/developers/api/types#characterappearance)) ist `{ model, data }`: der Hash des Ped-Modells und die eigenen Daten des Kleidungs-Skripts. Behandle `data` als geschlossene Kiste: Hol dir ein Aussehen vom Server (`appearance.get(charId)` in der Server-Lib, `aiLib.appearance.get` in Lua) oder von `GetPedAppearance` und gib es unverändert zurück.

### ApplyAppearance

Legt über das aktive Kleidungs-Skript ein Aussehen auf einen Ped. Nutze es, um einen lokalen Ped als Charakter anzuziehen (ein Ladenbesitzer, der wie der Eigentümer aussieht, ein schlafender Körper, ein Foto) oder um ein gespeichertes Aussehen wieder auf den Spieler zu legen.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
ApplyAppearance(ped: number, look: CharacterAppearance): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:ApplyAppearance(ped, look) -- oder aiLib.appearance.apply(ped, look)
```

#### Parameter

<TypeTable
  type={{
    ped: { type: 'number', description: 'Das Ped-Handle. Sein Modell muss das `model` des Aussehens sein: Erstelle den Ped mit `look.model`.', required: true },
    look: { type: 'CharacterAppearance', description: '`{ model, data }` genau so, wie der Server oder `GetPedAppearance` es geliefert hat.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#characterappearance' },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn das Kleidungs-Skript das Aussehen erhalten hat. `false`, wenn der Ped nicht existiert, sein Modell von `look.model` abweicht, das Aussehen keine `{ model, data }`-Tabelle ist oder kein Kleidungs-Skript läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/server/index.ts"
import { appearance, onClientCallback, resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

// Das eigene gespeicherte Aussehen des fragenden Spielers.
onClientCallback("myscript:myLook", async (source) => {
  const character = core.GetCharacter(source);
  return character ? await appearance.get(character.id) : null;
});
```

```ts title="resource/client/index.ts"
import { appearance, requestModel, triggerServerCallback } from "@aifivem/lib/client";
import { toCharacterAppearance } from "@aifivem/shared";

// Eine lokale Kopie des Spielers, die an einem Punkt steht und wie er gekleidet ist.
export async function spawnLookalike(x: number, y: number, z: number): Promise<number> {
  const look = toCharacterAppearance(await triggerServerCallback("myscript:myLook", []));
  if (!look) return 0;
  await requestModel(look.model);
  const ped = CreatePed(4, look.model, x, y, z, 0, false, false);
  SetModelAsNoLongerNeeded(look.model);
  appearance.apply(ped, look);
  return ped;
}
```
</Tab>
<Tab value="Lua">
```lua title="server.lua"
-- Das eigene gespeicherte Aussehen des fragenden Spielers.
aiLib.onClientCallback('myscript:myLook', function(source)
  local character = exports['ai-core']:GetCharacter(source)
  return character and aiLib.appearance.get(character.id) or nil
end)
```

```lua title="client.lua"
-- Eine lokale Kopie des Spielers, die an einem Punkt steht und wie er gekleidet ist (aus einem Thread aufrufen).
local function spawnLookalike(x, y, z)
  local look = aiLib.triggerServerCallback('myscript:myLook', {})
  if not look then return 0 end
  aiLib.requestModel(look.model)
  local ped = CreatePed(4, look.model, x, y, z, 0.0, false, false)
  SetModelAsNoLongerNeeded(look.model)
  aiLib.appearance.apply(ped, look)
  return ped
end
```
</Tab>
</Tabs>

<Callout type="warn">
Auf dem eigenen Ped des Spielers ändert `ApplyAppearance`, was er jetzt trägt. Ob diese Änderung gespeichert wird, ist die Regel des Kleidungs-Skripts, nicht die von ai-core. Um den Spieler in eine Uniform zu kleiden, die nie gespeichert wird, nutze [WearOutfit](#wearoutfit).
</Callout>

### GetPedAppearance

Gibt das Aussehen zurück, das ein Ped gerade trägt, in derselben `{ model, data }`-Form, die die gespeicherten Aussehen des Servers nutzen.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
GetPedAppearance(ped: number): CharacterAppearance | null
```

```lua title="Lua"
local look = exports['ai-core']:GetPedAppearance(ped) -- oder aiLib.appearance.read(ped)
```

#### Parameter

<TypeTable
  type={{
    ped: { type: 'number', description: 'Das Ped-Handle (`cache.ped` für den lokalen Spieler).', required: true },
  }}
/>

#### Rückgabe

[`CharacterAppearance`](/de/docs/developers/api/types#characterappearance): `model` ist der Modell-Hash des Peds, `data` die Daten des Kleidungs-Skripts. `null`, wenn der Ped nicht existiert, kein Kleidungs-Skript läuft oder das Kleidungs-Skript diesen Ped nicht lesen kann (manche lesen nur den eigenen Ped des lokalen Spielers).

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/photo.ts"
import { appearance, cache } from "@aifivem/lib/client";

// Kopiert, was der Spieler gerade trägt, auf einen anderen Ped desselben Modells.
export function copyPlayerLook(target: number): boolean {
  const look = appearance.read(cache.ped);
  return look !== null && appearance.apply(target, look);
}
```
</Tab>
<Tab value="Lua">
```lua title="client/photo.lua"
-- Kopiert, was der Spieler gerade trägt, auf einen anderen Ped desselben Modells.
local function copyPlayerLook(target)
  local look = aiLib.appearance.read(aiLib.cache.ped)
  return look ~= nil and aiLib.appearance.apply(target, look)
end
```
</Tab>
</Tabs>

### OpenClothingMenu

Öffnet eines der Menüs des aktiven Kleidungs-Skripts für den lokalen Spieler: das Kleidungsgeschäft, den Friseur oder die gespeicherten Outfits. Nutze es für deine eigenen Shop-Marker oder einen Kleiderschrank in einem Haus.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
OpenClothingMenu(menu: ClothingMenu): boolean
```

```lua title="Lua"
local opened = exports['ai-core']:OpenClothingMenu(menu) -- oder aiLib.appearance.openMenu(menu)
```

#### Parameter

<TypeTable
  type={{
    menu: { type: '"clothing" | "barber" | "outfits"', description: '`clothing`: das Kleidungsgeschäft. `barber`: Haare, Bart und Make-up. `outfits`: die gespeicherten Outfits des Spielers (ein Kleiderschrank).', required: true, typeDescriptionLink: '/de/docs/developers/api/types#clothingmenu' },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn das Kleidungs-Skript das Menü geöffnet hat. `false` für ein unbekanntes `menu`, wenn kein Kleidungs-Skript läuft oder das laufende kein solches Menü hat.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/wardrobe.ts"
import { appearance, notify, Points } from "@aifivem/lib/client";
import { Locale } from "common";

const points = new Points();

// Ein Kleiderschrank in einem Motelzimmer.
points.add("motel_wardrobe", {
  coords: { x: 151.3, y: -1001.2, z: -99.0 },
  label: Locale("WARDROBE"),
  onPressed: () => {
    if (!appearance.openMenu("outfits")) notify(Locale("NO_WARDROBE"), "error");
  },
});
```
</Tab>
<Tab value="Lua">
```lua title="client/wardrobe.lua"
local Locale = aiLib.locale()

RegisterCommand('wardrobe', function()
  if not aiLib.appearance.openMenu('outfits') then
    aiLib.notify(Locale('NO_WARDROBE'), 'error')
  end
end, false)
```
</Tab>
</Tabs>

### WearOutfit

Legt dem lokalen Spieler ein Job-Outfit (eine Uniform) an, bis `ReloadSkin` aufgerufen wird. Nur die Teile, die du auflistest, ändern sich; der Rest seiner Kleidung bleibt. Das Outfit wird nie als eigenes Aussehen des Spielers gespeichert.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
WearOutfit(outfit: JobOutfit): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:WearOutfit(outfit) -- oder aiLib.appearance.wearOutfit(outfit)
```

#### Parameter

<TypeTable
  type={{
    outfit: { type: 'JobOutfit', description: 'Die Teile, die angezogen werden. Felder unten.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#joboutfit' },
  }}
/>

#### JobOutfit

<TypeTable
  type={{
    components: { type: 'OutfitPiece[]', description: 'Kleidungskomponenten (Oberkörper, Beine, Schuhe...): `id` 0-11.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#outfitpiece' },
    props: { type: 'OutfitPiece[]', description: 'Props (Hüte, Brillen, Uhren...): `id` 0-13.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#outfitpiece' },
  }}
/>

#### OutfitPiece

Siehe auch [OutfitPiece](/de/docs/developers/api/types#outfitpiece).

<TypeTable
  type={{
    id: { type: 'number', description: 'Die Komponenten-ID (0-11) oder Prop-ID (0-13).', required: true },
    collection: { type: 'string', description: 'Der Name der Kleidungskollektion (DLC), aus der das Teil stammt; `""` für das Basisspiel. Höchstens 64 Zeichen.', required: true },
    index: { type: 'number', description: 'Der Drawable-Index innerhalb dieser Kollektion (0-1023). Bei einem Prop nimmt `-1` den Prop ab.', required: true },
    texture: { type: 'number', description: 'Die Textur (Farbvariante). Ein fehlender oder negativer Wert zählt als 0.', required: true },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn das Kleidungs-Skript das Outfit angelegt hat. `false`, wenn nach der Prüfung kein gültiges Teil übrig ist, kein Kleidungs-Skript läuft oder das laufende keine Outfits anlegen kann. Ungültige Teile (falscher ID-Bereich, schlechter Index) werden einzeln verworfen; die gültigen werden trotzdem angelegt.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/locker.ts"
import { appearance } from "@aifivem/lib/client";
import type { JobOutfit } from "@aifivem/shared";

// Eine schlichte Uniform aus Teilen des Basisspiels: Hemd, Hose, Schuhe, kein Hut.
const UNIFORM: JobOutfit = {
  components: [
    { id: 11, collection: "", index: 55, texture: 0 },
    { id: 4, collection: "", index: 35, texture: 0 },
    { id: 6, collection: "", index: 25, texture: 0 },
  ],
  props: [{ id: 0, collection: "", index: -1, texture: 0 }],
};

export const putOnUniform = (): boolean => appearance.wearOutfit(UNIFORM);
export const takeOffUniform = (): boolean => appearance.reloadSkin();
```
</Tab>
<Tab value="Lua">
```lua title="client/locker.lua"
-- Eine schlichte Uniform aus Teilen des Basisspiels: Hemd, Hose, Schuhe, kein Hut.
local UNIFORM = {
  components = {
    { id = 11, collection = '', index = 55, texture = 0 },
    { id = 4, collection = '', index = 35, texture = 0 },
    { id = 6, collection = '', index = 25, texture = 0 },
  },
  props = { { id = 0, collection = '', index = -1, texture = 0 } },
}

local function putOnUniform() return aiLib.appearance.wearOutfit(UNIFORM) end
local function takeOffUniform() return aiLib.appearance.reloadSkin() end
```
</Tab>
</Tabs>

<Callout type="info">
Drawable-Indizes unterscheiden sich zwischen dem männlichen und dem weiblichen Freemode-Modell: Halte ein Outfit pro Modell bereit und wähle es nach dem Modell des Spielers.
</Callout>

### ReloadSkin

Legt dem lokalen Spieler wieder sein gespeichertes Aussehen an. Nutze es, um ein Job-Outfit auszuziehen.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
ReloadSkin(): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:ReloadSkin() -- oder aiLib.appearance.reloadSkin()
```

#### Parameter

Keine.

#### Rückgabe

`boolean`: `true`, wenn das Kleidungs-Skript aufgefordert wurde, das Aussehen neu zu laden. `false`, wenn kein Kleidungs-Skript läuft oder das laufende nicht neu laden kann.

#### Beispiel

Siehe das Beispiel zu [WearOutfit](#wearoutfit).
