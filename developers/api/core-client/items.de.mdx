Diese Exports laufen über die **Inventar-Ebene** von ai-core: Das Inventar, das der Serverbesitzer gewählt hat (ai-inventory oder ein unterstütztes Inventar eines Drittanbieters), beantwortet sie. Dein Skript ruft nie die Exports eines bestimmten Inventars auf und funktioniert deshalb weiter, wenn das Inventar wechselt. Solange kein Inventar läuft, antworten die Prüfungen mit `false` / `null`, und Öffnen bewirkt nichts.

Der Client liest und öffnet nur. Items geben und nehmen passiert immer auf dem Server (Lib `inventory` auf dem Server oder die Server-Exports von ai-core), wo der Server den Spieler zuerst prüft.

### OpenInventory

Öffnet den eigenen Inventarbildschirm des Spielers im aktiven Inventar (mit dem, was dieses Inventar drumherum zeigt: den Boden, einen Kofferraum, ein Handschuhfach).

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
OpenInventory(): void
```

```lua title="Lua"
exports['ai-core']:OpenInventory() -- oder aiLib.inventory.openInventory()
```

#### Parameter

Keine.

#### Rückgabe

Nichts. Ohne aktives Inventar öffnet sich nichts.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { inventory } from "@aicore-fivem/lib/client";

RegisterCommand("bag", () => inventory.openInventory(), false);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('bag', function() aiLib.inventory.openInventory() end, false)
```
</Tab>
</Tabs>

### HasItem

Sagt, ob der Spieler mindestens eine bestimmte Anzahl eines Items hat. Nutze es, um eine Option ein- oder auszublenden (einen Radial-Eintrag, eine Target-Option), bevor du den Server bittest, etwas zu tun.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
HasItem(item: string, count?: number): boolean
```

```lua title="Lua"
local has = exports['ai-core']:HasItem(item, count) -- oder aiLib.inventory.hasItem(item, count)
```

#### Parameter

<TypeTable
  type={{
    item: { type: 'string', description: 'Der Item-Name, wie das Inventar ihn kennt (`"lockpick"`).', required: true },
    count: { type: 'number', description: 'Wie viele der Spieler haben muss. Ein fehlender, null oder negativer Wert zählt als 1.', default: '1' },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn der Spieler mindestens `count` hat. `false`, wenn er weniger hat, `item` kein String ist oder kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { inventory, notify, triggerServerCallback } from "@aicore-fivem/lib/client";
import { Locale } from "common";

RegisterCommand(
  "picklock",
  async () => {
    // Eine schnelle Prüfung für den Spieler; der Server prüft das Item erneut, bevor er etwas tut.
    if (!inventory.hasItem("lockpick")) return notify(Locale("NEED_LOCKPICK"), "error");
    await triggerServerCallback("myscript:picklock", []);
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
local Locale = aiLib.locale()

RegisterCommand('picklock', function()
  -- Eine schnelle Prüfung für den Spieler; der Server prüft das Item erneut, bevor er etwas tut.
  if not aiLib.inventory.hasItem('lockpick') then
    return aiLib.notify(Locale('NEED_LOCKPICK'), 'error')
  end
  CreateThread(function()
    aiLib.triggerServerCallback('myscript:picklock', {}) -- wartet auf die Antwort des Servers
  end)
end, false)
```
</Tab>
</Tabs>

<Callout type="warn">
Eine Client-Antwort kann von einem Cheater gefälscht werden. Nutze `HasItem` für das, was der Spieler sieht; der Server muss das Item selbst prüfen und entfernen.
</Callout>

### GetCurrentWeapon

Gibt das Waffen-Item zurück, das der Spieler in der Hand hält, mit seinem Label und Bild, über das aktive Inventar.

**Seite:** Client · **Wartet:** nein

```ts title="Signature"
GetCurrentWeapon(): HeldWeapon | null
```

```lua title="Lua"
local weapon = exports['ai-core']:GetCurrentWeapon() -- { name, label, image? } oder nil
```

#### Parameter

Keine.

#### Rückgabe

[`HeldWeapon`](/de/docs/developers/api/types#heldweapon), solange ein Waffen-Item in der Hand ist, `null`, wenn die Hände leer sind oder kein Inventar läuft.

<TypeTable
  type={{
    name: { type: 'string', description: 'Der Item-Name (`"WEAPON_PISTOL"`).', required: true },
    label: { type: 'string', description: 'Der Anzeigename des Items.', required: true },
    image: { type: 'string', description: 'Bild-URL (`nui://...`); fehlt, wenn das Inventar keines hat.' },
  }}
/>

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/weapon.ts"
import { inventory, onCache } from "@aicore-fivem/lib/client";

// Lies es, wenn die Waffe in der Hand wechselt, nicht in jedem Frame.
onCache("weapon", () => {
  const weapon = inventory.currentWeapon();
  SendNUIMessage({ action: "weapon", data: weapon });
});
```
</Tab>
<Tab value="Lua">
```lua title="client/weapon.lua"
-- Lies es, wenn die Waffe in der Hand wechselt, nicht in jedem Frame.
aiLib.cache.onChange('weapon', function()
  local weapon = aiLib.inventory.currentWeapon()
  SendNUIMessage({ action = 'weapon', data = weapon })
end)
```
</Tab>
</Tabs>

### OpenItemPicker

Öffnet die Item-Auswahl von ai-core: ein durchsuchbares Raster aller Items des aktiven Inventars mit Bildern, in dem der Spieler eine Liste von Items und Mengen zusammenstellt. Sie ist für Admin-Werkzeuge gedacht (einem Spieler Items geben): Die Item-Liste kommt vom Server, der sie nur an Admins sendet. Die Liste, die der Spieler übernimmt, kommt später als Client-Event `ai-lib:client:menuResult` an.

**Seite:** Client · **Wartet:** nein (die Antwort kommt als Event; `itemPicker` der Lib wartet für dich)

```ts title="Signature"
OpenItemPicker(requestId: number, request: ItemPickerRequest): void
```

```lua title="Lua"
local list = aiLib.itemPicker({ title = 'Give items', target = 12 }) -- wartet; innerhalb eines Threads aufrufen
```

#### Parameter

<TypeTable
  type={{
    requestId: { type: 'number', description: 'Deine Nummer für diese Anfrage. Sie kommt im Antwort-Event zurück, damit du weißt, welche Anfrage es beantwortet.', required: true },
    request: { type: 'ItemPickerRequest', description: 'Der Titel der Auswahl und für wessen Inventar die Items sind. Felder unten.', required: true, typeDescriptionLink: '/de/docs/developers/api/types#itempickerrequest' },
  }}
/>

#### ItemPickerRequest

Siehe auch [ItemPickerRequest](/de/docs/developers/api/types#itempickerrequest).

<TypeTable
  type={{
    title: { type: 'string', description: 'Der Titel oben in der Auswahl, bereits übersetzt. Auf 60 Zeichen gekürzt.', required: true },
    target: { type: 'number', description: 'Server-ID des Spielers, der die Items erhalten wird. Sein freies Gewicht begrenzt, was genommen werden kann. Weggelassen: der auswählende Admin.' },
  }}
/>

#### Rückgabe

Sofort nichts. Später löst ai-core `ai-lib:client:menuResult` mit `(resource, requestId, value)` aus: `value` ist eine [`PickedItem[]`](/de/docs/developers/api/types#pickeditem)-Liste (`{ name, count }`), wenn der Spieler sie übernommen hat, `null`, wenn er die Auswahl geschlossen hat. `itemPicker(request)` der Lib gibt `Promise<PickedItem[] | null>` mit diesem Wert zurück, und `aiLib.itemPicker(request)` gibt die Liste oder `nil` zurück.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/admin.ts"
import { itemPicker, triggerServerCallback } from "@aicore-fivem/lib/client";
import { Locale } from "common";

// Admin-Werkzeug: Items für einen Spieler auswählen, der Server prüft den Admin und gibt jedes Item.
export async function giveItemsTo(target: number): Promise<void> {
  const list = await itemPicker({ title: Locale("GIVE_ITEMS"), target });
  if (!list || list.length === 0) return;
  await triggerServerCallback("myadmin:giveItems", [target, list]);
}
```
</Tab>
<Tab value="Lua">
```lua title="client/admin.lua"
local Locale = aiLib.locale()

-- Admin-Werkzeug: Items für einen Spieler auswählen, der Server prüft den Admin und gibt jedes Item.
local function giveItemsTo(target)
  CreateThread(function()
    local list = aiLib.itemPicker({ title = Locale('GIVE_ITEMS'), target = target })
    if not list or #list == 0 then return end
    aiLib.triggerServerCallback('myadmin:giveItems', { target, list })
  end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
Die Auswahl zeigt Items nur Admins (`ai.admin`): Für alle anderen ist das Raster leer. Der Server beantwortet höchstens zwei Öffnungen pro Spieler in 2 Sekunden; ein `target`, der nicht online ist, zählt als der auswählende Admin. Die Antwort des Spielers sind Client-Daten: Dein Server muss prüfen, dass der Aufrufer ein Admin ist, und jedes Item und jede Menge prüfen, bevor er etwas gibt.
</Callout>
