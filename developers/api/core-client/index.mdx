A **client export** is a function that ai-core's client side offers to every other resource on the same player's game. Your client script calls it to read the local player's data, hide the HUD, add a radial menu item, check an item, play an emote and so on.

Most of these exports are **layers**: ai-core does not do the job itself, it forwards the call to whichever script the server runs for that job (the inventory, the clothing script, the radial menu, the emote menu, the death script, the MDT). Your script calls one name and keeps working when the server owner swaps one of those scripts for another.

## Before you start

- Every client export is **synchronous**: it answers at once and never waits. Nothing on these pages returns a Promise, and nothing needs a thread in Lua. The one export whose answer needs time (`OpenItemPicker`) answers through an event.
- Call them from **client** code only. The server has its own list: [ai-core server exports](/docs/developers/api/core-server).
- ai-core must be started. A resource that may run without ai-core uses `optionalExport("ai-core")` in TypeScript (it is `null` while ai-core is stopped).
- Every export also answers with the first letter's case swapped: `GetPlayerData` and `getPlayerData` are the same function.
- Things a resource adds through these exports (HUD hide reasons, key hints, radial items, world sync pauses) belong to that resource. ai-core removes them when the resource stops, so a crash or restart never leaves the HUD hidden or a dead menu item behind.

## Calling an export

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aicore-fivem/lib/client";

// One typed handle, at the top of the file. Types come from @aicore-fivem/shared (AiCoreClientExports).
const core = resourceExport("ai-core");

RegisterCommand(
  "myjob",
  () => {
    const data = core.GetPlayerData();
    console.log(data ? `job: ${data.job.job}` : "no character loaded");
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('myjob', function()
  local data = exports['ai-core']:GetPlayerData()
  print(data and ('job: %s'):format(data.job.job) or 'no character loaded')
end, false)
```
</Tab>
</Tabs>

## Use the lib helper when there is one

Most exports have a helper in `@aicore-fivem/lib/client` and the same helper on `aiLib` for Lua resources (`shared_script '@ai-lib/init.lua'`). The helpers call the export for you, check its answer and add a change listener where one exists. Prefer them; call the export directly when you cannot use the lib.

| Export | TypeScript lib | Lua `aiLib` | Page |

| `HideHud`, `ShowHud`, `IsHudVisible` | `hud.hide`, `hud.show`, `hud.visible`, `hud.onChange` | `aiLib.hud.hide`, `aiLib.hud.show`, `aiLib.hud.visible` | [HUD](/docs/developers/api/core-client/hud) |

## Do not call exports every frame

Exports cross a resource boundary, which costs more than a local function call. Read a value once, then follow the event that tells you when it changes. Each page names that event; they are all listed in [Events and state](/docs/developers/api/events).

<Callout type="info">
The menus, input dialogs, notifications, prompts, progress bar and minigames are ai-lib's, not ai-core's. Use the lib's `notify`, `menu`, `input`, `progress` and `skillCheck` (or the same names on `aiLib`).
</Callout>
