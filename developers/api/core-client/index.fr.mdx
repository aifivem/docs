Un **export client** est une fonction que le côté client d’ai-core offre à toutes les autres ressources dans le jeu du même joueur. Votre script client l’appelle pour lire les données du joueur local, masquer le HUD, ajouter une entrée au menu radial, vérifier un objet, jouer une emote, etc.

La plupart de ces exports sont des **couches** : ai-core ne fait pas le travail lui-même, il transmet l’appel au script que le serveur utilise pour cette tâche (l’inventaire, le script de vêtements, le menu radial, le menu d’emotes, le script de mort, le MDT). Votre script appelle un seul nom et continue de fonctionner quand le propriétaire du serveur remplace l’un de ces scripts par un autre.

## Avant de commencer

- Chaque export client est **synchrone** : il répond tout de suite et n’attend jamais. Rien sur ces pages ne renvoie de Promise, et rien n’a besoin d’un thread en Lua. Le seul export dont la réponse demande du temps (`OpenItemPicker`) répond par un événement.
- Appelez-les uniquement depuis du code **client**. Le serveur a sa propre liste : [exports serveur d’ai-core](/fr/docs/developers/api/core-server).
- ai-core doit être démarré. Une ressource qui peut tourner sans ai-core utilise `optionalExport("ai-core")` en TypeScript (il vaut `null` tant qu’ai-core est arrêté).
- Chaque export répond aussi avec la casse de la première lettre inversée : `GetPlayerData` et `getPlayerData` sont la même fonction.
- Ce qu’une ressource ajoute via ces exports (raisons de masquage du HUD, aides de touches, entrées radiales, pauses de la synchro du monde) appartient à cette ressource. ai-core les retire quand la ressource s’arrête, si bien qu’un crash ou un redémarrage ne laisse jamais le HUD masqué ni une entrée de menu morte.

## Appeler un export

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aicore-fivem/lib/client";

// Un seul handle typé, en haut du fichier. Les types viennent de @aicore-fivem/shared (AiCoreClientExports).
const core = resourceExport("ai-core");

RegisterCommand(
  "myjob",
  () => {
    const data = core.GetPlayerData();
    console.log(data ? `job: ${data.job.job}` : "no character loaded");
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('myjob', function()
  local data = exports['ai-core']:GetPlayerData()
  print(data and ('job: %s'):format(data.job.job) or 'no character loaded')
end, false)
```
</Tab>
</Tabs>

## Utilisez l’utilitaire de la lib quand il existe

La plupart des exports ont un utilitaire dans `@aicore-fivem/lib/client` et le même utilitaire sur `aiLib` pour les ressources Lua (`shared_script '@ai-lib/init.lua'`). Les utilitaires appellent l’export pour vous, vérifient sa réponse et ajoutent un écouteur de changement quand il en existe un. Préférez-les ; appelez l’export directement quand vous ne pouvez pas utiliser la lib.

## N’appelez pas les exports à chaque frame

Les exports franchissent la frontière d’une ressource, ce qui coûte plus qu’un appel de fonction local. Lisez une valeur une fois, puis suivez l’événement qui vous dit quand elle change. Chaque page nomme cet événement ; ils sont tous listés dans [Événements et état](/fr/docs/developers/api/events).

<Callout type="info">
Les menus, boîtes de saisie, notifications, invites, la barre de progression et les mini-jeux appartiennent à ai-lib, pas à ai-core. Utilisez `notify`, `menu`, `input`, `progress` et `skillCheck` de la lib (ou les mêmes noms sur `aiLib`).
</Callout>
