---
title: Weather and time sync
description: Pause the server's weather and time sync on one player's game while your script sets its own (an interior, a scene), resume it, and read whether it is paused.
icon: CloudSun
---

The weather script (ai-weathersync, or a third-party one) keeps every player on the server's weather and clock. When your script needs its own weather or time on one player's screen (a dark interior, a character creator, a cut scene), pause the sync first, otherwise the weather script overwrites your values a moment later.

Pausing works with **reasons**, like the HUD: the sync stays paused while at least one reason is set and runs again when the last one is cleared. Reasons belong to the resource that set them and are removed when it stops. ai-core tells the weather script through its own client event `ai-core:client:worldSync` and through the common pause events third-party weather scripts listen to (qb-weathersync, cd_easytime, vSync, av_weather). The other way round, when a script sends one of those events itself, ai-core counts it as a reason too, so one script's resume never ends another script's pause.

### PauseWorldSync

Pauses the weather and time sync on this player's game under a reason of your resource.

**Side:** Client · **Waits:** no

```ts title="Signature"
PauseWorldSync(reason: string): void
```

```lua title="Lua"
exports['ai-core']:PauseWorldSync(reason) -- or aiLib.world.pauseSync(reason)
```

#### Parameters

<TypeTable
  type={{
    reason: { type: 'string', description: 'A name for why you pause it (`"interior"`). Only your resource can clear it. Pausing again under the same name changes nothing.', required: true },
  }}
/>

#### Returns

Nothing. A `reason` that is not a string is ignored.

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/interior.ts"
import { world } from "@aicore-fivem/lib/client";

// A dark, clear night inside a custom interior, back to the server's weather on leaving.
export function enterInterior(): void {
  world.pauseSync("interior"); // same as resourceExport("ai-core").PauseWorldSync("interior")
  NetworkOverrideClockTime(23, 0, 0);
  SetWeatherTypeNowPersist("CLEAR");
}

export function leaveInterior(): void {
  NetworkClearClockTimeOverride();
  world.resumeSync("interior");
}
```
</Tab>
<Tab value="Lua">
```lua title="client/interior.lua"
-- A dark, clear night inside a custom interior, back to the server's weather on leaving.
local function enterInterior()
  aiLib.world.pauseSync('interior') -- same as exports['ai-core']:PauseWorldSync('interior')
  NetworkOverrideClockTime(23, 0, 0)
  SetWeatherTypeNowPersist('CLEAR')
end

local function leaveInterior()
  NetworkClearClockTimeOverride()
  aiLib.world.resumeSync('interior')
end
```
</Tab>
</Tabs>

<Callout type="warn">
The pause only stops the sync. Setting your own weather and time, and clearing them when you are done, is your script's job.
</Callout>

### ResumeWorldSync

Clears one pause reason of your resource. The sync runs again, and the weather script puts the server's weather and clock back, when no reason is left.

**Side:** Client · **Waits:** no

```ts title="Signature"
ResumeWorldSync(reason: string): void
```

```lua title="Lua"
exports['ai-core']:ResumeWorldSync(reason) -- or aiLib.world.resumeSync(reason)
```

#### Parameters

<TypeTable
  type={{
    reason: { type: 'string', description: 'The name you passed to `PauseWorldSync`. A name your resource never set does nothing.', required: true },
  }}
/>

#### Returns

Nothing.

#### Example

See the example of [PauseWorldSync](#pauseworldsync).

### IsWorldSyncPaused

Tells whether the sync is paused right now by any resource or third-party pause event. A weather script that starts later reads it once; afterwards it follows the client event `ai-core:client:worldSync`.

**Side:** Client · **Waits:** no

```ts title="Signature"
IsWorldSyncPaused(): boolean
```

```lua title="Lua"
local paused = exports['ai-core']:IsWorldSyncPaused() -- boolean
```

#### Parameters

None.

#### Returns

`boolean`: `true` while at least one reason is set, `false` when the sync runs.

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/weather.ts"
import { resourceExport } from "@aicore-fivem/lib/client";
import { CORE } from "@aicore-fivem/shared";

const core = resourceExport("ai-core");

// A weather script of your own: stop applying the server's weather while paused.
let paused = core.IsWorldSyncPaused();
on(CORE.clientWorldSyncEvent, (value: boolean) => {
  paused = value;
});

export const shouldApplyWeather = (): boolean => !paused;
```
</Tab>
<Tab value="Lua">
```lua title="client/weather.lua"
-- A weather script of your own: stop applying the server's weather while paused.
local paused = exports['ai-core']:IsWorldSyncPaused()
AddEventHandler('ai-core:client:worldSync', function(value) paused = value end)

function ShouldApplyWeather() return not paused end
```
</Tab>
</Tabs>
