**Eksport kliencki** to funkcja, którą kliencka strona ai-core oferuje każdemu innemu zasobowi w grze tego samego gracza. Twój skrypt kliencki wywołuje go, aby odczytać dane lokalnego gracza, ukryć HUD, dodać element menu radialnego, sprawdzić przedmiot, odtworzyć emotkę i tak dalej.

Większość tych eksportów to **warstwy**: ai-core nie wykonuje zadania sam, tylko przekazuje wywołanie do skryptu, którego serwer używa do tego zadania (ekwipunek, skrypt ubrań, menu radialne, menu emotek, skrypt śmierci, MDT). Twój skrypt wywołuje jedną nazwę i działa dalej, gdy właściciel serwera zamieni jeden z tych skryptów na inny.

## Zanim zaczniesz

- Każdy eksport kliencki jest **synchroniczny**: odpowiada od razu i nigdy nie czeka. Nic na tych stronach nie zwraca Promise i nic nie potrzebuje wątku w Lua. Jedyny eksport, którego odpowiedź wymaga czasu (`OpenItemPicker`), odpowiada przez zdarzenie.
- Wywołuj je tylko z kodu **klienckiego**. Serwer ma własną listę: [eksporty serwerowe ai-core](/pl/docs/developers/api/core-server).
- ai-core musi być uruchomiony. Zasób, który może działać bez ai-core, używa w TypeScript `optionalExport("ai-core")` (jest `null`, dopóki ai-core jest zatrzymany).
- Każdy eksport odpowiada też z zamienioną wielkością pierwszej litery: `GetPlayerData` i `getPlayerData` to ta sama funkcja.
- Rzeczy, które zasób dodaje przez te eksporty (powody ukrycia HUD, podpowiedzi klawiszy, elementy radialne, wstrzymania synchronizacji świata), należą do tego zasobu. ai-core usuwa je, gdy zasób się zatrzymuje, więc awaria lub restart nigdy nie zostawia ukrytego HUD ani martwego elementu menu.

## Wywołanie eksportu

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { resourceExport } from "@aifivem/lib/client";

// Jeden typowany uchwyt na początku pliku. Typy pochodzą z @aifivem/shared (AiCoreClientExports).
const core = resourceExport("ai-core");

RegisterCommand(
  "myjob",
  () => {
    const data = core.GetPlayerData();
    console.log(data ? `job: ${data.job.job}` : "no character loaded");
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('myjob', function()
  local data = exports['ai-core']:GetPlayerData()
  print(data and ('job: %s'):format(data.job.job) or 'no character loaded')
end, false)
```
</Tab>
</Tabs>

## Używaj funkcji pomocniczej liba, gdy istnieje

Większość eksportów ma funkcję pomocniczą w `@aifivem/lib/client` i tę samą funkcję w `aiLib` dla zasobów Lua (`shared_script '@ai-lib/init.lua'`). Funkcje pomocnicze wywołują eksport za ciebie, sprawdzają jego odpowiedź i dodają nasłuchiwanie zmian, gdzie ono istnieje. Preferuj je; wywołuj eksport bezpośrednio, gdy nie możesz użyć liba.

## Nie wywołuj eksportów w każdej klatce

Eksporty przechodzą przez granicę zasobu, co kosztuje więcej niż wywołanie lokalnej funkcji. Odczytaj wartość raz, potem śledź zdarzenie, które mówi, kiedy się zmienia. Każda strona wymienia to zdarzenie; wszystkie są w [Zdarzenia i stan](/pl/docs/developers/api/events).

<Callout type="info">
Menu, okna wprowadzania, powiadomienia, podpowiedzi, pasek postępu i minigry należą do ai-lib, nie do ai-core. Używaj `notify`, `menu`, `input`, `progress` i `skillCheck` z liba (albo tych samych nazw w `aiLib`).
</Callout>
