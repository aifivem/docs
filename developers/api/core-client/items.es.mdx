title: Objetos

icon: Package
---

Estos exports pasan por la **capa de inventario** de ai-core: responde el inventario que eligió el dueño del servidor (ai-inventory, o un inventario de terceros compatible). Tu script nunca llama a los exports de un inventario concreto, así que sigue funcionando cuando cambia el inventario. Mientras no hay ningún inventario en marcha, las comprobaciones responden `false` / `null` y abrir no hace nada.

El cliente solo lee y abre. Dar y quitar objetos siempre ocurre en el servidor (`inventory` de la lib en el servidor, o los exports de servidor de ai-core), donde el servidor comprueba primero al jugador.

### OpenInventory

Abre la pantalla del inventario propio del jugador en el inventario activo (con lo que ese inventario muestre alrededor: el suelo, un maletero, una guantera).

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
OpenInventory(): void
```

```lua title="Lua"
exports['ai-core']:OpenInventory() -- o aiLib.inventory.openInventory()
```

#### Parámetros

Ninguno.

#### Devuelve

Nada. Sin un inventario activo no se abre nada.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { inventory } from "@aicore-fivem/lib/client";

RegisterCommand("bag", () => inventory.openInventory(), false);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
RegisterCommand('bag', function() aiLib.inventory.openInventory() end, false)
```
</Tab>
</Tabs>

### HasItem

Indica si el jugador tiene al menos cierta cantidad de un objeto. Úsalo para mostrar u ocultar una opción (un elemento radial, una opción de target) antes de pedir al servidor que haga algo.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
HasItem(item: string, count?: number): boolean
```

```lua title="Lua"
local has = exports['ai-core']:HasItem(item, count) -- o aiLib.inventory.hasItem(item, count)
```

#### Parámetros

<TypeTable
  type={{
    item: { type: 'string', description: 'El nombre del objeto tal como lo conoce el inventario (`"lockpick"`).', required: true },
    count: { type: 'number', description: 'Cuántos debe tener el jugador. Un valor ausente, cero o negativo cuenta como 1.', default: '1' },
  }}
/>

#### Devuelve

`boolean`: `true` cuando el jugador tiene al menos `count`. `false` cuando tiene menos, cuando `item` no es una cadena o cuando no hay ningún inventario en marcha.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/index.ts"
import { inventory, notify, triggerServerCallback } from "@aicore-fivem/lib/client";
import { Locale } from "common";

RegisterCommand(
  "picklock",
  async () => {
    // Una comprobación rápida para el jugador; el servidor vuelve a comprobar el objeto antes de hacer nada.
    if (!inventory.hasItem("lockpick")) return notify(Locale("NEED_LOCKPICK"), "error");
    await triggerServerCallback("myscript:picklock", []);
  },
  false,
);
```
</Tab>
<Tab value="Lua">
```lua title="client.lua"
local Locale = aiLib.locale()

RegisterCommand('picklock', function()
  -- Una comprobación rápida para el jugador; el servidor vuelve a comprobar el objeto antes de hacer nada.
  if not aiLib.inventory.hasItem('lockpick') then
    return aiLib.notify(Locale('NEED_LOCKPICK'), 'error')
  end
  CreateThread(function()
    aiLib.triggerServerCallback('myscript:picklock', {}) -- espera la respuesta del servidor
  end)
end, false)
```
</Tab>
</Tabs>

<Callout type="warn">
Un tramposo puede falsear la respuesta de un cliente. Usa `HasItem` para lo que ve el jugador; el servidor debe comprobar y quitar el objeto por sí mismo.
</Callout>

### GetCurrentWeapon

Devuelve el objeto de arma que el jugador tiene en la mano, con su etiqueta y su imagen, a través del inventario activo.

**Lado:** Cliente · **Espera:** no

```ts title="Firma"
GetCurrentWeapon(): HeldWeapon | null
```

```lua title="Lua"
local weapon = exports['ai-core']:GetCurrentWeapon() -- { name, label, image? } o nil
```

#### Parámetros

Ninguno.

#### Devuelve

[`HeldWeapon`](/es/docs/developers/api/types#heldweapon) mientras hay un objeto de arma en la mano, `null` cuando las manos están vacías o no hay ningún inventario en marcha.

<TypeTable
  type={{
    name: { type: 'string', description: 'El nombre del objeto (`"WEAPON_PISTOL"`).', required: true },
    label: { type: 'string', description: 'El nombre visible del objeto.', required: true },
    image: { type: 'string', description: 'Url de la imagen (`nui://...`); ausente cuando el inventario no tiene.' },
  }}
/>

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/weapon.ts"
import { inventory, onCache } from "@aicore-fivem/lib/client";

// Léelo cuando cambie el arma en la mano, no en cada frame.
onCache("weapon", () => {
  const weapon = inventory.currentWeapon();
  SendNUIMessage({ action: "weapon", data: weapon });
});
```
</Tab>
<Tab value="Lua">
```lua title="client/weapon.lua"
-- Léelo cuando cambie el arma en la mano, no en cada frame.
aiLib.cache.onChange('weapon', function()
  local weapon = aiLib.inventory.currentWeapon()
  SendNUIMessage({ action = 'weapon', data = weapon })
end)
```
</Tab>
</Tabs>

### OpenItemPicker

Abre el selector de objetos de ai-core: una cuadrícula con buscador de cada objeto del inventario activo con imágenes, donde el jugador arma una lista de objetos y cantidades. Está pensado para herramientas de admin (dar objetos a un jugador): la lista de objetos viene del servidor, que solo se la envía a los admins. La lista que toma el jugador llega más tarde como el evento de cliente `ai-lib:client:menuResult`.

**Lado:** Cliente · **Espera:** no (la respuesta llega como un evento; el `itemPicker` de la lib espera por ti)

```ts title="Firma"
OpenItemPicker(requestId: number, request: ItemPickerRequest): void
```

```lua title="Lua"
local list = aiLib.itemPicker({ title = 'Give items', target = 12 }) -- espera; llámalo dentro de un thread
```

#### Parámetros

<TypeTable
  type={{
    requestId: { type: 'number', description: 'Tu número para esta petición. Vuelve en el evento de respuesta para que sepas a qué petición responde.', required: true },
    request: { type: 'ItemPickerRequest', description: 'El título del selector y para el inventario de quién son los objetos. Campos abajo.', required: true, typeDescriptionLink: '/docs/developers/api/types#itempickerrequest' },
  }}
/>

#### ItemPickerRequest

Consulta también [ItemPickerRequest](/es/docs/developers/api/types#itempickerrequest).

<TypeTable
  type={{
    title: { type: 'string', description: 'El título encima del selector, ya traducido. Se corta a 60 caracteres.', required: true },
    target: { type: 'number', description: 'Id de servidor del jugador que recibirá los objetos. Su peso libre limita lo que se puede tomar. Si se omite, el admin que elige.' },
  }}
/>

#### Devuelve

Nada en el momento. Más tarde ai-core dispara `ai-lib:client:menuResult` con `(resource, requestId, value)`: `value` es una lista [`PickedItem[]`](/es/docs/developers/api/types#pickeditem) (`{ name, count }`) cuando el jugador la tomó, `null` cuando cerró el selector. El `itemPicker(request)` de la lib devuelve `Promise<PickedItem[] | null>` con ese valor, y `aiLib.itemPicker(request)` devuelve la lista o `nil`.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts title="resource/client/admin.ts"
import { itemPicker, triggerServerCallback } from "@aicore-fivem/lib/client";
import { Locale } from "common";

// Herramienta de admin: elige objetos para un jugador, el servidor comprueba al admin y da cada objeto.
export async function giveItemsTo(target: number): Promise<void> {
  const list = await itemPicker({ title: Locale("GIVE_ITEMS"), target });
  if (!list || list.length === 0) return;
  await triggerServerCallback("myadmin:giveItems", [target, list]);
}
```
</Tab>
<Tab value="Lua">
```lua title="client/admin.lua"
local Locale = aiLib.locale()

-- Herramienta de admin: elige objetos para un jugador, el servidor comprueba al admin y da cada objeto.
local function giveItemsTo(target)
  CreateThread(function()
    local list = aiLib.itemPicker({ title = Locale('GIVE_ITEMS'), target = target })
    if not list or #list == 0 then return end
    aiLib.triggerServerCallback('myadmin:giveItems', { target, list })
  end)
end
```
</Tab>
</Tabs>

<Callout type="warn">
El selector solo muestra objetos a los admins (`ai.admin`): para cualquier otro la cuadrícula está vacía. El servidor responde como mucho a dos aperturas por jugador en 2 segundos; un `target` que no está conectado cuenta como el admin que elige. La respuesta del jugador son datos del cliente: tu servidor debe comprobar que quien llama es admin y comprobar cada objeto y cantidad antes de dar nada.
</Callout>
