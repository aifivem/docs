Los scripts ai-* nunca se llaman entre sí para una tarea compartida: objetos, llaves, alertas, prisión, médico, aspectos, elementos del radial y clima pasan por ai-core (la lib), que llama a los exports de abajo. Llámalos tú mismo solo para lo que es propio de ese script. Los exports tipados en `@aicore-fivem/shared` funcionan con `resourceExport("ai-...")`; los demás con `callExport(resource, name, ...args)` o una llamada normal a `exports[...]`.

Cuando un script sustituye a otro (`provide`), también responden los nombres de export del otro script, así que `exports.ox_inventory:AddItem(...)` llega a ai-inventory.

## ai-lib

La interfaz compartida del jugador. Exports de cliente, tipados `AiLibClientExports`; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` y `lockpick` de la lib los llaman por ti.

| Export | Qué |
| --- | --- |
| `Notify(notification: Notification): void` | Una tarjeta de notificación (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Muestra la barra de progreso durante `duration` ms (quien llama ejecuta la acción). |
| `HideProgress(): void` | La oculta. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Muestra o actualiza el prompt de quien llama; `at` lo dibuja sobre un punto del mundo. |
| `HidePrompt(id: string): void` | Oculta un prompt. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Un menú; la elección llega como `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Un diálogo de entrada; los valores llegan como `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Una prueba de habilidad o una cerradura; el resultado llega como `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Cierra el menú o la entrada abiertos de quien llama (responde con null). |

El evento de servidor `ai-lib:client:notify` (`LIB_UI.notifyEvent`) con una `Notification` muestra una tarjeta en la pantalla de ese jugador.

## ai-inventory

Exports de servidor (propios): los demás scripts ai-* llegan a ellos a través de la capa de inventario de ai-core.

| Export | Qué |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Añade objetos. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Quita objetos. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Cuántos hay. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Cada pila con su etiqueta. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Si cabe. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | Si `handler` devuelve false se conserva el objeto; si no, se toma su cantidad `consume`. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Un stash. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Abre un inventario en la pantalla de un jugador. |
| `ClearInventory(inv: number \| string): void` | Lo vacía. |
| `Items(name?: string): unknown` | Una definición de objeto (forma de ox), o todas. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Peso cargado y límite en gramos. |

Exports de cliente: `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (el inventario propio con el suelo, el maletero o la guantera alrededor), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Evento local del servidor `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### API de ox_inventory

ai-inventory hace `provide` de `ox_inventory` y responde a sus exports (ox_inventory 2.44). Los inventarios se nombran como en ox: el source de un jugador, un nombre de stash, `{ id, owner }` para stashes personales, una matrícula para maleteros.

- Servidor: `AddItem` (devuelve `success, response`, llama a `cb`), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (stash, jugador, tienda), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Cliente: `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon`; `displayMetadata`, `weaponWheel`, `setStashTarget` se aceptan y no hacen nada.
- Sin respuesta: hooks (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (las tiendas vienen del panel).

### API de qb-inventory

ai-inventory hace `provide` de `qb-inventory` (API 2.0). Los objetos devueltos llevan ambas formas: `count` / `metadata` y `amount` / `info`.

- Servidor: `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (nombre, lista o `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Cliente: `HasItem`, `CloseInventory`.
- Sin respuesta: hooks y listeners, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.

## ai-vehicles

Vehículos con dueño. Exports de servidor, tipados `AiVehiclesServerExports`. `VehicleOwner` es `{ type: "character" \| "job" \| "gang" \| "resource", id }`.

| Export | Qué |
| --- | --- |
| `CreateVehicle(owner: VehicleOwner, model: string, garage: string \| null, props?): { id, plate } \| null` | Registra un nuevo vehículo con dueño. |
| `GetVehicle(ref: number \| string): OwnedVehicle \| null` | Un vehículo por id o matrícula. |
| `GetVehicles(owner: VehicleOwner): OwnedVehicle[]` | Vehículos de un personaje conectado, o la flota de un trabajo o banda. |
| `IsOwnedPlate(plate: string): boolean` | Si una matrícula pertenece a un vehículo con dueño. |
| `GetVehicleIdByEntity(entity: number): number \| null` | El id de un vehículo con dueño aparecido. |
| `GetPlateOwners(): [plate, type, id][]` | Cada vehículo con dueño en memoria (después sigue `ai-vehicles:owners`). |
| `GetEntity(id: number): number \| null` | La entidad aparecida de un vehículo. |
| `SaveVehicle(id: number, change: { props?, fuel?, engine?, body?, state?, garage? }): void` | Guarda estado y aspecto; el tuning guardado se mantiene. |
| `SaveTuning(id: number, props: unknown): void` | Guarda las props completas con el tuning (solo talleres de tuning). |
| `StoreVehicle(id: number, garage: string \| null, state?: VehicleState): void` | Mete un vehículo en un garaje (`garage`, `out`, `impound`). |
| `SetOwner(id: number, owner: VehicleOwner): void` | Cambia el dueño. |
| `DeleteVehicle(id: number): void` | Borra un vehículo. |
| `SpawnVehicle(id: number, at: { x, y, z, heading }, asker: number, cb: (netId: number \| null) => void, purpose?: KeyPurpose, setup?): void` | Crea la entidad; `cb` recibe su net id. |

ai-vehicles hace `provide` de `qbx_vehicles`: `GetPlayerVehicles(filters)`, `GetPlayerVehicle(id)`, `CreatePlayerVehicle(request)`, `SetPlayerVehicleOwner(id, citizenid)`, `DeletePlayerVehicles(idType, idValue)`, `GetVehicleIdByPlate(plate)`, `DoesPlayerVehiclePlateExist(plate)`, `SaveVehicle(entity, options)` (los filtros por citizenid necesitan al dueño conectado).

## ai-vehiclekeys

| Export | Qué |
| --- | --- |
| `HasKeys(source: number, vehicle: number \| string): boolean` | Si el jugador tiene las llaves. |
| `GiveKeys(source: number, vehicle: number \| string): void` | Da llaves. |
| `RemoveKeys(source: number, vehicle: number \| string): void` | Quita llaves. |
| `SetLockState(vehicle, state)` | Cierra (`"lock"`, `true`, `2`) o abre una entidad de vehículo. |
| `IsPlayerNearVehicle(source, vehicle)` | Si el jugador está cerca del vehículo. |

## ai-death

Exports de servidor, tipados `AiDeathServerExports`; `Revive` e `IsDead` también bajo `qbx_medical`. Los scripts usan en su lugar la capa médica de ai-core (`medical` de la lib).

| Export | Qué |

| `IsDead(source: number): boolean` | Si el jugador está abatido. |

## ai-radialmenu

Exports de cliente propios (tipados `AiRadialClientExports`): `AddItem(item)` (`onSelect` se acepta como `onPressed`), `RemoveItem(id, parent?)`, `Refresh()`. Los scripts usan `radial` de la lib.

Hace `provide` de las API de otras ruedas:

- `qb-radialmenu`: `AddOption(data, id?)` devuelve el id, `RemoveOption(id)`.
- `tgiann-radialmenu-target`: `AddMenuItem(item | items, parentId?)`, `RemoveMenuItem(id, parentId?)`, `ClearMenuItems()`, `RegisterSubMenu({ id, items })`, `RefreshMenu()`, `DisableMenu(state)`, `IsMenuDisabled()`, `OpenMenu()`, `CloseMenu()`, `IsMenuOpen()`, `HasMenuItem(id)`, `SetMenuItemHidden(id, state)`, `IsMenuItemHidden(id)`, `UpdateMenuItem(id, { label?, icon? })`, `ResetMenuItem(id)`.

## ai-target

Responde a la API de cliente de ox_target bajo `ai-target` y `ox_target`: `addSphereZone`, `addBoxZone`, `addPolyZone`, `removeZone`, `zoneExists`, `addModel`, `removeModel`, `addEntity`, `removeEntity`, `addLocalEntity`, `removeLocalEntity`, `addGlobalPed` / `Vehicle` / `Object` / `Player` y sus `removeGlobal*`, `disableTargeting`, `isActive`. `addGlobalOption` no se ofrece (registra un aviso). Los scripts usan `Points` de la lib, que elige prompt o target según el ajuste del dueño.

## ai-voice

Sustituye a pma-voice 7.x (hace `provide` de `pma-voice`, `mumble-voip`, `tokovoip`, `toko-voip`, `tokovoip_script`).

- Servidor, nombres de pma-voice: `setPlayerRadio`, `setPlayerCall`, `getPlayersInRadioChannel` / `GetPlayersInRadioChannel`, `addChannelCheck`, `overrideRadioNameGetter`, `isValidPlayer`.
- Servidor, propios: `getBackend`, `setPlayerProximityMode(source, index)`, `setPlayerRange(source, metres | null)`, `getPlayerProximity(source)`, `toggleMute(source, seconds?)`, `addProximityCheck(fn(source, index, distance))` (false rechaza), `addPlayerRadioListen` / `removePlayerRadioListen` / `setPlayerRadioActive(source, channel)`, `getPlayerRadioChannels(source)` (`{ active, channels }`), `addCallCheck(fn(source, callId))` (true permite), `setPlayerCallSpeaker(source, on)` / `getPlayerCallSpeaker(source)`, `setPlayerSubmix(source, name | null)`.
- Cliente: los exports de cliente de pma-voice (`setRadioChannel`, `setCallChannel`, `setRadioVolume`, `setCallVolume`, `setVoiceProperty`, `overrideProximityRange`, `toggleMutePlayer`, `toggleRadioAnim`...) más `addRadioDisableBit` / `removeRadioDisableBit`, `registerCustomSubmix`, `setEffectSubmix`; propios `addRadioChannel` / `removeRadioChannel` / `setActiveRadioChannel` / `getRadioChannels`, `setCallSpeaker` / `getCallSpeaker`, `setRadioAnimDisabled`, `createSubmix(name, spec)` / `getSubmix` / `editSubmix` / `listSubmixes`, `cycleProximity`, `getBackend`, `isRadioTalking`.
- Eventos locales: cliente `pma-voice:setTalkingMode`, `pma-voice:radioActive`, `pma-voice:toggleRadioAnim`; servidor `pma-voice:playerMuted`.

## ai-chat

Sustituye al recurso `chat` de FiveM.

- Cliente: exports `addMessage(message)`, `addSuggestion(name, help, params)`; eventos `chat:addMessage`, `chatMessage (author, color, text)`, `chat:addSuggestion(s)`, `chat:removeSuggestion`, `chat:addMode` / `chat:removeMode`, `chat:clear`.
