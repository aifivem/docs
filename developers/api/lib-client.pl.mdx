```ts title="TypeScript"
import { Points, notify, progress, cache } from "@aicore-fivem/lib/client";
```

Wejście klienckie eksportuje też funkcje `/fivem` (`every`, `ByResource`, `Reasons`, `caller`, `onStop`, `plateOf`, funkcje eksportów i tłumaczeń, klasy state bagów): zobacz [Lib: shared i fivem](/pl/docs/developers/api/lib-shared). Ostatnia kolumna podaje odpowiednik w `aiLib` ([Lib dla Lua](/pl/docs/developers/api/lua)).

## Rozmowa z serwerem

| Funkcja | Co | Lua |
| --- | --- | --- |
| `triggerServerCallback(name, args = [], timeoutMs?): Promise<unknown>` | Pyta serwer (tam `onClientCallback`); przeparsuj odpowiedź. | `triggerServerCallback` |
| `onServerCallback(name, handler: (...args) => unknown): void` | Odpowiada na `triggerClientCallback` serwera. | `onServerCallback` |
| `onServerEvent(name, handler)` / `onServerEvent(name, { args }, handler)` | Zdarzenie sieciowe z serwera; wywołania, które nie przyszły z serwera, są odrzucane. `args` parsuje ładunek. | `onServerEvent` |
| `fromServer(): boolean` | Czy obsługiwane zdarzenie przyszło z serwera. | |
| `callAction(name, args = [], { fallback, timeout?, silent? })` | Uruchamia akcję na serwerze, sam pokazuje przetłumaczoną odmowę, zwraca odpowiedź ok albo null. | `callAction` |
| `isActionOk(reply)`, `replyError(reply, fallback)` | Ręczne czytanie `ActionResult`. | |

```ts title="TypeScript"
const reply = await callAction("buy", [itemId], { fallback: "BUY_FAILED" });
if (reply) notify(t("BOUGHT"), "success");
```

## Miejsca i świat

| Funkcja | Co | Lua |
| --- | --- | --- |
| `new Points()` | Każde miejsce, z którego korzysta gracz: prompt albo target (wybór właściciela), NPC, blip. | `Points.new()` |
| `points.add(id, { coords, label, icon?, radius?, height?, canShow?, onPressed, onEnter?, onExit?, ped?, blip?, world?, promptOnly?, preferTarget? })` | Dodaje punkt; `label` może być funkcją. | `points:add` |
| `points.addModel(id, { models, label, icon?, radius?, canShow?(entity), onPressed(entity), vehicles?, inVehicle? })` | Punkt na każdym obiekcie danych modeli (bankomaty, krzesła). | `points:addModel` |
| `points.addVehicle(id, { label, icon?, radius?, canShow?(vehicle), onPressed(vehicle) })` | Punkt na każdym pojeździe sieciowym. | `points:addVehicle` |
| `points.remove(id)`, `clear()`, `refresh(id?)`, `isInside(id)` | Zarządzanie punktami; `refresh` ponownie czyta `canShow`. | |
| `new Zones()`: `add(id, options)`, `remove`, `clear`, `isInside`, `size` | Obszary bez interakcji. | `Zones.new()` |
| `new LocalPed({ model, coords, ... })`: `entity`, `remove` | Ped widoczny tylko dla tego klienta, tworzony w pobliżu gracza. | `LocalPed.new()` |
| `new Blips()`: `add(id, options)`, `get`, `remove`, `clear`; `createBlip(options)` | Nazwane blipy. | `Blips.new()`, `Blips.create()` |
| `showPrompt(id, text, at?)`, `hidePrompt(id)`, `onPromptPressed(handler)` | Prompt ai-lib ręcznie (`Points` go używa). | `showPrompt`, `hidePrompt`, `onPromptPressed` |
| `new AdminWorld(files)`: `get`, `onChange`, `view`, `records` | Kopia kliencka plików panelu skryptu z `sync: "all"`. | |

```ts title="TypeScript"
const points = new Points();
points.add("shop", {
  coords: { x: 25.7, y: -1347.3, z: 29.5 },
  label: t("OPEN_SHOP"),
  icon: "basket-shopping",
  blip: { sprite: 52, color: 2, scale: 0.8, label: t("SHOP") },
  onPressed: () => openShop(),
});
```

const done = await progress({
