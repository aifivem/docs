Les scripts ai-* ne s’appellent jamais entre eux pour une tâche partagée : objets, clés, alertes, prison, médical, apparences, entrées radiales et météo passent par ai-core (la lib), qui appelle les exports ci-dessous. Appelez-les vous-même seulement pour ce qui est propre à ce script. Les exports typés dans `@aicore-fivem/shared` fonctionnent avec `resourceExport("ai-...")` ; les autres avec `callExport(resource, name, ...args)` ou un simple appel `exports[...]`.

Quand un script en remplace un autre (`provide`), les noms d’export de l’autre script répondent aussi : `exports.ox_inventory:AddItem(...)` arrive à ai-inventory.

## ai-lib

L’interface joueur partagée. Exports client, typés `AiLibClientExports` ; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` et `lockpick` de la lib les appellent pour vous.

| Export | Rôle |
| --- | --- |
| `Notify(notification: Notification): void` | Une carte de notification (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Affiche la barre de progression pendant `duration` ms (l’appelant exécute l’action). |
| `HideProgress(): void` | La masque. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Affiche ou met à jour le prompt de l’appelant ; `at` le dessine au-dessus d’un point du monde. |
| `HidePrompt(id: string): void` | Masque un prompt. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Un menu ; le choix arrive comme `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Un dialogue de saisie ; les valeurs arrivent comme `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Un test d’adresse ou un crochetage ; le résultat arrive comme `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Ferme le menu ou la saisie ouverts de l’appelant (réponse null). |

L’événement serveur `ai-lib:client:notify` (`LIB_UI.notifyEvent`) avec une `Notification` affiche une carte sur l’écran de ce joueur.

## ai-inventory

Exports serveur (propres) : les autres scripts ai-* les atteignent via la couche d’inventaire d’ai-core.

| Export | Rôle |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Ajoute des objets. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Retire des objets. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Combien. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Chaque pile avec son libellé. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Si ça rentre. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | Si `handler` renvoie false, l’objet reste ; sinon sa quantité `consume` est retirée. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Un coffre. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Ouvre un inventaire sur l’écran d’un joueur. |
| `ClearInventory(inv: number \| string): void` | Le vide. |
| `Items(name?: string): unknown` | Une définition d’objet (forme ox), ou toutes. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Poids porté et limite en grammes. |

Exports client : `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (son propre inventaire avec le sol, le coffre ou la boîte à gants autour), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Événement local serveur `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### API ox_inventory

ai-inventory fait `provide` de `ox_inventory` et répond à ses exports (ox_inventory 2.44). Les inventaires sont nommés comme dans ox : une source de joueur, un nom de coffre, `{ id, owner }` pour les coffres personnels, une plaque pour les coffres de véhicule.

- Serveur : `AddItem` (renvoie `success, response`, appelle `cb`), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (coffre, joueur, boutique), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Client : `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon` ; `displayMetadata`, `weaponWheel`, `setStashTarget` sont acceptés et ne font rien.
- Sans réponse : les hooks (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (les boutiques viennent du panneau).

### API qb-inventory

ai-inventory fait `provide` de `qb-inventory` (API 2.0). Les objets renvoyés portent les deux formes : `count` / `metadata` et `amount` / `info`.

- Serveur : `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (nom, liste ou `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Client : `HasItem`, `CloseInventory`.
- Sans réponse : hooks et listeners, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.

## ai-vehicles

Véhicules possédés. Exports serveur, typés `AiVehiclesServerExports`. `VehicleOwner` vaut `{ type: "character" \| "job" \| "gang" \| "resource", id }`.

| Export | Rôle |
| --- | --- |
| `CreateVehicle(owner: VehicleOwner, model: string, garage: string \| null, props?): { id, plate } \| null` | Enregistre un nouveau véhicule possédé. |
| `GetVehicle(ref: number \| string): OwnedVehicle \| null` | Un véhicule par id ou plaque. |
| `GetVehicles(owner: VehicleOwner): OwnedVehicle[]` | Les véhicules d’un personnage en ligne, ou la flotte d’un métier ou d’un gang. |
| `IsOwnedPlate(plate: string): boolean` | Si une plaque appartient à un véhicule possédé. |
| `GetVehicleIdByEntity(entity: number): number \| null` | L’id d’un véhicule possédé sorti. |
| `GetPlateOwners(): [plate, type, id][]` | Chaque véhicule possédé en mémoire (suivre ensuite `ai-vehicles:owners`). |
| `GetEntity(id: number): number \| null` | L’entité sortie d’un véhicule. |
| `SaveVehicle(id: number, change: { props?, fuel?, engine?, body?, state?, garage? }): void` | Enregistre l’état et l’apparence ; le tuning enregistré reste. |
| `SaveTuning(id: number, props: unknown): void` | Enregistre les props complètes avec le tuning (garages de tuning seulement). |
| `StoreVehicle(id: number, garage: string \| null, state?: VehicleState): void` | Range un véhicule dans un garage (`garage`, `out`, `impound`). |
| `SetOwner(id: number, owner: VehicleOwner): void` | Change le propriétaire. |
| `DeleteVehicle(id: number): void` | Supprime un véhicule. |
| `SpawnVehicle(id: number, at: { x, y, z, heading }, asker: number, cb: (netId: number \| null) => void, purpose?: KeyPurpose, setup?): void` | Crée l’entité ; `cb` reçoit son net id. |

ai-vehicles fait `provide` de `qbx_vehicles` : `GetPlayerVehicles(filters)`, `GetPlayerVehicle(id)`, `CreatePlayerVehicle(request)`, `SetPlayerVehicleOwner(id, citizenid)`, `DeletePlayerVehicles(idType, idValue)`, `GetVehicleIdByPlate(plate)`, `DoesPlayerVehiclePlateExist(plate)`, `SaveVehicle(entity, options)` (les filtres par citizenid demandent que le propriétaire soit en ligne).

## ai-vehiclekeys

| --- | --- |

| `GiveKeys(source: number, vehicle: number \| string): void` | Donne les clés. |

## ai-death

Exports serveur, typés `AiDeathServerExports` ; `Revive` et `IsDead` aussi sous `qbx_medical`. Les scripts utilisent plutôt la couche médicale d’ai-core (lib `medical`).

| Export | Rôle |
| --- | --- |
| `Revive(source: number): boolean` | Relève un joueur à terre ; false s’il n’est pas à terre. |
| `IsDead(source: number): boolean` | Si le joueur est à terre. |
| `Heal(source: number): void` | Santé pleine pour un joueur qui n’est pas à terre. |

## ai-radialmenu

Exports client propres (typés `AiRadialClientExports`) : `AddItem(item)` (`onSelect` est accepté comme `onPressed`), `RemoveItem(id, parent?)`, `Refresh()`. Les scripts utilisent lib `radial`.

Il fait `provide` des API d’autres roues :

- `qb-radialmenu` : `AddOption(data, id?)` renvoie l’id, `RemoveOption(id)`.
- `tgiann-radialmenu-target` : `AddMenuItem(item | items, parentId?)`, `RemoveMenuItem(id, parentId?)`, `ClearMenuItems()`, `RegisterSubMenu({ id, items })`, `RefreshMenu()`, `DisableMenu(state)`, `IsMenuDisabled()`, `OpenMenu()`, `CloseMenu()`, `IsMenuOpen()`, `HasMenuItem(id)`, `SetMenuItemHidden(id, state)`, `IsMenuItemHidden(id)`, `UpdateMenuItem(id, { label?, icon? })`, `ResetMenuItem(id)`.

## ai-target

Répond à l’API client d’ox_target sous `ai-target` et `ox_target` : `addSphereZone`, `addBoxZone`, `addPolyZone`, `removeZone`, `zoneExists`, `addModel`, `removeModel`, `addEntity`, `removeEntity`, `addLocalEntity`, `removeLocalEntity`, `addGlobalPed` / `Vehicle` / `Object` / `Player` et leurs `removeGlobal*`, `disableTargeting`, `isActive`. `addGlobalOption` n’est pas proposé (il journalise un avertissement). Les scripts utilisent lib `Points`, qui choisit prompt ou target selon le réglage du propriétaire.

## ai-voice

Remplace pma-voice 7.x (fait `provide` de `pma-voice`, `mumble-voip`, `tokovoip`, `toko-voip`, `tokovoip_script`).

- Serveur, noms pma-voice : `setPlayerRadio`, `setPlayerCall`, `getPlayersInRadioChannel` / `GetPlayersInRadioChannel`, `addChannelCheck`, `overrideRadioNameGetter`, `isValidPlayer`.
- Serveur, propres : `getBackend`, `setPlayerProximityMode(source, index)`, `setPlayerRange(source, metres | null)`, `getPlayerProximity(source)`, `toggleMute(source, seconds?)`, `addProximityCheck(fn(source, index, distance))` (false refuse), `addPlayerRadioListen` / `removePlayerRadioListen` / `setPlayerRadioActive(source, channel)`, `getPlayerRadioChannels(source)` (`{ active, channels }`), `addCallCheck(fn(source, callId))` (true autorise), `setPlayerCallSpeaker(source, on)` / `getPlayerCallSpeaker(source)`, `setPlayerSubmix(source, name | null)`.
- Client : les exports client de pma-voice (`setRadioChannel`, `setCallChannel`, `setRadioVolume`, `setCallVolume`, `setVoiceProperty`, `overrideProximityRange`, `toggleMutePlayer`, `toggleRadioAnim`...) plus `addRadioDisableBit` / `removeRadioDisableBit`, `registerCustomSubmix`, `setEffectSubmix` ; propres `addRadioChannel` / `removeRadioChannel` / `setActiveRadioChannel` / `getRadioChannels`, `setCallSpeaker` / `getCallSpeaker`, `setRadioAnimDisabled`, `createSubmix(name, spec)` / `getSubmix` / `editSubmix` / `listSubmixes`, `cycleProximity`, `getBackend`, `isRadioTalking`.
- Événements locaux : client `pma-voice:setTalkingMode`, `pma-voice:radioActive`, `pma-voice:toggleRadioAnim` ; serveur `pma-voice:playerMuted`.

## ai-weathersync

## ai-chat

Remplace la ressource `chat` de FiveM.

- Client : exports `addMessage(message)`, `addSuggestion(name, help, params)` ; événements `chat:addMessage`, `chatMessage (author, color, text)`, `chat:addSuggestion(s)`, `chat:removeSuggestion`, `chat:addMode` / `chat:removeMode`, `chat:clear`.

## ai-mysql

Remplace oxmysql : exports sous `ai-mysql` et `oxmysql` : `query`, `single`, `scalar`, `insert`, `update`, `prepare`, `rawExecute`, `transaction`, `startTransaction`, `store`, `isReady`, `awaitConnection`, `execute`, `fetch`, chacun aussi en `<name>_async` / `<name>Sync`. Les noms de ghmattimysql (`execute`, `scalar`, `transaction`, `store`) et de mysql-async (`mysql_execute`, `mysql_insert`, `mysql_fetch_all`, `mysql_fetch_scalar`, `mysql_transaction`, `mysql_store`) aussi ; événements `oxmysql:error`, `oxmysql:transaction-error`.
