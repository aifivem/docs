Strony API zapisują typy po nazwie (`Vec3`, `ActionResult`, `InventoryRef`...). Ta strona wyjaśnia każdy z nich raz: jego pola, co znaczy każde pole i przykładową wartość.

Skąd pochodzi typ:

| Pakiet | Import | Typy |
| --- | --- | --- |
| `@aicore-fivem/shared` | `import type { AiPlayerData } from "@aicore-fivem/shared";` | Wszystko na tej stronie, chyba że nagłówek mówi inaczej. |
| `@aicore-fivem/lib/shared` | `import type { Vec3 } from "@aicore-fivem/lib/shared";` | `Vec3`, `Vec4`, `AccessRule`, `BlipStyle`, `ZoneShape`, `VehicleProps`, `VehicleSetup`, `PlacePed`. |
| `@aicore-fivem/lib/client` | `import type { ProgressOptions } from "@aicore-fivem/lib/client";` | `ProgressOptions`. |
| `@aicore-fivem/lib/server` | `import type { ProgressForOptions } from "@aicore-fivem/lib/server";` | `ProgressForOptions`. |

<Callout type="info">
Lua nie ma typów w czasie działania. Tabela Lua z tymi samymi kluczami to ta sama wartość: `{ x = 1.0, y = 2.0, z = 3.0 }` to `Vec3`. Tablice to listy Lua (`{ 'police', 'sheriff' }`), `null` to `nil`. Wektory opisuje [Lib dla Lua](/pl/docs/developers/api/lua).
</Callout>

## Pozycje

### Vec3

Punkt w świecie, w metrach. W GTA `x` to wschód, `y` to północ, `z` to góra.

<TypeTable
  type={{
    x: { type: 'number', description: 'Pozycja wschód-zachód w metrach.', required: true },
    y: { type: 'number', description: 'Pozycja północ-południe w metrach.', required: true },
    z: { type: 'number', description: 'Wysokość w metrach.', required: true },
  }}
/>

```ts title="Przykład"
const counter: Vec3 = { x: 25.7, y: -1347.3, z: 29.5 };
```

```lua title="Lua"
local counter = vector3(25.7, -1347.3, 29.5) -- albo { x = 25.7, y = -1347.3, z = 29.5 }
```

### Vec4

Punkt z kierunkiem: gdzie stoi ped lub pojawia się pojazd i w którą stronę jest zwrócony. Pola `vec4` panelu i narzędzie punktu w panelu zapisują ten kształt.

<TypeTable
  type={{
    x: { type: 'number', description: 'Pozycja wschód-zachód w metrach.', required: true },
    y: { type: 'number', description: 'Pozycja północ-południe w metrach.', required: true },
    z: { type: 'number', description: 'Wysokość w metrach.', required: true },
    heading: { type: 'number', description: "Kierunek w stopniach, 0-360 (jak w GTA: 0 = północ, przeciwnie do ruchu wskazówek zegara).", required: true },
  }}
/>

```ts title="Przykład"
const spawn: Vec4 = { x: -42.1, y: -1098.4, z: 26.4, heading: 158.0 };
```

<Callout type="info">
`vector4` w Lua nazywa kierunek `w`. Czytniki liba ([readVec4](/pl/docs/developers/api/lib-shared/input#readvec4)) przyjmują zarówno `heading`, jak i `w`.
</Callout>

### ZoneShape

Obszar w świecie. Używany przez klienckie `Zones` i przez serwerowe sprawdzanie obszarów ([geometria stref](/pl/docs/developers/api/lib-shared/zones)). To jeden z trzech kształtów, wybierany przez `type`.

**Sphere** (kula wokół punktu):

<TypeTable
  type={{
    type: { type: '"sphere"', description: 'Wybiera ten kształt.', required: true },
    center: { type: 'Vec3', description: 'Środek kuli.', required: true, typeDescription: '{ x, y, z }' },
    radius: { type: 'number', description: 'Promień w metrach.', required: true },
  }}
/>

**Cylinder** (okrąg na ziemi, sięgający w górę i w dół):

<TypeTable
  type={{
    type: { type: '"cylinder"', description: 'Wybiera ten kształt.', required: true },
    center: { type: 'Vec3', description: 'Środek okręgu.', required: true },
    radius: { type: 'number', description: 'Promień na płaszczyźnie ziemi, w metrach.', required: true },
    height: { type: 'number', description: 'Jak daleko strefa sięga w górę i w dół od `center.z`, w metrach (całkowita wysokość jest dwa razy większa).', required: true },
  }}
/>

**Poly** (wielokąt na ziemi między dwiema wysokościami):

<TypeTable
  type={{
    type: { type: '"poly"', description: 'Wybiera ten kształt.', required: true },
    points: { type: 'Array<{ x: number; y: number }>', description: 'Rogi na ziemi, po kolei wokół obszaru. Co najmniej 3.', required: true },
    minZ: { type: 'number', description: 'Najniższa wysokość wewnątrz strefy.', required: true },
    maxZ: { type: 'number', description: 'Najwyższa wysokość wewnątrz strefy.', required: true },
  }}
/>

```ts title="Przykład"

const lot: ZoneShape = {
  type: "poly",
  points: [ { x: 210, y: -810 }, { x: 240, y: -800 }, { x: 230, y: -770 }, { x: 200, y: -780 } ],
  minZ: 28,
  maxZ: 36,
};
```

## Wyniki

### ActionResult

Odpowiedź każdej akcji serwera dla klienta: albo sukces, albo klucz językowy, który klient pokazuje jako powód. Dodatkowe pola mogą jechać na gałęzi sukcesu (`ActionResult<{ id: number }>`). Sam nowy stan nigdy nie podróżuje w odpowiedzi: przychodzi jako delta.

**Sukces:**

<TypeTable
  type={{
    ok: { type: 'true', description: 'Akcja została wykonana.', required: true },
    '...T': { type: 'T', description: 'Dodatkowe pola `ActionResult<T>` (na przykład id nowego rekordu).' },
  }}
/>

**Odmowa:**

<TypeTable
  type={{
    ok: { type: 'false', description: 'Akcja została odrzucona.', required: true },
    error: { type: 'string', description: 'Klucz językowy z `locales/*.json` zasobu (`"NOT_ENOUGH_MONEY"`). Klient go tłumaczy i pokazuje.', required: true },
  }}
/>

```ts title="Przykład"
const done: ActionResult = { ok: true };
const created: ActionResult<{ id: number }> = { ok: true, id: 42 };
const refused: ActionResult = { ok: false, error: "NOT_ENOUGH_MONEY" };
```

```lua title="Lua"
return { ok = true }
return aiLib.fail('NOT_ENOUGH_MONEY') -- { ok = false, error = 'NOT_ENOUGH_MONEY' }
```

Odmowy buduj przez [fail](/pl/docs/developers/api/lib-shared/input#fail); odpowiedzi czytaj przez [isActionOk](/pl/docs/developers/api/lib-shared/input#isactionok) i [replyError](/pl/docs/developers/api/lib-shared/input#replyerror).

## Pieniądze

### Nazwy kont

Pieniądze są na nazwanych kontach. Lista **Accounts** w panelu ustala, które istnieją; ai-core dostarcza te:

| Nazwa | Etykieta | Kwota startowa |
| --- | --- | --- |
| `cash` | Cash (gotówka) | 500 |
| `bank` | Bank | 5000 |
| `black_money` | Dirty money (brudne pieniądze) | 0 |
| `crypto` | Crypto (kryptowaluta) | 0 |

Właściciel serwera może dodawać, zmieniać nazwy lub usuwać konta w panelu, więc czytaj listę eksportem `GetAccountTypes` zamiast ją zakładać. Gdy lista jest pusta, ai-core trzyma jedno konto `cash`.

```ts title="Przykład"
core.AddMoney(source, "bank", 250, "Paycheck");
```

## Ekwipunek

### InventoryRef

Na którym ekwipunku działa wywołanie.

| Wartość | Znaczy |
| --- | --- |
| `number` | Id serwera gracza: własny ekwipunek tego gracza. |
| `string` | Dowolny inny ekwipunek według jego id: nazwa schowka, id bagażnika lub schowka w desce rozdzielczej. |

```ts title="Przykład"
inventory.addItem(source, "water", 2);          // gracz
inventory.addItem("police_evidence", "phone", 1); // schowek
```

### ItemMetadata

Dowolne dane zapisane na jednym stosie przedmiotów (`Record<string, unknown>`): numer seryjny, wytrzymałość, notatka. Każdy ekwipunek sam pokazuje niektóre klucze (`label`, `description`, `image` w większości z nich).

```ts title="Przykład"
const metadata: ItemMetadata = { serial: "AB-1029", durability: 100 };
```

<Callout type="warn">
Metadane trzymaj małe i bezpieczne dla JSON (stringi, liczby, wartości logiczne, zwykłe obiekty i tablice). Dwa stosy z różnymi metadanymi nigdy się nie łączą.
</Callout>

### UsableItemHandler

`(source: number, item: UsedItem) => unknown`: działa, gdy gracz używa przedmiotu. Zwrócenie `false` zatrzymuje przedmiot w ekwipunkach, które same zabierają użyty przedmiot (ai-inventory zabiera ilość `consume` przedmiotu); inne ekwipunki działają według własnych ustawień przedmiotu.

```ts title="Przykład"
const onUse: UsableItemHandler = (source, item) => {
  if (item.metadata.durability === 0) return false; // zatrzymaj go
  return true;
};
```
