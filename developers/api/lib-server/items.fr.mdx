---
title: Objets
description: "inventory : donner, retirer et compter des objets, coffres, boutiques et objets utilisables, quel que soit l’inventaire que fait tourner le serveur."
icon: Package
---

```ts title="TypeScript"
import { inventory } from "@aicore-fivem/lib/server";
```

`inventory` fait passer chaque appel d’objet par la couche d’inventaire d’ai-core : c’est l’inventaire que fait tourner le serveur (ai-inventory, ou un autre que le propriétaire choisit dans le panneau d’ai-core) qui répond. Votre script n’appelle jamais les exports propres à un inventaire, il continue donc de fonctionner quand le propriétaire change d’inventaire.

**L’argument d’inventaire** (`inv`, type [`InventoryRef`](/fr/docs/developers/api/types#inventoryref)) est l’id serveur d’un joueur (un nombre) ou l’id d’un autre inventaire (une chaîne : un nom de coffre, une plaque).

**Les quantités** sont des nombres entiers de 1 ou plus ; une fraction est arrondie à l’inférieur, une quantité de `0` ou négative fait échouer l’appel.

<Callout type="info">
Tant qu’aucun inventaire ne tourne, les appels échouent silencieusement : `false`, `0`, une liste vide ou `null`. Les équivalents Lua sur `aiLib.inventory` ont les mêmes noms et le même ordre d’arguments.
</Callout>

### inventory.addItem

Donne des objets à un inventaire.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
inventory.addItem(inv: InventoryRef, item: string, count?: number, metadata?: ItemMetadata, slot?: number): boolean
```

```lua title="Lua"
local ok = aiLib.inventory.addItem(inv, item, count, metadata, slot)
```

#### Paramètres

<TypeTable
  type={{
    inv: { type: "InventoryRef", typeDescriptionLink: "/fr/docs/developers/api/types#inventoryref", description: "Id serveur du joueur, ou un nom de coffre ou une plaque.", required: true },
    item: { type: "string", description: "Nom de l’objet tel que l’inventaire le connaît (`water`).", required: true },
    count: { type: "number", description: "Combien.", default: "1" },
    metadata: { type: "ItemMetadata", typeDescriptionLink: "/fr/docs/developers/api/types#itemmetadata", description: "Données supplémentaires stockées sur la pile (`{ serial: \"A1\" }`). Les piles aux métadonnées différentes ne fusionnent pas.", required: false },
    slot: { type: "number", description: "Les placer dans cet emplacement (1 ou plus) quand l’inventaire le permet.", required: false },
  }}
/>

#### Retour

`boolean` : `true` quand ils ont été donnés. `false` quand ils ne rentrent pas, que l’objet n’existe pas, qu’un argument est incorrect ou qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

if (!inventory.addItem(source, "phone", 1, { number: "555-0101" })) return fail("INVENTORY_FULL");
```
</Tab>
<Tab value="Lua">
```lua
if not aiLib.inventory.addItem(source, 'phone', 1, { number = '555-0101' }) then
    return aiLib.fail('INVENTORY_FULL')
end
```
</Tab>
</Tabs>

<Callout type="warn">
Vérifiez d’abord `canCarryItem` quand vous prenez quelque chose en échange (de l’argent, un autre objet) : prenez-le seulement après que `addItem` a répondu `true`, ou rendez-le.
</Callout>

### inventory.openInventory

Ouvre un coffre ou l’inventaire d’un autre joueur sur l’écran d’un joueur.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
inventory.openInventory(source: number, inv: InventoryRef): boolean
```

```lua title="Lua"
local ok = aiLib.inventory.openInventory(source, inv)
```

<TypeTable
  type={{
    source: { type: "number", description: "Id serveur du joueur qui le voit.", required: true },
    inv: { type: "InventoryRef", typeDescriptionLink: "/fr/docs/developers/api/types#inventoryref", description: "Nom de coffre, plaque, ou id serveur d’un autre joueur.", required: true },
  }}
/>

#### Retour

`boolean` : `true` quand l’inventaire l’a ouvert.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, near, online, inventory } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const ARMORY = { x: 452.3, y: -980.0, z: 30.7 };

onClientCallback(
  "my-police:armory",
  (source) => {
    if (!online.onDutyIn(source, ["police"])) return fail("NOT_ON_DUTY");
    return { ok: inventory.openInventory(source, "police_armory") };
  },
  { guards: [near(ARMORY, 3)] },
);
```
</Tab>
<Tab value="Lua">
```lua
local ARMORY = vector3(452.3, -980.0, 30.7)

aiLib.onClientCallback('my-police:armory', function(source)
    if aiLib.online.dutyJob(source) ~= 'police' then return aiLib.fail('NOT_ON_DUTY') end
    if #(GetEntityCoords(GetPlayerPed(source)) - ARMORY) > 3.0 then return aiLib.fail('TOO_FAR') end
    return { ok = aiLib.inventory.openInventory(source, 'police_armory') }
end)
```
</Tab>
</Tabs>

<Callout type="warn">
Aucun contrôle de distance ni d’accès n’a lieu ici : vérifiez la distance, le métier et la propriété avant de l’appeler.
</Callout>

### inventory.registerUsableItem

Exécute votre gestionnaire quand un joueur utilise un objet. ai-core conserve le gestionnaire pour les inventaires qui démarrent plus tard et à travers les redémarrages d’inventaire, enregistrez-le donc une seule fois au démarrage de votre script.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
inventory.registerUsableItem(name: string, handler: UsableItemHandler): void
```

```lua title="Lua"
aiLib.inventory.registerUsableItem(name, handler) -- handler(source, item)
```

#### Paramètres

<TypeTable
  type={{
    name: { type: "string", description: "Nom de l’objet.", required: true },
    handler: { type: "(source: number, item: UsedItem) => unknown", typeDescriptionLink: "/fr/docs/developers/api/types#usableitemhandler", description: "Reçoit le joueur et la pile utilisée `{ name, slot, count, metadata }` (type `UsedItem`). Renvoyer `false` garde l’objet dans les inventaires qui retirent eux-mêmes un objet utilisé (ai-inventory : la quantité `consume` de l’objet) ; les autres inventaires suivent leurs propres réglages d’objet.", required: true },
  }}
/>

La pile utilisée est un [`UsedItem`](/fr/docs/developers/api/types#useditem).

<Callout type="warn">
Les inventaires qui retirent eux-mêmes un objet utilisé (ai-inventory) le retirent dès que le gestionnaire renvoie autre chose que `false`. Quand votre gestionnaire attend (une barre de progression) et retire l’objet lui-même, renvoyez `false` tout de suite, sinon l’objet est retiré deux fois.
</Callout>

#### Retour

`void`.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, progressFor, medical, createLocale } from "@aicore-fivem/lib/server";

const Locale = createLocale();

async function bandage(source: number) {
  const done = await progressFor(source, { label: Locale("BANDAGING"), duration: 4000, canCancel: true });
  if (done && inventory.removeItem(source, "bandage")) medical.heal(source);
}

inventory.registerUsableItem("bandage", (source) => {
  void bandage(source);
  return false; // garder l'objet pour l'instant : bandage() le retire après la barre
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

aiLib.inventory.registerUsableItem('bandage', function(source, item)
    CreateThread(function()
        local done = aiLib.progressFor(source, { label = Locale('BANDAGING'), duration = 4000, canCancel = true })
        if done and aiLib.inventory.removeItem(source, 'bandage', 1) then
            exports['ai-core']:HealPlayer(source)
        end
    end)
    return false -- garder l'objet pour l'instant : le thread le retire après la barre
end)
```
</Tab>
</Tabs>
