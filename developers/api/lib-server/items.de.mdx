title: Items
description: "inventory: Items geben, nehmen und zählen, Lager, Shops und benutzbare Items über das Inventar, das der Server betreibt."
icon: Package
---

```ts title="TypeScript"
import { inventory } from "@aifivem/lib/server";
```

`inventory` schickt jeden Item-Aufruf über die Inventar-Ebene von ai-core: Das Inventar, das der Server betreibt (ai-inventory, oder ein anderes, das der Betreiber im Panel von ai-core wählt), antwortet. Dein Skript ruft nie die eigenen Exports eines Inventars auf, daher funktioniert es weiter, wenn der Betreiber das Inventar wechselt.

**Das Inventar-Argument** (`inv`, Typ [`InventoryRef`](/de/docs/developers/api/types#inventoryref)) ist die Server-ID eines Spielers (eine Zahl) oder die ID eines anderen Inventars (ein String: ein Lagername, ein Kennzeichen).

**Anzahlen** sind ganze Zahlen ab 1; ein Bruch wird abgerundet, `0` oder eine negative Anzahl lässt den Aufruf fehlschlagen.

<Callout type="info">
Solange kein Inventar läuft, schlagen Aufrufe still fehl: `false`, `0`, eine leere Liste oder `null`. Die Lua-Zwillinge auf `aiLib.inventory` haben dieselben Namen und dieselbe Argumentreihenfolge.
</Callout>

### inventory.addItem

Gibt Items in ein Inventar.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
inventory.addItem(inv: InventoryRef, item: string, count?: number, metadata?: ItemMetadata, slot?: number): boolean
```

```lua title="Lua"
local ok = aiLib.inventory.addItem(inv, item, count, metadata, slot)
```

#### Parameter

<TypeTable
  type={{
    inv: { type: "InventoryRef", typeDescriptionLink: "/de/docs/developers/api/types#inventoryref", description: "Server-ID eines Spielers, oder ein Lagername oder Kennzeichen.", required: true },
    item: { type: "string", description: "Item-Name, wie ihn das Inventar kennt (`water`).", required: true },
    count: { type: "number", description: "Wie viele.", default: "1" },
    metadata: { type: "ItemMetadata", typeDescriptionLink: "/de/docs/developers/api/types#itemmetadata", description: "Zusätzliche Daten, die auf dem Stapel gespeichert werden (`{ serial: \"A1\" }`). Stapel mit unterschiedlichen Metadaten werden nicht zusammengeführt.", required: false },
    slot: { type: "number", description: "Lege sie in diesen Slot (1 oder höher), wenn das Inventar das unterstützt.", required: false },
  }}
/>

#### Rückgabewert

`boolean`: `true`, wenn gegeben. `false`, wenn sie nicht passen, das Item nicht existiert, ein Argument falsch ist oder kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

if (!inventory.addItem(source, "phone", 1, { number: "555-0101" })) return fail("INVENTORY_FULL");
```
</Tab>
<Tab value="Lua">
```lua
if not aiLib.inventory.addItem(source, 'phone', 1, { number = '555-0101' }) then
    return aiLib.fail('INVENTORY_FULL')
end
```
</Tab>
</Tabs>

<Callout type="warn">
Prüfe zuerst `canCarryItem`, wenn du im Tausch etwas nimmst (Geld, ein anderes Item): Nimm es erst, nachdem `addItem` mit `true` geantwortet hat, oder gib es zurück.
</Callout>

### inventory.openInventory

Öffnet ein Lager oder das Inventar eines anderen Spielers auf dem Bildschirm eines Spielers.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
inventory.openInventory(source: number, inv: InventoryRef): boolean
```

```lua title="Lua"
local ok = aiLib.inventory.openInventory(source, inv)
```

<TypeTable
  type={{
    source: { type: "number", description: "Server-ID des Spielers, der es sieht.", required: true },
    inv: { type: "InventoryRef", typeDescriptionLink: "/de/docs/developers/api/types#inventoryref", description: "Lagername, Kennzeichen oder die Server-ID eines anderen Spielers.", required: true },
  }}
/>

#### Rückgabewert

`boolean`: `true`, wenn das Inventar es geöffnet hat.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, near, online, inventory } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const ARMORY = { x: 452.3, y: -980.0, z: 30.7 };

onClientCallback(
  "my-police:armory",
  (source) => {
    if (!online.onDutyIn(source, ["police"])) return fail("NOT_ON_DUTY");
    return { ok: inventory.openInventory(source, "police_armory") };
  },
  { guards: [near(ARMORY, 3)] },
);
```
</Tab>
<Tab value="Lua">
```lua
local ARMORY = vector3(452.3, -980.0, 30.7)

aiLib.onClientCallback('my-police:armory', function(source)
    if aiLib.online.dutyJob(source) ~= 'police' then return aiLib.fail('NOT_ON_DUTY') end
    if #(GetEntityCoords(GetPlayerPed(source)) - ARMORY) > 3.0 then return aiLib.fail('TOO_FAR') end
    return { ok = aiLib.inventory.openInventory(source, 'police_armory') }
end)
```
</Tab>
</Tabs>

<Callout type="warn">
Hier findet keine Reichweiten- oder Zugriffsprüfung statt: Prüfe Entfernung, Job und Besitz, bevor du es aufrufst.
</Callout>

### inventory.registerUsableItem

Führt deinen Handler aus, wenn ein Spieler ein Item benutzt. ai-core behält den Handler für Inventare, die später starten, und über Inventar-Neustarts hinweg, registriere ihn also einmal beim Start deines Skripts.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
inventory.registerUsableItem(name: string, handler: UsableItemHandler): void
```

```lua title="Lua"
aiLib.inventory.registerUsableItem(name, handler) -- handler(source, item)
```

#### Parameter

<TypeTable
  type={{
    name: { type: "string", description: "Item-Name.", required: true },
    handler: { type: "(source: number, item: UsedItem) => unknown", typeDescriptionLink: "/de/docs/developers/api/types#usableitemhandler", description: "Bekommt den Spieler und den benutzten Stapel `{ name, slot, count, metadata }` (Typ `UsedItem`). Die Rückgabe von `false` behält das Item in Inventaren, die ein benutztes Item selbst abziehen (ai-inventory: die `consume`-Menge des Items); andere Inventare folgen ihren eigenen Item-Einstellungen.", required: true },
  }}
/>

Der benutzte Stapel ist ein [`UsedItem`](/de/docs/developers/api/types#useditem).

<Callout type="warn">
Inventare, die ein benutztes Item selbst abziehen (ai-inventory), nehmen es, sobald der Handler etwas anderes als `false` zurückgibt. Wenn dein Handler wartet (ein Fortschrittsbalken) und das Item selbst entfernt, gib sofort `false` zurück, sonst wird das Item zweimal genommen.
</Callout>

#### Rückgabewert

`void`.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { inventory, progressFor, medical, createLocale } from "@aifivem/lib/server";

const Locale = createLocale();

async function bandage(source: number) {
  const done = await progressFor(source, { label: Locale("BANDAGING"), duration: 4000, canCancel: true });
  if (done && inventory.removeItem(source, "bandage")) medical.heal(source);
}

inventory.registerUsableItem("bandage", (source) => {
  void bandage(source);
  return false; // das Item vorerst behalten: bandage() nimmt es nach dem Balken
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

aiLib.inventory.registerUsableItem('bandage', function(source, item)
    CreateThread(function()
        local done = aiLib.progressFor(source, { label = Locale('BANDAGING'), duration = 4000, canCancel = true })
        if done and aiLib.inventory.removeItem(source, 'bandage', 1) then
            exports['ai-core']:HealPlayer(source)
        end
    end)
    return false -- das Item vorerst behalten: der Thread nimmt es nach dem Balken
end)
```
</Tab>
</Tabs>
