Ein **Spieler** ist ein verbundener Client mit einer Server-ID (`source`). Ein **Charakter** ist die Person, die er spielt; ein Spieler auf dem Charakterbildschirm hat keinen Charakter geladen. ai-core besitzt Spieler und Charaktere; diese Helfer lesen sie.

## online

`online` ist die Kopie deiner Ressource von den geladenen Spielern in ai-core: Charaktere, Job- und Gang-Mitgliedschaften mit Rängen, Mitgliederlisten pro Job und Gang und Dienst. Es liest ai-core einmal beim ersten Gebrauch und folgt danach den Events von ai-core, daher ist ein Lesezugriff ein Nachschlagen im Speicher. Nutze es in heißen Pfaden (jede Chatnachricht, jeder Alarm), statt die Exports von ai-core aufzurufen.

In Lua fragt `aiLib.online` bei jedem Aufruf die Exports von ai-core: in Ordnung für Aktionen, nicht für jeden Tick. Es hat `character`, `name`, `jobs`, `gangs`, `jobGrade`, `gangGrade`, `dutyJob` und `sources`; der Rest hat keinen Lua-Zwilling.

### online.sources

Die Server-IDs aller Spieler mit geladenem Charakter.

**Seite:** Server · **Wartet:** nein

#### Rückgabewert

### online.allows

Ob der Spieler einen Ort nutzen darf, der durch eine Zugriffsregel gesperrt ist (Jobs, Gangs, Mindestränge, im Dienst). `allows` auf dem Client nutzt dieselbe Regel, sodass ein Spieler genau das sieht, was der Server ihn nutzen lässt.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
online.allows(source: number, rule: AccessRule): boolean
```

Kein Lua-Zwilling.

<TypeTable
  type={{
    source: { type: "number", description: "Server-ID des Spielers.", required: true },
    rule: { type: "AccessRule", typeDescriptionLink: "/de/docs/developers/api/types#accessrule", description: "`{ jobs, gangs, grades, onDuty }`, aus einem Panel-Eintrag mit `readAccess(record)` gelesen. Beide Listen leer: alle.", required: true },
  }}
/>

**Rückgabewert:** `true`, wenn die Listen leer sind, der Spieler in einer der `gangs` mit deren Mindestrang ist oder in einem der `jobs` mit dessen Mindestrang (und dafür im Dienst, wenn `onDuty` gesetzt ist).

```ts
import { online } from "@aicore-fivem/lib/server";
import { readAccess, fail } from "@aicore-fivem/lib/shared";

const rule = readAccess(stashRecord); // { jobs: ["police"], gangs: [], grades: { police: 2 }, onDuty: true }
if (!online.allows(source, rule)) return fail("NO_ACCESS");
```

## Lebenszyklus eines Charakters

### onCharacter

Führt deinen Code aus, wenn ein Charakter die Welt betritt und wenn er sie verlässt. Es spielt außerdem die Charaktere erneut ab, die schon in der Welt sind, wenn deine Ressource (neu) startet, und deckt Verbindungsabbrüche ab, daher brauchst du daneben keinen `playerDropped`-Handler.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
onCharacter(handlers: CharacterHandlers): void
```

```lua title="Lua"
aiLib.onCharacter({ loaded = function(source, character) end, unloaded = function(source, charId, reason) end })
```

#### CharacterHandlers

<TypeTable
  type={{
    loaded: { type: "(source: number, character: CharacterInfo) => void | Promise<void>", typeDescriptionLink: "/de/docs/developers/api/types#characterinfo", description: "Ein Charakter hat die Welt betreten. Läuft außerdem einmal, im nächsten Tick nach deinem Aufruf von `onCharacter`, für jeden Charakter, der vor dem Start deiner Ressource geladen wurde. Ein geworfener Fehler oder eine Ablehnung wird geloggt.", required: false },
    unloaded: { type: '(source: number, charId: number, reason: "dropped" | "switch") => void', description: "Der Charakter ist gegangen: `switch` bei Logout oder Charakterwechsel, `dropped`, wenn der Spieler die Verbindung getrennt hat. Jedes `loaded` bekommt genau ein `unloaded`.", required: false },
  }}
/>

#### Rückgabewert

`void`.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onCharacter, PlayerMap } from "@aicore-fivem/lib/server";

const playtime = new PlayerMap<{ charId: number; since: number }>();

onCharacter({
  loaded(source, character) {
    playtime.set(source, { charId: character.id, since: Date.now() });
  },
  unloaded(source, charId, reason) {
    const entry = playtime.get(source);
    if (entry) console.log(`character ${charId} played ${Date.now() - entry.since} ms (${reason})`);
    playtime.delete(source);
  },
});
```
</Tab>
<Tab value="Lua">
```lua
local since = {}

aiLib.onCharacter({
    loaded = function(source, character)
        since[source] = os.time()
    end,
    unloaded = function(source, charId, reason)
        print(('character %d played %ds (%s)'):format(charId, os.time() - (since[source] or os.time()), reason))
        since[source] = nil
    end,
})
```
</Tab>
</Tabs>

<Callout type="info">
Rufe es einmal auf oberster Ebene einer Server-Datei auf. Die PlayerMap oben leert sich beim Verlassen selbst; der `unloaded`-Handler läuft bei einem Verbindungsabbruch trotzdem zuerst, sodass du dort Daten speichern kannst.
</Callout>

### isOnline

Ob ein Spieler noch verbunden ist. Prüfe es nach einem langen `await`, bevor du etwas gibst.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
isOnline(source: number): boolean
```

Kein Lua-Zwilling: `GetPlayerName(source) ~= nil`.

```ts

```

Diese fragen ai-core, welche Spieler im OneSync-Bereich der anderen sind (etwa 424 Meter), und messen nur diese wenigen, statt jeden Spieler auf dem Server durchzugehen. Ein Radius größer als etwa 424 m findet niemanden weiter weg.

## Speicher pro Spieler

Keiner davon hat einen Lua-Zwilling: Nutze eine Lua-Tabelle und leere sie in `playerDropped`. Erstelle jeden Speicher einmal auf Modulebene, nie in einem Handler.

Eine `Map` mit der Server-ID des Spielers als Schlüssel, die sich selbst leert, wenn der Spieler geht. Nutze sie für alles, was du pro Spieler hältst (ein offener Bildschirm, ein ausgewähltes Item).

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new PlayerMap<V>(options?: { onDrop?: (source: number, value: V) => void })
```

<TypeTable
  type={{
    "options.onDrop": { type: "(source: number, value: V) => void", description: "Läuft, nachdem der Eintrag eines gegangenen Spielers entfernt wurde, mit seinem letzten Wert (eine Aktion abschließen, etwas speichern).", required: false },
  }}
/>

Sie hat jede Methode einer JavaScript-`Map` (`get`, `set`, `has`, `delete`, `size`, Iteration).

```ts
import { PlayerMap } from "@aicore-fivem/lib/server";

const carrying = new PlayerMap<string>({
  onDrop: (source, item) => console.log(`${source} left while carrying ${item}`),
});
carrying.set(source, "box");
```

### Cooldowns

Cooldowns pro Spieler auf der Spieluhr, freigegeben, wenn der Spieler geht.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new Cooldowns()
ready(source: number): boolean
start(source: number, ms: number): void
take(source: number, ms: number): boolean
left(source: number): number
clear(source: number): void
```

| Methode | Was sie tut | Rückgabewert |
| --- | --- | --- |
| `ready(source)` | Für den Spieler läuft kein Cooldown. | `boolean` |
| `start(source, ms)` | Startet (oder startet neu) den Cooldown des Spielers für `ms` Millisekunden. | `void` |
| `take(source, ms)` | Startet den Cooldown, wenn er bereit ist. | `true`, wenn gestartet, `false`, solange noch einer läuft |
| `left(source)` | Verbleibende Millisekunden. | `number`, `0`, wenn bereit |
| `clear(source)` | Beendet den Cooldown des Spielers. | `void` |

```ts
import { onClientCallback, Cooldowns } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const searchCooldown = new Cooldowns();

onClientCallback("my-bins:search", (source) => {
  if (!searchCooldown.take(source, 30_000)) return fail("WAIT");
  return { ok: true };
});
```

<Callout type="warn">
Ein Spieler kann sich neu verbinden, um einen `Cooldowns`-Eintrag zurückzusetzen. Ein Cooldown, der einen Reconnect überleben muss, nutzt `KeyedCooldowns` mit `online.charId(source)` als Schlüssel.
</Callout>

### KeyedCooldowns

Cooldowns nach einem beliebigen Schlüssel, der eine Verbindung überdauert: eine Charakter-ID, eine Entity, eine Tür-ID. Abgelaufene Einträge werden aufgeräumt, wenn die Map wächst.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new KeyedCooldowns<K = number>()
ready(key: K): boolean
start(key: K, ms: number): void
take(key: K, ms: number): boolean
left(key: K): number
clear(key: K): void
```

Dieselben Methoden wie `Cooldowns`, nach `key`. `start` mit `ms` von 0 oder weniger beendet den Cooldown.

```ts
import { KeyedCooldowns, online } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const robbed = new KeyedCooldowns<string>(); // nach Laden-ID
const perCharacter = new KeyedCooldowns(); // nach Charakter-ID

function canRob(source: number, store: string) {
  const charId = online.charId(source);
  if (charId === undefined) return fail("NO_CHARACTER");
  if (!robbed.ready(store)) return fail("STORE_EMPTY");
  if (!perCharacter.take(charId, 15 * 60_000)) return fail("WAIT");
  robbed.start(store, 30 * 60_000);
  return { ok: true };
}
```

### SourceLock

Eine laufende Aktion pro Spieler über mehrere Callbacks hinweg. Das eigene `lock: true` eines Callbacks deckt nur diesen Callback ab; zwei Aktionen, die sich gegenseitig ausschließen müssen (dasselbe Fahrzeug anbieten und verkaufen), teilen sich ein `SourceLock`.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new SourceLock()
run<T, B>(source: number, busy: B, task: () => Promise<T>): Promise<T | B>
release(source: number): void
```

<TypeTable
  type={{
    source: { type: "number", description: "Server-ID des Spielers.", required: true },
    busy: { type: "B", description: "Was `run` zurückgibt, wenn beim Spieler schon eine Aufgabe läuft (`fail(\"BUSY\")`).", required: true },
    task: { type: "() => Promise<T>", description: "Die Aktion. Die Sperre wird freigegeben, wenn sie abgeschlossen ist, auch wenn sie wirft.", required: true },
  }}
/>

**Rückgabewert** (`run`): das Ergebnis der Aufgabe, oder `busy`. `release(source)` gibt den Spieler frei; rufe es aus `playerDropped` auf (eine noch laufende Aufgabe behält ihren eigenen Eintrag, bis sie abgeschlossen ist).

```ts
import { onClientCallback, SourceLock } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const dealer = new SourceLock();
on("playerDropped", () => dealer.release(Number(globalThis.source)));

onClientCallback("my-dealer:list", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
onClientCallback("my-dealer:sell", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
```

### RateLimit

Ein Burst-Limit pro Spieler: höchstens `count` Aktionen innerhalb eines beliebigen `windowMs`. Das Gate begrenzt bereits jede Eingabe; nutze dies für ein zusätzliches, langsameres Limit für eine Aktion.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new RateLimit(count: number, windowMs: number)
take(source: number): boolean
release(source: number): void
```

```lua title="Lua"
local limit = aiLib.RateLimit.new(count, windowMs)
local allowed = limit:take(source)
limit:release(source)
```

<TypeTable
  type={{
    count: { type: "number", description: "Erlaubte Aktionen pro Fenster.", required: true },
    windowMs: { type: "number", description: "Fensterlänge in Millisekunden (ein gleitendes Fenster).", required: true },
  }}
/>

**Rückgabewert** (`take`): `true` und zählt eine Aktion, oder `false`, wenn der Spieler über dem Limit ist (nicht gezählt). `release(source)` vergisst den Spieler; rufe es aus `playerDropped` auf.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, RateLimit } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const reports = new RateLimit(3, 60_000);
on("playerDropped", () => reports.release(Number(globalThis.source)));

onClientCallback("my-report:send", (source) => {
  if (!reports.take(source)) return fail("TOO_MANY_REPORTS");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local reports = aiLib.RateLimit.new(3, 60000)
AddEventHandler('playerDropped', function() reports:release(source) end)

aiLib.onClientCallback('my-report:send', function(source)
    if not reports:take(source) then return aiLib.fail('TOO_MANY_REPORTS') end
    return { ok = true }
end)
```
</Tab>
</Tabs>

### KeyWatchers

Die Spieler, die Live-Änderungen eines Schlüssels empfangen (die Autos eines Parkplatzes, ein offenes Charakterblatt). Ein Schlüssel pro Spieler: Einen neuen Schlüssel zu beobachten beendet den alten. Beim Verlassen freigegeben; jede Operation läuft in konstanter Zeit.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
new KeyWatchers<K>()
watch(source: number, key: K): void
stop(source: number): void
of(key: K): ReadonlySet<number> | undefined
keyOf(source: number): K | undefined
```

| Methode | Was sie tut | Rückgabewert |
| --- | --- | --- |
| `watch(source, key)` | Der Spieler beobachtet `key` und hört auf, den vorherigen zu beobachten. | `void` |
| `stop(source)` | Der Spieler hört auf zu beobachten. | `void` |
| `of(key)` | Die Spieler, die `key` beobachten. | ein Set, oder `undefined`, wenn niemand beobachtet |
| `keyOf(source)` | Der Schlüssel, den der Spieler beobachtet. | der Schlüssel, oder `undefined` |

```ts
import { onClientCallback, onClientEvent, KeyWatchers } from "@aicore-fivem/lib/server";
import { oneArg, readText } from "@aicore-fivem/lib/shared";

const lots = new KeyWatchers<string>();

onClientCallback("my-lot:open", { args: oneArg((v) => readText(v, 32)) }, (source, lot) => {
  lots.watch(source, lot);
  return { ok: true, cars: [] }; // der Snapshot
});
onClientEvent("my-lot:close", (source) => lots.stop(source));

function carChanged(lot: string, car: unknown) {
  for (const source of lots.of(lot) ?? []) emitNet("my-lot:car", source, car); // das Delta
}
```
