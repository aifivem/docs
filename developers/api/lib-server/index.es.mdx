La lib de servidor es el conjunto de utilidades que usa cada script de servidor `ai-*` en lugar de escribir el mismo código otra vez: responder a los clientes de forma segura, comandos, jugadores, objetos, vehículos, dinero, logs y el panel de administración. La mayoría de las utilidades que tocan otro sistema (inventario, llaves, teléfono, prisión...) pasan por **ai-core**, así que tu script sigue funcionando cuando el dueño del servidor cambia el script de inventario o de teléfono.

## TypeScript

Importa desde `@aifivem/lib/server` en los archivos bajo `resource/server/`. Las utilidades que funcionan en cualquier lado (rechazos, lectores de entrada, matemáticas) vienen de `@aifivem/lib/shared`.

```ts title="resource/server/index.ts"
import { onClientCallback, inventory, notify } from "@aifivem/lib/server";
import { fail, oneArg, readId } from "@aifivem/lib/shared";
```

Cada recurso creado a partir de la plantilla de ai-core ya depende del paquete (`"@aifivem/lib": "workspace:*"` en `package.json`); la compilación lo empaqueta en `dist/server.js`.

## Lua

Los recursos Lua obtienen las mismas utilidades en la tabla global `aiLib` desde el recurso `ai-lib`. Añade dos líneas a tu `fxmanifest.lua`:

```lua title="fxmanifest.lua"
dependency 'ai-lib'
shared_script '@ai-lib/init.lua'
```

Después llama a `aiLib.<name>` en cualquier archivo de servidor. Cada módulo se carga la primera vez que lo usas y se ejecuta dentro de tu recurso, así que los comandos y callbacks que registras pertenecen a tu recurso y desaparecen cuando se detiene.

```lua title="server.lua"
aiLib.addCommand('hello', { help = 'Says hello' }, function(source)
    aiLib.notify(source, 'Hello!', 'success')
end)
```

<Callout type="warn">
Las funciones Lua marcadas con **Espera** (`progressFor`, `minigameFor`, `spawnVehicle`, `triggerClientCallback`, `billing.unpaid`, `appearance.get`) pausan el código hasta que llega la respuesta. Solo funcionan dentro de un hilo. Los handlers de `aiLib.onClientCallback` y `aiLib.onClientEvent` ya se ejecutan en uno; en cualquier otro sitio, envuelve la llamada en `CreateThread(function() ... end)`.
</Callout>

No todas las utilidades de TypeScript tienen un equivalente en Lua. Cada entrada lo indica cuando no lo tiene. Las que faltan en Lua: `PendingActions`, `PlayerMap`, `Cooldowns`, `KeyedCooldowns`, `SourceLock`, `KeyWatchers`, las utilidades de posición, `AreaStream`, las clases de state bags, `AdminPanel`, `DataFile` y las utilidades de base de datos (los recursos Lua usan la API oxmysql de ai-mysql para SQL).

## Utilidades compartidas con el cliente

La entrada de servidor también reexporta las utilidades de `/fivem`, así que puedes importarlas también desde `@aifivem/lib/server`. Se documentan una sola vez en [Lib: compartido y fivem](/es/docs/developers/api/lib-shared):

`registerExport`, `resourceExport`, `optionalExport`, `callExport`, `provideExport`, `isResourceStarted`, `createLocale`, `loadLocaleTexts`, `LOCALE_CONVAR`, `ByResource`, `caller`, `onStop`, `plateOf`, `Reasons`, `every` (con los tipos `EveryOptions` y `Job`), `stateBoolean`, `stateNumber`, `stateString` (tipo `StateParse`).

Las clases de state bags `EntityState`, `PlayerState`, `GlobalKey` y `GlobalGroup` exportadas desde la entrada de servidor son las versiones de servidor: añaden `set`. Consulta [State bags](/es/docs/developers/api/lib-server/state-bags).

## Dos utilidades que solo usa ai-core

`sendPlayerData(source, key, value)` y `patchPlayerData(source, key, patch)` envían un valor de los datos de un jugador (`AiPlayerData`) al cliente de ese jugador. ai-core las llama; tu script nunca las necesita. Lee los datos del jugador en el cliente con `getPlayerData` ([Lib: cliente](/es/docs/developers/api/lib-client)).
