**Gracz** to połączony klient z id serwerowym (`source`). **Postać** to osoba, którą gra; gracz na ekranie wyboru postaci nie ma wczytanej postaci. ai-core jest właścicielem graczy i postaci; te funkcje je czytają.

## online

`online` to kopia wczytanych graczy ai-core w twoim zasobie: postacie, członkostwa w pracach i gangach ze stopniami, listy członków każdej pracy i gangu oraz służba. Czyta ai-core raz przy pierwszym użyciu, a potem śledzi zdarzenia ai-core, więc odczyt to wyszukanie w pamięci. Używaj go na gorących ścieżkach (każda wiadomość na czacie, każdy alert) zamiast wywoływać eksporty ai-core.

W Lua `aiLib.online` pyta eksporty ai-core przy każdym wywołaniu: w porządku dla akcji, nie dla każdego ticku. Ma `character`, `name`, `jobs`, `gangs`, `jobGrade`, `gangGrade`, `dutyJob` i `sources`; reszta nie ma odpowiednika w Lua.

### online.allows

Czy gracz może korzystać z miejsca zablokowanego regułą dostępu (prace, gangi, minimalne stopnie, służba). `allows` klienta używa tej samej reguły, więc to, co widzi gracz, jest tym, z czego serwer pozwala mu korzystać.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
online.allows(source: number, rule: AccessRule): boolean
```

Brak odpowiednika w Lua.

<TypeTable
  type={{
    source: { type: "number", description: "Id serwerowe gracza.", required: true },
    rule: { type: "AccessRule", typeDescriptionLink: "/pl/docs/developers/api/types#accessrule", description: "`{ jobs, gangs, grades, onDuty }`, odczytane z rekordu panelu przez `readAccess(record)`. Obie listy puste: wszyscy.", required: true },
  }}
/>

**Zwraca** `true`, gdy listy są puste, gracz jest w jednym z `gangs` od jego minimalnego stopnia albo w jednej z `jobs` od jej minimalnego stopnia (i jest w niej na służbie, gdy ustawiono `onDuty`).

```ts
import { online } from "@aicore-fivem/lib/server";
import { readAccess, fail } from "@aicore-fivem/lib/shared";

const rule = readAccess(stashRecord); // { jobs: ["police"], gangs: [], grades: { police: 2 }, onDuty: true }
if (!online.allows(source, rule)) return fail("NO_ACCESS");
```

## Cykl życia postaci

### onCharacter

Uruchamia twój kod, gdy postać wchodzi do świata i gdy go opuszcza. Odtwarza też postacie już obecne w świecie, gdy twój zasób (ponownie) startuje, i obsługuje wyjścia graczy, więc nie potrzebujesz obok handlera `playerDropped`.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
onCharacter(handlers: CharacterHandlers): void
```

```lua title="Lua"
aiLib.onCharacter({ loaded = function(source, character) end, unloaded = function(source, charId, reason) end })
```

#### CharacterHandlers

<TypeTable
  type={{
    loaded: { type: "(source: number, character: CharacterInfo) => void | Promise<void>", typeDescriptionLink: "/pl/docs/developers/api/types#characterinfo", description: "Postać weszła do świata. Działa też raz, w następnym ticku po wywołaniu `onCharacter`, dla każdej postaci wczytanej przed startem twojego zasobu. Rzucony błąd albo odrzucenie jest logowane.", required: false },
    unloaded: { type: '(source: number, charId: number, reason: "dropped" | "switch") => void', description: "Postać wyszła: `switch` przy wylogowaniu albo zmianie postaci, `dropped`, gdy gracz się rozłączył. Każde `loaded` dostaje dokładnie jedno `unloaded`.", required: false },
  }}
/>

#### Zwracana wartość

`void`.

#### Przykład

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onCharacter, PlayerMap } from "@aicore-fivem/lib/server";

const playtime = new PlayerMap<{ charId: number; since: number }>();

onCharacter({
  loaded(source, character) {
    playtime.set(source, { charId: character.id, since: Date.now() });
  },
  unloaded(source, charId, reason) {
    const entry = playtime.get(source);
    if (entry) console.log(`character ${charId} played ${Date.now() - entry.since} ms (${reason})`);
    playtime.delete(source);
  },
});
```
</Tab>
<Tab value="Lua">
```lua
local since = {}

aiLib.onCharacter({
    loaded = function(source, character)
        since[source] = os.time()
    end,
    unloaded = function(source, charId, reason)
        print(('character %d played %ds (%s)'):format(charId, os.time() - (since[source] or os.time()), reason))
        since[source] = nil
    end,
})
```
</Tab>
</Tabs>

<Callout type="info">
Wywołaj ją raz na najwyższym poziomie pliku serwera. PlayerMap wyżej opróżnia się sam przy wyjściu gracza; handler `unloaded` i tak działa przy wyjściu najpierw, więc możesz tam zapisać dane.
</Callout>

## Magazyny na gracza

Żaden z nich nie ma odpowiednika w Lua: użyj tabeli Lua i czyść ją w `playerDropped`. Twórz każdy magazyn raz na poziomie modułu, nigdy wewnątrz handlera.

### PlayerMap

`Map` kluczowana id serwerowym gracza, która sama się opróżnia, gdy gracz wyjdzie. Używaj jej do wszystkiego, co trzymasz na gracza (otwarty ekran, wybrany przedmiot).

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new PlayerMap<V>(options?: { onDrop?: (source: number, value: V) => void })
```

<TypeTable
  type={{
    "options.onDrop": { type: "(source: number, value: V) => void", description: "Działa po usunięciu wpisu gracza, który wyszedł, z jego ostatnią wartością (dokończ akcję, zapisz coś).", required: false },
  }}
/>

Ma każdą metodę `Map` z JavaScript (`get`, `set`, `has`, `delete`, `size`, iteracja).

```ts
import { PlayerMap } from "@aicore-fivem/lib/server";

const carrying = new PlayerMap<string>({
  onDrop: (source, item) => console.log(`${source} left while carrying ${item}`),
});
carrying.set(source, "box");
```

### Cooldowns

Cooldowny na gracza według zegara gry, zwalniane, gdy gracz wyjdzie.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new Cooldowns()
ready(source: number): boolean
start(source: number, ms: number): void
take(source: number, ms: number): boolean
left(source: number): number
clear(source: number): void
```

| Metoda | Co robi | Zwraca |
| --- | --- | --- |
| `ready(source)` | Dla gracza nie trwa żaden cooldown. | `boolean` |
| `start(source, ms)` | Zaczyna (albo zaczyna od nowa) cooldown gracza na `ms` milisekund. | `void` |
| `take(source, ms)` | Zaczyna cooldown, gdy jest gotowy. | `true`, gdy zaczęty, `false`, dopóki jeden jeszcze trwa |
| `left(source)` | Ile milisekund zostało. | `number`, `0`, gdy gotowy |
| `clear(source)` | Kończy cooldown gracza. | `void` |

```ts
import { onClientCallback, Cooldowns } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const searchCooldown = new Cooldowns();

onClientCallback("my-bins:search", (source) => {
  if (!searchCooldown.take(source, 30_000)) return fail("WAIT");
  return { ok: true };
});
```

<Callout type="warn">
Gracz może połączyć się ponownie, żeby zresetować wpis `Cooldowns`. Cooldown, który musi przetrwać ponowne połączenie, używa `KeyedCooldowns` kluczowanych przez `online.charId(source)`.
</Callout>

### KeyedCooldowns

Cooldowny według dowolnego klucza, który przetrwa połączenie: id postaci, encji, drzwi. Wygasłe wpisy są sprzątane w miarę wzrostu mapy.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new KeyedCooldowns<K = number>()
ready(key: K): boolean
start(key: K, ms: number): void
take(key: K, ms: number): boolean
left(key: K): number
clear(key: K): void
```

Te same metody co `Cooldowns`, według `key`. `start` z `ms` równym 0 lub mniej kończy cooldown.

```ts
import { KeyedCooldowns, online } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const robbed = new KeyedCooldowns<string>(); // według id sklepu
const perCharacter = new KeyedCooldowns(); // według id postaci

function canRob(source: number, store: string) {
  const charId = online.charId(source);
  if (charId === undefined) return fail("NO_CHARACTER");
  if (!robbed.ready(store)) return fail("STORE_EMPTY");
  if (!perCharacter.take(charId, 15 * 60_000)) return fail("WAIT");
  robbed.start(store, 30 * 60_000);
  return { ok: true };
}
```

### SourceLock

Jedna trwająca akcja na gracza w kilku callbackach. Własne `lock: true` callbacka obejmuje tylko ten callback; dwie akcje, które muszą się wzajemnie wykluczać (wystawienie i sprzedaż tego samego pojazdu), dzielą jeden `SourceLock`.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new SourceLock()
run<T, B>(source: number, busy: B, task: () => Promise<T>): Promise<T | B>
release(source: number): void
```

<TypeTable
  type={{
    source: { type: "number", description: "Id serwerowe gracza.", required: true },
    busy: { type: "B", description: "Co zwraca `run`, gdy gracz ma już trwające zadanie (`fail(\"BUSY\")`).", required: true },
    task: { type: "() => Promise<T>", description: "Akcja. Blokada jest zwalniana, gdy się zakończy, nawet gdy rzuci wyjątek.", required: true },
  }}
/>

**Zwraca** (`run`) wynik zadania albo `busy`. `release(source)` zwalnia gracza; wywołuj go z `playerDropped` (zadanie, które jeszcze trwa, trzyma własny wpis, aż się zakończy).

```ts
import { onClientCallback, SourceLock } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const dealer = new SourceLock();
on("playerDropped", () => dealer.release(Number(globalThis.source)));

onClientCallback("my-dealer:list", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
onClientCallback("my-dealer:sell", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
```

### RateLimit

Limit serii na gracza: najwyżej `count` akcji w dowolnym `windowMs`. Bramka już ogranicza częstotliwość każdego wejścia; używaj tego dla dodatkowego, wolniejszego limitu jednej akcji.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new RateLimit(count: number, windowMs: number)
take(source: number): boolean
release(source: number): void
```

```lua title="Lua"
local limit = aiLib.RateLimit.new(count, windowMs)
local allowed = limit:take(source)
limit:release(source)
```

<TypeTable
  type={{
    count: { type: "number", description: "Akcje dozwolone na okno.", required: true },
    windowMs: { type: "number", description: "Długość okna w milisekundach (okno przesuwne).", required: true },
  }}
/>

**Zwraca** (`take`) `true` i liczy jedną akcję albo `false`, gdy gracz przekroczył limit (nie liczone). `release(source)` zapomina gracza; wywołuj go z `playerDropped`.

```ts
});
```

### KeyWatchers

Gracze, którzy dostają zmiany jednego klucza na żywo (samochody parkingu, otwarta karta postaci). Jeden klucz na gracza: obserwowanie nowego klucza kończy obserwowanie starego. Zwalniane przy wyjściu; każda operacja ma stały czas.

**Strona:** Serwer · **Czeka:** nie

```ts title="Sygnatura"
new KeyWatchers<K>()
watch(source: number, key: K): void
stop(source: number): void
of(key: K): ReadonlySet<number> | undefined
keyOf(source: number): K | undefined
```

| Metoda | Co robi | Zwraca |
| --- | --- | --- |
| `watch(source, key)` | Gracz obserwuje `key` i przestaje obserwować poprzedni. | `void` |
| `stop(source)` | Gracz przestaje obserwować. | `void` |
| `of(key)` | Gracze obserwujący `key`. | zbiór albo `undefined`, gdy nikt nie obserwuje |
| `keyOf(source)` | Klucz, który obserwuje gracz. | klucz albo `undefined` |

```ts
import { onClientCallback, onClientEvent, KeyWatchers } from "@aicore-fivem/lib/server";
import { oneArg, readText } from "@aicore-fivem/lib/shared";

const lots = new KeyWatchers<string>();

onClientCallback("my-lot:open", { args: oneArg((v) => readText(v, 32)) }, (source, lot) => {
  lots.watch(source, lot);
  return { ok: true, cars: [] }; // migawka
});
onClientEvent("my-lot:close", (source) => lots.stop(source));

function carChanged(lot: string, car: unknown) {
  for (const source of lots.of(lot) ?? []) emitNet("my-lot:car", source, car); // delta
}
```
