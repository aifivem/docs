Lib serwerowy to zestaw funkcji pomocniczych, których każdy serwerowy skrypt `ai-*` używa zamiast pisać ten sam kod od nowa: bezpieczne odpowiadanie klientom, komendy, gracze, przedmioty, pojazdy, pieniądze, logi i panel administratora. Większość funkcji, które dotykają innego systemu (ekwipunek, klucze, telefon, więzienie...), przechodzi przez **ai-core**, więc twój skrypt działa dalej, gdy właściciel serwera wymieni skrypt ekwipunku albo telefonu.

## TypeScript

Importuj z `@aicore-fivem/lib/server` w plikach w `resource/server/`. Funkcje działające po każdej stronie (odmowy, czytniki wejścia, matematyka) pochodzą z `@aicore-fivem/lib/shared`.

```ts title="resource/server/index.ts"
import { onClientCallback, inventory, notify } from "@aicore-fivem/lib/server";
import { fail, oneArg, readId } from "@aicore-fivem/lib/shared";
```

Każdy zasób zrobiony z szablonu ai-core już zależy od tego pakietu (`"@aicore-fivem/lib": "workspace:*"` w `package.json`); build pakuje go do `dist/server.js`.

## Lua

Zasoby Lua dostają te same funkcje w globalnej tabeli `aiLib` z zasobu `ai-lib`. Dodaj dwie linie do swojego `fxmanifest.lua`:

```lua title="fxmanifest.lua"
dependency 'ai-lib'
shared_script '@ai-lib/init.lua'
```

Potem wywołuj `aiLib.<name>` w dowolnym pliku serwera. Każdy moduł wczytuje się przy pierwszym użyciu i działa wewnątrz twojego zasobu, więc komendy i callbacki, które rejestrujesz, należą do twojego zasobu i znikają, gdy się zatrzyma.

```lua title="server.lua"
aiLib.addCommand('hello', { help = 'Says hello' }, function(source)
    aiLib.notify(source, 'Hello!', 'success')
end)
```

<Callout type="warn">
Funkcje Lua oznaczone jako **Czeka** (`progressFor`, `minigameFor`, `spawnVehicle`, `triggerClientCallback`, `billing.unpaid`, `appearance.get`) wstrzymują kod, aż przyjdzie odpowiedź. Działają tylko wewnątrz wątku. Handlery `aiLib.onClientCallback` i `aiLib.onClientEvent` już w nim działają; w każdym innym miejscu opakuj wywołanie w `CreateThread(function() ... end)`.
</Callout>

Nie każda funkcja TypeScript ma odpowiednik w Lua. Każdy wpis mówi to wprost, gdy go nie ma. Brakuje w Lua: `PendingActions`, `PlayerMap`, `Cooldowns`, `KeyedCooldowns`, `SourceLock`, `KeyWatchers`, funkcji pozycji, `AreaStream`, klas state bagów, `AdminPanel`, `DataFile` i funkcji bazy danych (zasoby Lua używają do SQL API oxmysql z ai-mysql).

## Funkcje wspólne z klientem

Wejście serwera ponownie eksportuje też funkcje `/fivem`, więc możesz je importować także z `@aicore-fivem/lib/server`. Są opisane raz na stronie [Lib: shared i fivem](/pl/docs/developers/api/lib-shared):

`registerExport`, `resourceExport`, `optionalExport`, `callExport`, `provideExport`, `isResourceStarted`, `createLocale`, `loadLocaleTexts`, `LOCALE_CONVAR`, `ByResource`, `caller`, `onStop`, `plateOf`, `Reasons`, `every` (z typami `EveryOptions` i `Job`), `stateBoolean`, `stateNumber`, `stateString` (typ `StateParse`).

Klasy state bagów `EntityState`, `PlayerState`, `GlobalKey` i `GlobalGroup` eksportowane z wejścia serwera to wersje serwerowe: dodają `set`. Zobacz [State bagi](/pl/docs/developers/api/lib-server/state-bags).

## Dwie funkcje, których używa tylko ai-core

`sendPlayerData(source, key, value)` i `patchPlayerData(source, key, patch)` wypychają jedną wartość danych gracza (`AiPlayerData`) do klienta tego gracza. Wywołuje je ai-core; twój skrypt nigdy ich nie potrzebuje. Dane gracza czytaj na kliencie przez `getPlayerData` ([Lib: klient](/pl/docs/developers/api/lib-client)).
