Un **joueur** est un client connecté qui a un id serveur (`source`). Un **personnage** est la personne qu’il incarne ; un joueur sur l’écran de sélection de personnage n’a aucun personnage chargé. ai-core possède les joueurs et les personnages ; ces helpers les lisent.

## online

`online` est la copie, dans votre ressource, des joueurs chargés d’ai-core : personnages, appartenances aux métiers et aux gangs avec leurs grades, listes de membres par métier et par gang, et service. Elle lit ai-core une fois à la première utilisation puis suit les événements d’ai-core, donc une lecture est une simple consultation en mémoire. Utilisez-la dans les chemins critiques (chaque message de chat, chaque alerte) au lieu d’appeler les exports d’ai-core.

En Lua, `aiLib.online` interroge les exports d’ai-core à chaque appel : convenable pour des actions, pas pour chaque tick. Elle propose `character`, `name`, `jobs`, `gangs`, `jobGrade`, `gangGrade`, `dutyJob` et `sources` ; le reste n’a pas d’équivalent Lua.

### online.sources

Les ids serveur de tous les joueurs qui ont un personnage chargé.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
online.sources(): IterableIterator<number>
```

```lua title="Lua"
local list = aiLib.online.sources() -- integer[]
```

#### Retour

`IterableIterator<number>` (Lua : un tableau). Les joueurs sur l’écran de sélection de personnage n’y figurent pas.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { online, notify } from "@aicore-fivem/lib/server";

for (const source of online.sources()) notify(source, "Server restart in 5 minutes", "warning", 10_000);
```
</Tab>
<Tab value="Lua">
```lua
for _, source in ipairs(aiLib.online.sources()) do
    aiLib.notify(source, 'Server restart in 5 minutes', 'warning', 10000)
end
```
</Tab>
</Tabs>

### online.charId

L’id du personnage chargé du joueur (l’id en base de données, stable d’une reconnexion à l’autre).

**Côté :** serveur · **Attend :** non

```ts title="Signature"
online.charId(source: number): number | undefined
```

Pas d’équivalent Lua : `(aiLib.online.character(source) or {}).id`.

**Retour** l’id du personnage, ou `undefined` quand aucun n’est chargé. Indexez par cet id, et non par `source`, les données qui doivent survivre à une reconnexion (cooldowns, propriété).

### online.allows

Si le joueur peut utiliser un lieu verrouillé par une règle d’accès (métiers, gangs, grades minimaux, service). Le `allows` côté client utilise la même règle, donc ce qu’un joueur voit correspond à ce que le serveur le laisse utiliser.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
online.allows(source: number, rule: AccessRule): boolean
```

Pas d’équivalent Lua.

<TypeTable
  type={{
    source: { type: "number", description: "Id serveur du joueur.", required: true },
    rule: { type: "AccessRule", typeDescriptionLink: "/fr/docs/developers/api/types#accessrule", description: "`{ jobs, gangs, grades, onDuty }`, lu depuis un enregistrement du panneau avec `readAccess(record)`. Les deux listes vides : tout le monde.", required: true },
  }}
/>

**Retour** `true` quand les listes sont vides, que le joueur fait partie de l’un des `gangs` avec son grade minimal, ou de l’un des `jobs` avec son grade minimal (et en service pour ce métier quand `onDuty` est défini).

```ts
import { online } from "@aicore-fivem/lib/server";
import { readAccess, fail } from "@aicore-fivem/lib/shared";

const rule = readAccess(stashRecord); // { jobs: ["police"], gangs: [], grades: { police: 2 }, onDuty: true }
if (!online.allows(source, rule)) return fail("NO_ACCESS");
```

## Cycle de vie du personnage

### onCharacter

Exécute votre code quand un personnage entre dans le monde et quand il le quitte. Elle rejoue aussi les personnages déjà présents dans le monde quand votre ressource (re)démarre, et couvre les déconnexions, vous n’avez donc besoin d’aucun gestionnaire `playerDropped` à côté.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
onCharacter(handlers: CharacterHandlers): void
```

```lua title="Lua"
aiLib.onCharacter({ loaded = function(source, character) end, unloaded = function(source, charId, reason) end })
```

#### CharacterHandlers

<TypeTable
  type={{
    loaded: { type: "(source: number, character: CharacterInfo) => void | Promise<void>", typeDescriptionLink: "/fr/docs/developers/api/types#characterinfo", description: "Un personnage est entré dans le monde. S’exécute aussi une fois, au tick qui suit votre appel à `onCharacter`, pour chaque personnage chargé avant le démarrage de votre ressource. Une erreur levée ou un rejet est journalisé.", required: false },
    unloaded: { type: '(source: number, charId: number, reason: "dropped" | "switch") => void', description: "Le personnage est parti : `switch` pour une déconnexion du personnage ou un changement de personnage, `dropped` quand le joueur s’est déconnecté. Chaque `loaded` reçoit exactement un `unloaded`.", required: false },
  }}
/>

#### Retour

`void`.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onCharacter, PlayerMap } from "@aicore-fivem/lib/server";

const playtime = new PlayerMap<{ charId: number; since: number }>();

onCharacter({
  loaded(source, character) {
    playtime.set(source, { charId: character.id, since: Date.now() });
  },
  unloaded(source, charId, reason) {
    const entry = playtime.get(source);
    if (entry) console.log(`character ${charId} played ${Date.now() - entry.since} ms (${reason})`);
    playtime.delete(source);
  },
});
```
</Tab>
<Tab value="Lua">
```lua
local since = {}

aiLib.onCharacter({
    loaded = function(source, character)
        since[source] = os.time()
    end,
    unloaded = function(source, charId, reason)
        print(('character %d played %ds (%s)'):format(charId, os.time() - (since[source] or os.time()), reason))
        since[source] = nil
    end,
})
```
</Tab>
</Tabs>

<Callout type="info">
Appelez-la une seule fois au niveau supérieur d’un fichier serveur. Le PlayerMap ci-dessus se vide de lui-même à la déconnexion ; le gestionnaire `unloaded` s’exécute quand même en premier lors d’une déconnexion, vous pouvez donc y sauvegarder des données.
</Callout>

### isOnline

Si un joueur est toujours connecté. Vérifiez-le après un long `await` avant de donner quoi que ce soit.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
isOnline(source: number): boolean
```

Pas d’équivalent Lua : `GetPlayerName(source) ~= nil`.

**Retour** `true` tant que le joueur est connecté.

```ts

```

## Joueurs proches

Ces fonctions demandent à ai-core quels joueurs se trouvent dans le scope OneSync les uns des autres (environ 424 mètres) et ne mesurent que ces quelques joueurs, au lieu de parcourir tous les joueurs du serveur. Un rayon supérieur à environ 424 m ne trouve personne au-delà.

### playersNear

Les joueurs situés à moins de `radius` mètres d’un joueur.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
playersNear(source: number, radius: number): number[]
```

```lua title="Lua"
local list = aiLib.playersNear(source, radius) -- integer[]
```

<TypeTable
  type={{

/>

<Tabs items={['TypeScript', 'Lua']}>

</Tabs>

## Positions

Pas d’équivalents Lua : Lua dispose des calculs vectoriels (`GetEntityCoords(GetPlayerPed(source))`, `#(a - b)`).


## Stockages par joueur

Aucun d’eux n’a d’équivalent Lua : utilisez une table Lua et videz-la dans `playerDropped`. Créez chaque stockage une seule fois au niveau du module, jamais dans un gestionnaire.

### PlayerMap

Une `Map` indexée par id serveur de joueur, qui se vide d’elle-même quand le joueur se déconnecte. Utilisez-la pour tout ce que vous gardez par joueur (un écran ouvert, un objet sélectionné).

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new PlayerMap<V>(options?: { onDrop?: (source: number, value: V) => void })
```

<TypeTable
  type={{
    "options.onDrop": { type: "(source: number, value: V) => void", description: "S’exécute après le retrait de l’entrée d’un joueur déconnecté, avec sa dernière valeur (terminer une action, sauvegarder quelque chose).", required: false },
  }}
/>

Elle a toutes les méthodes d’une `Map` JavaScript (`get`, `set`, `has`, `delete`, `size`, itération).

```ts
import { PlayerMap } from "@aicore-fivem/lib/server";

const carrying = new PlayerMap<string>({
  onDrop: (source, item) => console.log(`${source} left while carrying ${item}`),
});
carrying.set(source, "box");
```

### Cooldowns

Des cooldowns par joueur sur l’horloge du jeu, libérés quand le joueur se déconnecte.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new Cooldowns()
ready(source: number): boolean
start(source: number, ms: number): void
take(source: number, ms: number): boolean
left(source: number): number
clear(source: number): void
```

| Méthode | Ce qu’elle fait | Retour |
| --- | --- | --- |
| `ready(source)` | Aucun cooldown ne tourne pour le joueur. | `boolean` |
| `start(source, ms)` | Démarre (ou redémarre) le cooldown du joueur pour `ms` millisecondes. | `void` |
| `take(source, ms)` | Démarre le cooldown quand il est prêt. | `true` s’il a démarré, `false` tant qu’un cooldown tourne encore |
| `left(source)` | Millisecondes restantes. | `number`, `0` quand il est prêt |
| `clear(source)` | Termine le cooldown du joueur. | `void` |

```ts
import { onClientCallback, Cooldowns } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const searchCooldown = new Cooldowns();

onClientCallback("my-bins:search", (source) => {
  if (!searchCooldown.take(source, 30_000)) return fail("WAIT");
  return { ok: true };
});
```

<Callout type="warn">
Un joueur peut se reconnecter pour réinitialiser une entrée de `Cooldowns`. Un cooldown qui doit survivre à une reconnexion utilise `KeyedCooldowns` indexé par `online.charId(source)`.
</Callout>

### KeyedCooldowns

Des cooldowns par n’importe quelle clé qui survit à une connexion : un id de personnage, une entité, un id de porte. Les entrées expirées sont nettoyées à mesure que la map grandit.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new KeyedCooldowns<K = number>()
ready(key: K): boolean
start(key: K, ms: number): void
take(key: K, ms: number): boolean
left(key: K): number
clear(key: K): void
```

Mêmes méthodes que `Cooldowns`, par `key`. `start` avec un `ms` de 0 ou moins termine le cooldown.

```ts
import { KeyedCooldowns, online } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const robbed = new KeyedCooldowns<string>(); // par id de magasin
const perCharacter = new KeyedCooldowns(); // par id de personnage

function canRob(source: number, store: string) {
  const charId = online.charId(source);
  if (charId === undefined) return fail("NO_CHARACTER");
  if (!robbed.ready(store)) return fail("STORE_EMPTY");
  if (!perCharacter.take(charId, 15 * 60_000)) return fail("WAIT");
  robbed.start(store, 30 * 60_000);
  return { ok: true };
}
```

### SourceLock

Une seule action en cours par joueur sur plusieurs callbacks. Le `lock: true` d’un callback ne couvre que ce callback ; deux actions qui doivent s’exclure (mettre en vente et vendre le même véhicule) partagent un même `SourceLock`.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new SourceLock()
run<T, B>(source: number, busy: B, task: () => Promise<T>): Promise<T | B>
release(source: number): void
```

<TypeTable
  type={{
    source: { type: "number", description: "Id serveur du joueur.", required: true },
    busy: { type: "B", description: "Ce que `run` renvoie quand le joueur a déjà une tâche en cours (`fail(\"BUSY\")`).", required: true },
    task: { type: "() => Promise<T>", description: "L’action. Le verrou est libéré quand elle se termine, même si elle lève une erreur.", required: true },
  }}
/>

**Retour** (`run`) le résultat de la tâche, ou `busy`. `release(source)` libère le joueur ; appelez-la depuis `playerDropped` (une tâche encore en cours garde sa propre entrée jusqu’à sa fin).

```ts
import { onClientCallback, SourceLock } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const dealer = new SourceLock();
on("playerDropped", () => dealer.release(Number(globalThis.source)));

onClientCallback("my-dealer:list", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
onClientCallback("my-dealer:sell", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
```

### RateLimit

Une limite de rafale par joueur : au plus `count` actions sur n’importe quelle fenêtre de `windowMs`. La porte limite déjà la fréquence de chaque entrée ; utilisez ceci pour une limite supplémentaire, plus lente, sur une action précise.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new RateLimit(count: number, windowMs: number)
take(source: number): boolean
release(source: number): void
```

```lua title="Lua"
local limit = aiLib.RateLimit.new(count, windowMs)
local allowed = limit:take(source)
limit:release(source)
```

<TypeTable
  type={{
    count: { type: "number", description: "Actions autorisées par fenêtre.", required: true },
    windowMs: { type: "number", description: "Durée de la fenêtre en millisecondes (une fenêtre glissante).", required: true },
  }}
/>

**Retour** (`take`) `true` en comptant une action, ou `false` quand le joueur dépasse la limite (non comptée). `release(source)` oublie le joueur ; appelez-la depuis `playerDropped`.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, RateLimit } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const reports = new RateLimit(3, 60_000);
on("playerDropped", () => reports.release(Number(globalThis.source)));

onClientCallback("my-report:send", (source) => {
  if (!reports.take(source)) return fail("TOO_MANY_REPORTS");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local reports = aiLib.RateLimit.new(3, 60000)
AddEventHandler('playerDropped', function() reports:release(source) end)

aiLib.onClientCallback('my-report:send', function(source)
    if not reports:take(source) then return aiLib.fail('TOO_MANY_REPORTS') end
    return { ok = true }
end)
```
</Tab>
</Tabs>

### KeyWatchers

Les joueurs qui reçoivent les changements en direct d’une clé (les voitures d’un parking, une fiche de personnage ouverte). Une clé par joueur : observer une nouvelle clé arrête l’ancienne. Libéré à la déconnexion ; chaque opération est en temps constant.

**Côté :** serveur · **Attend :** non

```ts title="Signature"
new KeyWatchers<K>()
watch(source: number, key: K): void
stop(source: number): void
of(key: K): ReadonlySet<number> | undefined
keyOf(source: number): K | undefined
```

| Méthode | Ce qu’elle fait | Retour |
| --- | --- | --- |
| `watch(source, key)` | Le joueur observe `key` et arrête d’observer la précédente. | `void` |
| `stop(source)` | Le joueur arrête d’observer. | `void` |
| `of(key)` | Les joueurs qui observent `key`. | un ensemble, ou `undefined` quand personne n’observe |
| `keyOf(source)` | La clé que le joueur observe. | la clé, ou `undefined` |

```ts
import { onClientCallback, onClientEvent, KeyWatchers } from "@aicore-fivem/lib/server";
import { oneArg, readText } from "@aicore-fivem/lib/shared";

const lots = new KeyWatchers<string>();

onClientCallback("my-lot:open", { args: oneArg((v) => readText(v, 32)) }, (source, lot) => {
  lots.watch(source, lot);
  return { ok: true, cars: [] }; // le snapshot
});
onClientEvent("my-lot:close", (source) => lots.stop(source));

function carChanged(lot: string, car: unknown) {
  for (const source of lots.of(lot) ?? []) emitNet("my-lot:car", source, car); // le delta
}
```
