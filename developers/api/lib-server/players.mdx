A **player** is a connected client with a server id (`source`). A **character** is the person they play; a player on the character screen has no character loaded. ai-core owns players and characters; these helpers read them.

## online

`online` is your resource's copy of ai-core's loaded players: characters, job and gang memberships with grades, member lists per job and gang, and duty. It reads ai-core once on first use and then follows ai-core's events, so a read is a memory lookup. Use it in hot paths (every chat message, every alert) instead of calling ai-core's exports.

In Lua, `aiLib.online` asks ai-core's exports on every call: fine for actions, not for every tick. It has `character`, `name`, `jobs`, `gangs`, `jobGrade`, `gangGrade`, `dutyJob` and `sources`; the rest has no Lua twin.

### online.sources

The server ids of every player with a loaded character.

**Side:** Server · **Waits:** no

```ts title="Signature"

```

```lua title="Lua"

```

#### Returns

`IterableIterator<number>` (Lua: an array). Players on the character screen are not in it.

#### Example

### online.charId

The id of the player's loaded character (the database id, stable across reconnects).

**Side:** Server · **Waits:** no


No Lua twin: `(aiLib.online.character(source) or {}).id`.

### online.allows

Whether the player may use a place locked by an access rule (jobs, gangs, minimum grades, on-duty). The client's `allows` uses the same rule, so what a player sees is what the server lets them use.

**Side:** Server · **Waits:** no

```ts title="Signature"
online.allows(source: number, rule: AccessRule): boolean
```

No Lua twin.

<TypeTable
  type={{
    source: { type: "number", description: "Server id of the player.", required: true },
    rule: { type: "AccessRule", typeDescriptionLink: "/docs/developers/api/types#accessrule", description: "`{ jobs, gangs, grades, onDuty }`, read from a panel record with `readAccess(record)`. Both lists empty: everyone.", required: true },


## Character lifecycle

### onCharacter

Runs your code when a character enters the world and when it leaves. It also replays the characters already in the world when your resource (re)starts, and covers drops, so you need no `playerDropped` handler next to it.

**Side:** Server · **Waits:** no

```ts title="Signature"
onCharacter(handlers: CharacterHandlers): void
```

```lua title="Lua"
aiLib.onCharacter({ loaded = function(source, character) end, unloaded = function(source, charId, reason) end })
```

#### CharacterHandlers

<TypeTable
  type={{
    loaded: { type: "(source: number, character: CharacterInfo) => void | Promise<void>", typeDescriptionLink: "/docs/developers/api/types#characterinfo", description: "A character entered the world. Also runs once, on the next tick after you call `onCharacter`, for every character loaded before your resource started. A thrown error or rejection is logged.", required: false },
    unloaded: { type: '(source: number, charId: number, reason: "dropped" | "switch") => void', description: "The character left: `switch` for logout or a character switch, `dropped` when the player disconnected. Every `loaded` gets exactly one `unloaded`.", required: false },
  }}
/>

#### Returns

`void`.

#### Example

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onCharacter, PlayerMap } from "@aifivem/lib/server";

const playtime = new PlayerMap<{ charId: number; since: number }>();

onCharacter({
  loaded(source, character) {
    playtime.set(source, { charId: character.id, since: Date.now() });
  },
  unloaded(source, charId, reason) {
    const entry = playtime.get(source);
    if (entry) console.log(`character ${charId} played ${Date.now() - entry.since} ms (${reason})`);
    playtime.delete(source);
  },
});
```
</Tab>
<Tab value="Lua">
```lua
local since = {}

aiLib.onCharacter({
    loaded = function(source, character)
        since[source] = os.time()
    end,
    unloaded = function(source, charId, reason)
        print(('character %d played %ds (%s)'):format(charId, os.time() - (since[source] or os.time()), reason))
        since[source] = nil
    end,
})
```
</Tab>
</Tabs>

<Callout type="info">
Call it once at the top level of a server file. The PlayerMap above is emptied on drop by itself; the `unloaded` handler still runs first for a drop, so you can save data there.
</Callout>

## Per-player stores

None of these have a Lua twin: use a Lua table and clear it in `playerDropped`. Create every store once at module level, never inside a handler.

### PlayerMap

A `Map` keyed by player server id that empties itself when the player drops. Use it for anything you keep per player (an open screen, a selected item).

**Side:** Server · **Waits:** no

```ts title="Signature"
new PlayerMap<V>(options?: { onDrop?: (source: number, value: V) => void })
```

<TypeTable
  type={{
    "options.onDrop": { type: "(source: number, value: V) => void", description: "Runs after the entry of a dropped player was removed, with its last value (finish an action, save something).", required: false },
  }}
/>

It has every method of a JavaScript `Map` (`get`, `set`, `has`, `delete`, `size`, iteration).

```ts
import { PlayerMap } from "@aifivem/lib/server";

const carrying = new PlayerMap<string>({
  onDrop: (source, item) => console.log(`${source} left while carrying ${item}`),
});
carrying.set(source, "box");
```

### Cooldowns

Per-player cooldowns on the game clock, freed when the player drops.

**Side:** Server · **Waits:** no

```ts title="Signature"
new Cooldowns()
ready(source: number): boolean
start(source: number, ms: number): void
take(source: number, ms: number): boolean
left(source: number): number
clear(source: number): void
```

| Method | What it does | Returns |
| --- | --- | --- |
| `ready(source)` | No cooldown runs for the player. | `boolean` |
| `start(source, ms)` | Starts (or restarts) the player's cooldown for `ms` milliseconds. | `void` |
| `take(source, ms)` | Starts the cooldown when it is ready. | `true` when started, `false` while one still runs |
| `left(source)` | Milliseconds left. | `number`, `0` when ready |
| `clear(source)` | Ends the player's cooldown. | `void` |

```ts
import { onClientCallback, Cooldowns } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const searchCooldown = new Cooldowns();

onClientCallback("my-bins:search", (source) => {
  if (!searchCooldown.take(source, 30_000)) return fail("WAIT");
  return { ok: true };
});
```

<Callout type="warn">
A player can reconnect to reset a `Cooldowns` entry. A cooldown that must survive a reconnect uses `KeyedCooldowns` keyed by `online.charId(source)`.
</Callout>

### KeyedCooldowns

Cooldowns by any key that outlives a connection: a character id, an entity, a door id. Expired entries are cleaned up as the map grows.

**Side:** Server · **Waits:** no

```ts title="Signature"
new KeyedCooldowns<K = number>()
ready(key: K): boolean
start(key: K, ms: number): void
take(key: K, ms: number): boolean
left(key: K): number
clear(key: K): void
```

Same methods as `Cooldowns`, by `key`. `start` with `ms` of 0 or less ends the cooldown.

```ts
import { KeyedCooldowns, online } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const robbed = new KeyedCooldowns<string>(); // by store id
const perCharacter = new KeyedCooldowns(); // by character id

function canRob(source: number, store: string) {
  const charId = online.charId(source);
  if (charId === undefined) return fail("NO_CHARACTER");
  if (!robbed.ready(store)) return fail("STORE_EMPTY");
  if (!perCharacter.take(charId, 15 * 60_000)) return fail("WAIT");
  robbed.start(store, 30 * 60_000);
  return { ok: true };
}
```

### SourceLock

One running action per player across several callbacks. A callback's own `lock: true` covers only that callback; two actions that must exclude each other (list and sell the same vehicle) share one `SourceLock`.

**Side:** Server · **Waits:** no

```ts title="Signature"
new SourceLock()
run<T, B>(source: number, busy: B, task: () => Promise<T>): Promise<T | B>
release(source: number): void
```

<TypeTable
  type={{
    source: { type: "number", description: "Server id of the player.", required: true },
    busy: { type: "B", description: "What `run` returns when the player already has a task running (`fail(\"BUSY\")`).", required: true },
    task: { type: "() => Promise<T>", description: "The action. The lock is freed when it settles, even when it throws.", required: true },
  }}
/>

**Returns** (`run`) the task's result, or `busy`. `release(source)` frees the player; call it from `playerDropped` (a task still running keeps its own entry until it settles).

```ts
import { onClientCallback, SourceLock } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const dealer = new SourceLock();
on("playerDropped", () => dealer.release(Number(globalThis.source)));

onClientCallback("my-dealer:list", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
onClientCallback("my-dealer:sell", (source) => dealer.run(source, fail("BUSY"), async () => ({ ok: true })));
```

### RateLimit

A per-player burst limit: at most `count` actions inside any `windowMs`. The gate already rate-limits every input; use this for an extra, slower limit on one action.

**Side:** Server · **Waits:** no

```ts title="Signature"
new RateLimit(count: number, windowMs: number)
take(source: number): boolean
release(source: number): void
```

```lua title="Lua"
local limit = aiLib.RateLimit.new(count, windowMs)
local allowed = limit:take(source)
limit:release(source)
```

<TypeTable
  type={{
    count: { type: "number", description: "Actions allowed per window.", required: true },
    windowMs: { type: "number", description: "Window length in milliseconds (a sliding window).", required: true },
  }}
/>

**Returns** (`take`) `true` and counts one action, or `false` when the player is over the limit (not counted). `release(source)` forgets the player; call it from `playerDropped`.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, RateLimit } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const reports = new RateLimit(3, 60_000);
on("playerDropped", () => reports.release(Number(globalThis.source)));

onClientCallback("my-report:send", (source) => {
  if (!reports.take(source)) return fail("TOO_MANY_REPORTS");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local reports = aiLib.RateLimit.new(3, 60000)
AddEventHandler('playerDropped', function() reports:release(source) end)

aiLib.onClientCallback('my-report:send', function(source)
    if not reports:take(source) then return aiLib.fail('TOO_MANY_REPORTS') end
    return { ok = true }
end)
```
</Tab>
</Tabs>

### KeyWatchers

The players who receive live changes of one key (a parking lot's cars, an open character sheet). One key per player: watching a new key stops the old one. Freed on drop; every operation is constant time.

**Side:** Server · **Waits:** no

```ts title="Signature"
new KeyWatchers<K>()
watch(source: number, key: K): void
stop(source: number): void
of(key: K): ReadonlySet<number> | undefined
keyOf(source: number): K | undefined
```

| Method | What it does | Returns |
| --- | --- | --- |
| `watch(source, key)` | The player watches `key` and stops watching the one before. | `void` |
| `stop(source)` | The player stops watching. | `void` |
| `of(key)` | The players watching `key`. | a set, or `undefined` when nobody watches |
| `keyOf(source)` | The key the player watches. | the key, or `undefined` |

```ts
import { onClientCallback, onClientEvent, KeyWatchers } from "@aifivem/lib/server";
import { oneArg, readText } from "@aifivem/lib/shared";

const lots = new KeyWatchers<string>();

onClientCallback("my-lot:open", { args: oneArg((v) => readText(v, 32)) }, (source, lot) => {
  lots.watch(source, lot);
  return { ok: true, cars: [] }; // the snapshot
});
onClientEvent("my-lot:close", (source) => lots.stop(source));

function carChanged(lot: string, car: unknown) {
  for (const source of lots.of(lot) ?? []) emitNet("my-lot:car", source, car); // the delta
}
```
