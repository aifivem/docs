A lib do servidor é o conjunto de helpers que todo script de servidor `ai-*` usa em vez de escrever o mesmo código de novo: responder clientes com segurança, comandos, jogadores, itens, veículos, dinheiro, logs e o painel de administração. A maioria dos helpers que tocam outro sistema (inventário, chaves, celular, prisão...) passa pelo **ai-core**, então seu script continua funcionando quando o dono do servidor troca o inventário ou o script de celular.

## TypeScript

Importe de `@aifivem/lib/server` em arquivos dentro de `resource/server/`. Helpers que funcionam em qualquer lado (recusas, leitores de entrada, matemática) vêm de `@aifivem/lib/shared`.

```ts title="resource/server/index.ts"
import { onClientCallback, inventory, notify } from "@aifivem/lib/server";
import { fail, oneArg, readId } from "@aifivem/lib/shared";
```

Todo recurso feito a partir do template do ai-core já depende do pacote (`"@aifivem/lib": "workspace:*"` no `package.json`); o build o empacota em `dist/server.js`.

## Lua

Recursos em Lua recebem os mesmos helpers na tabela global `aiLib`, do recurso `ai-lib`. Adicione duas linhas ao seu `fxmanifest.lua`:

```lua title="fxmanifest.lua"
dependency 'ai-lib'
shared_script '@ai-lib/init.lua'
```

Depois chame `aiLib.<name>` em qualquer arquivo de servidor. Cada módulo carrega na primeira vez que você o usa e roda dentro do seu recurso, então os comandos e callbacks que você registra pertencem ao seu recurso e somem quando ele para.

```lua title="server.lua"
aiLib.addCommand('hello', { help = 'Says hello' }, function(source)
    aiLib.notify(source, 'Hello!', 'success')
end)
```

<Callout type="warn">
Funções Lua marcadas com **Espera** (`progressFor`, `minigameFor`, `spawnVehicle`, `triggerClientCallback`, `billing.unpaid`, `appearance.get`) pausam o código até a resposta chegar. Elas só funcionam dentro de uma thread. Os handlers de `aiLib.onClientCallback` e `aiLib.onClientEvent` já rodam em uma; em qualquer outro lugar, envolva a chamada em `CreateThread(function() ... end)`.
</Callout>

Nem todo helper de TypeScript tem um equivalente em Lua. Cada entrada informa quando não tem. Os que faltam em Lua: `PendingActions`, `PlayerMap`, `Cooldowns`, `KeyedCooldowns`, `SourceLock`, `KeyWatchers`, os helpers de posição, `AreaStream`, as classes de state bag, `AdminPanel`, `DataFile` e os helpers de banco de dados (recursos em Lua usam a API oxmysql do ai-mysql para SQL).

## Helpers compartilhados com o cliente

A entrada do servidor também reexporta os helpers de `/fivem`, então você também pode importá-los de `@aifivem/lib/server`. Eles são documentados uma vez em [Lib: compartilhada e fivem](/pt/docs/developers/api/lib-shared):

`registerExport`, `resourceExport`, `optionalExport`, `callExport`, `provideExport`, `isResourceStarted`, `createLocale`, `loadLocaleTexts`, `LOCALE_CONVAR`, `ByResource`, `caller`, `onStop`, `plateOf`, `Reasons`, `every` (com os tipos `EveryOptions` e `Job`), `stateBoolean`, `stateNumber`, `stateString` (tipo `StateParse`).

As classes de state bag `EntityState`, `PlayerState`, `GlobalKey` e `GlobalGroup` exportadas pela entrada do servidor são as versões de servidor: elas adicionam `set`. Veja [State bags](/pt/docs/developers/api/lib-server/state-bags).

## Dois helpers que só o ai-core usa

`sendPlayerData(source, key, value)` e `patchPlayerData(source, key, patch)` enviam um valor dos dados de um jogador (`AiPlayerData`) para o cliente desse jogador. O ai-core os chama; seu script nunca precisa deles. Leia os dados do jogador no cliente com `getPlayerData` ([Lib: cliente](/pt/docs/developers/api/lib-client)).
