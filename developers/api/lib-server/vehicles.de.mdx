## Spawnen

### spawnVehicle

Erstellt ein vernetztes Fahrzeug auf dem Server und richtet es in einem Aufruf ein: Kennzeichen, Sprit, Aussehen, Verriegelung, Routing-Bucket, Schlüssel für den richtigen Zweck, ein Fahrer und Beifahrer. Nutze es für jedes Skript-Fahrzeug (Job-Fahrzeuge, Mietwagen, Garagenfahrzeuge, Admin-Spawns).

**Seite:** Server · **Wartet:** ja (Promise in TypeScript, hält in Lua den Thread an)

```ts title="Signatur"
spawnVehicle(options: SpawnVehicleOptions): Promise<number | null>
```

```lua title="Lua"
local vehicle = aiLib.spawnVehicle(options) -- Entity oder nil, innerhalb eines Threads aufrufen
```

#### Rückgabewert

`Promise<number | null>`: das Entity-Handle des Fahrzeugs. `null`, wenn das Modell nicht existiert (der `asker`-Client hat es gemeldet), die Entity nicht innerhalb von 5 Sekunden erstellt wurde oder der Typ unbekannt ist.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, spawnVehicle, hasCharacter, near } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const DEPOT = { x: 895.4, y: -179.3, z: 74.7 };

onClientCallback(
  "my-taxi:start",
  async (source) => {
    const vehicle = await spawnVehicle({
      model: "taxi",
      coords: { x: 899.1, y: -180.6, z: 73.8, heading: 238 },
      asker: source,
      keysTo: source,
      purpose: "job",
      driver: source,
      fuel: 100,
      setup: { dirt: 0 },
    });
    if (!vehicle) return fail("SPAWN_FAILED");
    return { ok: true, netId: NetworkGetNetworkIdFromEntity(vehicle) };
  },
  { guards: [hasCharacter(), near(DEPOT, 5)], lock: true },
);
```
</Tab>
<Tab value="Lua">
```lua
local DEPOT = vector3(895.4, -179.3, 74.7)

aiLib.onClientCallback('my-taxi:start', function(source)
    if #(GetEntityCoords(GetPlayerPed(source)) - DEPOT) > 5.0 then return aiLib.fail('TOO_FAR') end
    local vehicle = aiLib.spawnVehicle({
        model = 'taxi',
        coords = vector4(899.1, -180.6, 73.8, 238.0),
        asker = source,
        keysTo = source,
        purpose = 'job',
        driver = source,
        fuel = 100,
    })
    if not vehicle then return aiLib.fail('SPAWN_FAILED') end
    return { ok = true, netId = NetworkGetNetworkIdFromEntity(vehicle) }
end, { lock = true })
```
</Tab>
</Tabs>

<Callout type="info">
Die Schlüssel warten (bis zu 3 Sekunden), bis der Server das Kennzeichen liest: Vor dem ersten Sync des besitzenden Clients liest der Server ein leeres Kennzeichen. Hineingesetzte Spieler werden bis zu 2 Sekunden lang erneut gesetzt, bis sie sitzen. In TypeScript gilt der Typ eines Modells von einem Client nur für diesen Spieler, bis der Client eines zweiten Spielers dieselbe Antwort gibt; der Lua-Zwilling behält die erste Antwort, die er bekommt.
</Callout>

### vehicleType

Der Spawn-Typ eines Modells, beim Client eines Spielers erfragt. Nutze es, um zu prüfen, ob ein Modell existiert, bevor du Geld nimmst.

**Seite:** Server · **Wartet:** ja (Promise)

```ts title="Signatur"
vehicleType(model: string, asker: number): Promise<string | null>
```

Kein Lua-Zwilling: `aiLib.spawnVehicle` mit `asker` prüft es und gibt bei einem unbekannten Modell `nil` zurück.

<TypeTable
  type={{
    model: { type: "string", description: "Spawn-Name des Modells.", required: true },
    asker: { type: "number", description: "Server-ID des Spielers, dessen Client antwortet.", required: true },
  }}
/>

#### Rückgabewert

`Promise<string | null>`: `automobile`, `bike`, `boat`, `heli`, `plane`, `submarine`, `trailer` oder `train`; `null`, wenn das Spiel kein solches Fahrzeug hat oder der Client keine gültige Antwort gab. Eine Antwort wird für alle behalten, sobald sich die Clients zweier verschiedener Spieler darauf geeinigt haben, sodass ein modifizierter Client nur seine eigenen Spawns kaputt machen kann.

#### Beispiel

```ts
import { onClientCallback, vehicleType } from "@aicore-fivem/lib/server";
import { fail, oneArg, readText } from "@aicore-fivem/lib/shared";

onClientCallback("my-dealer:buy", { args: oneArg((v) => readText(v, 32)), lock: true }, async (source, model) => {
  if (!(await vehicleType(model, source))) return fail("UNKNOWN_MODEL");
  // das Geld nehmen, dann spawnVehicle(...)
  return { ok: true };
});
```

### randomPlate

Ein zufälliges Kennzeichen wie das des Spiels (zwei Ziffern, drei Buchstaben, drei Ziffern), oder dein Präfix gefolgt von Ziffern.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
randomPlate(prefix?: string): string
```

Kein Lua-Zwilling (`aiLib.spawnVehicle` setzt ein zufälliges Kennzeichen, wenn du keins übergibst).

<TypeTable
  type={{
    prefix: { type: "string", description: "Text, mit dem das Kennzeichen beginnt; der Rest wird bis 8 Zeichen mit Ziffern aufgefüllt. Länger als 8 wird abgeschnitten.", required: false },
  }}
/>

**Rückgabewert:** ein Kennzeichen mit 8 Zeichen (`42ABC123`, oder `TAXI1234` für `randomPlate("TAXI")`). Es wird nicht auf Eindeutigkeit geprüft: Prüfe deine eigene Tabelle, bevor du es speicherst.

```ts
const plate = randomPlate("RENT");
```

## Fahrzeuge finden

### nearestVehicleTo

Das nächstgelegene Fahrzeug innerhalb von `metres` um einen Spieler, das deinen Filter besteht. Das Fahrzeug, in dem der Spieler sitzt, hat Vorrang.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
nearestVehicleTo(source: number, metres: number, filter?: (vehicle: number) => boolean): number
```

```lua title="Lua"
local vehicle = aiLib.nearestVehicleTo(source, metres, filter) -- Entity oder 0
```

<TypeTable
  type={{

    metres: { type: "number", description: "Suchradius in Metern.", required: true },
    filter: { type: "(vehicle: number) => boolean", description: "Überspringt Fahrzeuge, für die er `false` antwortet (verriegelte Türen, ein Modell).", required: false },
  }}
/>

**Rückgabewert:** die Fahrzeug-Entity, oder `0`, wenn keins da ist.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">

</Tab>

<Callout type="warn">
Es geht jedes Fahrzeug auf dem Server durch: Nutze es für Befehle und Aktionen (mit Ratenlimit), nie in einem Tick.
</Callout>

### nearestVehicleAt

Das nächstgelegene Fahrzeug innerhalb von `metres` um einen Punkt. Nutze es, um zu prüfen, ob ein Spawnplatz frei ist.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
nearestVehicleAt(point: { x: number; y: number; z: number }, metres: number, filter?: (vehicle: number) => boolean): number
```

Kein Lua-Zwilling.

**Rückgabewert:** die Fahrzeug-Entity, oder `0`, wenn keins da ist. Geht jedes Fahrzeug durch, wie `nearestVehicleTo`.

```ts
const SPOT = { x: 899.1, y: -180.6, z: 73.8 };
if (nearestVehicleAt(SPOT, 3)) return fail("SPOT_BLOCKED");
```

## Entities aus Client-Eingaben

Ein Client sendet eine Netzwerk-ID, nie ein Entity-Handle. Diese Helfer machen aus einer Net-ID die lebende Server-Entity und prüfen sie, sodass du nie `NetworkGetEntityFromNetworkId` + `DoesEntityExist` + `GetEntityType` von Hand aufrufst.

### entityFromNet

Die lebende Entity hinter der Netzwerk-ID eines Clients.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
entityFromNet(netId: unknown, type?: 1 | 2 | 3): number
```

Kein Lua-Zwilling (Lua hat `vehicleFromNet`).

<TypeTable
  type={{
    netId: { type: "unknown", description: "Der rohe Wert vom Client.", required: true },
    type: { type: "1 | 2 | 3", description: "Geforderter Entity-Typ: 1 Ped, 2 Fahrzeug, 3 Objekt. Jeder Typ, wenn weggelassen.", required: false },
  }}
/>

**Rückgabewert:** die Entity, oder `0`, wenn der Wert keine positive ganze Zahl ist, nicht vernetzt, verschwunden oder von einem anderen Typ.

```ts
const prop = entityFromNet(rawNetId, 3);
if (!prop) return fail("NOT_FOUND");
```

## Sprit

`fuel` liest und setzt den Sprit eines Fahrzeugs (0 bis 100) über die Sprit-Ebene von ai-core, egal welches Sprit-Skript läuft. Kein Lua-Zwilling auf dem Server: Rufe die Exports `GetVehicleFuel` / `SetVehicleFuel` von ai-core auf.

### fuel.get

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
fuel.get(vehicle: number): number | null
```

**Rückgabewert:** der Stand einer Server-Fahrzeug-Entity (0 bis 100), oder `null`, wenn sie keinen hat.

```ts
const level = fuel.get(vehicle) ?? 0;
```

### fuel.set

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
fuel.set(vehicle: number, level: number): boolean
```

<TypeTable
  type={{
    vehicle: { type: "number", description: "Server-Fahrzeug-Entity.", required: true },
    level: { type: "number", description: "Neuer Stand, auf 0-100 begrenzt.", required: true },
  }}
/>

**Rückgabewert:** `true`, wenn gesetzt, `false` bei einem falschen Fahrzeug.

```ts
fuel.set(vehicle, 100);
```

### fuel.provider

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
fuel.provider(): string | null
```

**Rückgabewert:** der Ressourcenname des Sprit-Skripts, das antwortet (`ai-fuel`, `ox_fuel`, `LegacyFuel`...), oder `null`, wenn keins läuft.

```ts
console.log(`fuel through ${fuel.provider() ?? "nothing"}`);
```

## Garagen

`garages` läuft über die Garagen-Ebene von ai-core, egal welches Garagen-Skript läuft; jedes Skript beantwortet nur, was es bereitstellt. Kein Lua-Zwilling.

### garages.impound

Schickt ein Fahrzeug in den Abschlepphof oder öffnet das Abschleppformular des Garagen-Skripts für `by`.

**Seite:** Server · **Wartet:** nein

```ts title="Signatur"
garages.impound(vehicle: number, by?: number): boolean
```

<TypeTable
  type={{
    vehicle: { type: "number", description: "Server-Fahrzeug-Entity.", required: true },
    by: { type: "number", description: "Server-ID des abschleppenden Spielers (Skripte mit Formular öffnen es für diesen Spieler).", required: false },

/>

**Rückgabewert:** `true`, wenn das Garagen-Skript es übernommen hat. `false`, wenn nichts es übernommen hat: Lösche das Fahrzeug selbst.

```ts
if (!garages.impound(vehicle, source)) DeleteEntity(vehicle);
```

### garages.stored

Die Fahrzeuge eines Spielers in Garagen oder im Abschlepphof.

**Seite:** Server · **Wartet:** ja (Promise)
