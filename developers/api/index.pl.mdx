Wszystko, co inny skrypt może wywołać: eksporty ai-core, zdarzenia, które wysyła, oraz funkcje pomocnicze `@aicore-fivem/lib` (własne eksporty każdego skryptu ai-* są na jego stronie w sekcji Skrypty). Każda sygnatura na tych stronach pochodzi ze źródła (`@aicore-fivem/shared` `exports.ts`, JSDoc liba, wywołania eksportów w każdym skrypcie).

## Wybierz właściwą drogę

| Piszesz | Użyj |
| --- | --- |
| Skrypt ai-* lub dowolny zasób TypeScript | `@aicore-fivem/lib`: `inventory`, `vehicleKeys`, `online`, `medical`... Lib wywołuje ai-core za ciebie. |
| Zasób Lua | `aiLib` z ai-lib (`shared_script '@ai-lib/init.lua'`) albo bezpośrednio eksporty ai-core. |
| Skrypt ESX / QB / Qbox / vRP | Nic nowego: most odpowiada na własne API frameworka. Zobacz [Warstwy i most](/pl/docs/developers/layers). |

Przedmioty, klucze pojazdów, alerty, telefon, pogoda, więzienie, ubrania i śmierci zawsze przechodzą przez ai-core, nigdy przez eksporty konkretnego skryptu: ai-core przekazuje wywołanie do skryptu, którego serwer używa do tego zadania.

## Wywołanie eksportu

```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// Jeden typowany uchwyt na zasób, na początku pliku.
const core = resourceExport("ai-core");

const cash = core.GetMoney(source, "cash");
```

```lua
local cash = exports['ai-core']:GetMoney(source, 'cash')
```

- Typy: `resourceExport` czyta je z `CitizenExports` w `@aicore-fivem/shared`. Zasób, który może nie działać, używa `optionalExport("x")` (null, gdy jest zatrzymany).
- Nazwy: każdy eksport odpowiada też z zamienioną wielkością pierwszej litery (`GetMoney` i `getMoney`).
- Eksporty są synchroniczne i zwracają małe wartości. Gdy wartość wymaga czasu (zapisany wygląd), eksport przyjmuje callback: żaden promise nie przechodzi przez granicę zasobu.
- Gorące ścieżki śledzą zdarzenia ai-core zamiast wywoływać eksporty w pętli (tak robi lustro `online` liba).
