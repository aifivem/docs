Tudo o que outro script pode chamar: os exports do ai-core, os eventos que ele dispara, os exports de cada script ai-* e os helpers do `@aicore-fivem/lib`. Cada assinatura destas páginas vem do código-fonte (`@aicore-fivem/shared` `exports.ts`, o JSDoc da lib, as chamadas de export de cada script).

## Escolha a porta certa

| Você escreve | Use |
| --- | --- |
| Um script ai-* ou qualquer recurso em TypeScript | `@aicore-fivem/lib`: `inventory`, `vehicleKeys`, `online`, `medical`... A lib chama o ai-core por você. |
| Um recurso em Lua | `aiLib` do ai-lib (`shared_script '@ai-lib/init.lua'`), ou os exports do ai-core diretamente. |
| Um script de ESX / QB / Qbox | Nada novo: a ponte responde à API do próprio framework. Veja [Camadas e a ponte](/pt/docs/developers/layers). |

Itens, chaves de veículos, alertas, telefone, clima, prisão, roupas e mortes sempre passam pelo ai-core, nunca pelos exports de um script específico: o ai-core encaminha para o script que o servidor roda para aquela tarefa.

## Chamando um export

```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// One typed handle per resource, at the top of the file.
const core = resourceExport("ai-core");

const cash = core.GetMoney(source, "cash");
```

```lua
local cash = exports['ai-core']:GetMoney(source, 'cash')
```

- Tipos: `resourceExport` os lê de `CitizenExports` em `@aicore-fivem/shared`. Um recurso que pode não estar rodando usa `optionalExport("x")` (null enquanto parado).
- Nomes: cada export também responde com a primeira letra na caixa trocada (`GetMoney` e `getMoney`).
- Exports são síncronos e retornam valores pequenos. Quando um valor precisa de tempo (uma aparência salva), o export recebe um callback: nenhuma promise cruza a fronteira de um recurso.
- Caminhos quentes seguem os eventos do ai-core em vez de chamar exports em loop (o espelho `online` da lib faz isso).
