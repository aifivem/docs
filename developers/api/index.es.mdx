Todo lo que otro script puede llamar: los exports de ai-core, los eventos que dispara y las utilidades de `@aicore-fivem/lib` (los exports propios de cada script ai-* están en su página dentro de Scripts). Cada firma de estas páginas sale del código fuente (`exports.ts` de `@aicore-fivem/shared`, el JSDoc de la lib, las llamadas de export de cada script).

## Elige la puerta correcta

| Escribes | Usa |
| --- | --- |
| Un script ai-* o cualquier recurso en TypeScript | `@aicore-fivem/lib`: `inventory`, `vehicleKeys`, `online`, `medical`... La lib llama a ai-core por ti. |
| Un recurso en Lua | `aiLib` de ai-lib (`shared_script '@ai-lib/init.lua'`), o directamente los exports de ai-core. |
| Un script de ESX / QB / Qbox / vRP | Nada nuevo: el puente responde a la propia API del framework. Consulta [Capas y el puente](/es/docs/developers/layers). |

Objetos, llaves de vehículos, alertas, teléfono, clima, prisión, ropa y muertes pasan siempre por ai-core, nunca por los exports de un script concreto: ai-core lo reenvía al script que el servidor tenga para esa tarea.

## Llamar a un export

```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// Un handle tipado por recurso, al principio del archivo.
const core = resourceExport("ai-core");

const cash = core.GetMoney(source, "cash");
```

```lua
local cash = exports['ai-core']:GetMoney(source, 'cash')
```

- Tipos: `resourceExport` los lee de `CitizenExports` en `@aicore-fivem/shared`. Un recurso que puede no estar en marcha usa `optionalExport("x")` (null mientras está detenido).
- Nombres: cada export responde también con la primera letra en la otra caja (`GetMoney` y `getMoney`).
- Los exports son síncronos y devuelven valores pequeños. Cuando un valor necesita tiempo (un aspecto guardado), el export recibe un callback: ninguna promesa cruza el límite de un recurso.
- Las rutas calientes siguen los eventos de ai-core en lugar de llamar a exports en un bucle (el espejo `online` de la lib lo hace así).
