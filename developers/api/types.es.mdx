Las páginas de la API escriben los tipos por su nombre (`Vec3`, `ActionResult`, `InventoryRef`...). Esta página explica cada uno una sola vez: sus campos, qué significa cada campo y un valor de ejemplo.

De dónde viene un tipo:

| Paquete | Import | Tipos |
| --- | --- | --- |
| `@aifivem/shared` | `import type { AiPlayerData } from "@aifivem/shared";` | Todo lo de esta página salvo que el título diga otra cosa. |
| `@aifivem/lib/shared` | `import type { Vec3 } from "@aifivem/lib/shared";` | `Vec3`, `Vec4`, `AccessRule`, `BlipStyle`, `ZoneShape`, `VehicleProps`, `VehicleSetup`, `PlacePed`. |
| `@aifivem/lib/client` | `import type { ProgressOptions } from "@aifivem/lib/client";` | `ProgressOptions`. |
| `@aifivem/lib/server` | `import type { ProgressForOptions } from "@aifivem/lib/server";` | `ProgressForOptions`. |

<Callout type="info">
Lua no tiene tipos en tiempo de ejecución. Una tabla de Lua con las mismas claves es el mismo valor: `{ x = 1.0, y = 2.0, z = 3.0 }` es un `Vec3`. Los arrays son listas de Lua (`{ 'police', 'sheriff' }`), `null` es `nil`. Consulta [Lib para Lua](/es/docs/developers/api/lua) para los vectores.
</Callout>

## Posiciones

### Vec3

Un punto del mundo, en metros. En GTA `x` es el este, `y` el norte y `z` hacia arriba.

<TypeTable
  type={{
    x: { type: 'number', description: 'Posición este-oeste en metros.', required: true },
    y: { type: 'number', description: 'Posición norte-sur en metros.', required: true },
    z: { type: 'number', description: 'Altura en metros.', required: true },
  }}
/>

```ts title="Ejemplo"
const counter: Vec3 = { x: 25.7, y: -1347.3, z: 29.5 };
```

```lua title="Lua"
local counter = vector3(25.7, -1347.3, 29.5) -- o { x = 25.7, y = -1347.3, z = 29.5 }
```

### Vec4

Un punto con orientación: dónde está un ped o aparece un vehículo y hacia dónde mira. Los campos `vec4` del panel y la herramienta de puntos del panel guardan esta forma.

<TypeTable
  type={{
    x: { type: 'number', description: 'Posición este-oeste en metros.', required: true },
    y: { type: 'number', description: 'Posición norte-sur en metros.', required: true },
    z: { type: 'number', description: 'Altura en metros.', required: true },
    heading: { type: 'number', description: "Dirección en grados, 0-360 (la de GTA: 0 = norte, en sentido antihorario).", required: true },
  }}
/>

```ts title="Ejemplo"
const spawn: Vec4 = { x: -42.1, y: -1098.4, z: 26.4, heading: 158.0 };
```

<Callout type="info">
Un `vector4` de Lua llama `w` a la orientación. Los lectores de la lib ([readVec4](/es/docs/developers/api/lib-shared/input#readvec4)) aceptan tanto `heading` como `w`.
</Callout>

### ZoneShape

Un área del mundo. La usan las `Zones` de cliente y las comprobaciones de área del servidor ([geometría de zonas](/es/docs/developers/api/lib-shared/zones)). Es una de tres formas, elegida por `type`.

**Esfera** (una bola alrededor de un punto):

<TypeTable
  type={{
    type: { type: '"sphere"', description: 'Elige esta forma.', required: true },
    center: { type: 'Vec3', description: 'Centro de la bola.', required: true, typeDescription: '{ x, y, z }' },
    radius: { type: 'number', description: 'Radio en metros.', required: true },
  }}
/>

**Cilindro** (un círculo en el suelo que se extiende hacia arriba y hacia abajo):

<TypeTable
  type={{
    type: { type: '"cylinder"', description: 'Elige esta forma.', required: true },
    center: { type: 'Vec3', description: 'Centro del círculo.', required: true },
    radius: { type: 'number', description: 'Radio en el plano del suelo, en metros.', required: true },
    height: { type: 'number', description: 'Cuánto se extiende la zona hacia arriba y hacia abajo desde `center.z`, en metros (la altura total es el doble).', required: true },
  }}
/>

**Polígono** (un polígono en el suelo entre dos alturas):

<TypeTable
  type={{
    type: { type: '"poly"', description: 'Elige esta forma.', required: true },
    points: { type: 'Array<{ x: number; y: number }>', description: 'Esquinas en el suelo, en orden alrededor del área. Al menos 3.', required: true },
    minZ: { type: 'number', description: 'Altura más baja dentro de la zona.', required: true },
    maxZ: { type: 'number', description: 'Altura más alta dentro de la zona.', required: true },
  }}
/>

```ts title="Ejemplo"
const yard: ZoneShape = { type: "sphere", center: { x: 440.1, y: -981.2, z: 30.7 }, radius: 25 };
const lot: ZoneShape = {
  type: "poly",
  points: [ { x: 210, y: -810 }, { x: 240, y: -800 }, { x: 230, y: -770 }, { x: 200, y: -780 } ],
  minZ: 28,
  maxZ: 36,
};
```

## Resultados

### ActionResult

Lo que cada acción del servidor responde a un cliente: o éxito, o una clave de idioma que el cliente muestra como motivo. La rama de éxito puede llevar campos extra (`ActionResult<{ id: number }>`). El nuevo estado nunca viaja en la respuesta: llega como delta.

**Éxito:**

<TypeTable
  type={{
    ok: { type: 'true', description: 'La acción se ejecutó.', required: true },
    '...T': { type: 'T', description: 'Campos extra de `ActionResult<T>` (por ejemplo el id del nuevo registro).' },
  }}
/>

**Rechazo:**

<TypeTable
  type={{
    ok: { type: 'false', description: 'La acción fue rechazada.', required: true },
    error: { type: 'string', description: 'Una clave de idioma de los `locales/*.json` del recurso (`"NOT_ENOUGH_MONEY"`). El cliente la traduce y la muestra.', required: true },
  }}
/>

```ts title="Ejemplo"
const done: ActionResult = { ok: true };
const created: ActionResult<{ id: number }> = { ok: true, id: 42 };
const refused: ActionResult = { ok: false, error: "NOT_ENOUGH_MONEY" };
```

```lua title="Lua"
return { ok = true }
return aiLib.fail('NOT_ENOUGH_MONEY') -- { ok = false, error = 'NOT_ENOUGH_MONEY' }
```

Crea los rechazos con [fail](/es/docs/developers/api/lib-shared/input#fail); lee las respuestas con [isActionOk](/es/docs/developers/api/lib-shared/input#isactionok) y [replyError](/es/docs/developers/api/lib-shared/input#replyerror).

## Dinero

### Nombres de cuenta

El dinero vive en cuentas con nombre. La lista **Accounts** del panel decide cuáles existen; ai-core trae estas:

| Nombre | Etiqueta | Cantidad inicial |
| --- | --- | --- |
| `cash` | Cash (efectivo) | 500 |
| `bank` | Bank (banco) | 5000 |
| `black_money` | Dirty money (dinero sucio) | 0 |
| `crypto` | Crypto (cripto) | 0 |

Un dueño de servidor puede añadir, renombrar o quitar cuentas en el panel, así que lee la lista con el export `GetAccountTypes` en lugar de suponerla. Cuando la lista está vacía, ai-core mantiene una sola cuenta `cash`.

```ts title="Ejemplo"
core.AddMoney(source, "bank", 250, "Paycheck");
```

### LookupSource

Una lista de valores entre los que elige un campo del panel. Un `lookup` en un campo de texto o de nombres hace que el servidor rechace cualquier otra cosa y que el panel ofrezca la lista.

| Valor | La lista |
| --- | --- |
| `"item"` | Objetos del inventario activo. |
| `"job"` | Trabajos de la lista Jobs del panel. |
| `"gang"` | Bandas de la lista Gangs del panel. |
| `"account"` | Cuentas de dinero. |
| `"resource"` | Recursos iniciados. |
| `"player"` | Jugadores conectados, por citizen id. |
| `"vehicle"` | Cada modelo de vehículo que tiene el juego del admin, addons incluidos. El servidor nunca lo rechaza (no puede listar modelos). |
| `"ped"` | Los modelos de ped de GTA. El servidor nunca lo rechaza. |

## Puente de vRP

### VrpConfig

El mapeo de permisos de vRP del panel (`data/vrp.json`), tal como lo lee el puente de vRP de ai-core (export de servidor `GetVrpConfig`; el evento local `ai-core:vrp:config` lleva la misma forma tras un cambio).

<TypeTable
  type={{
    defaults: { type: '{ jobPrefix: boolean; jobOnDuty: boolean; adminPrefix: boolean; playerPrefix: boolean }', description: 'Reglas integradas que se usan cuando ninguna entrada de `permissions` nombra el permiso: `jobPrefix`: `<job>.*` = miembro de ese trabajo (solo de servicio con `jobOnDuty`); `adminPrefix`: `admin.*` = admin (`ai.admin`); `playerPrefix`: `player.*` = todo el mundo.', required: true },
    permissions: { type: 'VrpPermissionRule[]', description: 'Reglas de permisos, campos abajo.', required: true },
    groups: { type: 'Record<string, VrpGroupAlias>', description: 'Nombre de grupo de vRP a lo que significa en ai-core, campos abajo.', required: true },
    items: { type: 'Record<string, string>', description: 'Id de objeto de vRP (`"edible|tacos"`, `"wbody|WEAPON_PISTOL"`) a nombre de objeto del inventario.', required: true },
  }}
/>

**VrpPermissionRule:** concede `permission` a quien coincida con cualquier objetivo rellenado.

<TypeTable
  type={{
    permission: { type: 'string', description: 'El permiso, exacto o un prefijo cuando termina en `*`.', required: true },
