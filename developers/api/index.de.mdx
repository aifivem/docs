Alles, was ein anderes Skript aufrufen kann: die Exports von ai-core, die Events, die es auslöst, und die Helfer von `@aifivem/lib` (die eigenen Exports jedes ai-*-Skripts stehen auf seiner Seite unter Skripte). Jede Signatur auf diesen Seiten stammt aus dem Quellcode (`@aifivem/shared` `exports.ts`, das JSDoc der Lib, die Export-Aufrufe jedes Skripts).

## Der richtige Zugang

| Du schreibst | Nutze |
| --- | --- |
| Ein ai-*-Skript oder eine beliebige TypeScript-Ressource | `@aifivem/lib`: `inventory`, `vehicleKeys`, `online`, `medical`... Die Lib ruft ai-core für dich auf. |
| Eine Lua-Ressource | `aiLib` aus ai-lib (`shared_script '@ai-lib/init.lua'`) oder direkt die Exports von ai-core. |
| Ein ESX- / QB- / Qbox- / vRP-Skript | Nichts Neues: Die Brücke beantwortet die eigene API des Frameworks. Siehe [Ebenen und die Brücke](/de/docs/developers/layers). |

Items, Fahrzeugschlüssel, Alarme, Handy, Wetter, Gefängnis, Kleidung und Tode laufen immer über ai-core, nie über die Exports eines bestimmten Skripts: ai-core leitet an das Skript weiter, das der Server für diese Aufgabe nutzt.

## Einen Export aufrufen

```ts
import { resourceExport } from "@aifivem/lib/server";

// Ein typisiertes Handle pro Ressource, oben in der Datei.
const core = resourceExport("ai-core");

const cash = core.GetMoney(source, "cash");
```

```lua
local cash = exports['ai-core']:GetMoney(source, 'cash')
```

- Typen: `resourceExport` liest sie aus `CitizenExports` in `@aifivem/shared`. Eine Ressource, die eventuell nicht läuft, nutzt `optionalExport("x")` (null, solange sie gestoppt ist).
- Namen: Jeder Export antwortet auch mit vertauschter Groß-/Kleinschreibung des ersten Buchstabens (`GetMoney` und `getMoney`).
- Exports sind synchron und geben kleine Werte zurück. Wo ein Wert Zeit braucht (ein gespeichertes Aussehen), nimmt der Export einen Callback: Kein Promise überquert eine Ressourcengrenze.
- Heiße Pfade folgen den Events von ai-core, statt Exports in einer Schleife aufzurufen (der `online`-Spiegel der Lib macht das).
