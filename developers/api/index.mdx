Everything another script can call: ai-core's exports, the events it fires and the `@aicore-fivem/lib` helpers (each ai-* script's own exports are on its page under Scripts). Every signature on these pages comes from the source (`@aicore-fivem/shared` `exports.ts`, the lib's JSDoc, each script's export calls).

## Pick the right door

| You write | Use |
| --- | --- |
| An ai-* script or any TypeScript resource | `@aicore-fivem/lib`: `inventory`, `vehicleKeys`, `online`, `medical`... The lib calls ai-core for you. |
| A Lua resource | `aiLib` from ai-lib (`shared_script '@ai-lib/init.lua'`), or ai-core's exports directly. |
| An ESX / QB / Qbox / vRP script | Nothing new: the bridge answers the framework's own API. See [Layers and the bridge](/docs/developers/layers). |

Items, vehicle keys, alerts, phone, weather, prison, clothing and deaths always go through ai-core, never a specific script's exports: ai-core forwards to whatever script the server runs for that job.

## Calling an export

```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// One typed handle per resource, at the top of the file.
const core = resourceExport("ai-core");

const cash = core.GetMoney(source, "cash");
```

```lua
local cash = exports['ai-core']:GetMoney(source, 'cash')
```

- Types: `resourceExport` reads them from `CitizenExports` in `@aicore-fivem/shared`. A resource that may not run uses `optionalExport("x")` (null while stopped).
- Names: every export also answers with the first letter's case swapped (`GetMoney` and `getMoney`).
- Exports are synchronous and return small values. Where a value needs time (a stored look), the export takes a callback: no promise crosses a resource boundary.
- Hot paths follow ai-core's events instead of calling exports in a loop (the lib's `online` mirror does this).
