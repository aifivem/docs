Jeder Item-Aufruf läuft über ai-core, nie über die eigenen Exports eines Inventar-Skripts. ai-core leitet jeden Aufruf an das **aktive Inventar** weiter: das, das die Panel-Einstellung **Inventory script** (Inventar-Skript) wählt, oder das erste, das läuft, wenn sie auf automatisch steht (ai-inventory, ox_inventory, qb-inventory, tgiann-inventory und die anderen aus der Kompatibilitätsliste). Wenn der Serverbesitzer das Inventar wechselt, funktioniert dein Skript unverändert weiter.

Was du wissen solltest:

- Ein **Inventar** wird über eine `InventoryRef` benannt: die Server-ID eines Spielers (eine Zahl) für die Taschen dieses Spielers oder eine Text-ID für alles andere (ein Lagername, ein Kofferraum-Kennzeichen). Siehe [InventoryRef](/de/docs/developers/api/types#inventoryref).
- **Item-Namen** sind die Item-Namen des Inventars (`water`, `bandage`, `WEAPON_PISTOL`).
- **Metadaten** sind eine Tabelle zusätzlicher Werte auf einem Stapel (eine Seriennummer, Haltbarkeit). Siehe [ItemMetadata](/de/docs/developers/api/types#itemmetadata).
- Solange **kein Inventar läuft**, antwortet jeder Aufruf mit seinem „Nichts“-Wert: `false`, `0`, einer leeren Liste oder `null`.
- Lager, Shops und benutzbare Items, die du registrierst, werden **von ai-core verwahrt** und an jedes Inventar übergeben, das später aktiv wird, auch nach einem Neustart des Inventars. Registriere sie einmal, wenn dein Skript startet.

### AddItem

Gibt einem Inventar Items.

**Seite:** Server · **Wartet:** nein · **Lib:** [`inventory.addItem`](/de/docs/developers/api/lib-server/items#inventoryadditem)

```ts title="Signature"
AddItem(inv: InventoryRef, item: string, count?: number, metadata?: ItemMetadata, slot?: number): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:AddItem(source, 'water', 2)
```

#### Parameter

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Die Server-ID eines Spielers oder eine Lager- / Kofferraum-ID.', required: true, typeDescription: 'number | string' },
    item: { type: 'string', description: 'Item-Name.', required: true },
    count: { type: 'number', description: 'Wie viele. Eine Zahl ab 1; ein Bruch wird abgerundet.', default: '1' },
    metadata: { type: 'ItemMetadata', description: 'Zusätzliche Werte für den neuen Stapel. Alles, was keine Tabelle ist, wird ignoriert.' },
    slot: { type: 'number', description: 'Slot, in den sie kommen (eine ganze Zahl über 0). Sonst ignoriert; das Inventar wählt.' },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn das Inventar die Items hinzugefügt hat. `false`, wenn sie nicht passen, das Item im Inventar nicht existiert, ein Argument falsch ist (`count` unter 1, leerer Item-Name) oder kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, near } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const core = resourceExport("ai-core");
const TAP = { x: 1206.4, y: -3110.2, z: 5.6 };

onClientCallback("myscript:fillBottle", { guards: [near(TAP, 2)], lock: true }, (source) => {
  if (!core.RemoveItem(source, "empty_bottle")) return fail("NO_BOTTLE");
  if (!core.AddItem(source, "water")) {
    core.AddItem(source, "empty_bottle");
    return fail("NO_SPACE");
  }
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local TAP = vector3(1206.4, -3110.2, 5.6)

aiLib.onClientCallback('myscript:fillBottle', function(source)
  if #(GetEntityCoords(GetPlayerPed(source)) - TAP) > 2.0 then return aiLib.fail('TOO_FAR') end
  if not exports['ai-core']:RemoveItem(source, 'empty_bottle') then return aiLib.fail('NO_BOTTLE') end
  if not exports['ai-core']:AddItem(source, 'water') then
    exports['ai-core']:AddItem(source, 'empty_bottle')
    return aiLib.fail('NO_SPACE')
  end
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, minigameFor, resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

onClientCallback("myscript:pickLock", { lock: true }, async (source) => {
  if (!core.HasItem(source, "lockpick")) return fail("NO_LOCKPICK");
  const result = await minigameFor(source, { game: "lockpick", minMs: 1500 });
  if (result === "broken") core.RemoveItem(source, "lockpick");

});
```

```lua
  if result ~= 'won' then return aiLib.fail('LOCKPICK_FAILED') end
  return { ok = true }
end, { lock = true })
```

### GetItems

Jeder Stapel in einem Inventar, mit Labels.

```ts title="Signature"

```

```lua title="Lua"
local stacks = exports['ai-core']:GetItems(source) -- Liste von Tabellen
```

#### Parameter

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Die Server-ID eines Spielers oder eine Lager- / Kofferraum-ID.', required: true, typeDescription: 'number | string' },
  }}
/>

#### Rückgabe

`InventoryStack[]`: ein Eintrag pro Stapel mit `name`, `label`, `count`, `slot` und `metadata`. Siehe [InventoryStack](/de/docs/developers/api/types#inventorystack). Eine leere Liste für ein leeres oder unbekanntes Inventar, ein falsches Argument oder wenn kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

// Ein Pfandhaus listet jedes Item, das der Spieler trägt und das es ankauft.
const BUYS: Record<string, number> = { gold_ring: 120, rolex: 400 };

onClientCallback("myscript:pawnList", (source) => ({
  ok: true,
  rows: core.GetItems(source)
    .filter((stack) => BUYS[stack.name] !== undefined)
    .map((stack) => ({ slot: stack.slot, label: stack.label, count: stack.count, price: BUYS[stack.name] })),
}));
```
</Tab>
<Tab value="Lua">
```lua
local BUYS = { gold_ring = 120, rolex = 400 }

aiLib.onClientCallback('myscript:pawnList', function(source)
  local rows = {}
  for _, stack in ipairs(exports['ai-core']:GetItems(source)) do
    if BUYS[stack.name] then
      rows[#rows + 1] = { slot = stack.slot, label = stack.label, count = stack.count, price = BUYS[stack.name] }
    end
  end
  return { ok = true, rows = rows }
end)
```
</Tab>
</Tabs>

### RegisterStash

Erstellt ein Lager: eine Aufbewahrungskiste, die Spieler über ihren Namen öffnen. ai-core verwahrt es und registriert es erneut bei jedem Inventar, das aktiv wird.

**Seite:** Server · **Wartet:** nein · **Lib:** [`inventory.registerStash`](/de/docs/developers/api/lib-server/items#inventoryregisterstash)

```ts title="Signature"
RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterStash('police_evidence', 'Evidence', 100, 500000, { 'police' })
```

#### Parameter

<TypeTable
  type={{
    name: { type: 'string', description: 'Eindeutige Lager-ID, zugleich die `InventoryRef`, um es zu öffnen (`police_evidence`).', required: true },
    label: { type: 'string', description: 'Titel auf dem Lagerbildschirm. Übergib einen übersetzten Text.', required: true, default: 'name' },
    slots: { type: 'number', description: 'Anzahl der Slots (über 0, abgerundet).', required: true, default: '50' },
    maxWeight: { type: 'number', description: 'Gewichtslimit in der Einheit des Inventars (Gramm in ai-inventory). Über 0.', required: true, default: '100000' },
    jobs: { type: 'string[]', description: 'Jobs, die es in Inventaren öffnen dürfen, die Jobs prüfen. Leer: alle.', default: '[]' },
  }}
/>

Die Standardwerte gelten, wenn ein Wert fehlt oder falsch ist.

#### Rückgabe

Nichts. Ohne einen Text-`name` tut der Aufruf nichts. Wird derselbe Name erneut registriert, ersetzt das das Lager.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, near } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";
import { Locale } from "common";

const core = resourceExport("ai-core");
const LOCKER = { x: 474.9, y: -994.7, z: 26.3 };

// Einmal beim Start; ai-core übergibt es an Inventare, die später starten.
core.RegisterStash("police_evidence", Locale("STASH_EVIDENCE"), 100, 500_000, ["police"]);

onClientCallback("myscript:openEvidence", { guards: [near(LOCKER, 2)] }, (source) => {
  if (core.GetDutyJob(source) !== "police") return fail("NOT_POLICE");
  return core.OpenInventory(source, "police_evidence") ? { ok: true } : fail("STASH_FAILED");
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()
local LOCKER = vector3(474.9, -994.7, 26.3)

exports['ai-core']:RegisterStash('police_evidence', Locale('STASH_EVIDENCE'), 100, 500000, { 'police' })

  if #(GetEntityCoords(GetPlayerPed(source)) - LOCKER) > 2.0 then return aiLib.fail('TOO_FAR') end
  if exports['ai-core']:GetDutyJob(source) ~= 'police' then return aiLib.fail('NOT_POLICE') end
  if not exports['ai-core']:OpenInventory(source, 'police_evidence') then return aiLib.fail('STASH_FAILED') end
  return { ok = true }
end)
```

### OpenInventory

Öffnet ein Lager, einen Kofferraum oder das Inventar eines anderen Spielers auf dem Bildschirm eines Spielers, neben seinem eigenen.

**Seite:** Server · **Wartet:** nein · **Lib:** [`inventory.openInventory`](/de/docs/developers/api/lib-server/items#inventoryopeninventory)

```ts title="Signature"
OpenInventory(source: number, inv: InventoryRef): boolean
```

```lua title="Lua"
local opened = exports['ai-core']:OpenInventory(source, 'police_evidence')
```

#### Parameter

<TypeTable
  type={{
    source: { type: 'number', description: 'Server-ID des Spielers, der den Bildschirm sieht.', required: true },
    inv: { type: 'InventoryRef', description: 'Was geöffnet wird: eine Lager-ID, eine Kofferraum-ID oder die Server-ID eines anderen Spielers (einen Spieler durchsuchen).', required: true, typeDescription: 'number | string' },
  }}
/>

#### Rückgabe

`boolean`: `true`, wenn das Inventar den Bildschirm geöffnet hat. `false`, wenn es das nicht konnte (unbekanntes Lager, der Spieler hat kein Inventar), ein Argument falsch ist oder kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, isNear, coordsOf, resourceExport } from "@aicore-fivem/lib/server";
import { fail, oneArg, readId } from "@aicore-fivem/lib/shared";

const core = resourceExport("ai-core");

// Die Polizei durchsucht einen gefesselten Spieler, der neben ihr steht.
onClientCallback("myscript:search", { args: oneArg(readId) }, (source, target) => {
  if (core.GetDutyJob(source) !== "police") return fail("NOT_POLICE");
  if (target === source || !isNear(target, coordsOf(source), 2)) return fail("TOO_FAR");
  return core.OpenInventory(source, target) ? { ok: true } : fail("SEARCH_FAILED");
});
```
</Tab>
<Tab value="Lua">
```lua
aiLib.onClientCallback('myscript:search', function(source, target)
  if math.type(target) ~= 'integer' or target == source then return aiLib.fail('BAD_TARGET') end
  if exports['ai-core']:GetDutyJob(source) ~= 'police' then return aiLib.fail('NOT_POLICE') end
  local a, b = GetEntityCoords(GetPlayerPed(source)), GetEntityCoords(GetPlayerPed(target))
  if #(a - b) > 2.0 then return aiLib.fail('TOO_FAR') end
  if not exports['ai-core']:OpenInventory(source, target) then return aiLib.fail('SEARCH_FAILED') end
  return { ok = true }
end)
```
</Tab>
</Tabs>

<Callout type="warn">
Das Inventar prüft hier weder Reichweite noch Berechtigung. Prüfe den Job, die Entfernung und den Zustand des Ziels selbst, bevor du es aufrufst.
</Callout>

### RegisterUsableItem

Macht ein Item benutzbar: Wenn ein Spieler es im Inventar benutzt, läuft deine Funktion. ai-core verwahrt die Funktion, sodass sie mit Inventaren funktioniert, die später starten, und einen Neustart des Inventars übersteht.

**Seite:** Server · **Wartet:** nein · **Lib:** [`inventory.registerUsableItem`](/de/docs/developers/api/lib-server/items#inventoryregisterusableitem)

```ts title="Signature"
RegisterUsableItem(name: string, handler: UsableItemHandler): void
// UsableItemHandler = (source: number, item: UsedItem) => unknown
```

```lua title="Lua"
exports['ai-core']:RegisterUsableItem('bandage', function(source, item) end)
```

#### Parameter

<TypeTable
  type={{
    name: { type: 'string', description: 'Item-Name.', required: true },
    handler: { type: 'UsableItemHandler', description: 'Läuft bei jeder Benutzung mit der Server-ID des Spielers und dem benutzten Stapel (`name`, `slot`, `count`, `metadata`). Gib `false` zurück, um das Item zu behalten.', required: true, typeDescription: '(source: number, item: UsedItem) => unknown' },
  }}
/>

Siehe [UsableItemHandler](/de/docs/developers/api/types#usableitemhandler) und [UsedItem](/de/docs/developers/api/types#useditem).

#### Rückgabe

Nichts. Ohne einen Text-`name` oder eine Funktion tut der Aufruf nichts. Ein zweiter Aufruf für dasselbe Item ersetzt den Handler.

Was nach der Benutzung mit dem Item passiert, hängt vom Inventar ab: Inventare, die ein benutztes Item selbst nehmen (ai-inventory nimmt die **consume**-Menge des Items), behalten es, wenn dein Handler `false` zurückgibt; andere Inventare folgen ihren eigenen Item-Einstellungen, also entferne das Item dort bei Bedarf selbst.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { progressFor, resourceExport } from "@aicore-fivem/lib/server";
import { Locale } from "common";

const core = resourceExport("ai-core");

core.RegisterUsableItem("bandage", (source) => {
  // Der Handler muss sofort antworten; der zeitgesteuerte Teil läuft für sich.
  void (async () => {
    if (!(await progressFor(source, { label: Locale("BANDAGING"), duration: 4000 }))) return;
    if (!core.RemoveItem(source, "bandage")) return;
    emitNet("myscript:client:heal", source, 25); // dein Client-Skript fügt die Gesundheit hinzu
  })();
  return false; // behalten: Es wird oben entfernt, sobald der Balken fertig ist
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

exports['ai-core']:RegisterUsableItem('bandage', function(source, item)
  CreateThread(function()
    if not aiLib.progressFor(source, { label = Locale('BANDAGING'), duration = 4000 }) then return end
    if not exports['ai-core']:RemoveItem(source, 'bandage') then return end
    TriggerClientEvent('myscript:client:heal', source, 25) -- dein Client-Skript fügt die Gesundheit hinzu
  end)
  return false
end)
```
</Tab>
</Tabs>

<Callout type="info">
Eine Benutzung löst außerdem das Server-Event `ai-core:itemUsed (src, name, status)` aus, dem Item-Effekte wie Hunger und Durst folgen. Siehe [Events und Zustand](/de/docs/developers/api/events).
</Callout>

### GetItemDefinition

Ein Item, wie das aktive Inventar es definiert: Label, Gewicht, ob es stapelbar ist, Bild.

**Seite:** Server · **Wartet:** nein · **Lib:** [`inventory.getItemDefinition`](/de/docs/developers/api/lib-server/items#inventorygetitemdefinition)

```ts title="Signature"
GetItemDefinition(name: string): ItemDefinition | null
```

```lua title="Lua"
local def = exports['ai-core']:GetItemDefinition('water') -- Tabelle oder nil
```

#### Parameter

<TypeTable
  type={{
    name: { type: 'string', description: 'Item-Name.', required: true },
  }}
/>

#### Rückgabe

`ItemDefinition | null`: das Item mit `name`, `label`, `weight`, `unique`, `close`, `description` und `image`, wenn das Inventar eines hat. Siehe [ItemDefinition](/de/docs/developers/api/types#itemdefinition). `null` für ein unbekanntes Item, einen leeren Namen oder wenn kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { notify, resourceExport } from "@aicore-fivem/lib/server";
import { Locale } from "common";

const core = resourceExport("ai-core");

/** „Du hast 2x Wasser erhalten“ mit dem eigenen Label des Inventars. */
export function giveWithNotice(source: number, item: string, count: number): void {
  if (!core.AddItem(source, item, count)) return;
  const label = core.GetItemDefinition(item)?.label ?? item;
  notify(source, Locale("NOTIFY_RECEIVED", count, label), "success");
}
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

function GiveWithNotice(source, item, count)
  if not exports['ai-core']:AddItem(source, item, count) then return end
  local def = exports['ai-core']:GetItemDefinition(item)
  aiLib.notify(source, Locale('NOTIFY_RECEIVED', count, def and def.label or item), 'success')
end
```
</Tab>
</Tabs>

### GetItemDefinitions

Jedes Item, das das aktive Inventar definiert, nach Namen geordnet. Nutze es selten (eine Liste einmal aufbauen); für ein einzelnes Item nutze `GetItemDefinition`.

**Seite:** Server · **Wartet:** nein · **Lib:** keine

```ts title="Signature"
GetItemDefinitions(): Record<string, ItemDefinition>
```

```lua title="Lua"
local items = exports['ai-core']:GetItemDefinitions() -- Tabelle mit Item-Namen als Schlüssel
```

#### Parameter

Keine.

#### Rückgabe

`Record<string, ItemDefinition>`: jedes Item. Eine leere Tabelle, solange kein Inventar läuft.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

/** Warnt beim Start vor Items in deiner Config, die das Inventar nicht kennt. */
export function checkItems(names: string[]): void {
  const known = core.GetItemDefinitions();
  for (const name of names) if (!known[name]) console.log(`unknown item: ${name}`);
}
```
</Tab>
<Tab value="Lua">
```lua
function CheckItems(names)
  local known = exports['ai-core']:GetItemDefinitions()
  for _, name in ipairs(names) do
    if not known[name] then print('unknown item: ' .. name) end
  end
end
```
</Tab>
</Tabs>

<Callout type="info">
Führe eine solche Prüfung aus, nachdem das Inventar gestartet ist: Direkt nach einem Serverstart läuft das Inventar eventuell noch nicht, und die Tabelle ist leer.
</Callout>

### UseItem

Führt den für ein Item registrierten Handler aus, als hätte der Spieler es benutzt. Die ESX- / QB-Brücke von ai-core ruft es auf (aus `ESX.UseItem` und QBs `CanUseItem`); ein normales Skript hat keinen Grund dazu.

**Seite:** Server · **Wartet:** nein · **Lib:** keine (nur Brücke)

```ts title="Signature"
UseItem(source: number, name: string, item?: unknown): unknown
```

```lua title="Lua"
local result = exports['ai-core']:UseItem(source, 'bandage', stack)
```

#### Parameter

<TypeTable
  type={{
    source: { type: 'number', description: 'Server-ID des Spielers.', required: true },
    name: { type: 'string', description: 'Item-Name.', required: true },
    item: { type: 'unknown', description: 'Der Stapel, wie das Inventar ihn übergeben hat; wird für den Handler in ein `UsedItem` umgewandelt.' },
  }}
/>

#### Rückgabe

`unknown`: was der Handler zurückgegeben hat. `false`, wenn kein Handler registriert ist, die Argumente falsch sind oder der Handler einen Fehler geworfen hat (wird geloggt).

#### Beispiel

Kein Beispiel: Inventare und die Brücke rufen es auf. Um auf eine Benutzung zu reagieren, registriere das Item mit `RegisterUsableItem`.
