Chaque appel d’objet passe par ai-core, jamais par les exports propres à un script d’inventaire. ai-core transmet chaque appel à l’**inventaire actif** : celui que choisit le réglage **Inventory script** du panneau, ou le premier qui tourne quand il est en automatique (ai-inventory, ox_inventory, qb-inventory, tgiann-inventory et les autres de la liste de compatibilité). Quand le propriétaire du serveur change d’inventaire, votre script continue de fonctionner sans modification.

Ce qu’il faut savoir :

- Un **inventaire** est désigné par un `InventoryRef` : l’id serveur d’un joueur (un nombre) pour les poches de ce joueur, ou un id texte pour tout le reste (un nom de coffre, une plaque de coffre de véhicule). Voir [InventoryRef](/fr/docs/developers/api/types#inventoryref).
- Les **noms d’objets** sont les noms d’objets de l’inventaire (`water`, `bandage`, `WEAPON_PISTOL`).
- Les **métadonnées** sont une table de valeurs supplémentaires sur une pile (un numéro de série, une durabilité). Voir [ItemMetadata](/fr/docs/developers/api/types#itemmetadata).
- Tant qu’**aucun inventaire ne tourne**, chaque appel répond sa valeur « rien » : `false`, `0`, une liste vide ou `null`.
- Les coffres, magasins et objets utilisables que vous enregistrez sont **gardés par ai-core** et transmis à chaque inventaire qui devient actif plus tard, y compris après un redémarrage de l’inventaire. Enregistrez-les une fois au démarrage de votre script.

### AddItem

Donne des objets à un inventaire.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.addItem`](/fr/docs/developers/api/lib-server/items#inventoryadditem)

```ts title="Signature"
AddItem(inv: InventoryRef, item: string, count?: number, metadata?: ItemMetadata, slot?: number): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:AddItem(source, 'water', 2)
```

#### Paramètres

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Un id serveur de joueur, ou un id de coffre / coffre de véhicule.', required: true, typeDescription: 'number | string' },
    item: { type: 'string', description: 'Nom de l’objet.', required: true },
    count: { type: 'number', description: 'Combien. Un nombre de 1 ou plus ; une fraction est arrondie à l’inférieur.', default: '1' },
    metadata: { type: 'ItemMetadata', description: 'Valeurs supplémentaires pour la nouvelle pile. Tout ce qui n’est pas une table est ignoré.' },
    slot: { type: 'number', description: 'L’emplacement où les mettre (un nombre entier supérieur à 0). Ignoré sinon ; l’inventaire choisit.' },
  }}
/>

#### Retour

`boolean` : `true` quand l’inventaire a ajouté les objets. `false` quand ils ne tiennent pas, que l’objet n’existe pas dans l’inventaire, qu’un argument est incorrect (`count` inférieur à 1, nom d’objet vide) ou qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, near } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const core = resourceExport("ai-core");
const TAP = { x: 1206.4, y: -3110.2, z: 5.6 };

onClientCallback("myscript:fillBottle", { guards: [near(TAP, 2)], lock: true }, (source) => {
  if (!core.RemoveItem(source, "empty_bottle")) return fail("NO_BOTTLE");
  if (!core.AddItem(source, "water")) {
    core.AddItem(source, "empty_bottle");
    return fail("NO_SPACE");
  }
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local TAP = vector3(1206.4, -3110.2, 5.6)

aiLib.onClientCallback('myscript:fillBottle', function(source)
  if #(GetEntityCoords(GetPlayerPed(source)) - TAP) > 2.0 then return aiLib.fail('TOO_FAR') end
  if not exports['ai-core']:RemoveItem(source, 'empty_bottle') then return aiLib.fail('NO_BOTTLE') end
  if not exports['ai-core']:AddItem(source, 'water') then
    exports['ai-core']:AddItem(source, 'empty_bottle')
    return aiLib.fail('NO_SPACE')
  end
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

### RemoveItem

Retire des objets d’un inventaire.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.removeItem`](/fr/docs/developers/api/lib-server/items#inventoryremoveitem)

```ts title="Signature"
RemoveItem(inv: InventoryRef, item: string, count?: number, metadata?: ItemMetadata, slot?: number): boolean
```

```lua title="Lua"
local ok = exports['ai-core']:RemoveItem(source, 'lockpick', 1)
```

#### Paramètres

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Un id serveur de joueur, ou un id de coffre / coffre de véhicule.', required: true, typeDescription: 'number | string' },
    item: { type: 'string', description: 'Nom de l’objet.', required: true },
    count: { type: 'number', description: 'Combien. Un nombre de 1 ou plus ; une fraction est arrondie à l’inférieur.', default: '1' },
    metadata: { type: 'ItemMetadata', description: 'Ne retirer que les piles avec ces valeurs de métadonnées.' },
    slot: { type: 'number', description: 'Ne retirer que depuis cet emplacement (un nombre entier supérieur à 0).' },
  }}
/>

#### Retour

`boolean` : `true` quand les objets ont été retirés. `false` quand l’inventaire en contient moins (aucun n’est alors retiré), qu’un argument est incorrect ou qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, minigameFor, resourceExport } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const core = resourceExport("ai-core");

onClientCallback("myscript:pickLock", { lock: true }, async (source) => {
  if (!core.HasItem(source, "lockpick")) return fail("NO_LOCKPICK");
  const result = await minigameFor(source, { game: "lockpick", minMs: 1500 });
  if (result === "broken") core.RemoveItem(source, "lockpick");
  return result === "won" ? { ok: true } : fail("LOCKPICK_FAILED");
});
```
</Tab>
<Tab value="Lua">
```lua
aiLib.onClientCallback('myscript:pickLock', function(source)
  if not exports['ai-core']:HasItem(source, 'lockpick') then return aiLib.fail('NO_LOCKPICK') end
  local result = aiLib.minigameFor(source, { game = 'lockpick', minMs = 1500 })
  if result == 'broken' then exports['ai-core']:RemoveItem(source, 'lockpick') end
  if result ~= 'won' then return aiLib.fail('LOCKPICK_FAILED') end
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

### HasItem

Indique si un inventaire contient au moins une quantité d’un objet.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.hasItem`](/fr/docs/developers/api/lib-server/items#inventoryhasitem)

```ts title="Signature"
HasItem(inv: InventoryRef, item: string, count?: number): boolean
```

```lua title="Lua"
local has = exports['ai-core']:HasItem(source, 'repairkit')
```

#### Paramètres

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Un id serveur de joueur, ou un id de coffre / coffre de véhicule.', required: true, typeDescription: 'number | string' },
    item: { type: 'string', description: 'Nom de l’objet.', required: true },
    count: { type: 'number', description: 'Combien en faut-il (1 ou plus ; une fraction est arrondie à l’inférieur).', default: '1' },
  }}
/>

#### Retour

`boolean` : `true` quand l’inventaire en contient `count` ou plus. `false` quand il en contient moins, que `count` est inférieur à 1, ou qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, progressFor, resourceExport } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";
import { Locale } from "common";

const core = resourceExport("ai-core");

onClientCallback("myscript:repair", { lock: true }, async (source) => {
  if (!core.HasItem(source, "repairkit")) return fail("NO_KIT");
  if (!(await progressFor(source, { label: Locale("REPAIRING"), duration: 8000 }))) return fail("CANCELLED");
  if (!core.RemoveItem(source, "repairkit")) return fail("NO_KIT");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

aiLib.onClientCallback('myscript:repair', function(source)
  if not exports['ai-core']:HasItem(source, 'repairkit') then return aiLib.fail('NO_KIT') end
  if not aiLib.progressFor(source, { label = Locale('REPAIRING'), duration = 8000 }) then return aiLib.fail('CANCELLED') end
  if not exports['ai-core']:RemoveItem(source, 'repairkit') then return aiLib.fail('NO_KIT') end
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

<Callout type="info">
Revérifiez avec la réponse de `RemoveItem` après tout ce qui attend (une barre de progression, un mini-jeu) : le joueur a pu jeter l’objet entre-temps.
</Callout>

### GetItems

Chaque pile d’un inventaire, avec libellés.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.getItems`](/fr/docs/developers/api/lib-server/items#inventorygetitems)

```ts title="Signature"
GetItems(inv: InventoryRef): InventoryStack[]
```

```lua title="Lua"
local stacks = exports['ai-core']:GetItems(source) -- liste de tables
```

#### Paramètres

<TypeTable
  type={{
    inv: { type: 'InventoryRef', description: 'Un id serveur de joueur, ou un id de coffre / coffre de véhicule.', required: true, typeDescription: 'number | string' },
  }}
/>

#### Retour

`InventoryStack[]` : une entrée par pile avec `name`, `label`, `count`, `slot` et `metadata`. Voir [InventoryStack](/fr/docs/developers/api/types#inventorystack). Une liste vide pour un inventaire vide ou inconnu, un argument incorrect ou aucun inventaire en cours.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

// Un prêteur sur gages liste chaque objet que porte le joueur et qu’il rachète.
const BUYS: Record<string, number> = { gold_ring: 120, rolex: 400 };

onClientCallback("myscript:pawnList", (source) => ({
  ok: true,
  rows: core.GetItems(source)
    .filter((stack) => BUYS[stack.name] !== undefined)
    .map((stack) => ({ slot: stack.slot, label: stack.label, count: stack.count, price: BUYS[stack.name] })),
}));
```
</Tab>
<Tab value="Lua">
```lua
local BUYS = { gold_ring = 120, rolex = 400 }

aiLib.onClientCallback('myscript:pawnList', function(source)
  local rows = {}
  for _, stack in ipairs(exports['ai-core']:GetItems(source)) do
    if BUYS[stack.name] then
      rows[#rows + 1] = { slot = stack.slot, label = stack.label, count = stack.count, price = BUYS[stack.name] }
    end
  end
  return { ok = true, rows = rows }
end)
```
</Tab>
</Tabs>

### RegisterStash

Crée un coffre : une boîte de stockage que les joueurs ouvrent par son nom. ai-core le garde et l’enregistre de nouveau auprès de chaque inventaire qui devient actif.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.registerStash`](/fr/docs/developers/api/lib-server/items#inventoryregisterstash)

```ts title="Signature"
RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterStash('police_evidence', 'Evidence', 100, 500000, { 'police' })
```

#### Paramètres

<TypeTable
  type={{
    name: { type: 'string', description: 'Id unique du coffre, aussi l’`InventoryRef` pour l’ouvrir (`police_evidence`).', required: true },
    label: { type: 'string', description: 'Titre affiché sur l’écran du coffre. Passez un texte traduit.', required: true, default: 'name' },
    slots: { type: 'number', description: 'Nombre d’emplacements (supérieur à 0, arrondi à l’inférieur).', required: true, default: '50' },
    maxWeight: { type: 'number', description: 'Limite de poids dans l’unité de l’inventaire (grammes dans ai-inventory). Supérieure à 0.', required: true, default: '100000' },
    jobs: { type: 'string[]', description: 'Métiers autorisés à l’ouvrir dans les inventaires qui vérifient les métiers. Vide : tout le monde.', default: '[]' },
  }}
/>

Les valeurs par défaut s’appliquent quand une valeur manque ou est incorrecte.

#### Retour

Rien. Sans `name` texte, l’appel ne fait rien. Enregistrer de nouveau le même nom remplace le coffre.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, near } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";
import { Locale } from "common";

const core = resourceExport("ai-core");
const LOCKER = { x: 474.9, y: -994.7, z: 26.3 };

// Une fois au démarrage ; ai-core le transmet aux inventaires qui démarrent plus tard.
core.RegisterStash("police_evidence", Locale("STASH_EVIDENCE"), 100, 500_000, ["police"]);

onClientCallback("myscript:openEvidence", { guards: [near(LOCKER, 2)] }, (source) => {
  if (core.GetDutyJob(source) !== "police") return fail("NOT_POLICE");
  return core.OpenInventory(source, "police_evidence") ? { ok: true } : fail("STASH_FAILED");
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()
local LOCKER = vector3(474.9, -994.7, 26.3)

exports['ai-core']:RegisterStash('police_evidence', Locale('STASH_EVIDENCE'), 100, 500000, { 'police' })

aiLib.onClientCallback('myscript:openEvidence', function(source)
  if #(GetEntityCoords(GetPlayerPed(source)) - LOCKER) > 2.0 then return aiLib.fail('TOO_FAR') end
  if exports['ai-core']:GetDutyJob(source) ~= 'police' then return aiLib.fail('NOT_POLICE') end
  if not exports['ai-core']:OpenInventory(source, 'police_evidence') then return aiLib.fail('STASH_FAILED') end
  return { ok = true }
end)
```
</Tab>
</Tabs>

### OpenInventory

Ouvre un coffre, un coffre de véhicule ou l’inventaire d’un autre joueur sur l’écran d’un joueur, à côté du sien.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.openInventory`](/fr/docs/developers/api/lib-server/items#inventoryopeninventory)

```ts title="Signature"
OpenInventory(source: number, inv: InventoryRef): boolean
```

```lua title="Lua"
local opened = exports['ai-core']:OpenInventory(source, 'police_evidence')
```

#### Paramètres

<TypeTable
  type={{
    source: { type: 'number', description: 'Id serveur du joueur qui voit l’écran.', required: true },
    inv: { type: 'InventoryRef', description: 'Quoi ouvrir : un id de coffre, un id de coffre de véhicule, ou l’id serveur d’un autre joueur (fouiller un joueur).', required: true, typeDescription: 'number | string' },
  }}
/>

#### Retour

`boolean` : `true` quand l’inventaire a ouvert l’écran. `false` quand il n’a pas pu (coffre inconnu, le joueur n’a pas d’inventaire), qu’un argument est incorrect ou qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, isNear, coordsOf, resourceExport } from "@aifivem/lib/server";
import { fail, oneArg, readId } from "@aifivem/lib/shared";

const core = resourceExport("ai-core");

// La police fouille un joueur menotté debout à côté d’elle.
onClientCallback("myscript:search", { args: oneArg(readId) }, (source, target) => {
  if (core.GetDutyJob(source) !== "police") return fail("NOT_POLICE");
  if (target === source || !isNear(target, coordsOf(source), 2)) return fail("TOO_FAR");
  return core.OpenInventory(source, target) ? { ok: true } : fail("SEARCH_FAILED");
});
```
</Tab>
<Tab value="Lua">
```lua
aiLib.onClientCallback('myscript:search', function(source, target)
  if math.type(target) ~= 'integer' or target == source then return aiLib.fail('BAD_TARGET') end
  if exports['ai-core']:GetDutyJob(source) ~= 'police' then return aiLib.fail('NOT_POLICE') end
  local a, b = GetEntityCoords(GetPlayerPed(source)), GetEntityCoords(GetPlayerPed(target))
  if #(a - b) > 2.0 then return aiLib.fail('TOO_FAR') end
  if not exports['ai-core']:OpenInventory(source, target) then return aiLib.fail('SEARCH_FAILED') end
  return { ok = true }
end)
```
</Tab>
</Tabs>

<Callout type="warn">
L’inventaire ne fait ici aucune vérification de distance ni de permission. Vérifiez vous-même le métier, la distance et l’état de la cible avant de l’appeler.
</Callout>

### RegisterShop

Crée un magasin de script : une liste d’objets avec des prix que votre script ouvre pour un joueur (une armurerie, un distributeur automatique). L’inventaire dessine le magasin et prend le paiement à sa façon (liquide, puis banque). ai-core le garde et le transmet à chaque inventaire qui devient actif.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.registerShop`](/fr/docs/developers/api/lib-server/items#inventoryregistershop)

```ts title="Signature"
RegisterShop(name: string, label: string, items: ShopProduct[]): void
```

```lua title="Lua"

```

#### Paramètres

<TypeTable
  type={{
    name: { type: 'string', description: 'Id unique du magasin (`police_armoury`).', required: true },

    items: { type: 'ShopProduct[]', description: 'Les produits : `{ name, price }` avec un prix entier de 0 ou plus par objet. 200 au plus ; les lignes avec un nom ou un prix incorrect sont ignorées.', required: true, typeDescription: '{ name: string; price: number }[]' },
  }}
/>

```ts
import { onClientCallback, resourceExport, near } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";
import { Locale } from "common";

const core = resourceExport("ai-core");
const ARMOURY = { x: 482.6, y: -995.2, z: 30.7 };

core.RegisterShop("police_armoury", Locale("SHOP_ARMOURY"), [
  { name: "WEAPON_STUNGUN", price: 0 },
  { name: "bandage", price: 10 },
]);

onClientCallback("myscript:armoury", { guards: [near(ARMOURY, 2)] }, (source) => {
  if (core.GetDutyJob(source) !== "police") return fail("NOT_POLICE");
  return core.OpenShop(source, "police_armoury") ? { ok: true } : fail("SHOP_FAILED");
});
```

### OpenShop

Ouvre sur l’écran d’un joueur un magasin enregistré avec `RegisterShop`.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.openShop`](/fr/docs/developers/api/lib-server/items#inventoryopenshop)

```ts title="Signature"
OpenShop(source: number, name: string): boolean
```

```lua title="Lua"
local opened = exports['ai-core']:OpenShop(source, 'police_armoury')
```

#### Paramètres

<TypeTable
  type={{
    source: { type: 'number', description: 'Id serveur du joueur.', required: true },
    name: { type: 'string', description: 'Id du magasin donné à `RegisterShop`.', required: true },
  }}
/>

#### Retour

`boolean` : `true` quand le magasin s’est ouvert. `false` quand aucun magasin ne porte ce nom, que l’inventaire actif n’a pas de magasins de script, qu’il n’a pas pu l’ouvrir, ou qu’aucun inventaire ne tourne.

#### Exemple

Voir l’exemple de `RegisterShop` ci-dessus : enregistrez une fois au démarrage, puis ouvrez après vos propres vérifications de métier et de distance.

<Callout type="warn">
Comme `OpenInventory`, ceci ne fait aucune vérification de distance ni d’accès. Vérifiez-les d’abord.
</Callout>

### RegisterUsableItem

Rend un objet utilisable : quand un joueur l’utilise dans l’inventaire, votre fonction s’exécute. ai-core garde la fonction, elle fonctionne donc avec les inventaires qui démarrent plus tard et survit à un redémarrage de l’inventaire.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.registerUsableItem`](/fr/docs/developers/api/lib-server/items#inventoryregisterusableitem)

```ts title="Signature"
RegisterUsableItem(name: string, handler: UsableItemHandler): void
// UsableItemHandler = (source: number, item: UsedItem) => unknown
```

```lua title="Lua"
exports['ai-core']:RegisterUsableItem('bandage', function(source, item) end)
```

#### Paramètres

<TypeTable
  type={{
    name: { type: 'string', description: 'Nom de l’objet.', required: true },
    handler: { type: 'UsableItemHandler', description: 'S’exécute à chaque utilisation avec l’id serveur du joueur et la pile utilisée (`name`, `slot`, `count`, `metadata`). Renvoyez `false` pour garder l’objet.', required: true, typeDescription: '(source: number, item: UsedItem) => unknown' },
  }}
/>

Voir [UsableItemHandler](/fr/docs/developers/api/types#usableitemhandler) et [UsedItem](/fr/docs/developers/api/types#useditem).

#### Retour

Rien. Sans `name` texte ou sans fonction, l’appel ne fait rien. Un second appel pour le même objet remplace le handler.

Ce qu’il advient de l’objet après utilisation dépend de l’inventaire : les inventaires qui retirent eux-mêmes un objet utilisé (ai-inventory retire la quantité **consume** de l’objet) le gardent quand votre handler renvoie `false` ; les autres inventaires suivent leurs propres réglages d’objets, retirez donc l’objet vous-même là où c’est nécessaire.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { progressFor, resourceExport } from "@aifivem/lib/server";
import { Locale } from "common";

const core = resourceExport("ai-core");

core.RegisterUsableItem("bandage", (source) => {
  // Le handler doit répondre tout de suite ; la partie temporisée tourne d’elle-même.
  void (async () => {
    if (!(await progressFor(source, { label: Locale("BANDAGING"), duration: 4000 }))) return;
    if (!core.RemoveItem(source, "bandage")) return;
    emitNet("myscript:client:heal", source, 25); // votre script client ajoute la santé
  })();
  return false; // le garder : il est retiré plus haut une fois la barre terminée
});
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

exports['ai-core']:RegisterUsableItem('bandage', function(source, item)
  CreateThread(function()
    if not aiLib.progressFor(source, { label = Locale('BANDAGING'), duration = 4000 }) then return end
    if not exports['ai-core']:RemoveItem(source, 'bandage') then return end
    TriggerClientEvent('myscript:client:heal', source, 25) -- votre script client ajoute la santé
  end)
  return false
end)
```
</Tab>
</Tabs>

<Callout type="info">
Une utilisation déclenche aussi l’événement serveur `ai-core:itemUsed (src, name, status)`, que suivent les effets d’objets comme la faim et la soif. Voir [Événements et état](/fr/docs/developers/api/events).
</Callout>

### GetItemDefinition

Un objet tel que le définit l’inventaire actif : libellé, poids, s’il s’empile, image.

**Côté :** Serveur · **Attend :** non · **Lib :** [`inventory.getItemDefinition`](/fr/docs/developers/api/lib-server/items#inventorygetitemdefinition)

```ts title="Signature"
GetItemDefinition(name: string): ItemDefinition | null
```

```lua title="Lua"
local def = exports['ai-core']:GetItemDefinition('water') -- table ou nil
```

#### Paramètres

<TypeTable
  type={{
    name: { type: 'string', description: 'Nom de l’objet.', required: true },
  }}
/>

#### Retour

`ItemDefinition | null` : l’objet avec `name`, `label`, `weight`, `unique`, `close`, `description` et `image` quand l’inventaire en a une. Voir [ItemDefinition](/fr/docs/developers/api/types#itemdefinition). `null` pour un objet inconnu, un nom vide ou aucun inventaire en cours.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { notify, resourceExport } from "@aifivem/lib/server";
import { Locale } from "common";

const core = resourceExport("ai-core");

/** "You received 2x Water" with the inventory's own label. */
export function giveWithNotice(source: number, item: string, count: number): void {
  if (!core.AddItem(source, item, count)) return;
  const label = core.GetItemDefinition(item)?.label ?? item;
  notify(source, Locale("NOTIFY_RECEIVED", count, label), "success");
}
```
</Tab>
<Tab value="Lua">
```lua
local Locale = aiLib.locale()

function GiveWithNotice(source, item, count)
  if not exports['ai-core']:AddItem(source, item, count) then return end
  local def = exports['ai-core']:GetItemDefinition(item)
  aiLib.notify(source, Locale('NOTIFY_RECEIVED', count, def and def.label or item), 'success')
end
```
</Tab>
</Tabs>

### GetItemDefinitions

Chaque objet que définit l’inventaire actif, indexé par nom. Utilisez-le rarement (construire une liste une fois) ; pour un seul objet, utilisez `GetItemDefinition`.

**Côté :** Serveur · **Attend :** non · **Lib :** aucune

```ts title="Signature"
GetItemDefinitions(): Record<string, ItemDefinition>
```

```lua title="Lua"
local items = exports['ai-core']:GetItemDefinitions() -- table indexée par nom d’objet
```

#### Paramètres

Aucun.

#### Retour

`Record<string, ItemDefinition>` : chaque objet. Une table vide tant qu’aucun inventaire ne tourne.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

/** Warns at start about items in your config that the inventory does not know. */
export function checkItems(names: string[]): void {
  const known = core.GetItemDefinitions();
  for (const name of names) if (!known[name]) console.log(`unknown item: ${name}`);
}
```
</Tab>
<Tab value="Lua">
```lua
function CheckItems(names)
  local known = exports['ai-core']:GetItemDefinitions()
  for _, name in ipairs(names) do
    if not known[name] then print('unknown item: ' .. name) end
  end
end
```
</Tab>
</Tabs>

<Callout type="info">
Faites une telle vérification après le démarrage de l’inventaire : juste après un démarrage du serveur, l’inventaire peut ne pas encore tourner et la table est vide.
</Callout>

<TypeTable

  }}
/>

`{ weight, maxWeight } | null` : le poids porté et la limite, en grammes. `null` quand l’inventaire actif ne les donne pas, que le joueur n’a pas d’inventaire chargé ou qu’aucun inventaire ne tourne.

### UseItem

Exécute le handler enregistré pour un objet, comme si le joueur l’avait utilisé. Le pont ESX / QB d’ai-core l’appelle (depuis `ESX.UseItem` et `CanUseItem` de QB) ; un script normal n’a aucune raison de le faire.

**Côté :** Serveur · **Attend :** non · **Lib :** aucune (pont uniquement)

```ts title="Signature"
UseItem(source: number, name: string, item?: unknown): unknown
```

```lua title="Lua"
local result = exports['ai-core']:UseItem(source, 'bandage', stack)
```

#### Paramètres

<TypeTable
  type={{
    source: { type: 'number', description: 'Id serveur du joueur.', required: true },
    name: { type: 'string', description: 'Nom de l’objet.', required: true },
    item: { type: 'unknown', description: 'La pile telle que l’inventaire l’a donnée ; transformée en `UsedItem` pour le handler.' },
  }}
/>

#### Retour

`unknown` : ce que le handler a renvoyé. `false` quand aucun handler n’est enregistré, que les arguments sont incorrects ou que le handler a levé une erreur (elle est enregistrée dans le log).

#### Exemple

Pas d’exemple : les inventaires et le pont l’appellent. Pour réagir à une utilisation, enregistrez l’objet avec `RegisterUsableItem`.
