ai-core aloja un único panel de administración para todos los scripts. La mayoría de los exports de esta página son fontanería que `@aifivem/lib` llama por ti: un script construido con `AdminPanel` y `addCommand` de la lib nunca llama por sí mismo a `RegisterAdminPanel`, `AdminPanelChanged` ni `RegisterCommands`. Se documentan para que sepas qué ocurre y puedas darles soporte desde otro lenguaje. `RegisterExternalPanel` y `GetLookupValues` son útiles para cualquier script.

### RegisterAdminPanel

Anuncia que el recurso que llama tiene una sección en el panel. Entonces ai-core le pide su esquema y sus datos cada vez que un admin abre el panel.

**Lado:** Servidor · **Espera:** no · **Lib:** lo llama el [`AdminPanel`](/es/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib cuando se inicia

```ts title="Firma"
RegisterAdminPanel(resource: string): void
```

```lua title="Lua"
exports['ai-core']:RegisterAdminPanel(GetCurrentResourceName())
```

#### Parámetros

<TypeTable
  type={{
    resource: { type: 'string', description: 'Se mantiene por compatibilidad con llamadas antiguas y se ignora: el panel siempre pertenece al recurso que llama.', required: true },
  }}
/>

#### Devuelve

Nada. El registro se elimina cuando el recurso se detiene.

#### Ejemplo

Sin ejemplo: lo llama el `AdminPanel` de la lib. Un recurso que se registre sin la lib también debe responder a los exports a los que ai-core llama de vuelta (`AdminPanelSnapshot`, `AdminPanelData`, `AdminPanelSummary`, tipados como `AdminPanelResourceExports` en `@aifivem/shared`), que es trabajo de la lib.

### AdminPanelChanged

Un recurso de panel avisa a ai-core de que cambió uno de sus registros. ai-core reenvía el cambio a cada admin que tiene el panel abierto, para que su pantalla se actualice sin recargar.

**Lado:** Servidor · **Espera:** no · **Lib:** lo llama el [`AdminPanel`](/es/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib tras cada cambio guardado

```ts title="Firma"
AdminPanelChanged(delta: AdminDelta): void
```

```lua title="Lua"
exports['ai-core']:AdminPanelChanged({ resource = GetCurrentResourceName(), file = 'shops', key = 'shop_1', value = record })
```

#### Parámetros

<TypeTable
  type={{
    delta: { type: 'AdminDelta', description: 'Qué cambió: `resource`, `file` (el nombre del archivo de datos), `key` (el registro, ausente para un archivo de ajustes completo) y el nuevo `value` (`null` para un registro borrado).', required: true, typeDescription: '{ resource: string; file: string; key?: string; value: unknown }' },
  }}
/>

Consulta [AdminDelta](/es/docs/developers/api/types#admindelta).

#### Devuelve

Nada. ai-core no comprueba el delta; lo envía tal cual.

#### Ejemplo

Sin ejemplo: lo llama el `AdminPanel` de la lib después de validar y guardar un cambio.

### RegisterCommands

Lista los comandos de un recurso en la pestaña **Commands** (comandos) del panel, con su ayuda, sus parámetros y quién puede usarlos.

**Lado:** Servidor · **Espera:** no · **Lib:** lo llama el [`addCommand`](/es/docs/developers/api/lib-server/commands#addcommand) de la lib (TypeScript y `aiLib.addCommand` en Lua)

```ts title="Firma"
RegisterCommands(resource: string, commands: CommandInfo[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterCommands(GetCurrentResourceName(), commands)
```

#### Parámetros

<TypeTable
  type={{
    resource: { type: 'string', description: 'Se mantiene por compatibilidad con llamadas antiguas y se ignora: los comandos pertenecen al recurso que llama.', required: true },
    commands: { type: 'CommandInfo[]', description: 'Cada comando del recurso: `names` (el primero = el nombre, el resto = alias), `help`, `params` y `aces` (`null` = todo el mundo). Las entradas no válidas se saltan con un aviso en la consola.', required: true },
  }}
/>

Consulta [CommandInfo](/es/docs/developers/api/types#commandinfo) y [CommandParam](/es/docs/developers/api/types#commandparam).

#### Devuelve

Nada. La lista se elimina cuando el recurso se detiene. Para comandos restringidos a un principal (`group.admin`), ai-core también concede a ese principal `command.<name>`, lo que necesita `add_ace resource.ai-core command.add_ace allow` (y `command.remove_ace`) en `permission.cfg`.

#### Ejemplo

Sin ejemplo: usa `addCommand` de la lib (TypeScript) o `aiLib.addCommand` (Lua) y el comando aparece solo en la pestaña. Los comandos creados con un `RegisterCommand` a secas también se listan, marcados como simples.

### GetLookupValues

Los valores de una lista de valores: los nombres de objetos del inventario activo, los nombres de trabajos, de bandas, etc. La validación del panel de la lib lo usa para comprobar que existe un valor que ha escrito un admin.

**Lado:** Servidor · **Espera:** no · **Lib:** lo usa la validación del [`AdminPanel`](/es/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib

```ts title="Firma"
GetLookupValues(source: LookupSource): string[]
```

```lua title="Lua"
local items = exports['ai-core']:GetLookupValues('item') -- lista de nombres de objetos
```

#### Parámetros

<TypeTable
  type={{
    source: { type: 'LookupSource', description: 'Qué lista.', required: true, typeDescription: '"item" | "job" | "gang" | "account" | "resource" | "player" | "vehicle" | "ped"' },
  }}
/>

| `source` | Valores |
| --- | --- |
| `item` | Nombres de objetos del inventario activo. |
| `job` / `gang` | Nombres de trabajos / bandas del panel. |
| `account` | Nombres de tipos de cuenta (`cash`, `bank`...). |
| `resource` | Nombres de los recursos iniciados. |
| `player` | Citizen ids de los jugadores con un personaje cargado. |
| `vehicle` / `ped` | Siempre vacío: solo el juego del admin puede listar modelos. |

Consulta [LookupSource](/es/docs/developers/api/types#lookupsource).

#### Devuelve

`string[]`: los valores, ordenados por su etiqueta. Una lista vacía para un `source` desconocido, para `vehicle` y `ped`, y cuando la lista aún no se conoce (no hay ningún inventario en marcha): trata la lista vacía como "no se puede comprobar", no como "nada es válido".

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

/** Checks a reward item from your config; unknown is fine while no inventory runs. */
export function isKnownItem(name: string): boolean {
  const items = core.GetLookupValues("item");
  return items.length === 0 || items.includes(name);
}
```
</Tab>
<Tab value="Lua">
```lua
function IsKnownItem(name)
  local items = exports['ai-core']:GetLookupValues('item')
  if #items == 0 then return true end
  for _, item in ipairs(items) do
    if item == name then return true end
  end
  return false
end
```
</Tab>
</Tabs>

<Callout type="info">
La lista se construye de nuevo en cada llamada (la lista de objetos puede ser larga). Llámalo cuando valides, no en un bucle.
</Callout>

### RegisterExternalPanel

Lista la pantalla de ajustes propia de otro script en el dashboard del panel de ai-core, para que el dueño del servidor encuentre los ajustes de todos los scripts en un solo sitio. La tarjeta abre la pantalla con un comando de chat, o muestra una página web dentro del panel.

**Lado:** Servidor · **Espera:** no · **Lib:** ninguna

```ts title="Firma"
RegisterExternalPanel(panel: {
  id?: string;
  label: string;
  icon?: string;
  description?: string;
  command?: string;
  url?: string;
}): void
```

```lua title="Lua"
exports['ai-core']:RegisterExternalPanel({ label = 'My script', command = 'myscriptconfig' })
```

#### Parámetros

<TypeTable
  type={{
    panel: { type: 'object', description: 'La tarjeta del dashboard. Campos abajo.', required: true },
  }}
/>

#### Campos del panel

<TypeTable
  type={{
    id: { type: 'string', description: 'Id de la tarjeta, único dentro de tu recurso (de 2 a 48 letras, dígitos, `_`, `.`, `-`). Una segunda llamada con el mismo id reemplaza la tarjeta.', default: 'el nombre del recurso' },
    label: { type: 'string', description: 'Título de la tarjeta. Se corta a 48 caracteres.', required: true },
    icon: { type: 'string', description: 'Nombre del icono de la tarjeta. Se corta a 32 caracteres.' },
    description: { type: 'string', description: 'Una línea bajo el título. Se corta a 160 caracteres.' },
    command: { type: 'string', description: 'Comando de chat que abre tu pantalla (se quita una `/` inicial). Da `command` o `url`.' },
    url: { type: 'string', description: 'Una página web que se muestra dentro del panel. Solo direcciones `https://` (una página NUI de tu recurso o un sitio de confianza); se corta a 300 caracteres.' },
  }}
/>

#### Devuelve

Nada. Sin un `label`, o sin `command` ni `url`, la tarjeta no se añade. Las tarjetas se eliminan cuando tu recurso se detiene.

#### Ejemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

// Una vez al iniciar.
core.RegisterExternalPanel({
  label: "My script",
  icon: "gear",
  description: "Shops, prices and rewards",
  command: "myscriptconfig",
});
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-core']:RegisterExternalPanel({
  label = 'My script',
  icon = 'gear',
  description = 'Shops, prices and rewards',
  command = 'myscriptconfig',
})
```
</Tab>
</Tabs>

<Callout type="info">
Un script que no puedes cambiar puede listarse con líneas en su `fxmanifest.lua`: `ai_admin_label`, `ai_admin_command` o `ai_admin_url`, y opcionalmente `ai_admin_icon` y `ai_admin_description`. El dueño del servidor también puede añadir tarjetas a mano en el panel.
</Callout>
