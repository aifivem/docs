---
title: Chaves de veículos
description: Dê, remova e verifique chaves de veículos pelo script de chaves que o servidor roda.
icon: KeyRound
---

Toda chamada de chave passa pelo ai-core, nunca pelos exports próprios de um script de chaves (ai-vehiclekeys incluído). O ai-core a encaminha ao **sistema de chaves ativo**: o que a configuração **Key script** do painel escolhe, ou o primeiro que estiver rodando. Quando nenhum script de chaves está rodando, todo jogador conta como tendo todas as chaves.

Um **veículo** é informado como um handle de entidade do servidor (o número que `CreateVehicleServerSetter` ou `spawnVehicle` retorna) ou como um texto de placa. Uma placa é aparada e passada para maiúsculas antes, então `" ab12cde "` e `"AB12CDE"` são a mesma chave.

Cada chave tem um **propósito** que diz ao sistema de chaves por que o jogador a recebe. Alguns sistemas de chaves os tratam de forma diferente (um veículo comprado recebe um item de chave novo, um veículo de emprego uma chave fixa na ignição). Veja [KeyPurpose](/pt/docs/developers/api/types#keypurpose).

| Propósito | Quando |
| --- | --- |
| `purchase` | O jogador agora é dono do veículo (concessionária, admin deu): uma chave nova, cópias antigas param de funcionar. |
| `garage` | Um veículo próprio tirado da garagem: o dono já tem a chave. |
| `job` | Um veículo de trabalho para o turno. |
| `rental` | Um veículo alugado pelo tempo do aluguel. |
| `temporary` | Qualquer outra coisa de curta duração (spawn de admin, test drive, veículo de assalto). O padrão. |

### GiveVehicleKeys

Dá a um jogador as chaves de um veículo.

**Lado:** Servidor · **Espera:** não · **Lib:** [`vehicleKeys.give`](/pt/docs/developers/api/lib-server/vehicles#vehiclekeysgive) (e [`spawnVehicle({ keysTo, purpose })`](/pt/docs/developers/api/lib-server/vehicles#spawnvehicle) as dá por você)

```ts title="Assinatura"
GiveVehicleKeys(source: number, vehicle: number | string, purpose?: KeyPurpose): void
```

```lua title="Lua"
exports['ai-core']:GiveVehicleKeys(source, vehicle, 'rental')
```

#### Parâmetros

<TypeTable
  type={{
    source: { type: 'number', description: 'Id de servidor do jogador que recebe as chaves.', required: true },
    vehicle: { type: 'number | string', description: 'Handle de entidade do servidor do veículo, ou a placa dele.', required: true },
    purpose: { type: 'KeyPurpose', description: 'Por que o jogador as recebe. Qualquer outro valor conta como `temporary`.', default: '"temporary"', typeDescription: '"purchase" | "garage" | "job" | "rental" | "temporary"' },
  }}
/>

#### Retorno

Nada. A chamada não faz nada quando a entidade do veículo não existe, a placa está vazia, `source` não é um número ou nenhum sistema de chaves está rodando. Um erro do sistema de chaves é registrado no log, não lançado.

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, spawnVehicle } from "@aifivem/lib/server";
import { fail } from "@aifivem/lib/shared";

const core = resourceExport("ai-core");
const SPAWN = { x: -1023.5, y: -2694.1, z: 13.9, heading: 150 };

onClientCallback("myscript:rentScooter", { lock: true }, async (source) => {
  if (!core.RemoveMoney(source, "cash", 100, "scooter_rental")) return fail("NOT_ENOUGH_MONEY");
  const vehicle = await spawnVehicle({ model: "faggio", coords: SPAWN, asker: source });
  if (!vehicle) {
    core.AddMoney(source, "cash", 100, "scooter_rental_refund");
    return fail("SPAWN_FAILED");
  }
  core.GiveVehicleKeys(source, vehicle, "rental");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
local SPAWN = vector4(-1023.5, -2694.1, 13.9, 150.0)

aiLib.onClientCallback('myscript:rentScooter', function(source)
  if not exports['ai-core']:RemoveMoney(source, 'cash', 100, 'scooter_rental') then return aiLib.fail('NOT_ENOUGH_MONEY') end
  local vehicle = aiLib.spawnVehicle({ model = 'faggio', coords = SPAWN, asker = source })
  if not vehicle then
    exports['ai-core']:AddMoney(source, 'cash', 100, 'scooter_rental_refund')
    return aiLib.fail('SPAWN_FAILED')
  end
  exports['ai-core']:GiveVehicleKeys(source, vehicle, 'rental')
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

<Callout type="info">
Um veículo recém-criado não tem placa no servidor até o cliente dono dele sincronizá-lo. Passe a entidade, não uma placa que você leu logo depois de criá-lo; o `spawnVehicle` da lib espera a placa e pode dar as chaves ele mesmo (`keysTo`, `purpose`).
</Callout>

### RemoveVehicleKeys

Tira de um jogador as chaves de um veículo.

**Lado:** Servidor · **Espera:** não · **Lib:** [`vehicleKeys.remove`](/pt/docs/developers/api/lib-server/vehicles#vehiclekeysremove)

```ts title="Assinatura"
RemoveVehicleKeys(source: number, vehicle: number | string): void
```

```lua title="Lua"
exports['ai-core']:RemoveVehicleKeys(source, 'AB12CDE')
```

#### Parâmetros

<TypeTable
  type={{
    source: { type: 'number', description: 'Id de servidor do jogador.', required: true },
    vehicle: { type: 'number | string', description: 'Handle de entidade do servidor do veículo, ou a placa dele.', required: true },
  }}
/>

#### Retorno

Nada. Os mesmos casos silenciosos de `GiveVehicleKeys`.

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

/** The rental ended: the keys go, then the scooter. */
export function endRental(source: number, vehicle: number): void {
  core.RemoveVehicleKeys(source, vehicle);
  if (DoesEntityExist(vehicle)) DeleteEntity(vehicle);
}
```
</Tab>
<Tab value="Lua">
```lua
function EndRental(source, vehicle)
  exports['ai-core']:RemoveVehicleKeys(source, vehicle)
  if DoesEntityExist(vehicle) then DeleteEntity(vehicle) end
end
```
</Tab>
</Tabs>

<Callout type="warn">
Remova as chaves antes de apagar o veículo. Alguns sistemas de chaves leem a placa da entidade, o que falha depois que ela sumiu.
</Callout>

### HasVehicleKeys

Se um jogador tem as chaves de um veículo.

**Lado:** Servidor · **Espera:** não · **Lib:** [`vehicleKeys.has`](/pt/docs/developers/api/lib-server/vehicles#vehiclekeyshas)

```ts title="Assinatura"
HasVehicleKeys(source: number, vehicle: number | string): boolean
```

```lua title="Lua"
local has = exports['ai-core']:HasVehicleKeys(source, vehicle)
```

#### Parâmetros

<TypeTable
  type={{
    source: { type: 'number', description: 'Id de servidor do jogador.', required: true },
    vehicle: { type: 'number | string', description: 'Handle de entidade do servidor do veículo, ou a placa dele.', required: true },
  }}
/>

#### Retorno

`boolean`: `true` quando o jogador tem as chaves. Também `true` quando nenhum sistema de chaves está rodando, quando o sistema de chaves não sabe responder a essa pergunta ou quando ele falha, para que a falta de um script de chaves nunca tranque os jogadores para fora. `false` quando o jogador não tem chave, a entidade do veículo não existe, a placa está vazia ou `source` não é um número.

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport, vehicleNearPlayer } from "@aifivem/lib/server";
import { fail, oneArg, readId } from "@aifivem/lib/shared";

const core = resourceExport("ai-core");

// Abrir o porta-malas de um carro ao lado do jogador exige as chaves dele.
onClientCallback("myscript:openTrunk", { args: oneArg(readId) }, (source, netId) => {
  const vehicle = vehicleNearPlayer(source, netId, { metres: 4 });
  if (!vehicle) return fail("TOO_FAR");
  if (!core.HasVehicleKeys(source, vehicle)) return fail("NO_KEYS");
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
aiLib.onClientCallback('myscript:openTrunk', function(source, netId)
  local vehicle = aiLib.vehicleNearPlayer(source, netId, { metres = 4 }) -- 0 quando não está perto
  if vehicle == 0 then return aiLib.fail('TOO_FAR') end
  if not exports['ai-core']:HasVehicleKeys(source, vehicle) then return aiLib.fail('NO_KEYS') end
  return { ok = true }
end)
```
</Tab>
</Tabs>
