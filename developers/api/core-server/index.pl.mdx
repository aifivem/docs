ai-core to zasób frameworka. Inne zasoby pytają go o postać gracza, pieniądze, prace i przedmioty oraz zlecają mu zadania, takie jak "daj temu graczowi klucz" albo "wyślij alert policji". Robią to przez **eksporty**: funkcje, które ai-core udostępnia do wywołania z dowolnego innego zasobu na serwerze.

Te strony wymieniają każdy eksport serwerowy, który rejestruje ai-core, pogrupowany według tematu. Każdy wpis pokazuje, co robi eksport, jego dokładną sygnaturę, każdy parametr, co zwraca w każdym przypadku i działający przykład w TypeScript i Lua.

## Wywołanie eksportu

Eksport wywołuje się nazwą zasobu, do którego należy (`ai-core`), i nazwą eksportu.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Jeden typowany uchwyt na plik, na początku. Tu jest to bezpieczne: FiveM wyszukuje każdy
// eksport przy pierwszym użyciu i zapomina go, gdy ai-core się restartuje.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- Bez konfiguracji: exports['ai-core'] działa w każdym skrypcie serwerowym.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

Co trzeba wiedzieć przed rozpoczęciem:

- **Typy TypeScript.** `resourceExport("ai-core")` jest typowany z `AiCoreServerExports` w `@aifivem/shared`, więc twój edytor zna każdą nazwę, parametr i typ zwracany. Nigdy nie pisz `resourceExport("ai-core").GetMoney(...)` wewnątrz funkcji: trzymaj jeden uchwyt na początku pliku.
- **Lua używa dwukropka.** Pisz `exports['ai-core']:GetMoney(source, 'cash')`, nie z kropką. Odpowiedź `null` przychodzi w Lua jako `nil`, tablica jako lista Lua (od indeksu 1), obiekt jako tabela.
- **Dwie pisownie.** Każdy eksport odpowiada też z zamienioną wielkością pierwszej litery: `GetMoney` i `getMoney` to ta sama funkcja.
- **Eksporty nigdy nie czekają.** Każdy eksport odpowiada od razu małą wartością. Gdy odpowiedź wymaga bazy danych (zapisany wygląd, lista rachunków), eksport przyjmuje callback `done` zamiast zwracać Promise, bo Promise nie może przejść z jednego zasobu do drugiego.
- **Nie na gorących ścieżkach.** Wywołanie eksportu kopiuje jego argumenty i odpowiedź. Nie wywołuj eksportów w każdej klatce ani dla każdego gracza w pętli. Dla "kto jest na służbie", imienia postaci lub prac wielu graczy używaj lustra `online` liba, które śledzi zdarzenia ai-core ([Lib: serwer](/pl/docs/developers/api/lib-server)).
- **ai-core musi działać pierwszy.** Dodaj `dependency 'ai-core'` w swoim `fxmanifest.lua` (zasób ai-* wymienia go w `package.json` `fxDependencies`), aby twój zasób startował po ai-core.
- **`source` to id serwera gracza.** To liczba, którą FiveM daje połączonemu graczowi. Id postaci (`charId`) to inna liczba: id wiersza postaci w bazie danych.

## Lib czy eksport?

Większość eksportów ma opakowanie w `@aifivem/lib/server` (a wiele w `aiLib` dla Lua). Opakowanie wywołuje ten sam eksport, więc zachowanie jest identyczne; po prostu czyta się je przyjemniej (`inventory.addItem(source, "water")` zamiast `core.AddItem(source, "water")`) i zamienia callbacki na Promise tam, gdzie to bezpieczne. Każdy wpis podaje swoje opakowanie w linii **Lib**. Używaj tego, co wolisz; zasób Lua bez ai-lib wywołuje eksport bezpośrednio.

## Przykłady na tych stronach

Przykłady to kompletne pliki serwerowe. Przykłady TypeScript używają `addCommand` i `onClientCallback` z liba; przykłady Lua używają `aiLib.addCommand` i `aiLib.onClientCallback` z ai-lib, które wymagają tych linii w twoim `fxmanifest.lua`:

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Czekające wywołania Lua (`aiLib.progressFor`, `Wait`) działają tylko wewnątrz wątku; handlery komend i callbacków już w nim działają.
