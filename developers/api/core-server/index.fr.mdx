ai-core est la ressource du framework. Les autres ressources lui demandent le personnage, l’argent, les métiers et les objets d’un joueur, et lui confient du travail comme « donne une clé à ce joueur » ou « envoie une alerte police ». Elles le font via des **exports** : des fonctions qu’ai-core rend appelables depuis n’importe quelle autre ressource du serveur.

Ces pages listent chaque export serveur qu’enregistre ai-core, regroupés par thème. Chaque entrée montre ce que fait l’export, sa signature exacte, chaque paramètre, ce qu’il renvoie dans chaque cas, et un exemple fonctionnel en TypeScript et en Lua.

## Appeler un export

Un export s’appelle par le nom de la ressource qui le possède (`ai-core`) et le nom de l’export.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Un handle typé par fichier, en haut. C’est sûr ici : FiveM recherche chaque
// export à la première utilisation et l’oublie quand ai-core redémarre.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- Aucune préparation : exports['ai-core'] fonctionne dans n’importe quel script serveur.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

Ce qu’il faut savoir avant de commencer :

- **Types TypeScript.** `resourceExport("ai-core")` est typé depuis `AiCoreServerExports` dans `@aifivem/shared`, si bien que votre éditeur connaît chaque nom, paramètre et type de retour. N’écrivez jamais `resourceExport("ai-core").GetMoney(...)` dans une fonction : gardez l’unique handle en haut du fichier.
- **Lua utilise deux-points.** Écrivez `exports['ai-core']:GetMoney(source, 'cash')`, pas un point. Une réponse `null` arrive en Lua comme `nil`, un tableau comme une liste Lua (index 1 en premier), un objet comme une table.
- **Deux orthographes.** Chaque export répond aussi avec la casse de la première lettre inversée : `GetMoney` et `getMoney` sont la même fonction.
- **Les exports n’attendent jamais.** Chaque export répond tout de suite avec une petite valeur. Quand la réponse a besoin de la base de données (une apparence enregistrée, une liste de factures), l’export prend un callback `done` au lieu de renvoyer une Promise, car une Promise ne peut pas passer d’une ressource à une autre.
- **Pas dans les chemins chauds.** Un appel d’export copie ses arguments et sa réponse. N’appelez pas d’exports à chaque frame ni pour chaque joueur dans une boucle. Pour « qui est en service », le nom ou les métiers d’un personnage sur beaucoup de joueurs, utilisez le miroir `online` de la lib, qui suit les événements d’ai-core ([Lib : serveur](/fr/docs/developers/api/lib-server)).
- **ai-core doit tourner en premier.** Mettez `dependency 'ai-core'` dans votre `fxmanifest.lua` (une ressource ai-* le liste dans `fxDependencies` de `package.json`), pour que votre ressource démarre après ai-core.
- **`source` est l’id serveur du joueur.** C’est le nombre que FiveM donne à un joueur connecté. Un id de personnage (`charId`) est un autre nombre : l’id de la ligne du personnage dans la base de données.

## La lib ou l’export ?

La plupart des exports ont une enveloppe dans `@aifivem/lib/server` (et beaucoup dans `aiLib` en Lua). L’enveloppe appelle le même export, le comportement est donc identique ; elle se lit simplement mieux (`inventory.addItem(source, "water")` au lieu de `core.AddItem(source, "water")`) et transforme les callbacks en Promises quand c’est sûr. Chaque entrée nomme son enveloppe sur la ligne **Lib**. Utilisez ce que vous préférez ; une ressource Lua sans ai-lib appelle l’export directement.

## Les exemples de ces pages

Les exemples sont des fichiers serveur complets. Les exemples TypeScript utilisent `addCommand` et `onClientCallback` de la lib ; les exemples Lua utilisent `aiLib.addCommand` et `aiLib.onClientCallback` d’ai-lib, qui demandent ces lignes dans votre `fxmanifest.lua` :

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Les appels Lua qui attendent (`aiLib.progressFor`, `Wait`) ne fonctionnent que dans un thread ; les handlers de commandes et de callbacks tournent déjà dans un thread.
