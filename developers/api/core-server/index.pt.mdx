O ai-core é o recurso do framework. Os outros recursos pedem a ele o personagem, o dinheiro, os empregos e os itens de um jogador, e mandam trabalho para ele como "dê uma chave a este jogador" ou "envie um alerta à polícia". Eles fazem isso por **exports**: funções que o ai-core torna chamáveis por qualquer outro recurso do servidor.

Estas páginas listam cada export de servidor que o ai-core registra, agrupados por tema. Cada entrada mostra o que o export faz, a assinatura exata, cada parâmetro, o que ele retorna em cada caso e um exemplo funcional em TypeScript e Lua.

## Chamando um export

Um export é chamado pelo nome do recurso que o possui (`ai-core`) e pelo nome do export.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

// Um handle tipado por arquivo, no topo. Aqui é seguro: o FiveM procura cada
// export no primeiro uso e o esquece quando o ai-core reinicia.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- Nenhuma preparação: exports['ai-core'] funciona em qualquer script de servidor.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

O que saber antes de começar:

- **Tipos de TypeScript.** `resourceExport("ai-core")` é tipado a partir de `AiCoreServerExports` em `@aicore-fivem/shared`, então seu editor conhece cada nome, parâmetro e tipo de retorno. Nunca escreva `resourceExport("ai-core").GetMoney(...)` dentro de uma função: mantenha o único handle no topo do arquivo.
- **Lua usa dois-pontos.** Escreva `exports['ai-core']:GetMoney(source, 'cash')`, não um ponto. Uma resposta `null` chega em Lua como `nil`, um array como uma lista Lua (índice 1 primeiro), um objeto como uma table.
- **Duas grafias.** Cada export também responde com a primeira letra na caixa trocada: `GetMoney` e `getMoney` são a mesma função.
- **Exports nunca esperam.** Cada export responde na hora com um valor pequeno. Quando a resposta precisa do banco de dados (um visual salvo, uma lista de faturas), o export recebe um callback `done` em vez de retornar uma Promise, porque uma Promise não consegue passar de um recurso para outro.
- **Fora dos caminhos quentes.** Uma chamada de export copia os argumentos e a resposta. Não chame exports a cada frame ou para cada jogador num loop. Para "quem está em serviço", o nome ou os empregos de um personagem em muitos jogadores, use o espelho `online` da lib, que segue os eventos do ai-core ([Lib: servidor](/pt/docs/developers/api/lib-server)).
- **O ai-core precisa rodar primeiro.** Coloque `dependency 'ai-core'` no seu `fxmanifest.lua` (um recurso ai-* o lista em `fxDependencies` no `package.json`), para que seu recurso inicie depois do ai-core.
- **`source` é o id de servidor do jogador.** É o número que o FiveM dá a um jogador conectado. Um id de personagem (`charId`) é outro número: o id da linha do personagem no banco de dados.

## A lib ou o export?

A maioria dos exports tem um wrapper em `@aicore-fivem/lib/server` (e muitos no `aiLib` do Lua). O wrapper chama o mesmo export, então o comportamento é idêntico; ele só fica mais legível (`inventory.addItem(source, "water")` em vez de `core.AddItem(source, "water")`) e transforma callbacks em Promises onde isso é seguro. Cada entrada nomeia o seu wrapper na linha **Lib**. Use o que preferir; um recurso em Lua sem o ai-lib chama o export diretamente.

## Exemplos nestas páginas

Os exemplos são arquivos de servidor completos. Os exemplos em TypeScript usam `addCommand` e `onClientCallback` da lib; os exemplos em Lua usam `aiLib.addCommand` e `aiLib.onClientCallback` do ai-lib, que precisam destas linhas no seu `fxmanifest.lua`:

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Chamadas de Lua que esperam (`aiLib.progressFor`, `Wait`) só funcionam dentro de uma thread; handlers de comandos e callbacks já rodam numa.
