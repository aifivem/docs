ai-core héberge un seul panneau d’administration pour tous les scripts. La plupart des exports de cette page sont de la tuyauterie que `@aicore-fivem/lib` appelle pour vous : un script construit avec `AdminPanel` et `addCommand` de la lib n’appelle jamais lui-même `RegisterAdminPanel`, `AdminPanelChanged` ou `RegisterCommands`. Ils sont documentés pour que vous sachiez ce qui se passe et puissiez les prendre en charge depuis un autre langage. `RegisterExternalPanel` et `GetLookupValues` sont utiles à n’importe quel script.

### RegisterAdminPanel

Annonce que la ressource appelante a une section de panneau. ai-core lui demande alors son schéma et ses données chaque fois qu’un admin ouvre le panneau.

**Côté :** Serveur · **Attend :** non · **Lib :** appelé par [`AdminPanel`](/fr/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib à son démarrage

```ts title="Signature"
RegisterAdminPanel(resource: string): void
```

```lua title="Lua"
exports['ai-core']:RegisterAdminPanel(GetCurrentResourceName())
```

#### Paramètres

<TypeTable
  type={{
    resource: { type: 'string', description: 'Gardé pour les anciens appelants et ignoré : le panneau appartient toujours à la ressource qui appelle.', required: true },
  }}
/>

#### Retour

Rien. L’enregistrement est abandonné quand la ressource s’arrête.

#### Exemple

Pas d’exemple : `AdminPanel` de la lib l’appelle. Une ressource qui s’enregistre sans la lib doit aussi répondre aux exports qu’ai-core rappelle (`AdminPanelSnapshot`, `AdminPanelData`, `AdminPanelSummary`, typés `AdminPanelResourceExports` dans `@aicore-fivem/shared`), ce qui est le travail de la lib.

### AdminPanelChanged

Une ressource de panneau signale à ai-core que l’un de ses enregistrements a changé. ai-core transmet le changement à chaque admin qui a le panneau ouvert, pour que son écran se mette à jour sans rechargement.

**Côté :** Serveur · **Attend :** non · **Lib :** appelé par [`AdminPanel`](/fr/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib après chaque changement enregistré

```ts title="Signature"
AdminPanelChanged(delta: AdminDelta): void
```

```lua title="Lua"
exports['ai-core']:AdminPanelChanged({ resource = GetCurrentResourceName(), file = 'shops', key = 'shop_1', value = record })
```

#### Paramètres

<TypeTable
  type={{
    delta: { type: 'AdminDelta', description: 'Ce qui a changé : `resource`, `file` (le nom du fichier de données), `key` (l’enregistrement, absent pour un fichier de réglages entier) et la nouvelle `value` (`null` pour un enregistrement supprimé).', required: true, typeDescription: '{ resource: string; file: string; key?: string; value: unknown }' },
  }}
/>

Voir [AdminDelta](/fr/docs/developers/api/types#admindelta).

#### Retour

Rien. ai-core ne vérifie pas le delta ; il l’envoie tel quel.

#### Exemple

Pas d’exemple : `AdminPanel` de la lib l’appelle après qu’un changement a été validé et enregistré.

### RegisterCommands

Liste les commandes d’une ressource dans l’onglet **Commands** du panneau, avec leur aide, leurs paramètres et qui peut les utiliser.

**Côté :** Serveur · **Attend :** non · **Lib :** appelé par [`addCommand`](/fr/docs/developers/api/lib-server/commands#addcommand) de la lib (TypeScript et `aiLib.addCommand` en Lua)

```ts title="Signature"
RegisterCommands(resource: string, commands: CommandInfo[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterCommands(GetCurrentResourceName(), commands)
```

#### Paramètres

<TypeTable
  type={{
    resource: { type: 'string', description: 'Gardé pour les anciens appelants et ignoré : les commandes appartiennent à la ressource qui appelle.', required: true },
    commands: { type: 'CommandInfo[]', description: 'Chaque commande de la ressource : `names` (le premier = le nom, le reste = alias), `help`, `params` et `aces` (`null` = tout le monde). Les entrées invalides sont ignorées avec un avertissement dans la console.', required: true },
  }}
/>

Voir [CommandInfo](/fr/docs/developers/api/types#commandinfo) et [CommandParam](/fr/docs/developers/api/types#commandparam).

#### Retour

Rien. La liste est abandonnée quand la ressource s’arrête. Pour les commandes réservées à un principal (`group.admin`), ai-core accorde aussi à ce principal `command.<name>`, ce qui demande `add_ace resource.ai-core command.add_ace allow` (et `command.remove_ace`) dans `permission.cfg`.

#### Exemple

Pas d’exemple : utilisez `addCommand` de la lib (TypeScript) ou `aiLib.addCommand` (Lua) et la commande apparaît d’elle-même dans l’onglet. Les commandes créées avec un simple `RegisterCommand` sont listées aussi, marquées comme simples.

### GetLookupValues

Les valeurs d’une liste de recherche : les noms d’objets de l’inventaire actif, les noms de métiers, les noms de gangs, etc. La validation du panneau de la lib l’utilise pour vérifier qu’une valeur tapée par un admin existe.

**Côté :** Serveur · **Attend :** non · **Lib :** utilisé par la validation d’[`AdminPanel`](/fr/docs/developers/api/lib-server/admin-panel#adminpanel) de la lib

```ts title="Signature"
GetLookupValues(source: LookupSource): string[]
```

```lua title="Lua"
local items = exports['ai-core']:GetLookupValues('item') -- liste de noms d’objets
```

#### Paramètres

<TypeTable
  type={{
    source: { type: 'LookupSource', description: 'Quelle liste.', required: true, typeDescription: '"item" | "job" | "gang" | "account" | "resource" | "player" | "vehicle" | "ped"' },
  }}
/>

| `source` | Valeurs |
| --- | --- |
| `item` | Noms d’objets de l’inventaire actif. |
| `job` / `gang` | Noms de métiers / de gangs depuis le panneau. |
| `account` | Noms des types de comptes (`cash`, `bank`...). |
| `resource` | Noms des ressources démarrées. |
| `player` | Citizen ids des joueurs qui ont un personnage chargé. |
| `vehicle` / `ped` | Toujours vide : seul le jeu de l’admin peut lister les modèles. |

Voir [LookupSource](/fr/docs/developers/api/types#lookupsource).

#### Retour

`string[]` : les valeurs, triées par libellé. Une liste vide pour une `source` inconnue, pour `vehicle` et `ped`, et quand la liste n’est pas encore connue (aucun inventaire ne tourne) : traitez le vide comme « impossible de vérifier », pas comme « rien n’est valide ».

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

/** Checks a reward item from your config; unknown is fine while no inventory runs. */
export function isKnownItem(name: string): boolean {
  const items = core.GetLookupValues("item");
  return items.length === 0 || items.includes(name);
}
```
</Tab>
<Tab value="Lua">
```lua
function IsKnownItem(name)
  local items = exports['ai-core']:GetLookupValues('item')
  if #items == 0 then return true end
  for _, item in ipairs(items) do
    if item == name then return true end
  end
  return false
end
```
</Tab>
</Tabs>

<Callout type="info">
La liste est reconstruite à chaque appel (la liste d’objets peut être longue). Appelez-le au moment de valider, pas dans une boucle.
</Callout>

### RegisterExternalPanel

Liste l’écran de réglages propre à un autre script sur le tableau de bord du panneau d’ai-core, pour que le propriétaire du serveur trouve les réglages de chaque script au même endroit. La carte ouvre l’écran avec une commande de chat, ou affiche une page web dans le panneau.

**Côté :** Serveur · **Attend :** non · **Lib :** aucune

```ts title="Signature"
RegisterExternalPanel(panel: {
  id?: string;
  label: string;
  icon?: string;
  description?: string;
  command?: string;
  url?: string;
}): void
```

```lua title="Lua"
exports['ai-core']:RegisterExternalPanel({ label = 'My script', command = 'myscriptconfig' })
```

#### Paramètres

<TypeTable
  type={{
    panel: { type: 'object', description: 'La carte du tableau de bord. Champs ci-dessous.', required: true },
  }}
/>

#### Champs du panneau

<TypeTable
  type={{
    id: { type: 'string', description: 'Id de la carte, unique dans votre ressource (2-48 lettres, chiffres, `_`, `.`, `-`). Un second appel avec le même id remplace la carte.', default: 'le nom de la ressource' },
    label: { type: 'string', description: 'Titre de la carte. Coupé à 48 caractères.', required: true },
    icon: { type: 'string', description: 'Nom d’icône de la carte. Coupé à 32 caractères.' },
    description: { type: 'string', description: 'Une ligne sous le titre. Coupée à 160 caractères.' },
    command: { type: 'string', description: 'Commande de chat qui ouvre votre écran (un `/` en tête est retiré). Donnez `command` ou `url`.' },
    url: { type: 'string', description: 'Une page web affichée dans le panneau. Seulement des adresses `https://` (une page NUI de votre ressource ou un site de confiance) ; coupée à 300 caractères.' },
  }}
/>

#### Retour

Rien. Sans `label`, ou sans `command` ni `url`, la carte n’est pas ajoutée. Les cartes sont abandonnées quand votre ressource s’arrête.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

// Une fois au démarrage.
core.RegisterExternalPanel({
  label: "My script",
  icon: "gear",
  description: "Shops, prices and rewards",
  command: "myscriptconfig",
});
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-core']:RegisterExternalPanel({
  label = 'My script',
  icon = 'gear',
  description = 'Shops, prices and rewards',
  command = 'myscriptconfig',
})
```
</Tab>
</Tabs>

<Callout type="info">
Un script que vous ne pouvez pas modifier peut plutôt être listé par des lignes dans son `fxmanifest.lua` : `ai_admin_label`, `ai_admin_command` ou `ai_admin_url`, et en option `ai_admin_icon` et `ai_admin_description`. Le propriétaire du serveur peut aussi ajouter des cartes à la main dans le panneau.
</Callout>
