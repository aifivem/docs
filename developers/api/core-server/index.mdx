ai-core is the framework resource. Other resources ask it for a player's character, money, jobs and items, and send it work such as "give this player a key" or "send a police alert". They do that through **exports**: functions ai-core makes callable from any other resource on the server.

These pages list every server export ai-core registers, grouped by topic. Each entry shows what the export does, its exact signature, every parameter, what it returns in every case, and a working example in TypeScript and Lua.

## Calling an export

An export is called by the name of the resource that owns it (`ai-core`) and the export's name.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// One typed handle per file, at the top. It is safe here: FiveM looks each
// export up on first use and forgets it when ai-core restarts.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- No setup needed: exports['ai-core'] works in any server script.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

What to know before you start:

- **TypeScript types.** `resourceExport("ai-core")` is typed from `AiCoreServerExports` in `@aifivem/shared`, so your editor knows every name, parameter and return type. Never write `resourceExport("ai-core").GetMoney(...)` inside a function: keep the one handle at the top of the file.
- **Lua uses a colon.** Write `exports['ai-core']:GetMoney(source, 'cash')`, not a dot. A `null` answer arrives in Lua as `nil`, an array as a Lua list (index 1 first), an object as a table.
- **Two spellings.** Every export also answers with the first letter's case swapped: `GetMoney` and `getMoney` are the same function.
- **Exports never wait.** Every export answers at once with a small value. When the answer needs the database (a stored look, a list of bills), the export takes a `done` callback instead of returning a Promise, because a Promise cannot cross from one resource to another.
- **Not in hot paths.** An export call copies its arguments and its answer. Do not call exports every frame or for every player in a loop. For "who is on duty", a character's name or jobs across many players, use the lib's `online` mirror, which follows ai-core's events ([Lib: server](/docs/developers/api/lib-server)).
- **ai-core must run first.** Put `dependency 'ai-core'` in your `fxmanifest.lua` (an ai-* resource lists it in `package.json` `fxDependencies`), so your resource starts after ai-core.
- **`source` is the player's server id.** It is the number FiveM gives a connected player. A character id (`charId`) is a different number: the id of the character row in the database.

## The lib or the export?

Most exports have a wrapper in `@aifivem/lib/server` (and many in Lua's `aiLib`). The wrapper calls the same export, so the behaviour is identical; it only reads nicer (`inventory.addItem(source, "water")` instead of `core.AddItem(source, "water")`) and turns callbacks into Promises where that is safe. Each entry names its wrapper on the **Lib** line. Use whichever you like; a Lua resource without ai-lib calls the export directly.

## Examples on these pages

The examples are complete server files. TypeScript examples use the lib's `addCommand` and `onClientCallback`; Lua examples use ai-lib's `aiLib.addCommand` and `aiLib.onClientCallback`, which need these lines in your `fxmanifest.lua`:

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Waiting Lua calls (`aiLib.progressFor`, `Wait`) only work inside a thread; command and callback handlers already run in one.
