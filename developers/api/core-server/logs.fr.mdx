title: Logs
description: Envoyer les logs de votre ressource via ai-core vers Discord, Fivemanage, FiveM Stats et la console, et décrire vos canaux de log.

---

Chaque ressource écrit ses logs via ai-core. Votre ressource nomme un **canal** (`purchases`, `robberies`) et écrit un message ; ai-core décide où il va. Le propriétaire du serveur active les fournisseurs dans le panneau d’administration (console, Discord, Fivemanage, FiveM Stats), fixe le niveau minimum, et colle les urls de webhook Discord par ressource et par canal. Une ressource ne poste jamais elle-même vers un webhook ou un service de logs, et ne détient jamais d’url de webhook.

Passez les joueurs concernés comme `source` et `target` au lieu d’écrire leurs noms dans le message : ai-core ajoute le nom, le personnage, le citizen id et les identifiants de chaque joueur (l’IP seulement quand le panneau l’autorise).

### Log

Envoie une entrée de log de votre ressource.

**Côté :** Serveur · **Attend :** non · **Lib :** [`aiLog(channel, message, options?)`](/fr/docs/developers/api/lib-server/logs#ailog) (Lua : `aiLib.aiLog` ; tous deux écrivent plutôt dans la console tant qu’ai-core ne tourne pas)

```ts title="Signature"
Log(channel: string, message: string, options?: LogOptions): void
```

```lua title="Lua"
exports['ai-core']:Log('purchases', 'Bought a car', { source = source, metadata = { price = 25000 } })
```

#### Paramètres

<TypeTable
  type={{
    channel: { type: 'string', description: 'Nom de canal de votre ressource (`purchases`). Le webhook et l’interrupteur marche / arrêt sont par canal. `log` quand ce n’est pas un texte.', required: true },
    message: { type: 'string', description: 'Ce qui s’est passé, en anglais simple. Les autres valeurs sont converties en texte.', required: true },
    options: { type: 'LogOptions', description: 'Niveau, joueurs et valeurs supplémentaires. Champs ci-dessous.' },
  }}
/>

#### LogOptions

<TypeTable
  type={{
    level: { type: '"debug" | "info" | "warn" | "error"', description: 'Son importance. Les entrées sous le niveau minimum du panneau sont abandonnées.', default: '"info"' },
    source: { type: 'number', description: 'Id serveur du joueur qui l’a fait ; son nom, son personnage et ses identifiants sont ajoutés.' },
    target: { type: 'number', description: 'Id serveur du joueur qui l’a subi.' },
    metadata: { type: 'Record<string, unknown>', description: 'Valeurs supplémentaires (montants, noms d’objets, coordonnées). Pas une table : ignoré.' },
  }}
/>

Voir [LogOptions](/fr/docs/developers/api/types#logoptions) et [LogLevel](/fr/docs/developers/api/types#loglevel).

#### Retour

Rien. L’entrée est abandonnée sans un mot quand son niveau est sous le minimum du panneau ou que son canal est désactivé avec `LogChannels`.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { onClientCallback, resourceExport } from "@aicore-fivem/lib/server";
import { fail } from "@aicore-fivem/lib/shared";

const core = resourceExport("ai-core");

onClientCallback("myscript:buyCar", { lock: true }, (source) => {
  const price = 25_000;
  if (!core.RemoveMoney(source, "bank", price, "car_purchase")) return fail("NOT_ENOUGH_MONEY");
  // ... créer et ranger la voiture
  core.Log("purchases", "Bought a car", { source, metadata: { model: "sultan", price } });
  return { ok: true };
});
```
</Tab>
<Tab value="Lua">
```lua
aiLib.onClientCallback('myscript:buyCar', function(source)
  local price = 25000
  if not exports['ai-core']:RemoveMoney(source, 'bank', price, 'car_purchase') then return aiLib.fail('NOT_ENOUGH_MONEY') end
  -- ... créer et ranger la voiture
  exports['ai-core']:Log('purchases', 'Bought a car', { source = source, metadata = { model = 'sultan', price = price } })
  return { ok = true }
end, { lock = true })
```
</Tab>
</Tabs>

<Callout type="info">
Les logs sont destinés au propriétaire du serveur : le message reste donc en anglais et n’est pas traduit. Gardez le message court et mettez les valeurs dans `metadata`, où les services de logs peuvent les filtrer.
</Callout>

### LogChannels

Décrit les canaux de votre ressource : leur nom de dataset pour Fivemanage et FiveM Stats, et si chacun est activé. Appelez-le une fois au démarrage de votre ressource. Les canaux que vous ne décrivez jamais fonctionnent quand même avec les valeurs par défaut.

**Côté :** Serveur · **Attend :** non · **Lib :** [`aiLogChannels(channels)`](/fr/docs/developers/api/lib-server/logs#ailogchannels)

```ts title="Signature"
LogChannels(channels: Record<string, LogChannel>): void
```

```lua title="Lua"
exports['ai-core']:LogChannels({ purchases = { dataset = 'myscript-sales' }, debug = { active = false } })
```

#### Paramètres

<TypeTable
  type={{
    channels: { type: 'Record<string, LogChannel>', description: 'Nom du canal vers ses réglages. Les champs de chacun ci-dessous.', required: true },
  }}
/>

#### LogChannel

<TypeTable
  type={{
    dataset: { type: 'string', description: 'Nom de dataset pour Fivemanage et FiveM Stats.', default: 'le nom de la ressource' },
    active: { type: 'boolean', description: '`false` désactive le canal : ses entrées sont abandonnées.', default: 'true' },
  }}
/>

Voir [LogChannel](/fr/docs/developers/api/types#logchannel).

#### Retour

Rien. Un second appel remplace toute la description de votre ressource. Elle est abandonnée quand votre ressource s’arrête. Une valeur qui n’est pas une table ne fait rien.

#### Exemple

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aicore-fivem/lib/server";

const core = resourceExport("ai-core");

// Une fois au démarrage.
core.LogChannels({
  purchases: { dataset: "myscript-sales" },
  robberies: { dataset: "myscript-crime" },
  debug: { active: false },
});
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-core']:LogChannels({
  purchases = { dataset = 'myscript-sales' },
  robberies = { dataset = 'myscript-crime' },
  debug = { active = false },
})
```
</Tab>
</Tabs>

<Callout type="warn">
Les urls de webhook ne vont jamais ici ni nulle part dans votre ressource : le propriétaire du serveur les fixe dans le panneau d’ai-core, qui les garde dans un fichier non partagé.
</Callout>
