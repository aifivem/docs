O ai-core hospeda um painel de administração para todos os scripts. A maioria dos exports desta página é encanamento que o `@aifivem/lib` chama por você: um script feito com o `AdminPanel` e o `addCommand` da lib nunca chama `RegisterAdminPanel`, `AdminPanelChanged` ou `RegisterCommands` ele mesmo. Eles estão documentados para você saber o que acontece e poder suportá-los a partir de outra linguagem. `RegisterExternalPanel` e `GetLookupValues` são úteis para qualquer script.

### RegisterAdminPanel

Anuncia que o recurso que chama tem uma seção no painel. O ai-core então pede a ele o schema e os dados sempre que um admin abre o painel.

**Lado:** Servidor · **Espera:** não · **Lib:** chamado pelo [`AdminPanel`](/pt/docs/developers/api/lib-server/admin-panel#adminpanel) da lib quando ele inicia

```ts title="Assinatura"
RegisterAdminPanel(resource: string): void
```

```lua title="Lua"
exports['ai-core']:RegisterAdminPanel(GetCurrentResourceName())
```

#### Parâmetros

<TypeTable
  type={{
    resource: { type: 'string', description: 'Mantido para chamadores antigos e ignorado: o painel sempre pertence ao recurso que chama.', required: true },
  }}
/>

#### Retorno

Nada. O registro é descartado quando o recurso para.

#### Exemplo

Sem exemplo: o `AdminPanel` da lib o chama. Um recurso que se registra sem a lib também precisa responder aos exports que o ai-core chama de volta (`AdminPanelSnapshot`, `AdminPanelData`, `AdminPanelSummary`, tipados como `AdminPanelResourceExports` em `@aifivem/shared`), o que é trabalho da lib.

### AdminPanelChanged

Um recurso com painel avisa o ai-core que um dos seus registros mudou. O ai-core encaminha a mudança para cada admin que está com o painel aberto, então a tela dele atualiza sem recarregar.

**Lado:** Servidor · **Espera:** não · **Lib:** chamado pelo [`AdminPanel`](/pt/docs/developers/api/lib-server/admin-panel#adminpanel) da lib depois de cada mudança salva

```ts title="Assinatura"
AdminPanelChanged(delta: AdminDelta): void
```

```lua title="Lua"
exports['ai-core']:AdminPanelChanged({ resource = GetCurrentResourceName(), file = 'shops', key = 'shop_1', value = record })
```

#### Parâmetros

<TypeTable
  type={{
    delta: { type: 'AdminDelta', description: 'O que mudou: `resource`, `file` (o nome do arquivo de dados), `key` (o registro, ausente para um arquivo de configurações inteiro) e o novo `value` (`null` para um registro apagado).', required: true, typeDescription: '{ resource: string; file: string; key?: string; value: unknown }' },
  }}
/>

Veja [AdminDelta](/pt/docs/developers/api/types#admindelta).

#### Retorno

Nada. O ai-core não verifica o delta; ele o envia como recebeu.

#### Exemplo

Sem exemplo: o `AdminPanel` da lib o chama depois que uma mudança foi validada e salva.

### RegisterCommands

Lista os comandos de um recurso na aba **Commands** (Comandos) do painel, com a ajuda, os parâmetros e quem pode usá-los.

**Lado:** Servidor · **Espera:** não · **Lib:** chamado pelo [`addCommand`](/pt/docs/developers/api/lib-server/commands#addcommand) da lib (TypeScript e `aiLib.addCommand` em Lua)

```ts title="Assinatura"
RegisterCommands(resource: string, commands: CommandInfo[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterCommands(GetCurrentResourceName(), commands)
```

#### Parâmetros

<TypeTable
  type={{
    resource: { type: 'string', description: 'Mantido para chamadores antigos e ignorado: os comandos pertencem ao recurso que chama.', required: true },
    commands: { type: 'CommandInfo[]', description: 'Cada comando do recurso: `names` (o primeiro = o nome, o resto = aliases), `help`, `params` e `aces` (`null` = todos). Entradas inválidas são puladas com um aviso no console.', required: true },
  }}
/>

Veja [CommandInfo](/pt/docs/developers/api/types#commandinfo) e [CommandParam](/pt/docs/developers/api/types#commandparam).

#### Retorno

Nada. A lista é descartada quando o recurso para. Para comandos restritos a um principal (`group.admin`), o ai-core também concede a esse principal `command.<name>`, o que exige `add_ace resource.ai-core command.add_ace allow` (e `command.remove_ace`) no `permission.cfg`.

#### Exemplo

Sem exemplo: use o `addCommand` da lib (TypeScript) ou `aiLib.addCommand` (Lua) e o comando aparece na aba sozinho. Comandos criados com um `RegisterCommand` puro também são listados, marcados como simples.

### GetLookupValues

Os valores de uma lista de consulta: os nomes de itens do inventário ativo, os nomes de empregos, de gangues e assim por diante. A validação do painel da lib usa isto para verificar se um valor que um admin digitou existe.

**Lado:** Servidor · **Espera:** não · **Lib:** usado pela validação do [`AdminPanel`](/pt/docs/developers/api/lib-server/admin-panel#adminpanel) da lib

```ts title="Assinatura"
GetLookupValues(source: LookupSource): string[]
```

```lua title="Lua"
local items = exports['ai-core']:GetLookupValues('item') -- lista de nomes de itens
```

#### Parâmetros

<TypeTable
  type={{
    source: { type: 'LookupSource', description: 'Qual lista.', required: true, typeDescription: '"item" | "job" | "gang" | "account" | "resource" | "player" | "vehicle" | "ped"' },
  }}
/>

| `source` | Valores |
| --- | --- |
| `item` | Nomes de itens do inventário ativo. |
| `job` / `gang` | Nomes de empregos / gangues do painel. |
| `account` | Nomes de tipos de conta (`cash`, `bank`...). |
| `resource` | Nomes dos recursos iniciados. |
| `player` | Citizen ids dos jogadores com um personagem carregado. |
| `vehicle` / `ped` | Sempre vazio: só o jogo do admin consegue listar modelos. |

Veja [LookupSource](/pt/docs/developers/api/types#lookupsource).

#### Retorno

`string[]`: os valores, ordenados pelo rótulo. Uma lista vazia para um `source` desconhecido, para `vehicle` e `ped`, e quando a lista ainda não é conhecida (nenhum inventário rodando): trate vazio como "não dá para verificar", não como "nada é válido".

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

/** Checks a reward item from your config; unknown is fine while no inventory runs. */
export function isKnownItem(name: string): boolean {
  const items = core.GetLookupValues("item");
  return items.length === 0 || items.includes(name);
}
```
</Tab>
<Tab value="Lua">
```lua
function IsKnownItem(name)
  local items = exports['ai-core']:GetLookupValues('item')
  if #items == 0 then return true end
  for _, item in ipairs(items) do
    if item == name then return true end
  end
  return false
end
```
</Tab>
</Tabs>

<Callout type="info">
A lista é montada do zero a cada chamada (a lista de itens pode ser longa). Chame quando validar, não num loop.
</Callout>

### RegisterExternalPanel

Lista a própria tela de configurações de outro script no dashboard do painel do ai-core, para que o dono do servidor encontre as configurações de todos os scripts num só lugar. O card abre a tela com um comando de chat, ou mostra uma página web dentro do painel.

**Lado:** Servidor · **Espera:** não · **Lib:** nenhuma

```ts title="Assinatura"
RegisterExternalPanel(panel: {
  id?: string;
  label: string;
  icon?: string;
  description?: string;
  command?: string;
  url?: string;
}): void
```

```lua title="Lua"
exports['ai-core']:RegisterExternalPanel({ label = 'My script', command = 'myscriptconfig' })
```

#### Parâmetros

<TypeTable
  type={{
    panel: { type: 'object', description: 'O card do dashboard. Campos abaixo.', required: true },
  }}
/>

#### Campos do painel

<TypeTable
  type={{
    id: { type: 'string', description: 'Id do card, único dentro do seu recurso (2-48 letras, dígitos, `_`, `.`, `-`). Uma segunda chamada com o mesmo id substitui o card.', default: 'o nome do recurso' },
    label: { type: 'string', description: 'Título do card. Cortado em 48 caracteres.', required: true },
    icon: { type: 'string', description: 'Nome do ícone do card. Cortado em 32 caracteres.' },
    description: { type: 'string', description: 'Uma linha abaixo do título. Cortada em 160 caracteres.' },
    command: { type: 'string', description: 'Comando de chat que abre sua tela (uma `/` no início é removida). Informe `command` ou `url`.' },
    url: { type: 'string', description: 'Uma página web mostrada dentro do painel. Só endereços `https://` (uma página NUI do seu recurso ou um site em que você confia); cortado em 300 caracteres.' },
  }}
/>

#### Retorno

Nada. Sem um `label`, ou sem `command` e `url`, o card não é adicionado. Os cards são descartados quando seu recurso para.

#### Exemplo

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

// Uma vez ao iniciar.
core.RegisterExternalPanel({
  label: "My script",
  icon: "gear",
  description: "Shops, prices and rewards",
  command: "myscriptconfig",
});
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-core']:RegisterExternalPanel({
  label = 'My script',
  icon = 'gear',
  description = 'Shops, prices and rewards',
  command = 'myscriptconfig',
})
```
</Tab>
</Tabs>

<Callout type="info">
Um script que você não pode alterar pode ser listado por linhas no `fxmanifest.lua` dele: `ai_admin_label`, `ai_admin_command` ou `ai_admin_url`, e opcionalmente `ai_admin_icon` e `ai_admin_description`. O dono do servidor também pode adicionar cards à mão no painel.
</Callout>
