ai-core stellt ein Admin-Panel für jedes Skript bereit. Die meisten Exports auf dieser Seite sind Infrastruktur, die `@aifivem/lib` für dich aufruft: Ein Skript, das mit `AdminPanel` und `addCommand` der Lib gebaut ist, ruft `RegisterAdminPanel`, `AdminPanelChanged` oder `RegisterCommands` nie selbst auf. Sie sind dokumentiert, damit du weißt, was passiert, und sie aus einer anderen Sprache unterstützen kannst. `RegisterExternalPanel` und `GetLookupValues` sind für jedes Skript nützlich.

### RegisterAdminPanel

Kündigt an, dass die aufrufende Ressource einen Panel-Bereich hat. ai-core fragt sie dann nach ihrem Schema und ihren Daten, sobald ein Admin das Panel öffnet.

**Seite:** Server · **Wartet:** nein · **Lib:** wird von [`AdminPanel`](/de/docs/developers/api/lib-server/admin-panel#adminpanel) der Lib beim Start aufgerufen

```ts title="Signature"
RegisterAdminPanel(resource: string): void
```

```lua title="Lua"
exports['ai-core']:RegisterAdminPanel(GetCurrentResourceName())
```

#### Parameter

<TypeTable
  type={{
    resource: { type: 'string', description: 'Für ältere Aufrufer beibehalten und ignoriert: Das Panel gehört immer der aufrufenden Ressource.', required: true },
  }}
/>

#### Rückgabe

Nichts. Die Registrierung wird verworfen, wenn die Ressource stoppt.

#### Beispiel

Kein Beispiel: `AdminPanel` der Lib ruft es auf. Eine Ressource, die sich ohne die Lib registriert, muss auch die Exports beantworten, die ai-core zurückruft (`AdminPanelSnapshot`, `AdminPanelData`, `AdminPanelSummary`, typisiert als `AdminPanelResourceExports` in `@aifivem/shared`), was die Aufgabe der Lib ist.

### AdminPanelChanged

Eine Panel-Ressource teilt ai-core mit, dass sich einer ihrer Datensätze geändert hat. ai-core leitet die Änderung an jeden Admin weiter, der das Panel geöffnet hat, sodass sich sein Bildschirm ohne Neuladen aktualisiert.

**Seite:** Server · **Wartet:** nein · **Lib:** wird von [`AdminPanel`](/de/docs/developers/api/lib-server/admin-panel#adminpanel) der Lib nach jeder gespeicherten Änderung aufgerufen

```ts title="Signature"
AdminPanelChanged(delta: AdminDelta): void
```

```lua title="Lua"
exports['ai-core']:AdminPanelChanged({ resource = GetCurrentResourceName(), file = 'shops', key = 'shop_1', value = record })
```

#### Parameter

<TypeTable
  type={{
    delta: { type: 'AdminDelta', description: 'Was sich geändert hat: `resource`, `file` (der Name der Datendatei), `key` (der Datensatz, fehlt bei einer ganzen Einstellungsdatei) und der neue `value` (`null` für einen gelöschten Datensatz).', required: true, typeDescription: '{ resource: string; file: string; key?: string; value: unknown }' },
  }}
/>

Siehe [AdminDelta](/de/docs/developers/api/types#admindelta).

#### Rückgabe

Nichts. ai-core prüft das Delta nicht; es sendet es so, wie es übergeben wird.

#### Beispiel

Kein Beispiel: `AdminPanel` der Lib ruft es auf, nachdem eine Änderung validiert und gespeichert wurde.

### RegisterCommands

Listet die Befehle einer Ressource im Tab **Commands** (Befehle) des Panels, mit ihrer Hilfe, ihren Parametern und wer sie nutzen darf.

**Seite:** Server · **Wartet:** nein · **Lib:** wird von [`addCommand`](/de/docs/developers/api/lib-server/commands#addcommand) der Lib aufgerufen (TypeScript und Lua `aiLib.addCommand`)

```ts title="Signature"
RegisterCommands(resource: string, commands: CommandInfo[]): void
```

```lua title="Lua"
exports['ai-core']:RegisterCommands(GetCurrentResourceName(), commands)
```

#### Parameter

<TypeTable
  type={{
    resource: { type: 'string', description: 'Für ältere Aufrufer beibehalten und ignoriert: Die Befehle gehören der aufrufenden Ressource.', required: true },
    commands: { type: 'CommandInfo[]', description: 'Jeder Befehl der Ressource: `names` (erster = der Name, der Rest = Aliase), `help`, `params` und `aces` (`null` = alle). Ungültige Einträge werden mit einer Konsolenwarnung übersprungen.', required: true },
  }}
/>

Siehe [CommandInfo](/de/docs/developers/api/types#commandinfo) und [CommandParam](/de/docs/developers/api/types#commandparam).

#### Rückgabe

Nichts. Die Liste wird verworfen, wenn die Ressource stoppt. Für Befehle, die auf einen Principal beschränkt sind (`group.admin`), gewährt ai-core diesem Principal außerdem `command.<name>`, was `add_ace resource.ai-core command.add_ace allow` (und `command.remove_ace`) in der `permission.cfg` braucht.

#### Beispiel

Kein Beispiel: Nutze `addCommand` der Lib (TypeScript) oder `aiLib.addCommand` (Lua), und der Befehl erscheint von selbst im Tab. Befehle, die mit einem nackten `RegisterCommand` erstellt wurden, werden ebenfalls gelistet, als einfach markiert.

### GetLookupValues

Die Werte einer Nachschlageliste: die Item-Namen des aktiven Inventars, die Jobnamen, Gangnamen und so weiter. Die Panel-Validierung der Lib nutzt es, um zu prüfen, dass ein Wert, den ein Admin eingetippt hat, existiert.

**Seite:** Server · **Wartet:** nein · **Lib:** wird von der Validierung von [`AdminPanel`](/de/docs/developers/api/lib-server/admin-panel#adminpanel) der Lib genutzt

```ts title="Signature"
GetLookupValues(source: LookupSource): string[]
```

```lua title="Lua"
local items = exports['ai-core']:GetLookupValues('item') -- Liste von Item-Namen
```

#### Parameter

<TypeTable
  type={{
    source: { type: 'LookupSource', description: 'Welche Liste.', required: true, typeDescription: '"item" | "job" | "gang" | "account" | "resource" | "player" | "vehicle" | "ped"' },
  }}
/>

| `source` | Werte |
| --- | --- |
| `item` | Item-Namen des aktiven Inventars. |
| `job` / `gang` | Job- / Gangnamen aus dem Panel. |
| `account` | Namen der Kontotypen (`cash`, `bank`...). |
| `resource` | Namen gestarteter Ressourcen. |
| `player` | Citizen-IDs von Spielern mit geladenem Charakter. |
| `vehicle` / `ped` | Immer leer: Nur das Spiel des Admins kann Modelle auflisten. |

Siehe [LookupSource](/de/docs/developers/api/types#lookupsource).

#### Rückgabe

`string[]`: die Werte, nach ihrem Label sortiert. Eine leere Liste für eine unbekannte `source`, für `vehicle` und `ped` und wenn die Liste noch nicht bekannt ist (kein Inventar läuft): Behandle leer als „kann nicht prüfen“, nicht als „nichts ist gültig“.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

/** Prüft ein Belohnungs-Item aus deiner Config; unbekannt ist in Ordnung, solange kein Inventar läuft. */
export function isKnownItem(name: string): boolean {
  const items = core.GetLookupValues("item");
  return items.length === 0 || items.includes(name);
}
```
</Tab>
<Tab value="Lua">
```lua
function IsKnownItem(name)
  local items = exports['ai-core']:GetLookupValues('item')
  if #items == 0 then return true end
  for _, item in ipairs(items) do
    if item == name then return true end
  end
  return false
end
```
</Tab>
</Tabs>

<Callout type="info">
Die Liste wird bei jedem Aufruf neu aufgebaut (die Item-Liste kann lang sein). Rufe es beim Validieren auf, nicht in einer Schleife.
</Callout>

### RegisterExternalPanel

Listet den eigenen Einstellungsbildschirm eines anderen Skripts auf dem Panel-Dashboard von ai-core, sodass der Serverbesitzer die Einstellungen jedes Skripts an einem Ort findet. Die Karte öffnet den Bildschirm mit einem Chat-Befehl oder zeigt eine Webseite innerhalb des Panels.

**Seite:** Server · **Wartet:** nein · **Lib:** keine

```ts title="Signature"
RegisterExternalPanel(panel: {
  id?: string;
  label: string;
  icon?: string;
  description?: string;
  command?: string;
  url?: string;
}): void
```

```lua title="Lua"
exports['ai-core']:RegisterExternalPanel({ label = 'My script', command = 'myscriptconfig' })
```

#### Parameter

<TypeTable
  type={{
    panel: { type: 'object', description: 'Die Dashboard-Karte. Felder unten.', required: true },
  }}
/>

#### Panel-Felder

<TypeTable
  type={{
    id: { type: 'string', description: 'Karten-ID, eindeutig innerhalb deiner Ressource (2-48 Buchstaben, Ziffern, `_`, `.`, `-`). Ein zweiter Aufruf mit derselben ID ersetzt die Karte.', default: 'der Ressourcenname' },
    label: { type: 'string', description: 'Kartentitel. Auf 48 Zeichen gekürzt.', required: true },
    icon: { type: 'string', description: 'Icon-Name für die Karte. Auf 32 Zeichen gekürzt.' },
    description: { type: 'string', description: 'Eine Zeile unter dem Titel. Auf 160 Zeichen gekürzt.' },
    command: { type: 'string', description: 'Chat-Befehl, der deinen Bildschirm öffnet (ein führendes `/` wird entfernt). Gib `command` oder `url` an.' },
    url: { type: 'string', description: 'Eine Webseite, die innerhalb des Panels angezeigt wird. Nur `https://`-Adressen (eine NUI-Seite deiner Ressource oder eine Seite, der du vertraust); auf 300 Zeichen gekürzt.' },
  }}
/>

#### Rückgabe

Nichts. Ohne `label` oder ohne sowohl `command` als auch `url` wird die Karte nicht hinzugefügt. Karten werden verworfen, wenn deine Ressource stoppt.

#### Beispiel

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

const core = resourceExport("ai-core");

// Einmal beim Start.
core.RegisterExternalPanel({
  label: "My script",
  icon: "gear",
  description: "Shops, prices and rewards",
  command: "myscriptconfig",
});
```
</Tab>
<Tab value="Lua">
```lua
exports['ai-core']:RegisterExternalPanel({
  label = 'My script',
  icon = 'gear',
  description = 'Shops, prices and rewards',
  command = 'myscriptconfig',
})
```
</Tab>
</Tabs>

<Callout type="info">
Ein Skript, das du nicht ändern kannst, kann stattdessen über Zeilen in seiner `fxmanifest.lua` gelistet werden: `ai_admin_label`, `ai_admin_command` oder `ai_admin_url` und optional `ai_admin_icon` und `ai_admin_description`. Der Serverbesitzer kann Karten auch von Hand im Panel hinzufügen.
</Callout>
