ai-core es el recurso del framework. Los demás recursos le piden el personaje, el dinero, los trabajos y los objetos de un jugador, y le envían tareas como "dale una llave a este jugador" o "envía una alerta a la policía". Lo hacen mediante **exports**: funciones que ai-core hace llamables desde cualquier otro recurso del servidor.

Estas páginas listan cada export de servidor que registra ai-core, agrupados por tema. Cada entrada muestra qué hace el export, su firma exacta, cada parámetro, qué devuelve en cada caso y un ejemplo que funciona en TypeScript y Lua.

## Llamar a un export

Un export se llama por el nombre del recurso al que pertenece (`ai-core`) y el nombre del export.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Un handle tipado por archivo, al principio. Aquí es seguro: FiveM busca cada
// export la primera vez que se usa y lo olvida cuando ai-core se reinicia.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- No hace falta preparar nada: exports['ai-core'] funciona en cualquier script de servidor.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

Lo que debes saber antes de empezar:

- **Tipos de TypeScript.** `resourceExport("ai-core")` está tipado desde `AiCoreServerExports` en `@aifivem/shared`, así que tu editor conoce cada nombre, parámetro y tipo de retorno. Nunca escribas `resourceExport("ai-core").GetMoney(...)` dentro de una función: deja el único handle al principio del archivo.
- **Lua usa dos puntos.** Escribe `exports['ai-core']:GetMoney(source, 'cash')`, no un punto. Una respuesta `null` llega a Lua como `nil`, un array como una lista de Lua (empezando por el índice 1), un objeto como una tabla.
- **Dos grafías.** Cada export responde también con la primera letra en la otra caja: `GetMoney` y `getMoney` son la misma función.
- **Los exports nunca esperan.** Cada export responde al momento con un valor pequeño. Cuando la respuesta necesita la base de datos (un aspecto guardado, una lista de facturas), el export recibe un callback `done` en lugar de devolver una Promise, porque una Promise no puede pasar de un recurso a otro.
- **No en rutas calientes.** Una llamada a un export copia sus argumentos y su respuesta. No llames a exports en cada frame ni para cada jugador en un bucle. Para "quién está de servicio", el nombre de un personaje o los trabajos de muchos jugadores, usa el espejo `online` de la lib, que sigue los eventos de ai-core ([Lib: servidor](/es/docs/developers/api/lib-server)).
- **ai-core debe ejecutarse primero.** Pon `dependency 'ai-core'` en tu `fxmanifest.lua` (un recurso ai-* lo lista en `fxDependencies` de `package.json`), para que tu recurso se inicie después de ai-core.
- **`source` es el id de servidor del jugador.** Es el número que FiveM da a un jugador conectado. Un id de personaje (`charId`) es otro número: el id de la fila del personaje en la base de datos.

## ¿La lib o el export?

La mayoría de los exports tienen un envoltorio en `@aifivem/lib/server` (y muchos en el `aiLib` de Lua). El envoltorio llama al mismo export, así que el comportamiento es idéntico; solo se lee mejor (`inventory.addItem(source, "water")` en lugar de `core.AddItem(source, "water")`) y convierte los callbacks en Promises donde es seguro. Cada entrada nombra su envoltorio en la línea **Lib**. Usa el que prefieras; un recurso en Lua sin ai-lib llama al export directamente.

## Ejemplos de estas páginas

Los ejemplos son archivos de servidor completos. Los ejemplos de TypeScript usan `addCommand` y `onClientCallback` de la lib; los de Lua usan `aiLib.addCommand` y `aiLib.onClientCallback` de ai-lib, que necesitan estas líneas en tu `fxmanifest.lua`:

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Las llamadas de Lua que esperan (`aiLib.progressFor`, `Wait`) solo funcionan dentro de un thread; los handlers de comandos y callbacks ya se ejecutan en uno.
