ai-core - это ресурс фреймворка. Другие ресурсы спрашивают у него персонажа игрока, деньги, работы и предметы и поручают ему задачи вроде «выдай этому игроку ключ» или «отправь полицейское оповещение». Они делают это через **экспорты**: функции, которые ai-core делает доступными для вызова из любого другого ресурса на сервере.

На этих страницах перечислены все серверные экспорты, которые регистрирует ai-core, сгруппированные по темам. Каждая запись показывает, что делает экспорт, его точную сигнатуру, каждый параметр, что он возвращает в каждом случае, и рабочий пример на TypeScript и Lua.

## Вызов экспорта

Экспорт вызывается по имени ресурса, которому он принадлежит (`ai-core`), и имени экспорта.

<Tabs items={['TypeScript', 'Lua']}>
<Tab value="TypeScript">
```ts
import { resourceExport } from "@aifivem/lib/server";

// Один типизированный хэндл на файл, в начале. Здесь это безопасно: FiveM ищет каждый
// экспорт при первом использовании и забывает его, когда ai-core перезапускается.
const core = resourceExport("ai-core");

export function cashOf(source: number): number {
  return core.GetMoney(source, "cash") ?? 0;
}
```
</Tab>
<Tab value="Lua">
```lua
-- Настройка не нужна: exports['ai-core'] работает в любом серверном скрипте.
local function cashOf(source)
  return exports['ai-core']:GetMoney(source, 'cash') or 0
end
```
</Tab>
</Tabs>

Что нужно знать перед началом:

- **Типы TypeScript.** `resourceExport("ai-core")` типизирован по `AiCoreServerExports` из `@aifivem/shared`, поэтому редактор знает каждое имя, параметр и тип возврата. Никогда не пишите `resourceExport("ai-core").GetMoney(...)` внутри функции: держите один хэндл в начале файла.
- **В Lua используется двоеточие.** Пишите `exports['ai-core']:GetMoney(source, 'cash')`, а не через точку. Ответ `null` приходит в Lua как `nil`, массив как список Lua (первый индекс 1), объект как таблица.
- **Два написания.** Каждый экспорт отвечает и с изменённым регистром первой буквы: `GetMoney` и `getMoney` - одна и та же функция.
- **Экспорты никогда не ждут.** Каждый экспорт сразу отвечает небольшим значением. Когда ответу нужна база данных (сохранённая внешность, список счетов), экспорт принимает callback `done` вместо возврата Promise, потому что Promise не может перейти из одного ресурса в другой.
- **Не в горячих путях.** Вызов экспорта копирует аргументы и ответ. Не вызывайте экспорты каждый кадр или для каждого игрока в цикле. Для «кто на дежурстве», имени персонажа или работ многих игроков используйте зеркало `online` из библиотеки, которое следит за событиями ai-core ([Библиотека: сервер](/ru/docs/developers/api/lib-server)).
- **ai-core должен запуститься первым.** Укажите `dependency 'ai-core'` в своём `fxmanifest.lua` (ресурс ai-* перечисляет его в `fxDependencies` в `package.json`), чтобы ваш ресурс стартовал после ai-core.
- **`source` - это серверный id игрока.** Это число, которое FiveM даёт подключённому игроку. Id персонажа (`charId`) - другое число: id строки персонажа в базе данных.

## Библиотека или экспорт?

У большинства экспортов есть обёртка в `@aifivem/lib/server` (и у многих в `aiLib` для Lua). Обёртка вызывает тот же экспорт, поэтому поведение идентично; она лишь читается приятнее (`inventory.addItem(source, "water")` вместо `core.AddItem(source, "water")`) и превращает callback в Promise там, где это безопасно. Каждая запись называет свою обёртку в строке **Библиотека**. Используйте что нравится; ресурс на Lua без ai-lib вызывает экспорт напрямую.

## Примеры на этих страницах

Примеры - это полные серверные файлы. Примеры на TypeScript используют `addCommand` и `onClientCallback` из библиотеки; примеры на Lua используют `aiLib.addCommand` и `aiLib.onClientCallback` из ai-lib, которым нужны эти строки в вашем `fxmanifest.lua`:

```lua title="fxmanifest.lua"
shared_script '@ai-lib/init.lua'
dependency 'ai-lib'
dependency 'ai-core'
```

Ожидающие вызовы Lua (`aiLib.progressFor`, `Wait`) работают только внутри потока; обработчики команд и callback уже выполняются в нём.
