## Plates

GTA pads plates to 8 characters with spaces (`"  AI 1  "`). Every script that keeps data per plate (keys, fuel, garages) uses the **trimmed upper-case** plate as the key, so the same vehicle matches everywhere.

### plateOf

A vehicle's plate as keys use it: read from the entity, trimmed, upper case.

**Side:** Client and server · **Waits:** no

```ts title="Signature"
plateOf(vehicle: number): string
```

**Lua:** no twin; use `GetVehicleNumberPlateText(vehicle):match('^%s*(.-)%s*$'):upper()`.

#### Parameters

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Vehicle entity handle (on the server: a server entity).', required: true },
  }}
/>

#### Returns

`string`: the plate, trimmed and upper case.

#### Example

```ts title="resource/server/index.ts"
import { plateOf, vehicleOf } from "@aifivem/lib/server";

function plateOfPlayerVehicle(source: number): string | null {
  const vehicle = vehicleOf(source);
  return vehicle === 0 ? null : plateOf(vehicle);
}
```

### normalizePlate

The same trim and upper case for a plate you already have as text (typed by a player, stored in a database, sent by another script).

**Side:** Client, server and NUI · **Waits:** no

```ts title="Signature"
normalizePlate(plate: string): string
```

**Lua:** no twin; use `plate:match('^%s*(.-)%s*$'):upper()`.

#### Parameters

<TypeTable
  type={{
    plate: { type: 'string', description: 'Plate text in any form.', required: true },
  }}
/>

#### Returns

`string`: trimmed, upper case.

#### Example

```ts
import { normalizePlate } from "@aifivem/lib/shared";

normalizePlate("  ai 123 "); // "AI 123"
```

## Spawning

### vehicleTypeOfClass

Turns a GTA vehicle class (`GetVehicleClassFromName`) into the type `CreateVehicleServerSetter` needs: `"bike"`, `"boat"`, `"heli"`, `"plane"`, `"train"` or `"automobile"`. Lib `spawnVehicle` does this for you; use it only when you call `CreateVehicleServerSetter` yourself.

**Side:** Client, server and NUI · **Waits:** no

```ts title="Signature"
vehicleTypeOfClass(vehicleClass: number): string
```

**Lua:** no twin.

#### Parameters

<TypeTable
  type={{
    vehicleClass: { type: 'number', description: 'GTA vehicle class 0-22. Classes 8 (motorcycles) and 13 (cycles) are bikes, 14 boats, 15 helicopters, 16 planes, 21 trains.', required: true },
  }}
/>

#### Returns

`string`: the spawn type. Every class not listed above is `"automobile"`.

#### Example

```ts title="resource/client/index.ts"
import { vehicleTypeOfClass } from "@aifivem/lib/shared";

const type = vehicleTypeOfClass(GetVehicleClassFromName("frogger")); // "heli"
```

<Callout type="info">
`GetVehicleClassFromName` is a client native. The server learns a model's type from a client (lib `spawnVehicle` asks ai-core's client for you).
</Callout>

## Looks from untrusted data

### toVehicleProps

Checks stored or received vehicle props and returns a clean [VehicleProps](/docs/developers/api/types#vehicleprops) object, or `null` when the data is not in that shape. Missing optional parts get defaults (stock mods, no livery, full health); unknown fields are dropped; the plate is cut to 8 characters.

**Side:** Client, server and NUI · **Waits:** no

```ts title="Signature"
toVehicleProps(value: unknown): VehicleProps | null
```

**Lua:** no twin.

#### Parameters

<TypeTable
  type={{
    value: { type: 'unknown', description: 'Props from the database, a state bag, an export call or a client.', required: true },
  }}
/>

#### Returns

`VehicleProps`, or `null` when `value` is not an object, `v` is not `1`, `model` or `plate` is missing, or one of `colors`, `extraColors`, `neonColor`, `tyreSmoke`, `mods`, `extras`, `neon` is missing or the wrong length.

#### Example

```ts title="resource/server/index.ts"
import { optionalExport } from "@aifivem/lib/server";
import { toVehicleProps } from "@aifivem/lib/shared";

function storedColors(vehicleId: number): [number, number] | null {
  const vehicle = optionalExport("ai-vehicles")?.GetVehicle(vehicleId);
  const props = toVehicleProps(vehicle?.props);
  return props ? props.colors : null;
}
```

### toVehicleSetup

Checks a received [VehicleSetup](/docs/developers/api/types#vehiclesetup) field by field: wrong fields are dropped, the right ones kept. Use it on a setup that comes from a client or another resource before you pass it to `spawnVehicle`.

**Side:** Client, server and NUI · **Waits:** no

```ts title="Signature"
toVehicleSetup(value: unknown): VehicleSetup | null
```

**Lua:** no twin.

#### Parameters

<TypeTable
  type={{
    value: { type: 'unknown', description: 'The setup to check.', required: true },
  }}
/>

#### Returns

`VehicleSetup` with only the valid fields (colours 0-255, `livery` 0-100, `windowTint` 0-6, `dirt` 0-15; `maxed` and `engineOn` only when exactly `true`). `null` when `value` is not an object.

#### Example

```ts
import { toVehicleSetup } from "@aifivem/lib/shared";

toVehicleSetup({ colors: [27, 27], windowTint: 9, maxed: "yes" });
// { colors: [27, 27], windowTint: undefined, maxed: undefined, ... }: the bad fields are dropped
```

<Callout type="warn">
A client must never choose `maxed: true` or a free colour for a vehicle it pays for: check the price on the server for what the setup contains.
</Callout>
