Dos partes de la lib funcionan igual en el cliente y en el servidor:

| Entrada | Qué contiene | Dónde puedes usarla |
| --- | --- | --- |
| `@aicore-fivem/lib/shared` | Utilidades simples que nunca llaman a un native de FiveM: rechazos, lectores de entrada, formato de números y texto, matemáticas de vectores, geometría de zonas, lectores de datos del panel, los textos de idioma de una página NUI. | Cliente, servidor, `resource/common/` y código NUI (React). |
| `@aicore-fivem/lib/fivem` | Utilidades que llaman a natives que existen en ambos lados: exports entre recursos, el planificador, la gestión de la detención de recursos, el cargador de archivos de idioma. | Cliente, servidor y `resource/common/`. No en código NUI. |

Las entradas de cliente y de servidor reexportan todo lo de `/fivem`, así que en un archivo de cliente o de servidor también puedes importar esas utilidades desde `@aicore-fivem/lib/client` o `@aicore-fivem/lib/server`. Usa `/fivem` solo en los archivos de `resource/common/` que empaquetan ambos lados.

```ts title="TypeScript"
import { fail, readInt, groupDigits } from "@aicore-fivem/lib/shared";
import { resourceExport, every, createLocale } from "@aicore-fivem/lib/fivem";
```

## Lua

Solo unas pocas de estas utilidades tienen un equivalente en Lua en `aiLib` (cárgalo con `shared_script '@ai-lib/init.lua'`, consulta [Lib para Lua](/es/docs/developers/api/lua)): `every`, `waitFor`, `formatText`, `locale`, `fail`, `numbers.round`, `numbers.groupDigits`, `numbers.headingTo` y `stripGameText`. Cada entrada muestra la llamada Lua cuando la hay, y lo indica cuando no la hay. Lua tiene sus propias herramientas para el resto: matemáticas de vectores (`#(a - b)` para una distancia), `Entity(e).state` para los state bags, `exports['name']:Fn()` para los exports.
