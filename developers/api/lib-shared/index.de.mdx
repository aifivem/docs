Zwei Teile der Lib funktionieren auf dem Client und auf dem Server gleichermaßen:

| Einstieg | Was er enthält | Wo du ihn nutzen kannst |
| --- | --- | --- |
| `@aifivem/lib/shared` | Einfache Helfer, die nie ein FiveM-Native aufrufen: Ablehnungen, Eingabeleser, Zahlen- und Textformatierung, Vektor-Mathematik, Zonengeometrie, Leser für Panel-Daten, die Sprachtexte einer NUI-Seite. | Client, Server, `resource/common/` und NUI-Code (React). |
| `@aifivem/lib/fivem` | Helfer, die Natives aufrufen, die es auf beiden Seiten gibt: Exports zwischen Ressourcen, der Scheduler, Behandlung des Ressourcen-Stopps, der Lader für Sprachdateien. | Client, Server und `resource/common/`. Nicht im NUI-Code. |

Die Client- und Server-Einstiege exportieren alles aus `/fivem` erneut, sodass du diese Helfer in einer Client- oder Server-Datei auch aus `@aifivem/lib/client` oder `@aifivem/lib/server` importieren kannst. Nutze `/fivem` nur in Dateien unter `resource/common/`, die beide Seiten bündeln.

```ts title="TypeScript"
import { fail, readInt, groupDigits } from "@aifivem/lib/shared";
import { resourceExport, every, createLocale } from "@aifivem/lib/fivem";
```

## Lua

Nur wenige dieser Helfer haben einen Lua-Zwilling auf `aiLib` (lade es mit `shared_script '@ai-lib/init.lua'`, siehe [Lib für Lua](/de/docs/developers/api/lua)): `every`, `waitFor`, `formatText`, `locale`, `fail`, `numbers.round`, `numbers.groupDigits`, `numbers.headingTo` und `stripGameText`. Jeder Eintrag zeigt den Lua-Aufruf, wenn es einen gibt, und sagt es, wenn es keinen gibt. Für den Rest hat Lua eigene Werkzeuge: Vektor-Mathematik (`#(a - b)` für eine Entfernung), `Entity(e).state` für State Bags, `exports['name']:Fn()` für Exports.
