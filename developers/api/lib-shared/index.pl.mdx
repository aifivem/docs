Dwie części liba działają tak samo na kliencie i na serwerze:

| Wejście | Co zawiera | Gdzie możesz go użyć |
| --- | --- | --- |
| `@aicore-fivem/lib/shared` | Zwykłe funkcje pomocnicze, które nigdy nie wywołują natywki FiveM: odmowy, czytniki wejścia, formatowanie liczb i tekstu, matematyka wektorów, geometria stref, czytniki danych panelu, teksty językowe strony NUI. | Klient, serwer, `resource/common/` i kod NUI (React). |
| `@aicore-fivem/lib/fivem` | Funkcje pomocnicze wywołujące natywki dostępne po obu stronach: eksporty między zasobami, harmonogram, obsługa zatrzymania zasobu, loader plików językowych. | Klient, serwer i `resource/common/`. Nie w kodzie NUI. |

Wejścia klienta i serwera ponownie eksportują wszystko z `/fivem`, więc w pliku klienta lub serwera możesz importować te funkcje także z `@aicore-fivem/lib/client` albo `@aicore-fivem/lib/server`. Używaj `/fivem` tylko w plikach `resource/common/`, które budują obie strony.

```ts title="TypeScript"
import { fail, readInt, groupDigits } from "@aicore-fivem/lib/shared";
import { resourceExport, every, createLocale } from "@aicore-fivem/lib/fivem";
```

## Lua

Tylko kilka z tych funkcji ma odpowiednik w Lua w `aiLib` (wczytaj go przez `shared_script '@ai-lib/init.lua'`, zobacz [Lib dla Lua](/pl/docs/developers/api/lua)): `every`, `waitFor`, `formatText`, `locale`, `fail`, `numbers.round`, `numbers.groupDigits`, `numbers.headingTo` i `stripGameText`. Każdy wpis pokazuje wywołanie Lua, gdy istnieje, i mówi to wprost, gdy go nie ma. Do reszty Lua ma własne narzędzia: matematykę wektorów (`#(a - b)` dla odległości), `Entity(e).state` dla state bagów, `exports['name']:Fn()` dla eksportów.
