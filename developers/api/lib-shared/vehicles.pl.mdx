## Tablice rejestracyjne

GTA dopełnia tablice spacjami do 8 znaków (`"  AI 1  "`). Każdy skrypt, który trzyma dane według tablicy (klucze, paliwo, garaże), używa jako klucza tablicy **przyciętej i zapisanej wielkimi literami**, więc ten sam pojazd pasuje wszędzie.

### plateOf

Tablica pojazdu w formie używanej przez klucze: odczytana z encji, przycięta, wielkimi literami.

**Strona:** Klient i serwer · **Czeka:** nie

```ts title="Sygnatura"
plateOf(vehicle: number): string
```

**Lua:** brak odpowiednika; użyj `GetVehicleNumberPlateText(vehicle):match('^%s*(.-)%s*$'):upper()`.

#### Parametry

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Uchwyt encji pojazdu (na serwerze: encja serwerowa).', required: true },
  }}
/>

#### Zwracana wartość

`string`: tablica, przycięta i wielkimi literami.

#### Przykład

```ts title="resource/server/index.ts"
import { plateOf, vehicleOf } from "@aifivem/lib/server";

function plateOfPlayerVehicle(source: number): string | null {
  const vehicle = vehicleOf(source);
  return vehicle === 0 ? null : plateOf(vehicle);
}
```

### normalizePlate

To samo przycięcie i wielkie litery dla tablicy, którą masz już jako tekst (wpisaną przez gracza, zapisaną w bazie danych, wysłaną przez inny skrypt).

**Strona:** Klient, serwer i NUI · **Czeka:** nie

```ts title="Sygnatura"
normalizePlate(plate: string): string
```

**Lua:** brak odpowiednika; użyj `plate:match('^%s*(.-)%s*$'):upper()`.

#### Parametry

<TypeTable
  type={{
    plate: { type: 'string', description: 'Tekst tablicy w dowolnej formie.', required: true },
  }}
/>

#### Zwracana wartość

`string`: przycięta, wielkimi literami.

#### Przykład

```ts
import { normalizePlate } from "@aifivem/lib/shared";

normalizePlate("  ai 123 "); // "AI 123"
```

## Spawnowanie

### vehicleTypeOfClass

Zamienia klasę pojazdu GTA (`GetVehicleClassFromName`) w typ potrzebny `CreateVehicleServerSetter`: `"bike"`, `"boat"`, `"heli"`, `"plane"`, `"train"` albo `"automobile"`. `spawnVehicle` liba robi to za ciebie; używaj jej tylko wtedy, gdy sam wywołujesz `CreateVehicleServerSetter`.

**Strona:** Klient, serwer i NUI · **Czeka:** nie

```ts title="Sygnatura"
vehicleTypeOfClass(vehicleClass: number): string
```

**Lua:** brak odpowiednika.

#### Parametry

<TypeTable
  type={{
    vehicleClass: { type: 'number', description: 'Klasa pojazdu GTA 0-22. Klasy 8 (motocykle) i 13 (rowery) to bike, 14 łodzie, 15 helikoptery, 16 samoloty, 21 pociągi.', required: true },
  }}
/>

#### Zwracana wartość

`string`: typ spawnu. Każda klasa niewymieniona wyżej to `"automobile"`.

#### Przykład

```ts title="resource/client/index.ts"
import { vehicleTypeOfClass } from "@aifivem/lib/shared";

const type = vehicleTypeOfClass(GetVehicleClassFromName("frogger")); // "heli"
```

<Callout type="info">
`GetVehicleClassFromName` to natywka klienta. Serwer poznaje typ modelu od klienta (`spawnVehicle` liba pyta o to klienta ai-core za ciebie).
</Callout>

## Wygląd z niezaufanych danych

### toVehicleProps

Sprawdza zapisane albo otrzymane właściwości pojazdu i zwraca czysty obiekt [VehicleProps](/pl/docs/developers/api/types#vehicleprops) albo `null`, gdy dane nie mają tego kształtu. Brakujące części opcjonalne dostają wartości domyślne (fabryczne modyfikacje, brak malowania, pełne zdrowie); nieznane pola są usuwane; tablica jest skracana do 8 znaków.

**Strona:** Klient, serwer i NUI · **Czeka:** nie

```ts title="Sygnatura"
toVehicleProps(value: unknown): VehicleProps | null
```

**Lua:** brak odpowiednika.

#### Parametry

<TypeTable
  type={{
    value: { type: 'unknown', description: 'Właściwości z bazy danych, state bagu, wywołania eksportu albo od klienta.', required: true },
  }}
/>

#### Zwracana wartość

`VehicleProps` albo `null`, gdy `value` nie jest obiektem, `v` nie wynosi `1`, brakuje `model` albo `plate` lub gdy brakuje jednego z `colors`, `extraColors`, `neonColor`, `tyreSmoke`, `mods`, `extras`, `neon` albo ma on złą długość.

#### Przykład

```ts title="resource/server/index.ts"
import { optionalExport } from "@aifivem/lib/server";
import { toVehicleProps } from "@aifivem/lib/shared";

function storedColors(vehicleId: number): [number, number] | null {
  const vehicle = optionalExport("ai-vehicles")?.GetVehicle(vehicleId);
  const props = toVehicleProps(vehicle?.props);
  return props ? props.colors : null;
}
```

### toVehicleSetup

Sprawdza otrzymany [VehicleSetup](/pl/docs/developers/api/types#vehiclesetup) pole po polu: złe pola są usuwane, poprawne zostają. Używaj jej na konfiguracji, która przychodzi od klienta albo innego zasobu, zanim przekażesz ją do `spawnVehicle`.

**Strona:** Klient, serwer i NUI · **Czeka:** nie

```ts title="Sygnatura"
toVehicleSetup(value: unknown): VehicleSetup | null
```

**Lua:** brak odpowiednika.

#### Parametry

<TypeTable
  type={{
    value: { type: 'unknown', description: 'Konfiguracja do sprawdzenia.', required: true },
  }}
/>

#### Zwracana wartość

`VehicleSetup` tylko z poprawnymi polami (kolory 0-255, `livery` 0-100, `windowTint` 0-6, `dirt` 0-15; `maxed` i `engineOn` tylko gdy są dokładnie `true`). `null`, gdy `value` nie jest obiektem.

#### Przykład

```ts
import { toVehicleSetup } from "@aifivem/lib/shared";

toVehicleSetup({ colors: [27, 27], windowTint: 9, maxed: "yes" });
// { colors: [27, 27], windowTint: undefined, maxed: undefined, ... }: złe pola są usuwane
```

<Callout type="warn">
Klient nigdy nie może wybrać `maxed: true` ani darmowego koloru dla pojazdu, za który płaci: sprawdź na serwerze cenę tego, co zawiera konfiguracja.
</Callout>
