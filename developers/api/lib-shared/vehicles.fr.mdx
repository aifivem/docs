## Plaques

GTA complète les plaques à 8 caractères avec des espaces (`"  AI 1  "`). Chaque script qui garde des données par plaque (clés, carburant, garages) utilise comme clé la plaque **sans espaces autour et en majuscules**, pour que le même véhicule corresponde partout.

### plateOf

La plaque d’un véhicule telle que les clés l’utilisent : lue sur l’entité, sans espaces autour, en majuscules.

**Côté :** client et serveur · **Attend :** non

```ts title="Signature"
plateOf(vehicle: number): string
```

**Lua :** pas d’équivalent ; utilisez `GetVehicleNumberPlateText(vehicle):match('^%s*(.-)%s*$'):upper()`.

#### Paramètres

<TypeTable
  type={{
    vehicle: { type: 'number', description: 'Handle de l’entité véhicule (sur le serveur : une entité serveur).', required: true },
  }}
/>

#### Retour

`string` : la plaque, sans espaces autour et en majuscules.

#### Exemple

```ts title="resource/server/index.ts"
import { plateOf, vehicleOf } from "@aicore-fivem/lib/server";

function plateOfPlayerVehicle(source: number): string | null {
  const vehicle = vehicleOf(source);
  return vehicle === 0 ? null : plateOf(vehicle);
}
```

### normalizePlate

Le même nettoyage des espaces et passage en majuscules pour une plaque que vous avez déjà sous forme de texte (tapée par un joueur, stockée en base de données, envoyée par un autre script).

**Côté :** client, serveur et NUI · **Attend :** non

```ts title="Signature"
normalizePlate(plate: string): string
```

**Lua :** pas d’équivalent ; utilisez `plate:match('^%s*(.-)%s*$'):upper()`.

#### Paramètres

<TypeTable
  type={{
    plate: { type: 'string', description: 'Texte de plaque sous n’importe quelle forme.', required: true },
  }}
/>

#### Retour

`string` : sans espaces autour, en majuscules.

#### Exemple

```ts
import { normalizePlate } from "@aicore-fivem/lib/shared";

normalizePlate("  ai 123 "); // "AI 123"
```

## Spawn

### vehicleTypeOfClass

Transforme une classe de véhicule GTA (`GetVehicleClassFromName`) en type dont `CreateVehicleServerSetter` a besoin : `"bike"`, `"boat"`, `"heli"`, `"plane"`, `"train"` ou `"automobile"`. `spawnVehicle` de la lib le fait pour vous ; ne l’utilisez que quand vous appelez vous-même `CreateVehicleServerSetter`.

**Côté :** client, serveur et NUI · **Attend :** non

```ts title="Signature"
vehicleTypeOfClass(vehicleClass: number): string
```

**Lua :** pas d’équivalent.

#### Paramètres

<TypeTable
  type={{
    vehicleClass: { type: 'number', description: 'Classe de véhicule GTA 0-22. Les classes 8 (motos) et 13 (vélos) sont des bikes, 14 des bateaux, 15 des hélicoptères, 16 des avions, 21 des trains.', required: true },
  }}
/>

#### Retour

`string` : le type de spawn. Chaque classe non listée ci-dessus donne `"automobile"`.

#### Exemple

```ts title="resource/client/index.ts"
import { vehicleTypeOfClass } from "@aicore-fivem/lib/shared";

const type = vehicleTypeOfClass(GetVehicleClassFromName("frogger")); // "heli"
```

<Callout type="info">
`GetVehicleClassFromName` est une native client. Le serveur apprend le type d’un modèle auprès d’un client (`spawnVehicle` de la lib le demande pour vous au client d’ai-core).
</Callout>

## Apparence à partir de données non fiables

### toVehicleProps

Vérifie des props de véhicule stockées ou reçues et renvoie un objet [VehicleProps](/fr/docs/developers/api/types#vehicleprops) propre, ou `null` quand les données n’ont pas cette forme. Les parties facultatives manquantes reçoivent des valeurs par défaut (mods d’origine, pas de livrée, santé pleine) ; les champs inconnus sont retirés ; la plaque est coupée à 8 caractères.

**Côté :** client, serveur et NUI · **Attend :** non

```ts title="Signature"
toVehicleProps(value: unknown): VehicleProps | null
```

**Lua :** pas d’équivalent.

#### Paramètres

<TypeTable
  type={{
    value: { type: 'unknown', description: 'Des props venant de la base de données, d’un state bag, d’un appel d’export ou d’un client.', required: true },
  }}
/>

#### Retour

`VehicleProps`, ou `null` quand `value` n’est pas un objet, que `v` ne vaut pas `1`, que `model` ou `plate` manque, ou que l’un de `colors`, `extraColors`, `neonColor`, `tyreSmoke`, `mods`, `extras`, `neon` manque ou n’a pas la bonne longueur.

#### Exemple

```ts title="resource/server/index.ts"
import { optionalExport } from "@aicore-fivem/lib/server";
import { toVehicleProps } from "@aicore-fivem/lib/shared";

function storedColors(vehicleId: number): [number, number] | null {
  const vehicle = optionalExport("ai-vehicles")?.GetVehicle(vehicleId);
  const props = toVehicleProps(vehicle?.props);
  return props ? props.colors : null;
}
```

### toVehicleSetup

Vérifie champ par champ un [VehicleSetup](/fr/docs/developers/api/types#vehiclesetup) reçu : les champs invalides sont retirés, les bons gardés. Utilisez-le sur une configuration qui vient d’un client ou d’une autre ressource avant de la passer à `spawnVehicle`.

**Côté :** client, serveur et NUI · **Attend :** non

```ts title="Signature"
toVehicleSetup(value: unknown): VehicleSetup | null
```

**Lua :** pas d’équivalent.

#### Paramètres

<TypeTable
  type={{
    value: { type: 'unknown', description: 'La configuration à vérifier.', required: true },
  }}
/>

#### Retour

`VehicleSetup` avec seulement les champs valides (couleurs 0-255, `livery` 0-100, `windowTint` 0-6, `dirt` 0-15 ; `maxed` et `engineOn` seulement quand ils valent exactement `true`). `null` quand `value` n’est pas un objet.

#### Exemple

```ts
import { toVehicleSetup } from "@aicore-fivem/lib/shared";

toVehicleSetup({ colors: [27, 27], windowTint: 9, maxed: "yes" });
// { colors: [27, 27], windowTint: undefined, maxed: undefined, ... } : les champs invalides sont retirés
```

<Callout type="warn">
Un client ne doit jamais choisir `maxed: true` ou une couleur gratuite pour un véhicule qu’il paie : vérifiez sur le serveur le prix de ce que contient la configuration.
</Callout>
