Deux parties de la lib fonctionnent aussi bien sur le client que sur le serveur :

| Entrée | Ce qu’elle contient | Où l’utiliser |
| --- | --- | --- |
| `@aicore-fivem/lib/shared` | Des utilitaires simples qui n’appellent jamais de native FiveM : refus, lecteurs d’entrée, formatage des nombres et du texte, calcul vectoriel, géométrie des zones, lecteurs de données du panneau, textes de langue d’une page NUI. | Client, serveur, `resource/common/` et code NUI (React). |
| `@aicore-fivem/lib/fivem` | Des utilitaires qui appellent des natives présentes des deux côtés : exports entre ressources, planificateur, gestion de l’arrêt d’une ressource, chargeur de fichiers de langue. | Client, serveur et `resource/common/`. Pas dans le code NUI. |

Les entrées client et serveur réexportent tout ce que contient `/fivem` : dans un fichier client ou serveur, vous pouvez donc aussi importer ces utilitaires depuis `@aicore-fivem/lib/client` ou `@aicore-fivem/lib/server`. N’utilisez `/fivem` que dans les fichiers de `resource/common/` que les deux côtés intègrent à leur bundle.

```ts title="TypeScript"
import { fail, readInt, groupDigits } from "@aicore-fivem/lib/shared";
import { resourceExport, every, createLocale } from "@aicore-fivem/lib/fivem";
```

## Lua

Seuls quelques-uns de ces utilitaires ont un équivalent Lua sur `aiLib` (chargez-le avec `shared_script '@ai-lib/init.lua'`, voir [Lib pour Lua](/fr/docs/developers/api/lua)) : `every`, `waitFor`, `formatText`, `locale`, `fail`, `numbers.round`, `numbers.groupDigits`, `numbers.headingTo` et `stripGameText`. Chaque entrée montre l’appel Lua quand il existe, et précise quand il n’y en a pas. Pour le reste, Lua a ses propres outils : le calcul vectoriel (`#(a - b)` pour une distance), `Entity(e).state` pour les state bags, `exports['name']:Fn()` pour les exports.
