Две части lib одинаково работают и на клиенте, и на сервере:

| Точка входа | Что в ней | Где её можно использовать |
| --- | --- | --- |
| `@aicore-fivem/lib/shared` | Простые помощники, которые никогда не вызывают нативы FiveM: отказы, функции чтения ввода, форматирование чисел и текста, векторная математика, геометрия зон, функции чтения данных панели, языковые тексты страницы NUI. | Код клиента, сервера, `resource/common/` и NUI (React). |
| `@aicore-fivem/lib/fivem` | Помощники, которые вызывают нативы, существующие на обеих сторонах: экспорты между ресурсами, планировщик, обработка остановки ресурса, загрузчик языковых файлов. | Клиент, сервер и `resource/common/`. Не в коде NUI. |

Точки входа клиента и сервера реэкспортируют всё из `/fivem`, поэтому в файле клиента или сервера эти помощники можно импортировать и из `@aicore-fivem/lib/client` или `@aicore-fivem/lib/server`. Используйте `/fivem` только в файлах `resource/common/`, которые собираются для обеих сторон.

```ts title="TypeScript"
import { fail, readInt, groupDigits } from "@aicore-fivem/lib/shared";
import { resourceExport, every, createLocale } from "@aicore-fivem/lib/fivem";
```

## Lua

Лишь у немногих из этих помощников есть Lua-аналог в `aiLib` (загружается через `shared_script '@ai-lib/init.lua'`, см. [Lib для Lua](/ru/docs/developers/api/lua)): `every`, `waitFor`, `formatText`, `locale`, `fail`, `numbers.round`, `numbers.groupDigits`, `numbers.headingTo` и `stripGameText`. В каждой записи показан вызов на Lua, если он есть, и сказано, если его нет. Для остального в Lua есть свои средства: векторная математика (`#(a - b)` для расстояния), `Entity(e).state` для state bags, `exports['name']:Fn()` для экспортов.
