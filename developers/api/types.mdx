The API pages write types by name (`Vec3`, `ActionResult`, `InventoryRef`...). This page explains each one once: its fields, what each field means, and an example value.

Where a type comes from:

| Package | Import | Types |
| --- | --- | --- |
| `@aicore-fivem/shared` | `import type { AiPlayerData } from "@aicore-fivem/shared";` | Everything on this page unless the heading says otherwise. |
| `@aicore-fivem/lib/shared` | `import type { Vec3 } from "@aicore-fivem/lib/shared";` | `Vec3`, `Vec4`, `AccessRule`, `BlipStyle`, `ZoneShape`, `VehicleProps`, `VehicleSetup`, `PlacePed`. |
| `@aicore-fivem/lib/client` | `import type { ProgressOptions } from "@aicore-fivem/lib/client";` | `ProgressOptions`. |
| `@aicore-fivem/lib/server` | `import type { ProgressForOptions } from "@aicore-fivem/lib/server";` | `ProgressForOptions`. |

<Callout type="info">
Lua has no types at run time. A Lua table with the same keys is the same value: `{ x = 1.0, y = 2.0, z = 3.0 }` is a `Vec3`. Arrays are Lua lists (`{ 'police', 'sheriff' }`), `null` is `nil`. See [Lib for Lua](/docs/developers/api/lua) for vectors.
</Callout>

## Positions

### Vec3

A point in the world, in metres. GTA's `x` is east, `y` is north, `z` is up.

<TypeTable
  type={{
    x: { type: 'number', description: 'East-west position in metres.', required: true },
    y: { type: 'number', description: 'North-south position in metres.', required: true },
    z: { type: 'number', description: 'Height in metres.', required: true },
  }}
/>

```ts title="Example"
const counter: Vec3 = { x: 25.7, y: -1347.3, z: 29.5 };
```

```lua title="Lua"
local counter = vector3(25.7, -1347.3, 29.5) -- or { x = 25.7, y = -1347.3, z = 29.5 }
```

### Vec4

A point with a heading: where a ped stands or a vehicle spawns and which way it faces. Panel `vec4` fields and the panel's point tool store this shape.

<TypeTable
  type={{
    x: { type: 'number', description: 'East-west position in metres.', required: true },
    y: { type: 'number', description: 'North-south position in metres.', required: true },
    z: { type: 'number', description: 'Height in metres.', required: true },
    heading: { type: 'number', description: "Direction in degrees, 0-360 (GTA’s: 0 = north, counter-clockwise).", required: true },
  }}
/>

```ts title="Example"
const spawn: Vec4 = { x: -42.1, y: -1098.4, z: 26.4, heading: 158.0 };
```

<Callout type="info">
A Lua `vector4` calls the heading `w`. The lib's readers ([readVec4](/docs/developers/api/lib-shared/input#readvec4)) accept both `heading` and `w`.
</Callout>

### ZoneShape

An area in the world. Used by client `Zones` and by server area checks ([zone geometry](/docs/developers/api/lib-shared/zones)). It is one of three shapes, picked by `type`.

**Sphere** (a ball around a point):

<TypeTable
  type={{
    type: { type: '"sphere"', description: 'Picks this shape.', required: true },
    center: { type: 'Vec3', description: 'Middle of the ball.', required: true, typeDescription: '{ x, y, z }' },
    radius: { type: 'number', description: 'Radius in metres.', required: true },
  }}
/>

**Cylinder** (a circle on the ground, reaching up and down):

<TypeTable
  type={{
    type: { type: '"cylinder"', description: 'Picks this shape.', required: true },
    center: { type: 'Vec3', description: 'Middle of the circle.', required: true },
    radius: { type: 'number', description: 'Radius on the ground plane, in metres.', required: true },
    height: { type: 'number', description: 'How far the zone reaches up and down from `center.z`, in metres (total height is twice this).', required: true },
  }}
/>

**Poly** (a ground polygon between two heights):

<TypeTable
  type={{
    type: { type: '"poly"', description: 'Picks this shape.', required: true },
    points: { type: 'Array<{ x: number; y: number }>', description: 'Corners on the ground, in order around the area. At least 3.', required: true },
    minZ: { type: 'number', description: 'Lowest height inside the zone.', required: true },
    maxZ: { type: 'number', description: 'Highest height inside the zone.', required: true },
  }}
/>

```ts title="Example"
const yard: ZoneShape = { type: "sphere", center: { x: 440.1, y: -981.2, z: 30.7 }, radius: 25 };
const lot: ZoneShape = {
  type: "poly",
  points: [ { x: 210, y: -810 }, { x: 240, y: -800 }, { x: 230, y: -770 }, { x: 200, y: -780 } ],
  minZ: 28,
  maxZ: 36,
};
```

## Results

### ActionResult

What every server action answers a client: either success, or a lang key the client shows as the reason. Extra fields can ride on the success branch (`ActionResult<{ id: number }>`). The new state itself never travels in the reply: it arrives as a delta.

**Success:**

<TypeTable
  type={{
    ok: { type: 'true', description: 'The action ran.', required: true },
    '...T': { type: 'T', description: 'Extra fields of `ActionResult<T>` (for example the new record id).' },
  }}
/>

**Refusal:**

<TypeTable
  type={{
    ok: { type: 'false', description: 'The action was refused.', required: true },
    error: { type: 'string', description: 'A lang key from the resource\'s `locales/*.json` (`"NOT_ENOUGH_MONEY"`). The client translates and shows it.', required: true },
  }}
/>

```ts title="Example"
const done: ActionResult = { ok: true };
const created: ActionResult<{ id: number }> = { ok: true, id: 42 };
const refused: ActionResult = { ok: false, error: "NOT_ENOUGH_MONEY" };
```

```lua title="Lua"
return { ok = true }
return aiLib.fail('NOT_ENOUGH_MONEY') -- { ok = false, error = 'NOT_ENOUGH_MONEY' }
```

Build refusals with [fail](/docs/developers/api/lib-shared/input#fail); read replies with [isActionOk](/docs/developers/api/lib-shared/input#isactionok) and [replyError](/docs/developers/api/lib-shared/input#replyerror).

  }}

## Money

### Account names

Money lives in named accounts. The panel's **Accounts** list sets which exist; ai-core ships with these:

| Name | Label | Starting amount |
| --- | --- | --- |
| `cash` | Cash | 500 |
| `bank` | Bank | 5000 |
| `black_money` | Dirty money | 0 |
| `crypto` | Crypto | 0 |

A server owner can add, rename or remove accounts in the panel, so read the list with the `GetAccountTypes` export instead of assuming it. When the list is empty, ai-core keeps a single `cash` account.

```ts title="Example"
core.AddMoney(source, "bank", 250, "Paycheck");
```

## Inventory

### InventoryRef

Which inventory a call works on.

| Value | Means |
| --- | --- |
| `number` | A player's server id: that player's own inventory. |
| `string` | Any other inventory by its id: a stash name, a trunk or glovebox id. |

```ts title="Example"
inventory.addItem(source, "water", 2);          // a player
inventory.addItem("police_evidence", "phone", 1); // a stash
```

### ItemMetadata

Free data stored on one item stack (`Record<string, unknown>`): a serial number, durability, a note. Each inventory shows some keys itself (`label`, `description`, `image` in most of them).

```ts title="Example"
const metadata: ItemMetadata = { serial: "AB-1029", durability: 100 };
```

<Callout type="warn">
Keep metadata small and JSON-safe (strings, numbers, booleans, plain objects and arrays). Two stacks with different metadata never stack together.
</Callout>

### UsableItemHandler

`(source: number, item: UsedItem) => unknown`: runs when a player uses the item. Returning `false` keeps the item in inventories that take a used item themselves (ai-inventory takes the item's `consume` amount); other inventories follow their own item settings.

```ts title="Example"
const onUse: UsableItemHandler = (source, item) => {
  if (item.metadata.durability === 0) return false; // keep it
  return true;
};
```

## vRP bridge

### VrpConfig

The panel's vRP permission mapping (`data/vrp.json`), as ai-core's vRP bridge reads it (server export `GetVrpConfig`; the local event `ai-core:vrp:config` carries the same shape after a change).

<TypeTable
  type={{
    defaults: { type: '{ jobPrefix: boolean; jobOnDuty: boolean; adminPrefix: boolean; playerPrefix: boolean }', description: 'Built-in rules used when no entry of `permissions` names the permission: `jobPrefix`: `<job>.*` = member of that job (on duty only with `jobOnDuty`); `adminPrefix`: `admin.*` = admin (`ai.admin`); `playerPrefix`: `player.*` = everyone.', required: true },
    permissions: { type: 'VrpPermissionRule[]', description: 'Permission rules, fields below.', required: true },
    groups: { type: 'Record<string, VrpGroupAlias>', description: 'vRP group name to what it means in ai-core, fields below.', required: true },
    items: { type: 'Record<string, string>', description: 'vRP item id (`"edible|tacos"`, `"wbody|WEAPON_PISTOL"`) to inventory item name.', required: true },
  }}
/>

**VrpPermissionRule:** grants `permission` to whoever matches any filled target.

<TypeTable
  type={{
    permission: { type: 'string', description: 'The permission, exact or a prefix when it ends with `*`.', required: true },
    job: { type: 'string', description: 'Members of this job match (`""` = no job target).', required: true },
    gang: { type: 'string', description: 'Members of this gang match.', required: true },
    group: { type: 'string', description: 'An extra vRP group the character holds (groups vRP scripts add that are no job or gang).', required: true },
    grade: { type: 'number', description: 'Minimum job / gang grade.', required: true },
    onDuty: { type: 'boolean', description: 'The job counts only while on duty in it.', required: true },
    admin: { type: 'boolean', description: 'Admins match.', required: true },
    everyone: { type: 'boolean', description: 'Everyone matches.', required: true },
  }}
/>

**VrpGroupAlias:** a vRP group name that means a job or gang grade, or admin (vRPex style ranks such as `"Coronel"`).

<TypeTable
  type={{
    job: { type: 'string', description: 'The job it means (`""` = none).', required: true },
    gang: { type: 'string', description: 'The gang it means.', required: true },
    grade: { type: 'number', description: 'The grade in that job or gang.', required: true },
    admin: { type: 'boolean', description: 'The group means admin.', required: true },
  }}
/>

```ts title="Example"
const config: VrpConfig = {
  defaults: { jobPrefix: true, jobOnDuty: true, adminPrefix: true, playerPrefix: true },
  permissions: [{ permission: "police.armory", job: "police", gang: "", group: "", grade: 2, onDuty: true, admin: false, everyone: false }],
  groups: { Coronel: { job: "police", gang: "", grade: 4, admin: false } },
  items: { "edible|tacos": "tacos" },
};
```
