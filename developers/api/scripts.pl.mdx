Skrypty ai-* nigdy nie wywołują się nawzajem dla wspólnego zadania: przedmioty, klucze, alerty, więzienie, leczenie, wygląd, elementy menu radialnego i pogoda idą przez ai-core (lib), który wywołuje eksporty poniżej. Wywołuj je sam tylko dla tego, co jest specyficzne dla danego skryptu. Eksporty typowane w `@aicore-fivem/shared` działają z `resourceExport("ai-...")`; pozostałe przez `callExport(resource, name, ...args)` albo zwykłe wywołanie `exports[...]`.

Gdy skrypt zastępuje inny (`provide`), nazwy eksportów tamtego skryptu też odpowiadają, więc `exports.ox_inventory:AddItem(...)` trafia do ai-inventory.

## ai-lib

Wspólny interfejs gracza. Eksporty klienckie, typowane `AiLibClientExports`; `notify`, `progress`, `showPrompt`, `menu`, `input`, `skillCheck` i `lockpick` z liba wywołują je za ciebie.

| Eksport | Co |
| --- | --- |
| `Notify(notification: Notification): void` | Karta powiadomienia (`text`, `title?`, `kind`, `duration?`). |
| `ShowProgress(label: string, duration: number): void` | Pokazuje pasek postępu przez `duration` ms (akcję prowadzi wywołujący). |
| `HideProgress(): void` | Ukrywa go. |
| `ShowPrompt(id: string, text: string, at?: { x, y, z }): void` | Pokazuje lub aktualizuje prompt wywołującego; `at` rysuje go nad punktem w świecie. |
| `HidePrompt(id: string): void` | Ukrywa prompt. |
| `OpenMenu(requestId: number, request: MenuRequest): void` | Menu; wybór przychodzi jako `MENU_EVENTS.menuResult`. |
| `OpenInput(requestId: number, request: InputRequest): void` | Okno wprowadzania; wartości przychodzą jako `MENU_EVENTS.inputResult`. |
| `OpenMinigame(requestId: number, request: MinigameRequest): void` | Test umiejętności lub wytrych; wynik przychodzi jako `MENU_EVENTS.menuResult`. |
| `CloseDialog(): void` | Zamyka otwarte menu lub okno wprowadzania wywołującego (odpowiedź null). |

Zdarzenie serwerowe `ai-lib:client:notify` (`LIB_UI.notifyEvent`) z `Notification` pokazuje kartę na ekranie tego gracza.

## ai-inventory

Eksporty serwerowe (własne): inne skrypty ai-* docierają do nich przez warstwę ekwipunku ai-core.

| Eksport | Co |
| --- | --- |
| `AddItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Dodaje przedmioty. |
| `RemoveItem(inv: number \| string, item: string, count: number, metadata?, slot?): boolean` | Usuwa przedmioty. |
| `GetItemCount(inv: number \| string, item: string, metadata?): number` | Ile sztuk. |
| `GetItems(inv: number \| string): { name, label, count, slot, metadata }[]` | Każdy stos z nazwą. |
| `CanCarryItem(inv: number \| string, item: string, count: number, metadata?): boolean` | Czy się zmieści. |
| `RegisterUsableItem(name: string, handler: (source, item) => unknown): void` | `handler` zwracający false zostawia przedmiot; inaczej zabierana jest jego ilość `consume`. |
| `RegisterStash(name: string, label: string, slots: number, maxWeight: number, jobs?: string[], personal?: boolean): void` | Schowek. |
| `OpenInventory(source: number, inv: number \| string): boolean` | Otwiera ekwipunek na ekranie gracza. |
| `ClearInventory(inv: number \| string): void` | Opróżnia go. |
| `Items(name?: string): unknown` | Jedna definicja przedmiotu (kształt ox) albo wszystkie. |
| `GetWeight(inv: number \| string): { weight, maxWeight } \| null` | Niesiona waga i limit w gramach. |

Eksporty klienckie: `OpenInventory(type, data)`, `CloseInventory()`, `OpenSelf()` (własny ekwipunek z ziemią, bagażnikiem lub schowkiem obok), `GetItemCount(item)`, `HasItem(items: string \| string[] \| Record<string, number>, amount?)`, `GetPlayerItems()`.

Lokalne zdarzenie serwera `ai-inventory:usedItem (source, name, slot, metadata, status)`.

### API ox_inventory

ai-inventory robi `provide` dla `ox_inventory` i odpowiada na jego eksporty (ox_inventory 2.44). Ekwipunki nazywa się jak w ox: source gracza, nazwa schowka, `{ id, owner }` dla schowków osobistych, tablica dla bagażników.

- Serwer: `AddItem` (zwraca `success, response`, wywołuje `cb`), `RemoveItem`, `GetItem`, `GetItemCount`, `Search` (`count` / `slots`), `CanCarryItem`, `CanCarryWeight`, `CanCarryAmount`, `GetInventory`, `GetInventoryItems`, `GetSlot`, `GetSlotWithItem`, `GetSlotsWithItem`, `GetSlotIdWithItem`, `GetSlotIdsWithItem`, `GetEmptySlot`, `SetMetadata`, `SetDurability`, `SetMaxWeight`, `RegisterStash`, `ClearInventory`, `Items`, `ItemList`, `forceOpenInventory` (schowek, gracz, sklep), `CreateTemporaryStash`, `CustomDrop`, `RemoveInventory`, `SwapSlots`.
- Klient: `openInventory`, `closeInventory`, `Search`, `GetItemCount`, `GetPlayerItems`, `GetPlayerWeight`, `GetPlayerMaxWeight`, `Items`, `useSlot`, `getCurrentWeapon` / `GetCurrentWeapon`; `displayMetadata`, `weaponWheel`, `setStashTarget` są przyjmowane i nic nie robią.
- Bez odpowiedzi: hooki (`registerHook`, `removeHooks`), `UpdateVehicle`, `ConfiscateInventory` / `ReturnInventory`, `GetContainerFromSlot`, `RegisterShop` (sklepy pochodzą z panelu).

### API qb-inventory

ai-inventory robi `provide` dla `qb-inventory` (API 2.0). Zwracane przedmioty mają oba kształty: `count` / `metadata` i `amount` / `info`.

- Serwer: `AddItem(identifier, item, amount, slot, info)`, `RemoveItem`, `HasItem` (nazwa, lista albo `{ name = amount }`), `GetItemCount`, `GetItemByName`, `GetItemsByName`, `GetItemBySlot`, `CanAddItem`, `GetFreeWeight`, `GetSlots`, `ClearInventory`, `SetItemData`, `CreateInventory`, `OpenInventory`, `OpenInventoryById`, `RemoveInventory`, `CloseInventory`.
- Klient: `HasItem`, `CloseInventory`.
- Bez odpowiedzi: hooki i listenery, `CreateShop` / `OpenShop`, `SetInventory`, `GetInventory`, `SaveInventory`, `LoadInventory`, `UseItem`, `GetFirstSlotByItem`, `GetSlotsByItem`, `GetTotalWeight`.
