Tu script no tiene que ser un script `ai-*` para funcionar con AI Core. Lo que debes hacer depende de lo que estés escribiendo:

| Lo que tienes | Qué hacer |
| --- | --- |
| Un script escrito para ESX, QBCore, Qbox o vRP | Nada. AI Core provee `es_extended`, `qb-core`, `qbx_core` y `vrp` y responde su API, así que el script funciona sin cambios. Ver [Compatibilidad](/es/docs/compatibility). |
| Tu propio resource nuevo (Lua, TypeScript o JavaScript simple) | Cargar la lib y llamar a AI Core a través de ella. De eso trata esta página. |
| Un script que **provee** algo que otros scripts necesitan (un inventario, un teléfono, un sistema de llaves, un garaje, un script de combustible...) | Lo mismo que arriba, más un adaptador en esa capa para que el resto del servidor lo alcance. Ver [Scripts recomendados](/es/docs/developers/recommended-scripts). |

El objetivo en una frase: **todo lo que tu script comparte con otro script pasa por la lib o por ai-core, nunca por los exports de ese script.** Así el propietario puede cambiar el inventario, el sistema de llaves o el teléfono y tu script sigue funcionando.

## Cargar la lib

<Steps>
<Step>

### Lua

```lua title="fxmanifest.lua"
fx_version 'cerulean'
game 'gta5'
lua54 'yes'

dependency 'ai-lib'
shared_script '@ai-lib/init.lua'

client_script 'client.lua'
server_script 'server.lua'
```

`aiLib.<name>` queda disponible en todos los archivos de tu resource. La instalación completa, qué llamadas esperan y cómo cruzan las tablas y vectores de Lua a TypeScript: [La lib para Lua](/es/docs/developers/api/lua).

</Step>
<Step>

### TypeScript

```ts title="server.ts"
import { inventory, onClientCallback } from "@aifivem/lib/server";
```

`@aifivem/lib` viene de npm: un resource fuera del workspace de AI Core la instala con `bun install @aifivem/lib @aifivem/shared`. Un resource de JavaScript simple, sin paso de build, carga `@ai-lib/dist/server.js` y usa el mismo `aiLib` global.

</Step>
<Step>

### Orden de arranque

ai-core y ai-lib arrancan antes de tu resource:

```ini title="server.cfg"
ensure ai-core
ensure ai-lib
ensure my-resource
```

</Step>
</Steps>

## Llama a AI Core, no al otro script

Cada tarea compartida tiene una sola puerta. La llamada de la lib y el export de ai-core hacen lo mismo; usa el que encaje con tu lenguaje.

| Lo que necesitas | Lua | TypeScript | Referencia |
| --- | --- | --- | --- |
| Dar, quitar, contar objetos | `aiLib.inventory.addItem` | `inventory.addItem` | [Objetos](/es/docs/developers/api/lib-server/items#inventoryadditem), [objetos de ai-core](/es/docs/developers/api/core-server/items#additem) |
| Un objeto usable | `aiLib.inventory.registerUsableItem` | `inventory.registerUsableItem` | [registerUsableItem](/es/docs/developers/api/core-server/items#registerusableitem) |
| Un alijo o una tienda | `aiLib.inventory.registerStash` | `inventory.registerStash` | [Objetos](/es/docs/developers/api/lib-server/items#inventoryregisterstash) |
| Llaves de vehículo | `aiLib.vehicleKeys.give` / `.has` | `vehicleKeys.give` / `.has` | [Vehículos](/es/docs/developers/api/lib-server/vehicles#vehiclekeysgive) |
| Aparecer un vehículo (matrícula, combustible, aspecto, llaves y asientos en una llamada) | `aiLib.spawnVehicle` | `spawnVehicle` | [spawnVehicle](/es/docs/developers/api/lib-server/vehicles#spawnvehicle) |
| Guardar en garaje o llevar al depósito | `aiLib.garages.store` | `garages.store` | [garages.store](/es/docs/developers/api/lib-server/vehicles#garagesstore) |
| El dinero de un jugador | `exports['ai-core']:AddMoney(src, 'cash', 50, 'reason')` | `core.AddMoney(...)` | [Dinero](/es/docs/developers/api/core-server/money#addmoney) |
| Dinero entre dos cuentas, en una transacción | `aiLib.money.transfer` | `money.transfer` | [money.transfer](/es/docs/developers/api/lib-server/money#moneytransfer) |
| Trabajos, bandas, servicio | `exports['ai-core']:SetJob(src, 'police', 2)` | `core.SetJob(...)` | [Trabajos y bandas](/es/docs/developers/api/core-server/jobs-gangs#setjob) |
| Quién está en línea, su nombre, su trabajo | `aiLib.online.name` | `online.name` | [Jugadores](/es/docs/developers/api/lib-server/players#onlinename) |
| Un aviso policial | `aiLib.dispatch.alert` | `dispatch.alert` | [dispatch.alert](/es/docs/developers/api/lib-server/jobs#dispatchalert) |
| La cárcel | `aiLib.prison.jail` | `prison.jail` | [prison.jail](/es/docs/developers/api/lib-server/jobs#prisonjail) |
| Un registro en el MDT | `aiLib.mdt.record` | `mdt.record` | [mdt.record](/es/docs/developers/api/lib-server/jobs#mdtrecord) |
| Revivir, curar, "está muerto" | `aiLib.medical.revive` | `medical.revive` | [medical.revive](/es/docs/developers/api/lib-server/jobs#medicalrevive) |
| El teléfono (número, correo, mensaje, notificación) | `aiLib.phone.number` | `phone.number` | [Teléfono](/es/docs/developers/api/lib-server/phone-appearance#phonenumber) |
| Un aspecto, un conjunto de ropa | `aiLib.appearance.apply` | `appearance.apply` | [appearance.apply](/es/docs/developers/api/lib-client/layers#appearanceapply) |
| Clima y hora | `aiLib.world.setWeather` | `world.setWeather` | [Mundo](/es/docs/developers/api/lib-server/world#worldsetweather) |
| Cerrar una puerta | `aiLib.doors.setLocked` | `doors.setLocked` | [doors.setLocked](/es/docs/developers/api/lib-server/world#doorssetlocked) |
| Notificaciones, barras de progreso, menús, diálogos de entrada | `aiLib.notify`, `aiLib.progress`, `aiLib.menu.show` | `notify`, `progress`, `menu` | [Interfaz común](/es/docs/developers/api/lib-client/ui#notify) |
| Una entrada del menú radial | `aiLib.radial.add` | `radial.add` | [radial.add](/es/docs/developers/api/lib-client/layers#radialadd) |
| Un comando (listado en el panel de administración, comprobado por ACE) | `aiLib.addCommand` | `addCommand` | [addCommand](/es/docs/developers/api/lib-server/commands#addcommand) |
| Una línea de log en los canales del propietario | `aiLib.aiLog` | `aiLog` | [aiLog](/es/docs/developers/api/lib-server/logs#ailog) |

Qué script responde a cada uno de estos en este servidor, y la lista de adaptadores: [Capas y el bridge](/es/docs/developers/layers). Cada función con su firma, parámetros y retorno: [Referencia de la API](/es/docs/developers/api).

<Callout type="warn">
**Nunca consultes las tablas de AI Core.** `ai_core_characters`, `ai_core_accounts`, `ai_core_character_jobs`, `ai_vehicles_owned` y las demás tablas `ai_*` son internas: los personajes, el dinero, los trabajos y los vehículos viven en memoria y se escriben según el calendario de ai-core, así que un `SELECT` directo puede estar desactualizado y una columna puede cambiar en cualquier versión. Pregúntale a ai-core - responde igual para un jugador cargado que para un personaje guardado ([personajes](/es/docs/developers/api/core-server/characters), [dinero](/es/docs/developers/api/core-server/money), [trabajos](/es/docs/developers/api/core-server/jobs-gangs)). Lo mismo vale para los archivos de datos de otro script `ai-*` (`data/*.json` de su panel de administración): son el contenido del panel, no una interfaz.
</Callout>

<Callout type="warn">
**Un citizenid no es un id de personaje.** Hay dos ids: el id del personaje (`charId`, un número) y el `citizenid` (texto) que usan los scripts de otros frameworks. Nunca conviertas uno en el otro por tu cuenta - pregúntale a ai-core (`GetCharIdByCitizenId`, `GetSourceByCitizenId`, `GetSourceByCharId`): [Personajes](/es/docs/developers/api/core-server/characters#getsourcebycitizenid).
</Callout>

## Detectar AI Core

```lua title="Lua"
local onAiCore = GetResourceState('ai-core') == 'started'
```

En TypeScript la lib lo hace por ti: `isResourceStarted("ai-core")`, o `optionalExport("ai-core")`, que es `null` mientras el resource está detenido ([exports](/es/docs/developers/api/lib-shared/exports#isresourcestarted)).

Un script que soporta varios frameworks también encuentra `qbx_core`, `qb-core` y `es_extended` arrancados, porque ai-core los provee. Ese camino funciona, pero solo alcanza lo que esas API pueden decir. Comprueba `ai-core` **antes** que los nombres de los frameworks y toma el camino de AI Core cuando esté; deja el código del framework como respaldo para otros servidores.

## Las reglas con las que se juzga tu script

Son las mismas reglas que sigue cada script `ai-*` ([Visión general](/es/docs/developers)), y lo que mira una revisión:

<Steps>
<Step>

### El servidor decide

Cada petición del cliente pasa por la puerta de la lib: un límite de frecuencia, una llamada a la vez (`lock`), una comprobación ACE y, en TypeScript, además guardas (admin, tiene personaje, cerca de un punto) y un analizador de argumentos. El dinero, los objetos y los permisos nunca cambian en el cliente, y un valor del cliente nunca se usa tal como llega: en Lua compruebas cada argumento tú mismo.

```lua title="server.lua"
aiLib.onClientCallback('myshop:buy', function(source, item)
    if type(item) ~= 'string' or #item > 32 then return aiLib.fail('CORE_ERR_ARGS') end
    if not aiLib.inventory.canCarryItem(source, item, 1) then return aiLib.fail('INVENTORY_FULL') end
    -- cobra el dinero y entrega el objeto aquí, en el servidor
    return { ok = true }
end, { rate = { count = 5, windowMs = 10000 }, lock = true })
```

[Entrada del cliente](/es/docs/developers/api/lib-server/client-input#onclientcallback), los lectores estrictos de TypeScript ([readText](/es/docs/developers/api/lib-shared/input#readtext), [oneArg](/es/docs/developers/api/lib-shared/input#onearg)) y los rechazos ([fail](/es/docs/developers/api/lib-shared/input#fail), [ActionResult](/es/docs/developers/api/types#actionresult)).

</Step>
<Step>

### Snapshot y luego deltas

Los datos vivos van una vez completos a un cliente, luego solo lo que cambió, y solo a los jugadores que lo necesitan. Sin sondeo, sin señales de "algo cambió, vuelve a pedirlo", sin tráfico en cada tick. State bags para valores por entidad y por jugador, [AreaStream](/es/docs/developers/api/lib-server/area-stream#areastream) para objetos del mundo, [state bags](/es/docs/developers/api/lib-shared/state-bags#entitystate) para el resto.

</Step>
<Step>

### Los ajustes en el panel de administración

El propietario de un servidor no debería editar Lua. La pantalla de ajustes de tu script consigue una tarjeta en el panel de ai-core con una sola llamada, así el propietario encuentra los ajustes de todos los scripts en un solo lugar:

```lua title="server.lua"
exports['ai-core']:RegisterExternalPanel({
    label = 'My script',
    icon = 'gear',
    description = 'Shops, prices and rewards',
    command = 'myscriptconfig',
})
```

Un script que no puedes modificar se lista con las líneas `ai_admin_label` / `ai_admin_command` de su `fxmanifest.lua`: [RegisterExternalPanel](/es/docs/developers/api/core-server/admin#registerexternalpanel). Los comandos registrados con `aiLib.addCommand` y las teclas creadas con `aiLib.Keybind` aparecen por sí solos en las listas de comandos y teclas del panel.

</Step>
<Step>

### Tus propios datos son tuyos

Las tablas de tu resource son tu asunto: nómbralas según tu resource (`myscript_*`) y créalas al arrancar. Los resources Lua usan ai-mysql, que sustituye a oxmysql, mysql-async y ghmattimysql (`MySQL.query.await`, `MySQL.single.await`), así que tus consultas actuales siguen funcionando. Un resource que lee la cadena de conexión por su cuenta necesita además una línea en `env.cfg`:

```ini title="env.cfg"
add_convar_permission my-resource read mysql_connection_string
```

Ver [La base de datos](/es/docs/developers/database).

</Step>
</Steps>

## Antes de publicar

- `ai-lib` (o `@aifivem/lib`) cargada, `dependency 'ai-lib'` en el manifest.
- Ningún export de otro script para objetos, llaves, dinero, trabajos, teléfono, avisos, ropa, combustible, puertas, garajes o la cárcel.
- Ninguna consulta contra una tabla `ai_*` de AI Core, y ninguna lectura del `data/*.json` de otro script.
- Cada petición del cliente con límite de frecuencia y comprobada en el servidor.
- Datos vivos como snapshot y deltas.
- Ajustes en el panel, textos en tus propios archivos de idioma ([locale](/es/docs/developers/api/lib-shared/locale#createlocale)).
- Probado con los scripts `ai-*` que toca la función y, cuando hay una capa en juego, también con la elección del servidor cambiada (otro inventario, otro sistema de llaves).
