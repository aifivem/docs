Quase todo script de FiveM é escrito para ESX, QBCore, Qbox ou vRP, então rodá-los é um objetivo principal. O AI Core não traz scripts de terceiros e não favorece nenhum fornecedor: você instala os seus.

## Três camadas

<Steps>
<Step>

### Ponte de frameworks

O AI Core fornece `es_extended`, `qb-core` e `qbx_core` e responde aos exports, core objects, player objects, callbacks, eventos e inclusões de arquivos deles (`@qb-core/shared/locale.lua`, `@es_extended/imports.lua`, `@qbx_core/modules/playerdata.lua`), então scripts escritos para ESX, QBCore ou Qbox enxergam o AI Core como seu framework e rodam sem alterações. Para scripts de vRP, o AI Core também fornece `vrp` (veja **Scripts de vRP** mais abaixo). Os menus, avisos de texto, barras de progresso e caixas de entrada deles são desenhados com a própria UI do AI Core.

</Step>
<Step>

### Camadas de integração

O AI Core e os scripts `ai-*` precisam de coisas que outros scripts fornecem. Cada categoria tem uma interface e cada script suportado é um adaptador. O AI Core detecta o script instalado na inicialização e quando scripts iniciam ou param; o painel de administração pode substituir a escolha.

| Categoria | Exemplos |
| --- | --- |
| Inventário | ai-inventory, ox_inventory, qb-inventory, tgiann-inventory e mais |
| Chaves de veículos | ai-vehiclekeys, qbx_vehiclekeys e outros |
| Dispatch (alertas da polícia) | ai-policealert e scripts de alerta |
| Celular | tgiann-phone, lb-phone |
| Roupas | ai-appearance, tgiann-clothing |
| Morte | ai-death, qbx_medical, qb-ambulancejob, esx_ambulancejob, ars_ambulancejob |
| Clima e hora | ai-weathersync, qb-weathersync, Renewed-Weathersync, cd_easytime |
| Prisão | ai-prison, qb-prison |
| Menu radial | ai-radialmenu, qb-radialmenu, ox_lib |

</Step>
<Step>

### Substitutos

Vários scripts `ai-*` respondem à API do script que substituem, então scripts de terceiros funcionam com eles sem adaptador: ai-mysql substitui o oxmysql (e também o mysql-async e o ghmattimysql), ai-inventory o ox_inventory e o qb-inventory, ai-target o ox_target, ai-voice o pma-voice, ai-chat o chat, ai-vehicles e ai-vehiclekeys os scripts de veículos do Qbox.

</Step>
</Steps>

Veja a lista de [scripts compatíveis](/pt/scripts) para saber com o que o AI Core se integra hoje.

## Scripts de vRP

O AI Core também fornece `vrp`, então scripts escritos para o framework vRP o encontram e rodam com os personagens, o dinheiro, os empregos, as gangues e o inventário do AI Core. Não há nenhuma configuração: todas as versões abaixo são respondidas ao mesmo tempo, e o AI Core reconhece cada uma pelo jeito como ela o chama.

| Versão do vRP | O que roda |
| --- | --- |
| vRP 1.0 | Scripts que usam `Proxy` / `Tunnel` com `vRP.*` e `vRPclient.*`: usuários, dinheiro, grupos e permissões, inventário e baús, identidade, fome e sede, menus, avisos de texto, notificações, blips e marcadores. |
| vRPex, Zirix, Dunko | O mesmo, mais as funções extras que esses forks do vRP 1 adicionam (`format`, `hasPermissions`, `tryBankPayment` e outras). |
| O antigo estilo de chamada do vRP 0.5 | Chamadas que passam os argumentos numa tabela com um callback, como `vRP.getUserId({source})`. |
| vRP 2 e vRP 3 | Extensões que um script carrega com `vRP.loadScript`. Cada uma roda no seu próprio sandbox dentro do AI Core: as globais dela nunca tocam outro script, e tudo o que ela registrou é removido quando o recurso dela para. |

Os menus, avisos de texto e perguntas de sim / não dos scripts de vRP são desenhados com o menu e as caixas de diálogo do próprio AI Core. Quando um script adiciona itens ao menu principal do vRP, os jogadores o abrem com **F7**; você pode trocar a tecla em **Keybinds** no painel de administração.

O AI Core foi testado num servidor rodando com sete scripts públicos de vRP: vrp_basic_mission, vrp_chests, vrp_blips, self_storages, vrp_drugfarms, vrp_worlditems e party_system.

## Instalando um script de vRP

<Steps>
<Step>

### Remova o vRP original

Agora o AI Core é o seu recurso `vrp`, então o original precisa sair. Se o seu servidor tem uma pasta `vrp` ou um driver de banco de dados do vRP (`vrp_mysql`, `vrp_oxmysql`, `vrp_ghmattimysql`, `vRP-db-drivers`), apague a pasta e a linha `ensure` dela no `server.cfg`. Enquanto algum deles ainda estiver lá, o AI Core recusa as conexões e diz qual pasta apagar.

</Step>
<Step>

### Adicione o script

Coloque a pasta do script em `resources/[standalone]/` e adicione `ensure <nome da pasta>` no `server.cfg` abaixo das linhas `ensure ai-*`, como qualquer outro script. Não edite o script: a dependência `vrp` e o include `@vrp/lib/utils.lua` dele chegam ao AI Core sozinhos.

</Step>
<Step>

### Inicie e distribua as permissões

Reinicie o servidor e teste as funções do script no jogo. Depois abra o painel de administração (**F10**) e a aba **vRP scripts** do AI Core: **Asked permissions** lista cada nome de permissão que o script pediu. Decida quem recebe cada uma, como explica a próxima seção.

</Step>
</Steps>

## A aba vRP scripts

Scripts de vRP não perguntam "esse jogador é policial?". Eles pedem nomes de permissão (`police.service`), nomes de grupo (`police`, `vip`) e ids de item (`edible|tacos`). A aba **vRP scripts**, na parte do AI Core no painel de administração, decide o que esses nomes significam no seu servidor. Cada mudança é salva na hora, sem reiniciar. A aba tem cinco cartões:

<Steps>
<Step>

### Built-in rules (regras embutidas)

Essas três chaves respondem a todo nome de permissão que nenhuma regra menciona, então muitos scripts funcionam antes de você adicionar uma única regra:

- **Job permissions go to the job**: uma permissão que começa com o nome de um emprego, como `police.service`, vai para os membros desse emprego. Com **Only while on duty** ligado, eles só a têm enquanto estão em serviço.
- **admin. permissions go to admins**: uma permissão que começa com `admin.`, como `admin.tickets`, vai para os jogadores com direitos de admin (ACE `ai.admin`).
- **player. permissions go to everyone**: uma permissão que começa com `player.`, como `player.phone`, vai para todos os jogadores.

</Step>
<Step>

### Asked permissions (permissões pedidas)

Cada nome de permissão que os seus scripts pediram, com uma caixa de busca. Aperte **Add rule** ao lado de um nome e uma regra para ele aparece no topo de **Permission rules**. Uma regra nova dá a permissão só aos admins, até você escolher quem deve tê-la.

</Step>
<Step>

### Permission rules (regras de permissão)

Uma linha por regra. Em **Permission name**, escreva a permissão (`police.service`), ou um nome terminado em `*` (`police.*`) para cobrir todas as permissões que começam assim. Em **Who has it**, escolha uma opção:

- **Members of a job**: escolha o emprego e o **Lowest grade** (esse cargo e todos acima dele). Ligue **Only on duty** se eles só devem tê-la em serviço.
- **Members of a gang**: escolha a gangue e o cargo mais baixo.
- **Characters in a group**: escreva um nome de grupo que os scripts dão (veja **Group names**).
- **Admins** ou **Everyone**.

Várias regras podem citar a mesma permissão: quem se encaixa em qualquer uma delas a tem. Assim que uma regra cita uma permissão, as regras embutidas deixam de valer para ela. O painel recusa um cargo que o emprego ou a gangue não tem.

</Step>
<Step>

### Group names (nomes de grupo)

Scripts de vRP dão e verificam grupos pelo nome. O nome próprio de um emprego ou de uma gangue (`police`, `ballas`) funciona sem linha. Para qualquer outro nome que um script usa (`Coronel`, `sheriff`), adicione uma linha: escreva-o em **Group name** e escolha o que ele significa em **Means**:

- **A job grade** ou **A gang grade**: quando um script dá esse grupo, o personagem recebe esse emprego ou essa gangue nesse cargo; quando um script o verifica, a resposta é sim para esse cargo e todos acima dele.
- **Admins**: a verificação responde sim para jogadores com direitos de admin. Um script nunca pode tornar alguém admin: dar esse grupo é recusado.

Um nome sem linha continua sendo um grupo próprio, salvo com o personagem.

</Step>
<Step>

### Item names (nomes de item)

Ligue um id de item que um script usa (**Name scripts use**, como `edible|tacos`) a um item do seu inventário (**Inventory item**, escolhido na lista). Um id que já é o nome de um dos seus itens não precisa de linha. Sem linha, `wbody|WEAPON_X` significa o item da arma e qualquer outro id `a|b` significa `b`.

</Step>
</Steps>

<Callout>
Exemplo: um script de polícia pede `police.service`, mas o seu emprego de polícia se chama `lspd`. Adicione uma regra de permissão com o nome `police.service`, **Members of a job**, o emprego `lspd`, cargo mais baixo 0 e **Only on duty** ligado. Agora todo policial em serviço tem a permissão.
</Callout>

## O que não funciona com vRP

- **Creative v5.** A API dele (nomes em PascalCase, `@vrp/lib/Utils.lua`, `@vrp/config/*.lua`) é diferente e não é respondida.
- **SQL nas tabelas próprias do vRP.** O AI Core guarda os próprios dados, então um script que lê ou grava `vrp_users`, `vrp_user_identities`, `vrp_user_data`, `vrp_srv_data` ou tabelas parecidas com as próprias consultas não encontra nada.
- **Módulos do vRP que o AI Core não tem:** agenda do telefone, casas, empresas, veículos próprios e garagens, aptidões, fichas policiais e prisão, lojas, transformadores de itens, caixas eletrônicos, áudio e rádio, barras de progresso, bans e whitelist, e as missões do vRP 1 (as missões do vRP 2 / 3 funcionam). Um script que os usa perde essa parte.
- **Os menus não têm esquerda / direita.** Opções que mudam um valor com as setas só aceitam uma escolha simples.
- **`vRP:playerSpawn` dispara uma vez por carregamento de personagem**, não depois de um respawn: os respawns são do script de morte.
- **`vrp` sempre aparece como iniciado.** Um script que suporta vários frameworks e verifica o vRP primeiro usa o código de vRP dele. Se você quer o código de ESX ou QBCore, escolha esse framework na config do próprio script.
- **Uma extensão de vRP 2 / 3 roda dentro do AI Core**, então o tempo de CPU dela aparece em `ai-core` no `resmon`. Se ela falhar, o console escreve uma linha com o arquivo dela e o AI Core continua rodando.

## Substituindo um script ai-*

Se você instalar um script pago que substitui um `ai-*` (por exemplo, outro inventário), o AI Core diz qual pasta apagar e recusa conexões enquanto os dois estiverem rodando, para que dois scripts nunca briguem pela mesma tarefa.

## Adicionando um script

Dar suporte a um novo script é um trabalho pequeno e repetível: copie o modelo de adaptador da categoria, preencha as chamadas e adicione uma linha ao registro. Você pode pedir para sua IA fazer isso.
